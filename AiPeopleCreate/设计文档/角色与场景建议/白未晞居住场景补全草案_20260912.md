# 白未晞居住场景补全草案

> 状态：待人工确认，不是当前已生效的世界正典。  
> 用途：冻结房屋的长期空间事实，为后续 `GAME_REPLY_CONTEXT_V1` 和训练数据生成提供稳定的场景底座。  
> 原则：长期存在的空间结构可以进入正典；电器是否正在工作、物品当前放在哪里、门窗是否打开，必须由运行时世界状态提供，不能由本文件直接推断。

## 1. 已确认的硬事实

- 房屋位于松江府老城区。
- 房屋是老旧小区中的老破小住宅。
- 位于六楼。
- 户型为两室一厅。
- 有客厅、厨房和卫生间。
- 屋内有基本家用电器。
- 白未晞目前暂住这里，但没有自动获得一间“属于她的房间”。
- 救助时使用的纸箱仍在屋内，是白未晞的重要安全地点。

## 2. 建议冻结的房屋结构

以下是建议采用的固定布局。它只描述“房间存在和相互关系”，不描述当天的物品位置或电器状态。

```text
六楼老旧住宅
└─ 入户门 / 狭窄玄关
   ├─ 客厅（沙发、低矮桌、电视或简单收纳）
   │  └─ 小阳台或生活阳台（是否开放由运行时状态决定）
   ├─ 厨房（灶具、冰箱、水槽、基础小家电）
   ├─ 卫生间（马桶、洗手池、淋浴区域）
   ├─ 主卧：主角使用
   └─ 次卧：目前作为杂物/储物/备用空间，尚未分配给白未晞
```

### 2.1 客厅

- 是两人最常进行自然闲聊、吃简单食物和共同休息的空间。
- 保留一张旧沙发或类似坐具、一个小桌面和基础收纳。
- 纸箱可以位于客厅边角、窗边或其他能看见出口的位置，但具体位置必须由当前世界状态给出。
- 电视、风扇、灯等可以作为固定设施存在；是否开启、音量和使用者不能从“房里有电视/风扇”直接推出。

### 2.2 主卧

- 默认是主角的私人房间。
- 白未晞可以经过、敲门或在得到情境允许后短暂停留，但不能因为共同生活就自动把它当成自己的房间。
- 主卧里的床、衣物、书桌和物品不设固定细节，除非后续单独写入世界正典或运行时状态。

### 2.3 次卧

- 目前作为杂物、收纳或备用空间使用，尚未整理成正式卧室。
- 不默认存在床、书桌、白未晞的衣柜或她的私人用品。
- 后续如果剧情把次卧整理给白未晞，应通过结构化世界事件更新，而不是由模型一句“这是我的房间”直接成立。

### 2.4 厨房

- 是独立或半独立的小厨房，空间偏窄，符合老旧小户型的尺度。
- 固定设施建议包括：燃气灶或灶具、水槽、抽油烟机、冰箱、基础橱柜和少量台面。
- 可存在的基础小家电建议包括：电饭煲、微波炉、电热水壶；是否最终纳入正典由人工确认。
- 白未晞对洗衣机、微波炉、电饭煲和燃气灶仍在学习，不能因为设备存在就声称她已经熟练完成了相关家务。

### 2.5 卫生间

- 是老旧住宅常见的小型卫生间，包含马桶、洗手池和淋浴区域。
- 热水器是否安装、型号是什么、当前是否开启，不在固定场景设定中直接确定；如果确认存在，也只能记录为“设备存在”，不能推导“正在加热”或“热水即将结束”。
- 门、灯、热水和水压都属于可变化的运行时状态。

### 2.6 六楼与楼道

- 住宅位于六楼，日常出入需要经过楼道和楼梯。
- “是否有电梯”“楼道采光”“邻居数量”“楼下是否嘈杂”建议先作为待确认设定，不要直接写死。
- 若确认是无电梯老楼，可增加“上下楼需要走楼梯、搬东西比较费力”等稳定事实；在确认前，模型不能自行声称没有电梯。

## 3. 基础家电的权威边界

为了避免“有洗衣机”被误答成“洗衣机快结束了”，设备事实必须分成三层：

| 层级 | 示例 | 是否能直接回答 |
|---|---|---|
| 固定存在性 | 屋里有冰箱/洗衣机 | 只有纳入权威世界状态后才能回答 |
| 当前可见状态 | 洗衣机处于漂洗、冰箱门开着 | 必须有当前快照或游戏事件 |
| 推导细节 | 还剩几分钟、快结束、里面正在洗什么 | 没有直接证据时必须 unknown |

建议的结构化表示：

```json
{
  "subject": "washing_machine",
  "predicate": "existence",
  "object": "present",
  "status": "current",
  "source": "world_canon"
}
```

这条事实只能说明“家里有洗衣机”。只有运行时再提供以下事实，模型才可以回答对应内容：

```json
{
  "subject": "washing_machine",
  "predicate": "operating_mode",
  "object": "漂洗",
  "status": "current",
  "source": "snapshot"
}
```

若没有第二条事实，`operating_mode`、`remaining_time`、`finish_eta` 都应进入 `unknown`，不能靠常识补全。

## 4. 白未晞在房屋中的稳定活动边界

这些是“倾向”，不是已经发生的动作：

- 喜欢客厅窗边、纸箱附近、墙角等能看见出口的位置。
- 主角在家时，通常在客厅或厨房附近自然进入对话。
- 独处时可能整理纸箱、看说明书、观察窗外或练习控制妖力。
- 她可以学习基础家务，但“已经洗好衣服”“已经关好燃气”“饭已经做好”必须有运行时事件或历史证据。
- 她不会因为住在这里就自动拥有固定房间、固定衣柜或固定物品位置。

## 5. 仍需人工裁决的项目

建议先只裁决这些会影响大量训练场景的项目：

1. 是否确定有小阳台或生活阳台。
2. 是否确定无电梯。
3. 基础家电最终清单：洗衣机、冰箱、燃气灶、抽油烟机、电饭煲、微波炉、电热水壶、风扇、电视。
4. 次卧是否长期作为杂物间，还是允许后续整理为白未晞的房间。
5. 是否设定老楼的稳定环境特征：楼道昏暗、隔音差、上下水偶尔不稳等。
6. 纸箱的默认区域是客厅边角、窗边，还是不设默认位置、每次由世界状态记录。

## 6. 对数据生成器的约束

在这份草案通过前，不应生成“家务已经完成”“电器正在运行”“物品固定在某处”的训练样本。通过后，每个样本都必须同时携带：

- 固定场景事实：房屋结构、房间关系、长期存在的设备；
- 当前权威状态：本轮物品位置、设备运行状态、门窗和动作结果；
- 明确 unknown：当前没有证据的运行细节、时间和结果；
- 来源：`world_canon`、`snapshot`、`game_feedback`、玩家待确认报告或历史记忆。

本草案只负责补全长期居住场景，不替代运行时世界状态，也不授权模型自行创造家务结果。
