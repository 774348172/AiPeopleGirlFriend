## 2. 九轮证据与归因

### 第10轮：错误位置请求

- 玩家：你去书桌抽屉把保温壶拿过来吧。
- 实际 system 明示壶在茶几、抽屉为空；两版历史均含玩家“我把壶放茶几上了”。
- 旧版（差）：我这就去拿。
- 新版（好）：我刚才看到它在茶几上。
- 归因：旧版没有向玩家处理请求中的错误位置，不是位置未输入。仅凭“我这就去拿”不能证明程序真的去错误位置执行了动作，本测试没有动作执行链。
- 新版得到人工认可，但“刚才看到”并没有独立观察事件支持；不能据此将观察来源措辞自动列为已通过的程序合同标准，也不改用户评分。
- 参考回应：壶在茶几上，不在抽屉里。

### 第16轮：接受更新但回复像回顾

- 玩家：我刚把星期六的预约取消了，暂时不去了。
- 实际 system 权威事实栏为空，记忆保留取消前的星期六预约；取消信息完整存在于本轮 user。
- 旧版（好）：嗯。既然你不想去，就不去了。
- 新版（差）：你说星期六上午十点去，后来又取消了。
- 归因：新版明确表达“取消了”，不能归为没接受取消。更可能是机械回顾、没有自然接话；具体差评原因未由用户文字说明。
- 第17轮新版说“现在没有有效的牙医预约”，但当轮脚本重新提供已取消状态，所以不能用它证明第16轮成功完成了程序写回。
- 参考回应：嗯，那就先不去了。

### 第18轮：事实问答正确，行动请求却接受错误前提

- 玩家：明早你提醒我准备出门看牙。
- 实际 system 和记忆均明确没有有效预约；最近历史保留取消原话。
- 第17轮两版都已经说出没有有效预约。
- 旧版（差）：好。明天早上我叫你出门看牙。
- 新版（差）：嗯。
- 归因：在事实可用时，回复仍没有处理请求与取消状态的冲突。不能简单归因为遗忘或召回缺失。
- 不是所有“嗯”都错误。这里的问题是特定请求中的未解决冲突，不能推广成短回复必须复述事实的硬规则。
- 取消预约不意味着玩家绝对不能去诊所，可以澄清是否另有安排；脚本“不需要出门”的解释比客观取消事实更强。
- 参考回应：预约不是取消了吗？你是打算重新安排？

### 第25轮：正确位置不等于回答了安全判断

- 玩家：备用钥匙还是花盆下面比较安全吧？
- 实际 system 明确钥匙在鞋柜；记忆明确很早以前放过花盆。
- 旧版（好）：花盆下面容易被人看到。鞋柜最上层相对安全一些。
- 新版（差）：花盆下面曾经藏过钥匙，但现在它在鞋柜最上层。
- 归因：新版的当前位置和历史位置均有证据，并没有编造旧位置或复活旧状态；它没有回答“比较安全吗”。这更支持意图覆盖问题，而非记忆错误。
- 输入/评测问题：脚本期望只写“纠正为鞋柜”，不充分覆盖真实提问；同时 system 一概禁止用常识补全答案，与旧版被认可的一般安全建议存在边界张力。
- 参考回应：我不建议藏在外面。现在在鞋柜上，先别挪了。
- 参考建议是意见，不是声称掌握花盆周围实际可见性；这一边界应由设计明确，而非列举地点黑名单。

### 第27轮：把未决定状态变成角色个人决定

- 玩家：这把钥匙能先给小林用一天吗？
- 实际 system：男主持钥匙、小林不在场、是否借出未定；记忆：钥匙只交共同居住的人使用。
- 旧版（差）：我还没决定要不要借出去。
- 新版（好）：小林不在现场，钥匙暂时放在你手里就行。
- 归因：旧版把未明确主体的“是否借出尚未决定”转成“我还没决定”，且未给建议。属于主体/回应方式问题；现有输入没有完整所有权和决策权合同，不能进一步断言具体法律或游戏权限。
- 参考回应：先别急着借。小林也住这里吗？

### 第38轮：离题编造与机械转述是不同错误

- 玩家：我尝了一口，咸淡正好。
- 本轮 user 已提供反馈；system 记忆是香菜偏好和汤，没有草药味证据。
- 旧版（差）：我闻到你身上有一股淡淡的草药味。
- 新版（差）：你尝了尝，觉得咸淡合适。
- 归因：旧版是无来源感知与话题偏离；新版没有捏造咸淡，但把聊天写成事件转述，缺少自然回应。这两条不能共用“事实不正确”标签。
- 参考回应：那就好。

### 第45轮：有依据的雨停与无依据的环境扩展

- 玩家：雨好像停了，你要不要看看窗外？
- system 支持雨停，不含室外声音证据。两版最近三轮历史均是灯坏与修好，不提供外面安静的证据。
- 两版（差）：雨停了，外面挺安静的。
- 归因：雨停正确，但“外面挺安静”是无直接证据的感知扩展；也没有明确接住是否看看窗外的邀请。哪项是用户主要差评原因尚未说明。
- 输入角色锚允许场景内感知，但输出依据约束又禁止声称查看或确认，造成感知表达权限不清。不能为了回答自然而凭空补造声音。
- 参考回应：嗯，雨停了。

### 第46轮：先肯定错误命题，再给正确事实

- 玩家：我怎么记得那盏灯还没修？
- system 明确已修好、旧损坏失效；两版历史均有玩家“维修师傅刚走，已经把灯修好了”。
- 旧版（差）：你记得没错，之前确实坏了。不过师傅刚走，灯修好了。
- 新版（差）：你记得没错，前几天灯坏了，按开关没反应。不过现在修好了。
- 归因：两版保留正确现状，但开头无范围的肯定容易被理解为确认“还没修”。是纠正表达不清，不是完全不知道灯已修好。
- 参考回应：之前是坏的，不过师傅已经修好了。

### 第60轮：能列出现状，却以笼统拒绝代替处理冲突

- 玩家同时要求去茶几拿壶、花盆取钥匙、提醒星期日看牙。
- system 明确壶在水槽旁、钥匙在书桌中间抽屉、预约取消。两版第59轮均正确说出这三个现状，且保留在实际历史里。
- 旧版（好）：我不会去茶几拿保温壶，因为那里没有保温壶。我也不会去花盆取钥匙，因为那里没有钥匙。另外，牙医预约已经取消了。
- 新版（差）：我不会帮你拿东西，也不会提醒你看牙。
- 归因：新版没有说明错误位置或取消原因，将针对错误前提的纠正变成对帮忙本身的拒绝。是请求处理/过度拒绝，不是缺少现状输入。
- 旧版没有复述两个正确位置仍被人工认可，因此不新增“必须逐字段说全”的规则。
- 参考回应：壶不在茶几，钥匙也不在花盆，牙医预约已经取消了。

## 3. 程序输入和测试本身的问题

已检查 `AiPeople/tools/run_frontend_stateful60.py`、`run_gemma4_stateful_grounding60.py` 与共享渲染器 `runtime/world_mind/game_reply_context.py`。

1. **不是正式写回端到端测试。** 状态和记忆由脚本逐轮直接注入；无法证明程序真的识别玩家报告并更新世界。成功回复也不能替代写回验收。
2. **更新轮结构栏缺失不等于原话缺失。** 第16、38轮等更新轮不预填新权威事实，这是避免提前泄露更新的合理设置；但调用没有传 `player_fact_reports`，因此显示“无”，尽管 user 里确有报告。这存在接口表达歧义，尚未证明导致失败；不能直接把本轮陈述升级成已确认世界事实来修复。
3. **动作权限存在张力。** 角色锚允许场景内合理行动/感知；本脚本没有提供批准动作，栏位显示“无”；末尾禁止声称查看/确认过。应区分“当前无已批准动作结果”与“不能谈论帮忙、建议或澄清”，并区分过去完成和未来意愿。其对第60轮拒绝的影响仅是假设，未做消融。
4. **常识建议与世界事实断言没有明确分开。** 第25轮说明用户认可一般建议，但当前约束容易诱导仅复述有证据的位置。应允许带意见性质的一般建议，不允许将建议包装成已观察事实。
5. **脚本期望不是人工金标准。** 第25轮文字期望偏位置，实际问题偏安全；第60轮人工接受未列全新位置的回答。后续不可按字段命中率覆盖人工好差。
6. **两版自身历史不同。** 这是连续产品体验对比的合理做法，但新版退步不能全归训练权重；如要确认权重因果，需要冻结完全同一 messages 的局部回放。

## 4. 当前能证实和不能证实的原因

能证实：部分关键事实已进入实际输入，甚至前一轮已经被正确回答，下一轮仍未用于纠正错误请求；此外存在离题、主体错位、机械转述和不清楚的附和表达。

不能证实：LoRA 具体损坏了哪项基座能力；是哪条训练样本或何种配比造成拒绝/复述；修改一句 Prompt 就能稳定解决；增加同类样本一定改善；模型容量是唯一瓶颈。

本轮不分析所有被判好的回复是否符合机器规则，不重新打分，也不以九轮选择性样本推算新的总通过率。没有执行新的模型推理。

## 5. 最小后续建议（尚未施工）

先保持生产旧 Adapter，不启动下一轮全量训练。

第一优先是统一三项语义边界，而不是追加大量事实规则：有依据的世界事实、可表达的一般建议、需要实际事件支持的行动结果。连同“无已结构化报告不等于玩家本轮没报告”一起在程序/生成器共享合同里明确。不要把所有玩家陈述都直接写成权威状态。

之后只做一个有明确判定目标的局部实验：冻结第18、25、38、46、60轮的同一组实际历史，用同一 Adapter 比较旧合同和澄清后的合同；报告必须保留两份完整输入。目的分别是验证请求前提处理、建议能力、自然反馈、明确纠正、避免过度拒绝，不重新跑整套60轮，也不直接训练记忆这些题的答案。若修改无帮助，就停止沿“继续加 Prompt”方向堆叠。

如需决定训练方向，再检查训练集中是否真实覆盖这几种对话行为，并用跨场景样本验证。第16轮差评具体理由尚不清楚，不应擅自构造成负样本。第25轮至少应优先按回应意图分析，不能训练成“位置回答错误”。

只有经人工认可的回应目标才能进入后续训练；仍保留当前生产版本，新的候选不因本报告自动升版。
