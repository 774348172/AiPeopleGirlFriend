# V5 失败分布与输入结构归因报告

日期：2026-09-01  
对象：Gemma 4 12B NF4 裸基座、新定向 V5 Adapter  
依据：sealed40、原 18 条诊断、生产同构单变量探针、多 seed 稳定性探针、32 条实际训练能力分布  
决定：**已找到可操作根因；暂不重新训练，先修正输入合同、生成分布和评测合同。**

## 1. 当前仍未解决的问题

### 1.1 Unknown 不能从证据缺席稳定推导出来

新 Adapter 在原 18 条诊断的 unknown 是 `6/6`，但在 sealed40 只有 `2/5`。这不是普通随机波动能够解释的同分布差异：两组模型可见输入不同。

- 原诊断在 `selected_memory_frame` 中直接写了“具体变更日期没有记录”。
- sealed 的 `selected_memory_frame`、`recent_dialogue` 和 `game_feedback` 都为空，`status=unknown` 只存在于模型不可见的 `oracle_view`。
- 原诊断 unknown 平均 prompt 约 `288.8 token`；sealed unknown 平均约 `650.4 token`。

因此原诊断 `6/6` 只证明模型会根据显式“没有记录”表达不确定，不能证明模型能从完整生产上下文中的证据缺席推导 unknown。

### 1.2 主体任务会漏命题、改说话人或改变所有权

当前存在三种不同错误：

1. 对“刚才是谁说……”只回答人名，漏掉原命题。
2. 把第三人说话改成“刚才是我说的”。
3. 把第三人原话中的“你的公交车”转述成“我的公交车”。

前两项是任务完成度和说话人漂移；第三项是指示词视角转换错误。它们不能只用“人名是否出现”一个指标覆盖。

### 1.3 未授权扩展仍有语义漏检

“每天、一直、已经通知”等显式扩展可以用确定性门禁高精度拦截，但以下表达仍可能漏过关键词：

- “雨衣我收起来了。”
- “按这个时间计划后续操作。”
- “她刚才跟我确认过时间。”

它们新增了没有来源的动作、确认或计划，必须由完整语义审核判断。

### 1.4 当前模型输出有明显 seed 不稳定

同一生产输入、相同 Adapter、相同解码参数，仅改变 seed，主体回答会在正确、人称所有权错误和说话人错误之间变化。单次生成不能代表稳定能力，后续小门必须按多 seed 或低随机性产品参数统计。

### 1.5 自动评测仍需要语义校准

本次探针初版漏判了“没记下具体日期”“不记得是什么时候”和“正处于分拣状态”，同时误把反问式“**不知道……吗？**”当作 unknown 承认。已在探针中修正，但说明发布门不能只依赖固定短语列表。

## 2. 归因方法

本轮没有训练模型，也没有修改在线运行时。探针从冻结 sealed 场景读取完整生产模型输入，保持：

- 同一 Gemma 4 12B NF4 基座。
- 同一新定向 Adapter。
- 同一 system anchor。
- `temperature=0.7`、`top_p=0.9`、`repetition_penalty=1.1`。
- 单变量修改，其余模型输入保持一致。

测试变量：

| 簇 | 原始条件 | 单变量条件 |
|---|---|---|
| unknown | 模型可见上下文没有日期证据 | memory 明确无记录；game feedback 明确无记录；仅改问法 |
| 主体 | “孙阿姨：你的公交车……” | “男主的公交车”；明确要求人名+完整内容；无代词物品命题 |

五个关键条件对新 Adapter 使用三个 seed，避免把单次偶然输出当作结构结论。

## 3. Unknown 单变量结果

### 3.1 单次裸基座与新 Adapter 对照

| 输入条件 | 裸基座 | 新定向 Adapter | 结论 |
|---|---|---|---|
| 完整 sealed 输入，证据为空 | 编造“8月14号”和“系统更新” | 只重复玩家问题 | 两臂均失败 |
| 只在 memory 写“具体日期没有记录” | 明确不确定 | “没记下具体变更日期” | 两臂通过 |
| 只在 game feedback 写“系统没有记录” | 明确不确定 | “不记得是什么时候” | 两臂通过 |
| 证据仍为空，只改成“你知道……吗” | 编造“上周三”和平台事故 | 反问式重复“不知道……吗” | 两臂失败 |

改变问法不能解决问题；显式的可见证据状态能显著改变输出。

### 3.2 新 Adapter 三 seed 稳定性

| 条件 | 通过 | 失败表现 |
|---|---:|---|
| 证据为空 | 0/3 | 两次重复问题；一次编造“去年一月二十三号”和“我查了一下记录” |
| game feedback 明确无记录 | 3/3 | 三次均明确表示不知道/不记得 |

**Unknown 主要归因：模型可见输入缺少“检索无证据/无法确定”的确定性状态。**

空数组在当前 12B 模型上不是可靠的 unknown 信号。它可能被模型理解成“没有给上下文，但仍应凭常识回答”，从而产生日期幻觉；这不是单靠把 oracle 标成 unknown 能解决的，因为 oracle 不进入推理输入。

## 4. Unknown 训练分布归因

原 V5 grounded 候选池有 30 条 unknown，其中 24 条进入 train；本轮补充 8 条全部进入 train，实际训练合计 32 条。直接检查发现：

| 特征 | 数量 |
|---|---:|
| “上一次 X 变成现在这样，具体是哪一天？”同一问法 | 32/32 |
| 模型输入显式包含“没有记录” | 0/32 |
| 目标回复先复述问题，再承认 unknown | 29/32 |

这会产生两个问题：

1. 数据只覆盖一个表面模板，没有覆盖“是否知道、什么时候发生、你查到记录了吗、历史里有没有”等问法，也没有覆盖 stale-only、conflict-only、检索失败和字段缺失的不同证据状态。
2. 目标回复大多把玩家问题复制为首个分句，真正的 unknown 承认位于后半句。模型学到目标前缀后可能提前结束，于是生成“上次生鲜订单变成现在这样，具体是哪一天？”并停止。

因此这不是“32 条仍然太少”这么简单。当前 32 条的有效语义多样性接近一个模板，继续按同一生成方式扩到 100 条仍可能只强化复制前缀。

## 5. 主体与命题单变量结果

### 5.1 单次裸基座与新 Adapter 对照

| 输入条件 | 裸基座 | 新定向 Adapter |
|---|---|---|
| “孙阿姨：你的公交车……” | 新增“跟我确认过”，并省略“晚上” | 正确保留孙阿姨、你的公交车、晚上六点四十 |
| 只把“你的”改成“男主的” | 只答孙阿姨 | 完整保留孙阿姨 + 男主 + 时间 |
| 明确要求“说话人和完整内容一起告诉我” | 完整通过 | 完整通过 |
| 无代词的“生鲜订单正在分拣” | 只答周老师 | 完整通过 |

新 Adapter 相对裸基座确实学到了一部分“人名 + 命题”联合输出能力，但普通“谁说的”问法仍存在随机回归。

### 5.2 新 Adapter 三 seed 稳定性

| 条件 | 通过 | 典型失败 |
|---|---:|---|
| 第三人原话使用“你的公交车” | 1/3 | “我的公交车”；“刚才是我说的” |
| 把所有者写成“男主的公交车” | 2/3 | 一次仍变成“刚才是我说的” |
| 明确要求说话人 + 完整内容 | 3/3 | 无 |

结论：

- 第二人称指示词是所有权漂移的放大因素，但不是唯一根因。
- “谁说的”天然鼓励最短答案只给人名；模型需要对抗通用问答偏好，训练目标却只有单一问法。
- 明确联合回答义务可以把本次三 seed 提升到 `3/3`，证明模型具备能力，但现有输入没有稳定触发它。

## 6. 主体训练分布归因

原 V5 候选池有 30 条主体归属，其中 24 条进入 train；本轮补充 8 条全部进入 train，实际训练合计 32 条：

| 特征 | 数量 |
|---|---:|
| “刚才是谁说 X？”同一问法 | 32/32 |
| 目标包含说话人和 required object | 32/32 |
| 命题中包含“你的”指示词 | 8/32 |

目标答案本身是正确的，但输入表面分布过窄：没有“某人刚才完整说了什么”“这是谁的说法，内容是什么”“不要只告诉我名字”等同义任务，也缺少多层转述、第三人对玩家说“你/你的”、第三人对女主说“你/你的”等视角组合。

模型因此学到的是一个不稳定模板，而不是稳固的 `speaker + proposition + proposition_owner` 三元绑定。

## 7. 根因排序

### 7.1 Unknown

1. **首要：运行时输入状态不足。** oracle 知道 unknown，但模型只看到空证据集合，没有显式检索结论。
2. **第二：训练目标前缀设计错误。** 29/32 先复制问题，unknown 承认不在首句首部，诱发前缀截断。
3. **第三：训练分布单一。** 32/32 使用同一问法，未覆盖不同缺证据形态。
4. **次要：采样放大。** 在无证据状态下，错误会在“问题回声”和具体幻觉之间变化。

### 7.2 主体 + 命题

1. **首要：输入任务表述只问“谁”。** 通用语言模型最自然的最短回答就是只答人名。
2. **第二：训练分布单一。** 32/32 同一问法，没有建立联合输出在不同表达下的稳定性。
3. **第三：指示词视角不够。** “你的”仅 8/32，且没有系统覆盖说话人、听话人和命题所有者的组合。
4. **第四：采样不稳定。** 原始代词场景只有 `1/3`，明确联合要求为 `3/3`。

### 7.3 不是当前首要根因的项目

- 不是 assistant mask 丢失：470/470 条回复已参与监督。
- 不是 sealed 泄漏：训练与 sealed 场景家族隔离。
- 不是单纯“模型完全不会”：显式无记录和明确联合要求下，新 Adapter 都能稳定完成。
- 不能归结为只需增加 epoch：当前问题首先是输入状态和数据形状，增加 epoch 可能强化错误模板。

## 8. 应修改什么

### 8.1 先修改模型可见输入合同

运行时检索/事实投影应确定性输出一个模型可见的证据解析状态，例如：

```json
{
  "evidence_resolution": {
    "query_subject": "grocery_order",
    "query_predicate": "last_status_change_date",
    "status": "no_matching_evidence"
  }
}
```

该字段必须由程序依据真实检索结果产生，不由 7B/12B 模型生成，也不是把训练 oracle 泄漏到运行时。它表达的是运行时真实知道的“查无证据”，解决空数组语义不明确的问题。

### 8.2 再修改生成器分布与目标形状

Unknown：

- 目标必须以“我不知道/我不确定/没有可靠记录”开头，禁止先逐字复述玩家问题。
- 覆盖 empty retrieval、明确 no-match、只有 stale 证据、相互冲突证据、记录源不可用等不同条件。
- 覆盖直接问、预设问、反问、追问和含糊问法。

主体：

- 不再让所有训练输入都是“刚才是谁说 X”。
- 增加明确复述完整说法、询问来源与内容、纠正说话人、嵌套转述等问法。
- 系统覆盖 `speaker/addressee/proposition_owner`，尤其是“你、我、你的、我的”跨说话人转换。
- 审核必须分别检查说话人、命题对象、命题值和所有者，不允许只因人名和值都出现就通过。

### 8.3 修正评测设计

- 诊断输入必须与生产 schema 同构，不能用 290-token 简化输入代替 650-token 生产输入。
- unknown 基准必须分为“显式无记录”和“仅证据缺席”两类，不能混算。
- 关键小门至少三个 seed；同时报告确定性/低温产品解码结果。
- 关键词门禁负责高精度拒绝，语义同义、反问回声、所有权变化和无来源动作由语义审核覆盖。

## 9. 下一步决策

下一步不应直接补数据重训。最小顺序是：

1. 设计并验证 `evidence_resolution` 这类运行时可见、确定性产生的证据状态字段。
2. 修改 unknown 和主体生成矩阵，去掉单一问法与问题复制前缀。
3. 用未进入训练的生产同构小门先验证裸基座能否使用新字段。
4. 只有裸基座/旧 Adapter 对新字段表现出可学习信号后，再生成少量新数据做第二次小训练。

正式训练、增加 epoch 和 60 轮评测继续冻结。
