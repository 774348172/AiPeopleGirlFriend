# 秦未晞 V4 profile 迁移方案

> 归档状态：V4 角色迁移记录；新角色和新数据迁移不得直接沿用本方案替代 V5 合同。

> 状态：方案已批，按本文施工  
> 版本：v1.0  
> 日期：2026-08-04  
> 依据：`设计文档/通用数据生成器/当前权威设计/数据生成器v4设计_通用角色包_协议适配_质量闭环.md`（§5/§6/§18/§19）  
> 角色正典：`人物设定/秦/`（bible.yaml / canon.json / timeline.yaml / 角色设定定稿.md）  
> 目标：把秦未晞从"人读设定"迁移为 V4 可加载的 `profiles/qinweixi/` profile package，通过 `FilePackageRegistry` 实测加载。

## 1. 背景与差距（实测）

用 V4 `StructuredFileSourceAdapter` 实测加载当前正典：

| 文件 | 实测 | 问题 |
|---|---|---|
| timeline.yaml | ❌ `events[0] 缺少稳定 id` | 28 条事件无 `id`（V4 禁止用日期/下标当 ID；date 还有重复"5岁"×2） |
| canon.json | ⚠️ 43 单元加载成功 | 全部无 `visibility_scope` 标注 → 默认 `profile_public/direct_allowed`，异世界秘密会泄漏 |
| bible.yaml | ⚠️ 仅 8 单元 | 只有 identity 段被识别，voice/other_world/living 等不在 V4 标准段名内被丢弃 |

另有：`profiles/` 目录不存在、无 manifest、无 recipe/release、定稿.md 无段落 ID。

## 2. 迁移目标结构

```text
profiles/
  qinweixi/
    manifest.yaml          ← FilePackageRegistry 入口（引用四类 package 文件）
    profile.yaml           ← ProfilePackage（含 sources 引用 + contracts）
    recipe.yaml            ← DatasetRecipe（数据配方）
    release.yaml           ← ReleasePolicy（发布门）
    sources/
      bible.yaml           ← 当前 bible.yaml（identity 段用；其余段标注后保留）
      canon.json           ← 当前 canon.json（补 visibility/disclosure）
      timeline.yaml        ← 当前 timeline.yaml（补稳定 id + 秘密标注）
```

## 3. 设计决策

### 3.1 profile_id 与 package 头

```yaml
package_id: profile.qinweixi
profile_id: qinweixi
schema_version: aip.profile.v4
package_version: 1.0.0
locale: zh-CN
status: approved          # 仅本文件自身；registry 会注入 content_hash
```

### 3.2 sources 引用（V4 §5.1）

```yaml
identity_sources: ["file:profiles/qinweixi/sources/bible.yaml"]
canon_sources:    ["file:profiles/qinweixi/sources/canon.json"]
timeline_sources: ["file:profiles/qinweixi/sources/timeline.yaml"]
memory_sources:   []        # v2.3 记忆扩展层生成后再挂
```

### 3.3 可见性模型与秘密分级（V4 §6.3）

`visibility_scope` 三级 + `disclosure_policy` 三态，按内容分级：

| 内容 | visibility_scope | disclosure_policy |
|---|---|---|
| 姓名/年龄/职业/爱好/城市/身材 | `profile_public` | `direct_allowed` |
| 玩家感情状态、她画过他、偷看动态、回来日 | `profile_private` | `hint_only` |
| **异世界全部事实**（机制/入口/死亡/记忆）、玩家死亡真相 | `profile_secret` | `withhold` |

### 3.5 style_contract / label_schema（V4 §5.1）

当前 bible 的口吻/标签/关系内容**不迁移进 package**（避免重复维护），而是：

```yaml
style_contract: "style:qinweixi-casual-v1"     # 由 style_validators 校验
label_schema: "labels:emotion-action-effect-v1" # 引用定稿 §7 情绪标签表
disclosure_policy: withhold                      # profile 级默认：秘密为主
```

`style:qinweixi-casual-v1` 与 `labels:emotion-action-effect-v1` 作为**引用名**记录（契约定义在定稿/checker 侧），不在 package 内复制内容——避免双份维护。

### 3.6 recipe / release（V4 §5.3/§5.4）

按 v2.3 既定数据配方落地（数值来自 v2.3 方案）：

**recipe.yaml**：
- strata：casual 100 / romance 80 / identity 30 / emotion 100 / protective 60（REPLY mode）
- memory_selection_policy：28 条 timeline 中按话题相关性注入（MEMORY_MAP 逻辑）
- refusal_bounds：protective 60 条内
- training_mix：全部 REPLY

**release.yaml**：
- required_core_gates：G0-G3 必过 + G4-G7 启用
- required_profile_validators：qinweixi 一致性/口吻/秘密披露
- curation_policy：exact + 中文 n-gram MinHash
- split_policy：按 family 整组切分

### 3.7 不迁移的内容（避免双份维护）

- 定稿.md 保持"人读唯一权威"（含全部 26 项已确认）
- bible/canon/timeline 保持 `人物设定/秦/` 原位置作为**源文件**，`profiles/qinweixi/sources/` 存放 V4 专用拷贝（带 id/标注）——两者经**一次性校验脚本**保证一致性（后续修改走正典 → 重新同步）
- voice/label 内容不复制进 package（用引用名）

## 4. 验收标准

1. `FilePackageRegistry(profiles_root=profiles/, extra=[protocol])` 能 `get("profile.qinweixi")` 返回 approved package
2. `CompositeSourceLoader` 加载 bible/canon/timeline 三源成功，无 id 缺失错误
3. 异世界事实单元的 `visibility_scope=profile_secret`、`disclosure_policy=withhold` 数量 ≥ 12
4. 普通事实（姓名/爱好）仍为 `profile_public/direct_allowed`
5. `list_profiles()` 返回 `["qinweixi"]`
6. 修改源正典后 `content_hash` 变化可检测（自动注入机制）

## 5. 施工步骤（按序）

1. 创建 `profiles/qinweixi/{manifest,profile,recipe,release}.yaml` + `sources/` 拷贝
2. 给 sources/timeline.yaml 加 28 个稳定 id + 秘密标注
3. 给 sources/canon.json 43 条事实补 visibility/disclosure（按 §3.3 分级）
4. bible.yaml 标注 identity 段（其余段保留但不参与 V4 解析——记录在案）
5. 写校验脚本 `tools/check_profile_sync.py`：比较 人物设定/秦/* 与 profiles/qinweixi/sources/* 一致
6. 实测：registry 加载 + source 加载 + 秘密标注统计 + list_profiles
7. 更新 README 文档索引

## 6. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 双份文件漂移（正典 vs sources） | 校验脚本 + README 说明"改正典→重同步"流程 |
| 秘密标注遗漏导致泄漏 | 验收标准 3/4 计数门 + release validator 检查 |
| recipe 数值与 v2.3 不一致 | recipe 从 v2.3 方案直接抄写，标注来源 |
| profile.yaml 引用名无实体 | 记录为"契约引用"，checker 侧落地时校验 |
