## 1. 方法论边界（本文结论的可靠性分级）

本文的每条问题都标注了证据类别，防止再次出现"用 295 条盲评倒推 v4"的方法论错误：

| 类别 | 含义 | 用途 |
|---|---|---|
| **A 类：直接事实** | 在 v4 代码、sqlite 记录、2500 条 jsonl 上直接验证到的内容 | 构成问题清单的主体，独立成立，不依赖盲评 |
| **B 类：机制推论** | 盲评证明"机制 X 在 4B LoRA 上导致失败 Y"（295 条模型上成立）；本文在 v4 侧验证机制 X 存在 → 推断 v4 有同类风险 | 是"证据支持的假设"，不是结论；必须由 v4 训练 + 同口径评测确认 |
| **C 类：不作为证据** | 盲评的胜负数、分数本身 | 仅用于确定"哪些行为是产品验收项"，不用于断言 v4 数据或 v4 模型已坏 |

**明确声明：40 条盲评回答的是"295 条旧 v1 会话训练出了什么"，不回答"2500 条 v4 会怎样"。本文所有问题均先在 v4 侧验证后才列出；凡属 B 类推论均显式标注，不得当作已证事实。**

**范围边界**：本文评审覆盖 REPLY 生成链路（data_gen_v4 核心 + 秦 profile 包 + 训练打包 + 运行时 prompt + 2500 条数据）。运行时记忆召回链路（`relationship_runtime.py` / RECALL_PLAN / MEMORY_PROPOSE）经核查仅确认两点：实现存在、但**全部 sqlite 存档 2348 条候选 100% 为 REPLY 模式，记忆模式从未生成过训练数据**（P2-6）；其内部设计不在本文评审范围（与 CHAT-02E 诊断 §2 口径一致：不评价尚未接入的记忆整理与召回系统）。

## 2. 问题清单

### P0：决定训练路线正确性的问题（不修则新数据训出来仍然错）

#### P0-1 训练锚渲染损坏："你是 qinweixi"、未解析的 style 引用、元注释直插
- **现象**：2500/2500 条样本的 system 锚为：
  ```
  你是 qinweixi。以下事实与口吻是你的人格锚（训练与推理共用）：
  【身份与关键事实】
  - 秦未晞
  - 2004-11-07
  ...
  【风格合同】
  style:qinweixi-casual-v1        ← 未解析的引用 token，原样进入训练文本
  ```
- **证据（A 类）**：`renderers.py:38-57` 用 `profile.get("profile_id")` 当角色名（"qinweixi"而非"秦未晞"）；`style_contract` 原样直插（生成 prompt 有 resolver 解析、训练锚没有）；facts 列表含元注释"（南京古称的虚构写法，与玩家同城合租）"、重复项（"秦未晞"两次、"11月7日"与"2004-11-07"并存）；2500 条 jsonl 逐条验证命中。
- **影响**：身份行本身是错的（角色名是罗马化 ID）；模型从锚中学不到"你是秦未晞"；称呼混淆的根因之一就在锚本身；每样本重复 10+ 条身份事实（P1-3 诊断的放大来源）。
- **类别**：A。

#### P0-2 训练锚与运行时锚是两份不同文本（train/inference mismatch）
- **现象**：训练锚 = 生成器自动渲染（身份字段列表 + 输出协议）；运行时锚 = `runtime/_prompt.py:9-25` 手写（含"严肃时正确和清楚优先"、"不知道时坦率说明不得编造"、"召回证据只是引用不得补造"、【角色信念】三观段）。训练锚 0/2500 含【角色信念】，运行时锚有。
- **证据（A 类）**：`renderers.py:8` 声称"与生产推理一致"，实际逐段比对完全不一致；`qin_v4_2500.jsonl` system 段 vs `runtime/_prompt.py`。
- **影响**：诊断 P0-1/P0-2/P0-3 要修的行为（严肃优先、未知保持、证据边界）只进了运行时 prompt，模型在推理时**第一次见到**这些规则；2500 条数据即使训完，这些行为只能靠 prompt 硬顶，数据学不到。输出协议（15-80 字、标签前缀）也与运行时"回复通常自然简短"不一致，且数据里根本没有标签前缀。
- **类别**：A。

#### P0-3 质量门 G0–G7 从未在生产链路执行（§14 全空转）
- **现象**：`release.yaml` 声明 `required_core_gates: G0–G7`、`human_review_rules`（protective 100% 人工审核）、`metric_thresholds`（`otherworld_keyword_count: max 0`、`death_disclosure_count: max 0` 等）；实际全链路无一处调用。
- **证据（A 类）**：`ReleaseQualityGate` 仅被 `tests/stage5/test_qin_pipeline.py:151` 引用；`gen_qin_v4.py` 与 `engine.py` 不调用；全部 sqlite 存档（2348 candidate）**0 条 gate decision 记录**；全仓无代码读取 `metric_thresholds`。
- **影响**：生成器没有质量闭环，产出质量完全依赖教师模型自觉 + 事后人工抽检；"异世界关键词 0 泄漏"等阈值形同虚设（实测"地堡"38 条、"那一年"46 条）。
- **类别**：A。

#### P0-4 evidence_state / policy_distribution 是死配置，证据状态 97.5% 为 not_required
- **现象**：`recipe.yaml` 的 `evidence_state_distribution`（protective: supported 0.6 / insufficient 0.2 / false_premise 0.2）与 `policy_distribution` 无任何代码读取。实际 2348 条记录：`not_required` 2289（97.5%）、`insufficient` **9**（0.4%）、`false_premise` 8、`conflicted` 8、`supported` 34。且 `desired_policy` 字段**不进生成 prompt**（`reply.py:_generate` 从不读它）。
- **证据（A 类）**：`factory.py:68-91` 只读 pool 条目字段；sqlite 全量统计。
- **影响**：诊断 P0-3（信息不足保持未知）在数据层面只有约 9 条样本；"无证据不生成共同经历"（P0-2）没有负例监督；protective 的 withhold/ask_for_evidence 等策略只是标签，不产生行为约束。
- **类别**：A。

#### P0-5 事实校验是"命题自证"，不是"对正典校验"
- **现象**：`_check_semantics`（`reply.py:286-304`）只检查"模型自己写的命题是否逐字/片段出现在自己写的文本里"，不检查命题是否被 FACTS 支持；G2 证据 span 门因所有样本 `support_spans` 为空而恒 approved（`gates.py:108-110` 空 spans 直接放行）。
- **证据（A 类）**：代码逻辑；sqlite 记录中无任何 span 填充。
- **影响**：`reply_merge.txt:34`"不得新增人物、地点、物品、因果或时间"没有任何机械保障。教师模型编造的内容会原样进入训练数据——这是 v1→v4 共同的根因，也是 295 条盲评 fact_error/fabricated_reality 的机制来源（B 类推论：机制相同 → v4 有同类风险）。
- **类别**：A（机制存在）+ B（后果预期）。

### P1：决定数据质量的问题（不修则新数据是旧模式的放大版）

#### P1-1 口癖密度由生成提示词硬编码，不是数据偶然现象
- **现象**：`gen_qin_v4.py:47-80` 的 `qin_style_resolver` 把 bible voice 的 `tics`（10 个）与 `catchphrases`（"哼，谁稀罕。"等 4 条）**每轮拼进生成 prompt**。实测 2500 条：哼 35.91%（开头 23.61%）、喂 15.56%、谁稀罕 23.75%、B哥 17.91%——与诊断文档 P1-1 完全一致。
- **证据（A 类）**：代码 + 数据统计。
- **影响**：降频若只靠清洗数据，重新生成时口癖密度会原样回来；必须改生成侧 style contract 的注入方式。
- **类别**：A（机制）+ B（"模板化风险"预期）。

#### P1-2 池循环复用 → 语义模板重复是结构性的
- **现象**：池约 1000 条，casual 1200 / romance 768 靠取模循环（`factory.py:82` `pool[i % len(pool)]`），同一 topic/scene/player_view 被 2-3 个样本共享；教师模型在相同输入下（温度是唯一区分）产出高度相似对话。实测 74/2500 条首句完全重复（33 组），且同一桥段跨样本复用（"我偶尔半夜惊醒以为还在地堡"出现在样本 248 与 370）。
- **证据（A 类）**：代码 + 数据统计。
- **影响**：诊断 P2-2 的"语义模板重复"根源在此；循环复用还会放大口癖、桥段和属性朗读的条件概率。
- **类别**：A。

#### P1-3 required/forbidden behaviors 对 97.6% 的样本为空
- **现象**：pools 中只有 20 条 protective 条目带 `required_behaviors/forbidden_behaviors`；其余 2440 条（casual/romance/identity/emotion）渲染进 prompt 的【必须完成的行为】【禁止出现的命题】均为"（无）"（`reply.py:101-102`）。
- **证据（A 类）**：pools.yaml + factory 逻辑。
- **影响**：生成行为只由"场景 + 风格合同 + 教师自觉"决定；诊断 §8.1 的删除规则（属性朗读、无证据经历、严肃冒犯）没有任何生成期约束。
- **类别**：A。

#### P1-4 秘密边界无机械检查，训练数据泄漏异世界原词
- **现象**：2500 条回复中"地堡"38 条、"那一年"46 条、"灰蒙蒙"42 条、"防空洞"7 条、"废墟"8 条；其中"我偶尔半夜惊醒以为还在地堡"作为整句桥段复用。`release.yaml` 的 `otherworld_keyword_count: max 0` 阈值无人计算。
- **证据（A 类）**：数据统计 + release.yaml + 全仓 grep（G5 门无 checker 注入）。
- **影响**：与 protective 数据"withhold_without_lying"目标直接冲突；模型被训练成在普通对话里随口引用秘密场景，一旦玩家追问就面临编造或被迫揭穿。
- **类别**：A（泄漏事实）+ B（"推理时泄密"预期）。

#### P1-5 严肃场景覆盖稀疏（数据层面确认）
- **现象**：2500 条中 human 台词含"手术/去世/失眠/欠/哭/医院"关键词的仅 12 条；且既有严肃样本质量不佳（样本 248/370 均以"以为还在地堡"式桥段响应）。
- **证据（A 类）**：数据统计。
- **影响**：诊断 P0-1（严肃优先）在 v4 数据层面同样没有量；是否重演 serious_support 0:5 是 B 类假设，待 v4 训练后验证。
- **类别**：A（覆盖事实）+ B（失败预期）。

#### P1-6 生成稳定性差：约 1/3 调用失败
- **现象**：全部 run 共 4951 次调用、1181 条 failure（parse_error 672、provider_error 260、style_failure 209、internal_error 40）；含 60 次 "No module named 'openai'" 环境错误与 402 额度错误。2500 条是 8 线程并发 + 温度升温重试"凑"出来的。
- **证据（A 类）**：sqlite 记录统计。
- **影响**：不同批次样本的生成条件（重试次数、温度）不一致 → 样本质量方差大；parse_error 高说明教师输出格式不稳定，重试升温进一步加剧风格漂移。
- **类别**：A。

### P2：工程风险（不影响本轮正确性，但决定可维护性与可归因性）

#### P2-1 防泄漏 blocklist 只覆盖 CHAT-01
- **现象**：`eval_exclusions/chat01_v1.json` 仅 531 个 hash；实测 chat02 盲评 180 个问题文本仅 60 个命中。诊断 §10.1"40 条盲评题永久禁止进入训练"尚未落成文件（当前 2500 条与 chat02 无实际重叠是时间差所致，非机制保证）。
- **证据（A 类）**：hash 比对。
- **影响**：下一次生成/合并若混入 chat02 题面，防泄漏检查不会拦截。
- **类别**：A。

#### P2-2 训练参数路线分裂，结果不可归因
- **现象**：同一份 2500 条配两套互斥超参——m3_v2（MLX：3000 iters≈1.3 epoch、lr 1e-5、batch 1）vs h200（LLaMA-Factory：3 epochs、lr 5e-5（5 倍）、batch 8×2、rank 16/alpha 32）；h200 配置无 validation（`qinweixi_4b_h200.yaml` 无 eval_dataset）。
- **证据（A 类）**：两个包的训练脚本/配置。
- **影响**：两包训出的模型差异无法归因于数据或超参；诊断 §7"保留独立变量"的要求不满足。
- **类别**：A。

#### P2-3 称呼纠错走"补丁"路线，且与锚重复
- **现象**：41 条 corrections + `01_prepare_data.py` 每样本追加 NAME_CLARIFICATION；而训练锚本身已含 name_slots（"浩然（心情好时）/ B哥（平常）"），两处说法重复。诊断 P1-2 确认。
- **证据（A 类）**：代码 + 数据。
- **影响**：能修一个已知错误，但"何时用称呼/何时不叫/用户改名"等一般行为无覆盖；锚修复（P0-1）后这 41 条与澄清段是否需要保留需重新评估。
- **类别**：A。

#### P2-4 导出丢弃全部元数据，分层切分/抽样不可能
- **现象**：`export.py:27-34` 只输出 `{"conversations": [...]}`；CandidateRecordV4 中已有的 `task_type / evidence_state / desired_policy / required_behaviors / family_id / scene` 等全部丢弃。`01_prepare_data.py` 只能随机切分。
- **证据（A 类）**：代码。
- **影响**：诊断 §8.3 的元数据要求（scenario_type/evidence_scope/tone_mode 等）在训练侧不可用；验证集与训练集同源随机切（P2-1 诊断）无法从工程上修复。
- **类别**：A。

#### P2-6 记忆系统（RECALL_PLAN / MEMORY_PROPOSE）实现但从未生成训练数据
- **现象**：运行时记忆链路已实现（`relationship_runtime.py`、`_prompt.py` 召回证据注入），`structured_protocol.py` / `export.py` / `renderers.py` 定义了协议训练 mode；但全部 sqlite 存档 2348 条候选 **100% 为 REPLY 模式，0 条 RECALL_PLAN/MEMORY_PROPOSE**。
- **证据（A 类）**：sqlite 全量统计 + 全仓 grep。
- **影响**：记忆选择/召回行为目前完全靠运行时 prompt 驱动，无训练监督；"只使用注入的事实、不补造"的边界与 REPLY 数据 P0-5 是同一类风险，且记忆训练数据的生成管线尚未验证。
- **类别**：A。

#### P2-5 生成失败的错误码分类不区分基础设施与内容问题
- **现象**：provider_error（402 额度、环境缺包）与 parse_error 混在同一重试通道；`reply.py:_call_spec` 温度升温重试对内容错误有效、对额度/环境错误无效且浪费额度。
- **证据（A 类）**：`engine.py:360-367` 重试逻辑 + failure 统计。
- **影响**：批量生成时一个环境问题会污染整批样本的生成条件。
- **类别**：A。

### 3.1 P0 阶段（约 1 周，只改代码，不重新生成数据）

| # | 任务 | 目标 | 改动文件 | 验收标准 |
|---|---|---|---|---|
| P0-1 | 修复训练锚渲染 | 锚的身份行是"你是秦未晞"；style 引用被解析为实际口吻文本；去掉元注释与重复事实；补入【角色信念】 | `data_gen_v4/adapters/modes/renderers.py`、`gen_qin_v4.py` | 重新导出后 2500 条锚中 0 条含 `qinweixi` 作角色名、0 条含 `style:` 引用、0 条含"虚构写法"类元注释 |
| P0-2 | 训练锚与运行时锚统一 | 训练锚 = 运行时锚文本（`runtime/_prompt.py` 的结构与规则，含严肃优先/不编造/证据边界），由生成器渲染，禁止两处手写 | `renderers.py` + `runtime/_prompt.py` 收敛为单一事实源 | 训练锚与运行时锚静态文本 diff = 0（动态段除外）；`runtime/_prompt.py` 删除手写锚或改为引用同一渲染函数 |
| P0-3 | 接质量闭环最小版 | G5（秘密/安全关键词硬门）+ G2（span 从 facts 填充）+ gate decision 落盘；先计算 `otherworld_keyword_count` / `death_disclosure_count` 两项阈值 | `engine.py`（generate 后调用）、`gates.py`（G5 checker 注入）、`reply.py`（span 填充） | 生成链路产生 gate decision 记录；含"地堡/那一年/裂缝/废墟"且非 protective 允许样本被 rejected 或标记 needs_revision；阈值统计写入 run 报告 |
| P0-4 | evidence_state / policy 落地 | 工厂按 recipe 分布采样（insufficient ≥5%、false_premise ≥2%）；`desired_policy` 渲染进生成 prompt | `factory.py`、`reply.py`、`reply_merge.txt` | 新生成数据 evidence_state 分布 ≈ recipe 分布；prompt 在 insufficient 条目出现"证据不足，保持未知"指令；无 evidence 时禁止"上次/以前"类表述 |

### 3.2 P1 阶段（约 2-3 周，重新生成数据）

| # | 任务 | 目标 | 改动 | 验收标准 |
|---|---|---|---|---|
| P1-1 | 口癖降频（生成侧） | tics/catchphrases 从"每轮必传"改为"情境可选/概率注入"（如 30% 条目注入、其余要求克制） | `gen_qin_v4.py`（style resolver 注入策略） | 新数据开头"哼/喂/啧"率 <10%、任意位"谁稀罕"<10%；严肃/平静类 0 口癖 |
| P1-2 | 行为矩阵补齐 | 按诊断 §9 补 12 类：严肃支持、信息不足、无记忆证据、有记忆注入、普通日常、关系边界、玩家纠正、含糊与反讽、健康与安全、独立人格、安静陪伴、正典问答；每类含正例/边界/高诱惑负例 | pools/recipe 扩展 + 新增 pool 段 | 每类 ≥40 条且人工复核通过（严肃类 100% 人工）；负例类（无证据编造/越界/严肃冒犯）可溯源到 evidence_state 标签 |
| P1-3 | 打破池循环复用 | 循环轮次注入变体（换 scene/player_view/关系状态/话题角度）；或对同池条目做语义聚类后限量取 1 | `factory.py` | 同 topic 首句重复率 <1%；语义聚类报告中无跨样本整句桥段复用 |

| P1-5 | 导出保留元数据 | ShareGPT 行旁路输出 metadata 侧文件（task_type/evidence_state/desired_policy/family_id/scene）或行内扩展字段 | `export.py`、`01_prepare_data.py` | 训练包可按 scenario 分层切分训练/开发/冻结集；切分报告展示各场景占比 |

### 3.3 P2 阶段（约 1 周，工程收尾）

### 3.4 依赖关系与建议顺序

```
P0-1/P0-2（锚）→ P0-4（证据分布）→ P0-3（质量门）   ← 1 周，纯代码
        ↓
P1-1（口癖降频）→ P1-2（行为矩阵）→ P1-3（去循环）→ P1-5（元数据）
        ↓
P1-4（存量 2500 条审计）→ 重新生成数据（目标 2000-2500 条新批次）
        ↓
P2-1（防泄漏）→ P2-2（冻结路线）→ P2-3（纠错去重）→ P2-4（稳定性）
        ↓
单 checkpoint 训练 → 冻结评测 A/B（base / 旧 LoRA / 新 LoRA，profile 完全一致）
```

关键依赖：**P0-1/P0-2 必须先于一切数据重生成**（锚错了，重新生成等于复制错误）；P1-4 是对存量数据的兜底清洗，可与 P0 并行；P2-2 冻结路线必须在训练新 checkpoint 之前完成。

## 4. 验收总闸门（训练前 / 训练后）

### 4.1 数据入库前（每一条新批次必须过）

1. 每条回复通过"当前问题是否被直接承接"检查（人工抽样 + 自动承接打分）。
2. 每个过去事件引用可指向：本轮上下文 / 显式记忆输入 / 允许披露的正典——否则拒绝。
3. 严肃场景 100% 人工复核，不由生成模型自评。
4. 口癖开头率、属性字段率、称呼率、语义模板簇统计全部低于 P1 阶段设定阈值。
5. 秘密关键词（地堡/那一年/裂缝/废墟/防空洞）泄漏审计 = 0 直接泄密样本。
6. 训练 / 开发 / 冻结测试按场景来源隔离，禁止同池随机切分。
7. chat01 + chat02 全量 blocklist 强制读取，命中即排除。
8. evidence_state / policy 分布与 recipe 声明一致（差异 >2pp 则阻断）。

### 4.2 模型训练后（与诊断 §10.2 一致）

1. 固定对比 `base` / 旧 LoRA / 新 LoRA，推理 profile 完全相同。
2. 首要指标：fact_error、off_topic、fabricated_reality、serious_support 通过率。
3. 人格、关系自然、情绪、自然口语不低于当前训练模型。
4. 至少两名互不讨论评审完成盲评，再揭盲统计。
5. 若新模型只减少口癖却退回助手腔，不算通过。
6. 统计显著性阈值在评审扩充后冻结，禁止看完结果再改。

## 5. 禁止事项（本审查新增，与诊断 §12 并列执行）

1. 禁止在 P0-1/P0-2 未完成时重新生成任何数据（锚错误会复制进新批次）。
2. 禁止在未接入 G5 秘密门时发布含"地堡/那一年"等秘密词的训练包。
3. 禁止继续使用 `pool[i % len(pool)]` 循环取池补量而不做变体注入。
4. 禁止把 desired_policy/evidence_state 继续当作只记录不执行的标签。
5. 禁止 m3_v2 与 h200 两套超参同时训练同一份数据。
6. 禁止把 chat02 问题文本混入任何生成池或 blocklist 未覆盖的数据源。
7. 禁止把 40 条盲评结果作为 v4 数据"已坏"或"已好"的证据——v4 结论只能来自 v4 自己的评测。

## 6. 一句话结论

生成器与模型路线的设计文档是对的（证据状态、质量门、防泄漏、评测合同都想到了），**问题在实现层把全部"检查"降级成了"提示词软约束"**：G0-G7 不执行、evidence 不落地、锚渲染损坏、导出丢元数据。施工顺序的核心是"先接检查、再谈扩量"——P0 四项全部是纯代码修复，不动数据，一周内可以完成；完成后重生成的数据才值得投入训练。
