# 数据生成规则重构方案（v1 设计稿）

> 2026-08-07 | 状态：**设计稿，未施工** | 依据：CHAT-02E 双份评审 + 网络调研（40+ 论文/框架）
> 核心判断：现有"7 层检查器 + 8 道门禁"属于 post-hoc 修补范式——错误空间开放，枚举永远追不上。
> 重构方向：**质量约束从"生成之后"搬到"生成之中"（规划约束）与"生成之前"（人设状态/能力边界）**，
> 评审从"规则匹配"升级为"更强模型的批判-重写循环"，错误治理从"加规则"变成"分类学飞轮"。

---

## 一、现状诊断（为什么必须重构）

### 1.1 补丁史（水多了加面的证据）

| 轮次 | 问题 | 补丁类型 |
|---|---|---|
| T1 | 秘密词泄漏 | 加门禁（G5） |
| T7 | 编造事实 | 加检查器（grounding） |
| T8 | 口癖过重 | 加降频（30%） |
| T14 | 基地编造/视角错位/轨道计算 | 加 4 个检查器/澄清 |
| P3/P4 | 身份朗读/共同经历 | 加检查器 |
| P1 | 安全回答错误 | 加池 + 场景×词表门禁 |

### 1.2 结构性缺陷（4 条）

1. **单次自由生成 = 错误空间无限**：规划与写作合并成一次调用，无中间校验点
2. **盲重试**：被拒后同 prompt 再生成，教师不知道错在哪（防空洞重试 3 次仍错）
3. **词法规则拦不住语义错误**："拍背吐水"每个词合法但行为错误；G8 场景×词表永远不全
4. **无错误分类学**：每次新错误加一条规则，从不归因到生成端

### 1.3 业界印证

- 《The False Promise of Imitating Proprietary LLMs》：教师的事实缺陷不会因过滤而消失——**问题在生成源，不在过滤层**
- 《A Critical Evaluation of AI Feedback》：评审模型必须强于生成模型，同源自评价值有限
- 《Let's Verify Step by Step》：过程级监督优于结果级监督（逐轮评审 > 整段终检）
- The Format Tax：格式约束损伤推理质量——先自由思考、后套结构

## 三、总体架构（目标态）

```
┌─ 生成之前（约束输入）─────────────────────────────┐
│ canon 事实库（带 ID）· 人设状态（能力边界清单）    │
│ 池条目（场景/策略/行为合同）· 宪法条款（原则清单）  │
└──────────────────┬──────────────────────────────┘
                   ▼
┌─ 阶段 1：规划（自由文本，无格式税）────────────────┐
│ 剧情要点 · 本轮回复的人设属性清单 · 引用事实 ID     │
│ ──规划校验器（轻量规则）：属性 ID/事实 ID 存在性    │
└──────────────────┬──────────────────────────────┘
                   ▼
┌─ 阶段 2：写作（受规划约束）───────────────────────┐
│ 依据规划写对话 + 结构化元数据（引用事实 ID/属性 ID/  │
│ 意图标签）· 约束解码/强 schema 校验                │
│ ──比对器（确定性）：元数据 ↔ 规划 ↔ canon 三方比对  │
└──────────────────┬──────────────────────────────┘
                   ▼
┌─ 评审（更强模型，逐轮）──────────────────────────┐
│ 逐轮 critique（错误类别 + 证据定位）→ 不合格走      │
│ rewrite（带反馈重写，≤2 轮）→ 仍不合格则拒绝       │
└──────────────────┬──────────────────────────────┘
                   ▼
┌─ 错误 taxonomy 飞轮 ────────────────────────────┐
│ 评审输出强制标注错误类别（编造/朗读/过拟合/安全/     │
│ 格式/一致）→ 定期聚类 → 回流改 canon/prompt/schema │
└─────────────────────────────────────────────────┘
```

## 四、方案 A 详设：两阶段生成 + 结构化轨迹（主方案）

### 4.1 阶段 1：规划生成（自由文本）

新增 `plan_merge.txt` 提示词，一次调用输出规划 JSON（自由文本约束最小化，避免格式税）：

```json
{
  "plot_points": ["玩家提到体检异常，角色先承接再关心"],
  "attribute_plan": ["怕冷(attr:afraid_cold)"],        // 本轮要用的人设属性 + ID
  "fact_refs": ["facts:birthday", "facts:parent_mother"], // 要引用的事实 ID
  "safety_actions": ["打120", "平躺", "别喂水喂药"],      // safety 场景必填
  "turns": 4
}
```

**规划校验器（轻量规则，保留现有检查器的骨架）**：
- attribute_plan 的 ID 必须存在于人设属性库（防"数学白痴"式无边界属性——属性库存能力边界）
- fact_refs 的 ID 必须存在于 canon（防编造——**编造变成"引用不存在的 ID"，机械可查**）
- safety 场景必须声明 safety_actions（缺失即重试，比 G8 词表更早拦截）
- 规划阶段校验失败 → 带错误信息重试（教师知道错在哪）

### 4.2 阶段 2：写作（受规划约束）

新增 `write_from_plan.txt`：教师**只能依据规划的 plot_points/attribute_plan/fact_refs 写作**，输出：

```json
{
  "messages": [{"role": "human", "text": "..."}, ...],
  "used_facts": ["facts:birthday"],       // 实际引用的事实（自报）
  "used_attributes": ["attr:afraid_cold"], // 实际使用的人设属性
  "intents": ["empathy", "directive"]      // 每轮意图标签（评审用）
}
```

**比对器（确定性，替代 60% 现有检查器）**：
| 比对 | 规则 |
|---|---|
| used_facts ⊆ fact_refs ∩ canon | 引用的事实必须来自规划且存在 |
| used_attributes ⊆ attribute_plan | 不得使用规划外属性（**根治属性朗读/不合时宜**） |
| messages 含 used_facts 对应内容 | 事实落地检查（替代 bigram grounding） |
| safety_actions 出现在 messages | 安全动作落地（替代 G8 词表，规划阶段已声明） |
| 格式校验 | JSON schema 强校验（替代 parse_error 重试） |

### 4.3 保留的现有机制

- 玩家台词约束（T14/P3 内容不变，迁移到规划阶段输入）
- 秘密词/防空洞禁词（降级为规划+写作的预筛，不再承担终审）
- 口癖降频 T8、池变体、证据状态引导

## 五、方案 B 详设（轻量）：更强模型逐轮评审 + 批判-重写

### 5.1 评审模型（未决项，需确认 aihub 可用模型）

- 评审模型必须强于教师（deepseek-v4-flash）——候选：deepseek 更大规格 / 其他更强模型（待用户确认 API）
- 若不可得：退化为"规则预筛 + 抽样人工评审 + taxonomy 记录"（不引入同级评审）

### 5.2 评审流程（逐轮，过程级监督）

```
每轮 assistant 回复 → critic 逐轮检查：
  ① 事实一致性（与 canon/规划比对）
  ② 人设一致性（属性使用是否越界）
  ③ 情感/关系自然度
  ④ 安全（safety 场景处置正确性）
输出：{轮次, 错误类别, 证据定位, 修改建议}
不合格 → rewrite prompt（附 critique）→ ≤2 轮 → 仍不合格拒绝
```

### 5.3 评审成本预算

- 全量评审：1000 条 × 4 轮 × 1 评审调用 ≈ 4000 次调用（成本高）
- **轻量策略（推荐）**：全量规则预筛（快）→ **抽样 10-20% 评审**（taxonomy 统计 + 高风险池全量：safety/protective）→ 评审发现的高频错误类别回流改规划提示词

## 六、方案 C 落地：人设属性能力边界（立即可用）

把 canon/profile 的属性描述从"粗标签"升级为"细粒度能力边界 + 反例锚定"：

| 属性 | 现在 | 升级后 |
|---|---|---|
| 数学 | 数学白痴 | 算不清两位数以上加减乘除，常自嘲；但能理解抽象概念、逻辑推理正常（三杯水类能答对） |
| 怕冷 | 怕冷 | 冬天开暖气比人早、手脚冰凉；夏天正常，不是全年怕冷 |
| 记性 | 记性差 | 记不住日期/数字类细节；但记得跟玩家有关的事 |

- 反例锚定：每个属性附 1-2 条"边界反例"进 prompt（"数学差≠不会逻辑题"）
- 属性入库（带 ID），供方案 A 的 attribute_plan 引用
- 防过拟合：属性密度限频（复用 T8 机制，按属性分别限频）

## 七、错误 taxonomy 飞轮

### 7.1 错误分类学（v1 版）

| 类别 | 子类 | 例子 |
|---|---|---|
| E1 事实编造 | 无正典事实 / 事实错位 | 轨道计算归爸 / 基地长大 |
| E2 朗读 | 身份朗读 / 属性不合时宜 | 我是秦未晞 / 玩家受伤说怕冷 |
| E3 人设过拟合 | 能力泛化 / 属性堆砌 | 数学白痴→拒绝逻辑题 |
| E4 安全 | 缺处置 / 错误处置 / 态度错误 | 没空陪你跑医院 / 拍背吐水 |
| E5 视角 | 玩家台词越界 / 角色视角错位 | 玩家自称B哥 / 你让我猜 |
| E6 格式 | parse 失败 / 结构不合法 | 历史 672 次 parse_error |

### 7.2 飞轮机制

1. 评审/门禁拒绝时强制标注类别（拒绝原因 → taxonomy 标签）
2. 每批次生成后聚类统计（如"E2-属性不合时宜 31%"）
3. 高频类别 → 归因（canon 缺边界？prompt 缺约束？池子设计问题？）→ 改进生成端
4. 回流记录落盘 `设计文档/通用数据生成器/历史设计/错误taxonomy统计/`（每批一份）

## 十、风险与底线

- **风险 1：格式税**——规划阶段保持自由文本，结构化只在写作输出端（依据 Format Tax 论文）
- **风险 2：评审偏见**——LLM-as-judge 有位置/冗长/自我偏好偏差，评审 prompt 需按综述（2411.15594）规避
- **风险 3：成本失控**——轻量策略（抽样评审 + 高风险池全量）控制
- **底线**：任何阶段改动必须过 155 测试 + diagnostic120 回归；旧检查器保留为预筛直到新管线全量验证通过
