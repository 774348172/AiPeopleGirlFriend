# 提前编排输入与本地回复分工

用户授权：修复分工，生成 15 条小批量候选。此合同取代此前默认由本地模型自动编写世界、事件和整段历史的实验路径；不授权训练或扩产。

## 分工与入口

1. Codex 提前编排每条独立输入：场景快照、需要的过去事件、相关旧对白、最近至少两个来回、自然承接的当前男主发言。过去事件在回复前确定，禁止看答案补证。
2. Codex 逐条审核输入的事实来源、旧新关系、人物归属、知情边界与连续性，记录实名审核结论、理由、事实依赖和组件哈希。这是 Codex 的输入判断，不冒充本地模型审过，也不代表绝对正确。
3. `tools/run_curated_candidate_batch.py` 接收完整组件和输入审核记录，调用正式 `convert → model_view → build_messages → GAME_REPLY_CONTEXT_V1`。逐项检查最终请求的场景、状态、未知、人设投影和历史。完整组件与实际消息冻结；缺失、修改后未复核或续跑来源变化均拒绝。
4. 本地 `qwen3.5:27b` 只生成最终 `reply`。本入口没有世界、事件、历史生成调用，没有自动编剧回退，也不用伪造旧缓存跳过阶段。所有 Qwen 回复集中生成后，再切换到 Gemma 审核，减少显存模型切换。
5. 本地审核器默认使用 `gemma4:31b-it-qat`（2026-09-16 用户指定升级），使用现有完整证据审核协议，核对历史、意图和事实覆盖、对白质量、事实支持。正式入口可用 `--auditor` 指定精确标签，模型名写入批次配置。程序核查证据引用与结论一致性。保留实际请求、原始响应、机器结论和程序拒绝理由。审核失败不触发改写输入或重新采样答案。历史批次的 `gemma4:12b` 结果保留原样。
6. Codex 对候选逐条复核，独立记录与机器意见的差异。全量页保留备查，交给用户的主审核页只展示待裁决集合：Gemma/程序未放行、Codex提出内容疑点、边界项及双方分歧的并集。不得只检查机器拒绝项而忽略通过项漏判。所有候选保留在隔离目录，机器通过也不自动发布训练数据。

### 人工审核队列（2026-09-16）

- 正式本地默认审核器为 `gemma4:31b-it-qat`。历史 Gemma 12B 和 GPT 文件复核结果仅保留作对照，不覆盖本地审核记录。
- 正式生成入口完成后自动建立 `human_review_pending/review.html`，先收录本地机器/程序未放行项。`queue_manifest.json` 明确记录此时是否已有 Codex 复核，不得把尚未复核的机器通过项当作人工通过。
- Codex 逐条复核完成后，调用 `tools/build_pending_human_review.py --results <Gemma results.json> --semantic-results <Codex results.json> --output-root <新的审核目录>` 建立最终人工队列。工具强制核验两组样本 ID、回复、生成消息及 scenario 完全一致，旧审核目录不可覆盖。
- 每项保留原样本 ID、原始回复、实际完整模型输入、机器理由及 Codex 疑点。用户选择好/差、可写备注并下载 JSON；未判断的条目仍是待审，不算通过。人工作出结论后另行合并，不反写原机器判定。
- 2026-09-16人工校准后，新批次只对相同完整输入且相同回复作训练对去重；不同上下文的相同短答只记频次，不直接判差。输入编排阶段的整段对话近重复检查和每家族最多4条仍保留。旧批次结果不反写。
- 正式审核追加 `human_calibrated_review.CALIBRATION`：保留已知/未知、主体、旧新事实、设备状态与行动来源边界；允许明确虚构故事、主观设想和自然口语，不以单个“刚才”“没看到”关键词判捏造。详细过去行动仍须证据，歧义送人工。
- 历史校验仅对“男主已知设定”且具备不晚于该句的 `known_since` 允许旧记忆引用，未注明时间的当前快照仍不能证明旧事实。该例外不是一般性放宽当前状态。
- 人工24条17好7差，052拒绝无说明：只保留该样本拒绝，不归纳“好”字一律不好。人工结果与机器结果分层保存，冲突优先保留人工裁决，不偷偷修改模型原判。
- 原24条是校准集，回放一致率不是独立泛化准确率。新增100条是前瞻验证，与原100条组成200条试产；未完成的新条人工争议不能算验收通过。

## 扩产硬门禁（2026-09-16 修订）

- 扩产入口只接受 Codex 已编排、已审核并带哈希的 `seed-input`；旧的本地世界/历史自动编排入口永久拒绝，不得用 `--count` 绕过。
- 历史对白不是事实来源。任何过去事实必须有冻结事件，事件必须列出 `current_fact_ids`、`actors` 和 `known_by`；没有事件就只能写假设、主观意见或明确未知。
- 场景快照、冻结事件、历史对白、最近对白和当前问题在回复前一次性冻结，并对最终 `GAME_REPLY_CONTEXT_V1` 做哈希校验；回复阶段不得回填或修改它们。
- 扩产按“输入编排/审核 → 小批闸门 → 回复生成/审核”分阶段执行。输入通过率低于 90% 时停止，不调用回复模型；20 条、50 条、200 条逐级放大，不能直接跳到 1,000 条。
- 任何空回复、占位对白、`"null"` 字符串、话题漂移或缺少事件来源的输入都进入失败隔离，不计入候选数量。
- 20 条以上批次必须附独立的整批输入审核摘要（尝试数、通过数、审核运行 ID），通过率至少 90%，且每条 approval 必须带 `provenance=external_codex_review` 与 `review_run_id`。生成脚本不得在同一过程中自造“Codex 已批准”记录。
- `run_mixed_candidate_batch.py` 是历史自动编排实验入口，正式生产禁止调用；正式回复只能由 `run_curated_candidate_batch.py` 执行。

## 输入与质量边界

- 完整男主人设是作者资料；只有具备明确披露来源的内容进入女主已知。女主人设继续取自正式角色锚。
- 固定场景、当前快照和旧事件分开。库存目录不证明现货，设备断电不证明清洁，旧开门不证明当前营业。
- 自然聊天、假设、主观选择允许没有过去事件；不要为了满足“历史事件数量”捏造经历。具体事实问答必须登记已知或有意未知的依赖。
- 每条旧记忆是与最近对话相关的预设对白片段，不宣称进行了真实向量召回。本批 15 条使用独立对话链，不靠重复历史扩充数量。
- JSON 是存储及回复传输外壳，最终消息继续使用共享上下文；不得为省时删除权威世界。
- 这批用于验证“预先审核的输入 → 本地最终回复”的质量，不证明自动编剧已修好。自动编剧入口仍是隔离实验，不能混入本批。
- 空回复、截断或格式错误不得视为通过；本批每阶段首轮一次采样，失败保留原始证据。首轮完成后，`retry_curated_format_failures.py` 可对没有有效目标的生成失败槽位明确补试一次，输入完全不变，保存首轮结果与补试请求。内容不合格的有效回复禁止补抽。报告同时给出首轮失败和补试数量，不得掩盖首次失败率。

## 成本与可追溯性

2026-09-16 模型升级对照：`tools/reaudit_curated_replies.py` 只重放完成批次中保存的 100 条审核请求，验证候选回复、完整审核消息、JSON schema 与原批一致，保留 16K 上下文、关闭思考、温度 0、3400 输出预算及旧去重规则。仅审核模型改变。输出到独立目录，保存模型 digest、旧文件哈希、逐条新结论、状态转移和用量；不重新生成回复，不改旧结果。是否改善漏检、误杀由实际对照结果判断，不因模型变大预先认定合格。

Codex 编排和复核消耗当前 Codex 用量；Qwen/Gemma 调用仅发到本地 Ollama。日志分别记录生成、审核耗时和调用数。输入批准、机器判断、Codex 回复复核、用户批准是四种独立记录。

本批资产：`训练数据/curated15_inputs_20260915/` 为冻结前已审核组件；`训练数据/curated15_formal_20260915/` 为完整输入、实际调用及候选审查结果。最终验收以实际报告为准，本文不预填通过率。
