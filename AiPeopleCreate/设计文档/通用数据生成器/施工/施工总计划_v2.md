## 一、定位与权威判定

### 1.1 生成器定位（Magpie 范式，主方向正确）

data_gen_v4 **本质 = 主题驱动直出法（Magpie 范式）**：池条目（topic/场景标签）→ prompt 直出多轮对话 → 内置过滤链路。

**判定：主方向正确**（Magpie 是角色微调最常用方案）；对照完整方案清单存在 **2 个方向性缺口（DPO 全缺、难度梯度缺失）+ 4 个可改进点**。方向修正见 §四。

### 1.2 重构方案裁决（v2 审核报告）

| 项 | 结论 |
|---|---|
| 《数据生成规则重构方案_v1.md》（plan/write/critic 链） | **否决施工**——是更长补丁链，缺 4 个核心能力（候选池/数据集级选择/训练后效用闭环/不可变发布） |
| 目标态 | **目标驱动的数据搜索与发布 Module**：冻结目标与开发集 → 行为族级 gap → 场景蓝图 → N 个 Candidate → 硬校验 → 校准 judge 多轴打分 → 数据集级选择 → family-aware split → 原子发布 → 小批训练 → 效用闭环 |
| 迁移顺序 | 阶段 0 冻结现状 → 1 修合同完整性 → 2 Candidate Ledger → 3 硬校验与选择 → 4 去污染/切分/发布 → 5 训练后效用闭环 |
| 阻断问题 | P0-1 ReleasePolicy 未控制发布 / P0-2 证据链空 / P0-3 lineage 不成立 / P0-4 candidate_count 死字段 / P0-5 冻结合同未进 Seam / P0-6 997+119 状态不成立 / P0-7 split 锚丢失 |
| 晋升标准 | 7 条（见 §八.2），不以"生成成功率/条数达标"为准 |

### 1.3 方案对比速查表（SFT 5 / DPO 3 / 通用增强 3）

> 详表见 `分析/主流方案对比与改造建议_v1.md` §二；本节只保留判定，用于对照现状缺口。

| 类别 | 方案 | 现状 | 判定 | 处理 |
|---|---|---|---|---|
| SFT | ① 种子衍生（Self-Instruct） | 池条目≈种子，不衍生 | ⚠ 部分 | 不改（直出法更适合角色场景） |
| SFT | ② 主题驱动直出（Magpie） | **完全对应（主架构）** | ✅ | 保留 |
| SFT | ③ 进化指令（Evol-Instruct） | 池内场景平级、无难度梯度 | ❌ 缺失 | **P2**：蓝图按行为族演化难度/证据状态 |
| SFT | ④ 公开语料改写 | 无 | ❌ 缺失 | 低优先（有 qwx 语料可试，注意合规） |
| SFT | ⑤ 模板实体填充 | pool_variants ≈ 雏形 | ⚠ 部分 | 不另做 |
| DPO | ⑥ 同题双答配对 | 无 | ❌ **最大缺口** | **P0**：失败样本回收为候选 rejected 池（v2 修正：不自动进 DPO） |
| DPO | ⑦ 多回答打分排序（RLAIF） | 无 judge | ❌ | 依赖校准 judge（v2 阶段 3） |
| DPO | ⑧ 正向样本反向改造 | 无 | ❌ | 中优先，改造 prompt 即可 |
| 增强 | RAG 注入式知识 | 全量注入不分场景 | ⚠ 部分 | **P3**：core 去角色化 + 按池裁剪（v2 修正） |
| 增强 | 多模型混合 | 单一教师 | ❌ | 视 aihub 可用性 |
| 增强 | 三层质检 | 规则 ✅ / 去重 ❌ / 打分 ❌ | ⚠ 部分 | **P1** 去重（阶段 4）；打分=阶段 3 judge |

### 8.2 v2 晋升条件（7 条，替代"生成成功率/条数达标"）

1. safety blocker 通过率 100%
2. sealed contamination 0
3. family/semantic cluster 跨 split 泄漏 0
4. 目标行为族在至少 2/3 seed 中稳定改善
5. 通用能力和误拒率不显著退化
6. 人工盲测不低于当前最佳基线
7. 完整 release manifest 可从 ledger 重建

### 8.3 禁止事项（继承 V4 执行版 §7，执行期强制）

1. 阶段 0 未完成前，禁止继续扩大数据规模或重新生成。
2. 禁止在 G-D 等价门（G4）未过时启动正式训练；禁止用 prompt 补丁代替数据修复。
3. 禁止 m3 与 h200 两套超参同时训练同一份数据。
4. 禁止把 desired_policy/evidence_state 继续当作只记录不执行的标签。
5. 禁止把 40 条盲评结果当作 v4 数据"已坏/已好"的证据；结论只来自 v4 自己的评测。
6. 禁止普通 rejected Candidate 自动进入 DPO（须先过阶段 3 校准与配对条件）。
7. 禁止在 core 中保留秦未晞专属词表/分支（阶段 1 去角色化未过前不得新增）。
