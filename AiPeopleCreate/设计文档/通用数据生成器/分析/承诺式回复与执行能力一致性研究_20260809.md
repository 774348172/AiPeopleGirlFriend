## 一、背景与问题

训练数据（白未晞 25 条 + 秦 997/2500 条）中约 2%-8% 的回复是"承诺式"（"我去做饭""我帮你付"）。
真实游戏中，程序未必给女主角提供这些动作的执行能力；且玩家会期待"说了就要做"。
如果训练数据教模型随口承诺、运行时承诺后不落地 → 出戏。

**用户质疑**：数据侧"加承诺纪律提示词"是打补丁，补不完；真正要弄清的是
**微调后模型会不会把承诺变成高频/默认行为**，以及**现有设计能否拒绝承诺**。

## 二、现状核查（三侧）

### 2.1 运行时：承诺只是文本，无"承诺→执行"闭环（V6）

| 环节 | 现状 |
|---|---|
| 回复文本 | "我去给你做饭吧"只是一句话，**无结构化识别** |
| 意图字段 | `heroine_diegetic_actions`（受控动作候选）——**空壳**：无 schema/枚举/执行语义/消费方 |
| 审查 | `WORLD_CONTINUITY_REVIEW` 9 项审查**无"承诺悬空"项**；"把意图写成已发生"只针对心智 patch |
| 跟进 | `POST_REPLY_RECONCILE` / `FIVE_MINUTE_RECONCILE`：模型自觉 patch `current_activity`，程序"不得写死" |
| 记忆 | 承诺沉淀为 `future_event`——原文"**有跨回合意义但不保证触发的未来事项**"、无到期扫描 |
| 历史状态机 | 阶段 6 确定性承诺状态机（promise/reminder/shared_plan）**已暂停删除** |
| V6 实现状态 | TURN_MIND_ADVANCE / Critic / GAME_REPLY **尚未实现**（总纲 §2.2），当前是旧 RelationshipRuntime |

**GAME_REPLY prompt 合同**禁止清单（V6 §16）：无"不要承诺做不到的事"条款。
**需求 §7.2**"模型生成失败不得写入一条用户看不见的角色承诺"——是**原子性条款**（失败不落账），
不禁止可见承诺；需求反而明确要求**记住承诺**（目标 5、§6.5）。

### 2.2 生成器：无承诺约束，承诺绕过全部检查

- `reply_merge.txt` 只有"事实正典"约束；"我去做饭吧"不是事实命题（建议/行为/情绪不进 propositions）→ **天然绕过全部检查**
- `_check_grounding` 前缀表（我是/我叫/我今年…）**不含"我去/我来/我帮你"** → 承诺不做正典/能力校验
- `EVIDENCE_GUIDES`/`POLICY_GUIDES` 无"未来承诺"维度
- 白未晞 system 锚只禁现实侧承诺（"不要声称正在现实中陪伴玩家"），**世界内承诺不受约束**

### 2.3 数据：承诺悬空是默认（实测）

| 数据集 | 承诺会话占比 | 承诺回复占比 | 会话内收口 |
|---|---:|---:|---|
| baiweixi_review30_final（25 会话/52 回复） | 2/25 = 8.0% | 2/52 = 3.8% | **2/2 收口**（承诺即落实："好。我拿一下外套"） |
| qin_v4_1000_final（997/2087） | 44/997 = 4.4% | 44/2087 = 2.1% | **10/44 收口，34/44（77%）悬空**（33 条承诺是会话末句） |
| qin_v4_2500（2500/6780，v2500 实际训练源） | 79/2500 = 3.2% | 84/6780 = 1.2% | **24/84 收口，60/84（71%）悬空**（48 条为会话末句） |

- 承诺**按情境集中**（做饭/请客/跑腿/陪伴/健康），不按 task_type 集中（casual 4.3%/romance 4.6%/emotion 4.1%/protective 9.1%/identity 0%）
- 几乎每条承诺带"嘴硬心软"包装（"行吧行吧，看你那懒样"→答应）
- 典型悬空：`"回头我给你画一张专属的……那说定了啊，可不许反悔"`（承诺被二次确认但永不兑现）、`"碗你洗，我请你喝奶茶行不行"`（承诺在末句悬空）

## 三、证据链：数据分布 → 模型行为（项目内既有证据）

| 证据 | 数字 | 结论 |
|---|---|---|
| 口癖密度（CHAT-02E P1-1） | 哼 20.25%→35.91%、谁稀罕 10.40%→23.75% | 高频模式被压缩成固定模板："哼/喂/啧 + 否定 + 谁稀罕 + 迟到的关心" |
| 共同经历（P0-2） | 旧 v1 58.98% 会话命中强记忆措辞 | 模型把"像女友"误学成"随时声称我们以前一起做过某事"→ fabricated_reality 4 vs 1、fact_error 19 vs 11 |
| 属性朗读（P0-4） | 自由插画师 12.33%、怕冷 12.49% | 6-12% 已构成"插入任何话题"风险 |
| 低频被淹没（反方向） | 于谦 v1：75 条闲聊在 5554 条中占 1.3% | 完全淹没，"教自由对话的作用为零"；5% "太少没效果" |
| v2500 实测 | 健康情境输出"我陪你去医院也行啊" | 承诺=关心的绑定被学到；但 assistant_tone 7→0（训练压制助手腔） |
| 基座对照 | 基座在"列执行清单"题输出全天候服务承诺清单 | **承诺倾向是基座固有模式，训练方向是压制而非催生** |

**阈值规律**：1.3% 淹没 / 5% 无效 / 58.98% 成模板 / 6-12% 属性朗读才"插入任何话题"。

## 四、风险判定

### 4.1 "微调后模型全局频繁承诺" —— **不成立**

2-8% 的承诺分布 + 承诺天然绑定情境（做饭/请客/跑腿/陪伴/健康），模型学到的是
**"特定情境 → 条件承诺"映射**，而非"任意输入 → 承诺"；且承诺倾向是基座固有，
训练方向是压制助手腔而非催生承诺。阈值证据不支持"2-8% 会被放大成默认行为"。

### 4.2 两个真实风险 —— **成立，且当前完全拦不住**

1. **情境内承诺放大**：请客/做饭话题中"承诺+嘴硬"是主要表达（casual 池弱命中 26.6%），
   该情境内承诺率显著高于全局；v2500 已在健康情境输出"我陪你去医院也行啊"。
2. **承诺悬空成为默认**：数据 71-77% 承诺无收口，模型学到"说了要做某事"，
   但数据从不展示落实/改口/转移 —— **真实形态不是高频承诺，是"说了不算"**。

### 4.3 运行时现状：无法拒绝承诺

GAME_REPLY 合同无条款、Critic 无审查项、跟踪层只入账不强制、
V6 主干未实现（当前旧运行时无对应机制）→ **承诺悬空无任何硬保障**。

## 五、处置建议（分层）

### 数据侧（生成器，现有数据缺口，必要优先）
不是"删承诺"或"加提示词"（补不完），而是按 CHAT-02E 行为矩阵方法论补**收口轨迹**：
1. 给现有承诺样本补"承诺→落实 / 圆场 / 转移 / 明确搁置"的完整多轮轨迹样本，教模型**自然收口**
2. 请客/做饭情境承诺密度降下来，用"当下动作"替代承诺表达
3. 严肃/健康情境用当下动作（"我帮你拿药箱"）替代承诺式关心（"我陪你去医院"）
4. 记忆侧延续 v3 规则："来源没有的动作、承诺不得自动进入 detail"；"不重复旧承诺"

### 运行时侧（AI 程序，问题本质，V6 施工窗口内最便宜）
趁 V6 主干（TURN_MIND_ADVANCE/Critic/GAME_REPLY）尚未实现：
1. `GAME_REPLY` 合同加"已提出未落实的承诺必须在后续轮自然处理"条款
2. `WORLD_CONTINUITY_REVIEW` 加"承诺悬空"审查项
3. `MotiveState.pending_intentions` 入账（带证据 event_id）+ 下一轮注入上下文促使自然兑现
4. 明确 `heroine_diegetic_actions` 的 schema 与能力边界校验（当前空壳）
5. 可复用阶段 6 已冻结的 promise 状态机内核（P0-23/P0-24 全绿），删提醒/待办方向

### 评测侧
- 失败标签矩阵新增"承诺悬空"类（当前 8 类失败标签无此项，v2500 对比**测不出此问题**）
- 需求 §8.2 评测增加"承诺后 N 轮/若干分钟是否落实或被自然收口"验收项

## 六、结论

- 数据侧补丁（加承诺纪律提示词）确实补不完 —— 用户质疑成立；
- 但"微调后频繁承诺"大概率不会以全局默认行为出现 —— 阈值证据不支持；
- 真实风险是**"情境内承诺放大 + 承诺悬空成为默认"**，且当前运行时设计
  （无条款/Critic 无审查项/V6 未实现）**完全无法拒绝**；
- 数据侧补收口轨迹（现有 77% 悬空率硬伤）与运行时侧承诺执行条款（V6 施工窗口）
  都需要；前者是数据缺口，后者是"说了就要做"的最小硬保障；
- 评测侧补"承诺悬空"失败标签，让问题可被测量。
