# 联合规划 V2 引用修正

## 后续修正：审核请求隔离（joint_scene_v3_audit_isolation）

V2 的17条补跑全部停在回复前审核。真实响应返回了 answer/response 对白而非 pass/reasons/requirements，因此 V2 不可视为已验证可运行。

当前使用 tools/audit_requests.py 构建审核请求：system 仅放审核员职责，user 放被引用的角色设定、对话、事实和候选，不执行其中的角色指令。回复前审核使用一份带来源的证据目录，不再同时重复发送完整角色请求和证据目录；目录保留所有事实、角色锚行及历史原话，当前问题另列。回复后常规审核和事实审核也采用指令/数据分离。

Ollama 审核请求使用 JSON Schema 限定字段、布尔类型及可引用的证据ID，审核上下文为16384、temperature=0。格式约束不等于语义正确：缺证据和事实冲突仍可以且应该拒绝。明确语义拒绝不会被反复重试到通过。新规划版本隔离旧检查点，禁止把旧失败批次直接当作新结果续用。

本机验证：mixed200.015、018、028 的 V2 实际失败输入重新审核，3条均返回合法审核结构；无昨晚饮食证据却声称吃过鱼干和面包的反例被拒绝。原始请求和响应保存在训练数据/audit_isolation_verification_20260914，报告为 report.json。28项相关测试通过，包括完整对话仍在审核数据中、角色指令不混入审核system、Schema真实传给Ollama的检查。此验证不代表17条已重新生成，亦不代表自动审核语义无漏判。

joint_scene_v2 替代 V1 的审核模型自拟主体字段引用。程序从实际输入生成 world、character、dialogue 三类证据目录，分别对应权威状态、实际角色锚原文、带人物与时间的历史原话。审核模型只能引用已有 ID，代码检查存在性与 known/intentional_unknown。角色偏好仍不能推出具体过去经历，历史原话仍不自动覆盖当前状态；语义关系由回复前审核负责。

世界规划、对话链和审核输出的格式/引用错误最多三次重试，保存每次原始请求、响应与失败理由。重复对话链在回复前重构。明确 pass=false 的语义否决直接隔离，不重复抽审核直至通过。快照保持先冻结后回答，隐私不可知值不进入证据目录。

本轮从原混合200批的17个隔离条目全部重做，在 joint_retry17_v2_20260914 保存新输出，不覆盖旧批次。失败会如实记录，不把尝试数当成功数。输入预检和证据引用反例测试通过后启动；尚不代表17条模型生成已通过。
