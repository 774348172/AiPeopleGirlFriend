# 扩产流水线修复与回归结论

本次已修改程序并完成针对性验证，但不能宣布所有生成问题解决，更不能把自动通过等同于可入库。此次没有训练，也没有重跑完整 200 条。旧批次及原始模型响应保留。

## 已施工的内容

- 创作与审核分开配置；创作不再误用零温度审核通道，失败重试调整采样和表达方式。
- 删除编剧输入中的最近问句列表；参照数据只在程序侧去重。允许不同事实/话题背景下的同问对照，完整历史仍查重。
- 对白前规划并冻结独立历史事件，区分旧会话与最近会话时刻、参与者和知情者；与当前快照一同纳入哈希。可知事件进入最终完整上下文，隐藏事件不进入。
- 历史审核逐句提交事实类别、引用、是否对白和是否受支持；代码检查旧会话不能靠当前状态自证、过去事实必须有事件、后来事件不能证明之前对白。
- 问题审核先提取原意图和实际请求，再判断是否一致；已知与未知可同时引用。限制理由和引用数量，避免无关枚举导致截断。
- 回复使用精确 `reply` schema；空、截断、污染及附带说明不作为有效目标，最多三次格式重试，完整原始响应保留。有效回复不因审核失败反复重写。
- 进度中的回复数只统计格式有效目标；尝试、流程失败、自动疑点与额外人工复核意见分开保存。

## 验证结果

相关合同与回归测试 54 项通过。它们验证结构、时间/来源约束、隐藏信息边界、错误隔离及重试行为，不代表自然语言语义全部正确。

原失败输入的本地模型回放：

| 检查 | 结果 |
|---|---|
| 4 条回复格式失败 | 4 条均得到格式有效回复；未据此判为内容合格 |
| 建议去客厅被误当成已移动 | 逐句审核后通过 |
| 微波炉待机、内部食物未知 | 保留已知/未知区别，通过 |
| 原需求审核输出截断案例 | 在限定引用/理由后完成有效审核 |
| 2 条明显离题负例 | 增加独立意图比较后均拒绝 |
| 第一轮回归中被布尔审核漏放的 3 条历史 | 新的逐句证据检查全部拦截 |

完整新流程的三个原重复失败槽位：2 条因历史内容不合格在回复前隔离；1 条生成有效回复并被两个自动审核请求放行。但 Codex 复看发现其历史把“900 米走了 400 米”说成缩短一半多，算术关系错误，因此该条也另外隔离。这三个槽位目前没有可直接入库的数据，不能据此宣称扩产合格率提高。它们不再因旧问句列表反复抄写而失败，但历史编写质量仍未稳定。

自动通过记录没有篡改；补充检查在 `pipeline_fix_regression_20260915_v2/assistant_inspection.json`，合并后的隔离结果在 `assistant_checked_candidates.jsonl` 和 `final_summary.json`。该检查是 Codex 复核，不是用户人工批准。

在进一步允许“最近会话事件”后，只重测了受影响的第 018 槽位（`pipeline_fix_timeline_check_20260915/run/`）。规划器已实际生成最近会话时刻的事件，但编剧仍写出缺乏支持的旧会话，三次后被隔离，未生成最终回复。因此时间线入口已经接通，不代表历史编写质量已稳定；此补测没有提高入库条数。

## 尚未解决的边界

程序能强制已声明的证据编号、时间、格式和隔离规则成立，却不能证明模型对每句话的分类、推理和自然承接都正确。本次已经直接观察到编剧会编造未记录的观察过程、抄回角色上一句，审核也会漏掉数量推断错误。因此不能靠取消拦截来提高成功率，也不能把这些问题归因于需要再次训练 Adapter。

接下来需要稳定编剧对历史与当前问题的组织能力，并保留独立复核；当前不宜直接扩大为正式训练数据生产。先前少量人工构造输入的好结果，不能用来证明自动编写全部输入也已稳定。

证据目录：`AiPeopleCreate/训练数据/pipeline_fix_regression_20260915/`、`pipeline_fix_regression_20260915_v2/`。旧失败批次仍为 `expanded200_b01_20260914/`。
