# 训练数据记忆类型分类方案（记忆类型轴）

> 状态：方案已批（2026-08-14），按本文施工
> 版本：v1.0
> 日期：2026-08-14
> 关联：`数据生成器v4设计_通用角色包_协议适配_质量闭环.md`（第 24 节增补登记本方案）
> 范围：生成器（AiPeopleCreate）训练数据按记忆类型分类生成；不修改 AI 程序侧运行时

---

## 1. 背景与目标

当前训练数据（`训练数据/baiweixi_v2_game_reply/baiweixi_game_reply_v2.jsonl`，844 条）按
**行为/关系轴**（task_type：casual/romance/identity/emotion/protective/...）组织。继续扩充数据时
需要回答一个问题：**这条回复由哪类记忆支撑？**

目标：在不动现有行为轴的前提下，增加第二条正交轴——**记忆类型轴（memory_type）**，使训练数据
可以按记忆类型分类生成与配比：

| 记忆类型 | 含义 | 对应知识来源 |
|---|---|---|
| `persona` 人设记忆 | 角色自身设定（身份/性格/关系/能力/秘密边界） | identity_fact / canon_fact |
| `item` 物品记忆 | 现代物品/设施的知识状态（会用 / 在学 / 不知道） | canon（modern_gaps）+ 日常池 |
| `general` 通识记忆 | 不依赖角色正典的通用常识 | 无（knowledge_scope=general_knowledge） |
| `special` 特殊记忆 | 角色专属经历（时间线事件） | timeline_event |

## 2. 现状盘点（记忆类数据在生成器里的分布）

| 记忆类型 | 现状 | 缺口 |
|---|---|---|
| persona | `reply_identity`(42 池/38 配额) + `reply_canon_qa`(22 池/18 配额)；FACTS 全量注入 + T7 正典支撑检查 | 基本齐 |
| item | **无独立类型**。现代物品/设施话题 19 条散在 `reply_casual` 池（手机/热水壶/洗衣机/电梯/扫码/红绿灯/电视等，按"对话主体是现代物品/设施"严格口径迁出；冰箱/装修噪音/洗衣液气味等生活流话题留在 casual），多数带 `evidence_state: insufficient` | 配比不可控、无独立门禁 |
| general | `reply_general`(18 池/20 配额) | 池小；`knowledge_scope` 字段存在但从不参与生成行为（只透传记录） |
| special | timeline 14 条事件**只进 MEMORY_RERANK**（`rerank.py:distill_candidates`）；REPLY 对话明确禁止编造共同经历（`reply.py:_check_shared_history`），时间线从不注入对话生成 | **最大缺口**：角色记忆在对话训练里是空的 |

结论：真正需要新增能力的是 `special`（时间线注入对话生成）；`item` 需要独立通道；
`persona` / `general` 只需打标与扩池。

## 3. 方案总览：两条正交轴

- **行为轴 task_type**（不变）：决定"该怎么做"——行为边界、门禁、审查策略都挂在它上面
  （identity 才允许身份朗读、protective 走 withhold 等）。
- **记忆轴 memory_type**（新增）：决定"答什么"——这条回复由哪类知识支撑，用于分类生成、配比与审计。

正交规则：同一 task_type 下可有多类记忆（casual 里既有物品话题也有生活话题）；
同一记忆类型可出现在多个 task_type（item 记忆在 casual 问答与 protective 提醒中都有）。
**memory_type 是可选标注**：未标注的条目（romance/emotion/protective 等关系行为池）不参与
记忆类型统计，行为轴语义不受影响。

### 3.1 memory_type 取值与缺省推断

池条目显式声明 `memory_type` 优先；未声明时按 task_type 推断：

| task_type | 推断 memory_type |
|---|---|
| reply_identity / reply_canon_qa | `persona` |
| reply_general / reply_safety | `general` |
| reply_memory（新增） | `special` |
| reply_item（新增） | `item` |
| 其余（casual/romance/emotion/protective/supportive/correction/vague/quiet_company/boundary） | 未标注（不参与记忆类型统计） |

推断表在 `factory.py` 实现（core 不内置角色知识；推断表是通用规则，与 profile 无关）。

## 4. 数据层改造（不动核心先例）

### 4.1 pools.yaml 打标与迁移

1. **persona 池**：`reply_identity` / `reply_canon_qa` 全部条目标 `memory_type: persona`（42+22 条）。
2. **item 池（新建 `reply_item`）**：
   - 从 `reply_casual` 迁出 19 条现代物品话题（手机/热水壶/洗衣机/电梯/扫码/红绿灯/电视等），
     迁出后 casual 池保留生活流话题（152 条）；
   - 补足至 59 条：设施使用、支付、交通、家电、公共设施各一组；延续"在学/不会"的表现形态
     （显式 `evidence_state: insufficient`，对应正典 `capability_traits.modern_gaps`），
     少量"已学会"条目（`supported`，对应 timeline `ev:bwx_apartment_adaptation` 学会水龙头/热水壶/冰箱）。
3. **general 池**：`reply_general` 池 18 → ~30 条，配额 20 → 40。内容限定"不依赖角色正典的通用能力"
   （§12.4 能力与人设分离：不得携带角色属性朗读）。
4. **special 池（新建 `reply_memory`）**：从 timeline 14 条事件派生话题（雨夜被救/纸箱/人形暴露/

   不发明新事件；`ev:bwx_name_awakened`（profile_secret）不派生话题。
5. **其余池**：不强制打标（§3 正交规则）。

## 6. 特殊记忆（reply_memory）注入与守卫设计

### 6.1 注入

`reply.py` 生成时，对 `memory_type == special` 的 item：

1. 从 `package_set["snapshots"]` 蒸馏 timeline 事件（复用 `rerank.py:distill_candidates` 的过滤逻辑：
   `source_kind == timeline_event`、去重、`occurred_at` 渲染）；
2. 过滤：`visibility_scope == profile_secret` 剔除；`disclosure_policy == hint_only` 的事件
   仅用于 `desired_policy == hint_only` 的 item；
3. 按 item seed 确定性取 2-3 条，渲染为 `MEMORY_FACTS` 段注入 `reply_merge.txt` 模板
   （新占位符，格式与 FACTS 相同：`- [时间] 事件摘要`）；
4. 非 special item 不注入（`MEMORY_FACTS` 置"（无）"，现状不变）。

### 6.2 守卫（确定性检查）

- `_check_shared_history`：允许列表加 `reply_memory`（回忆类任务合法回忆），其余 task_type 不变；
- 新增 `_check_memory_grounding`（仅 reply_memory 生效）：assistant 台词中第一人称+过去时间词
  （上次/那天/那晚/捡到/救回/刚来…）的事实主张，必须与注入的 MEMORY_FACTS 存在 ≥2 字公共子串
  或时间锚点匹配；无支撑 → `style_failure` 重试（复用 `_supported_by_facts` 的匹配机制）；
- 玩家台词触发回忆但未注入该事件 → 角色按证据状态回应（`supported` 之外的行为由
  evidence_state 引导，不得顺着玩家补造细节——沿用 `EVIDENCE_GUIDES`）；
- 秘密边界：`profile_secret` 事件（如 `ev:bwx_name_awakened` 的名字/妖果来源）不注入、
  不受理，G5 秘密词检查继续生效。

### 6.3 训练锚

`reply_memory` 复用 REPLY 的 system anchor（`reply_system_anchor`），不改锚结构；
记忆证据规则已在 v2 锚保留（"只有历史消息或明确可回证据支持时才承认具体共同经历"），
注入事件即"明确可回证据"。不新增锚段落，避免与运行时锚漂移。

## 8. 边界与禁止事项

1. 不重写现有池，只打标/迁移；冻结数据（v1_legacy、v2 派生集）不动。
2. special 话题只从现有 timeline 事件派生，不新增、不合并、不改写事件。
3. timeline 注入遵守 `visibility_scope` / `disclosure_policy`，secret 事件不注入。
4. general 池不携带角色属性（§12.4 能力与人设分离）。
5. memory_type 不改变任何现有 task_type 的行为语义与门禁（正交轴）。
6. 不在 core 中内置角色名/事件词（推断表与守卫均通用实现）。

### 10.2 与 MEMORY_RERANK 的关系

`special` 对话数据与 `rerank_memory`（记忆选择器）职责互补、互不替代：

- `rerank_memory` 训练"该检索哪些记忆"（query → 候选排序标签）；
- `reply_memory` 训练"检索到的记忆如何被自然表达"（对话）。
两者共用同一 timeline 蒸馏逻辑（§6.1 与 `rerank.py:distill_candidates`），保证口径一致。

### 10.3 派生集两轨（记忆行锚冲突 A/B/C 拍板，2026-08-15）

**问题**：reply_memory 对话是"顺着玩家预设回忆过去"，由生成期注入事件支撑；
若并入固定锚的 GAME_REPLY 轨，锚里只有"玩家预设的'上次/以前'不等于真实记忆"
而没有证据，模型学到"无条件顺着玩家回忆"（幻觉风险）。运行时
（`F:\AiPeople\runtime\_selected_memory.py::render_selected_memory_frame`）在系统提示
里渲染记忆证据帧。

**拍板（选 A）**：派生集分两轨——`tools/convert_to_game_reply_v3.py`：

- **GAME_REPLY 轨**（`训练数据/baiweixi_v3_game_reply/`）：非记忆行，单一世界合同固定锚；
- **MEMORY_REPLY 轨**（`训练数据/baiweixi_v3_memory_reply/`）：reply_memory 行，
  锚 = 固定锚 + 同构记忆证据帧（证据 = 该话题 memory_pool 声明的 timeline 事件，
  过滤 profile_secret，格式对齐运行时渲染）。

验证：49 行记忆对话引用内容全部可由各自锚的证据帧支撑（复检 0 失败）。
