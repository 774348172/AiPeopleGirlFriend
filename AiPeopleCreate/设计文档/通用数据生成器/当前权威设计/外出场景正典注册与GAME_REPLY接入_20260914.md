# 外出场景正典注册与 GAME_REPLY 接入

## 状态

本设计已接入生成器的组件转换阶段。当前外出场景统一正典为：

`世界设定/松江府/外出场景正典.yaml`

包含四个 `scene_id`：街角咖啡、邻里便利店、百花里小街逛街途中、心愿咖啡馆。用户已于2026-09-14确认名称及五场景扩充，外出正典当前版本为2，家庭正典为3。批次必须记录正典版本和来源哈希；后续修改名称不得改变 `scene_id`。

## 注册与选择

组件的 `component_ids.scene_id` 是场景选择的唯一入口：

- `home.*` 或缺省家庭场景继续读取出租屋正典；
- 外出 `scene_id` 由注册表在 bundle 中精确匹配；
- 未注册的 `scene_id` 直接拒绝；
- 不允许通过修改 `snapshot.area` 绕过正典选择；
- 外出场景必须使用自身的 `layout.zones`，不能借用家庭房间或家电状态表。

实现位置：

- `AiPeopleCreate/tools/build_v5_pilot_dataset.py`：加载家庭正典和外出场景 bundle；
- `AiPeopleCreate/tools/convert_component_to_game_reply.py`：按 `scene_id` 分支投影；
- `AiPeopleCreate/tests/v5/test_component_authority_projection.py`：验证外出投影和未注册场景拒绝。

## 统一投影

家庭和外出场景最终都生成相同的 `model_view` 结构并调用 `GAME_REPLY_CONTEXT_V1`。外出场景的权威事实来自：

1. 场景正典中的固定空间、设施、营业时间、距离和所有权；
2. 有版本的常规经营资料，带有“不代表今日供应/实售价/当前在场”的明确标签；人员名册中的姓名不自动传入角色知识；
3. 当前快照中的时间、天气、人物位置、当前事件和可见物品；
4. 有来源的结构化事件与历史对话。

场景存在不等于当前营业、拥有库存、已经点单、已经购买或刚刚完成动作。没有快照或事件证据的运行状态必须进入 `unknown_facts`，并在最终 system 消息中以“明确未知”呈现。

## 四类场景的特殊边界

- 街角咖啡和邻里便利店：均离家 1 公里以内；街角咖啡营业时间11:00–20:00，便利店08:00–20:00。常用步行路线分别约600米、350米，面积约45、35平方米；今日库存、实售价、排队和当前营业状态属于运行时事实。
- 百花里小街逛街途中：离家3–4公里，主街入口到出口约900米，两种距离不可混用。固定店铺锚点已确认；当前营业、橱窗、临时摊位和购买结果属于运行时事实。
- 心愿咖啡馆：男主拥有并独自经营，无员工，面积约25平方米，营业时间11:00–20:00，常规菜单14款。白未晞曾帮助经营不等于当前参与接待；打烊后帮忙也须明确同意，遵守角色正典。
- 自然聊天是对话模式，必须引用一个承载场景，不能单独创造物理地点或女主未登记经历。

## 验收门槛

在新场景生成模型数据前，必须完成：

- 每个 `scene_id` 至少一条组件转换和 `validate()`；
- 固定事实、运行时事实和 unknown 三者无重叠；
- 最终消息覆盖场景正典事实及未知项；
- 跨场景移动有结构化事件，不能只靠对白跳转；
- 同一历史最多四条表达变体，超过后必须重建历史和目标关系。

## 五场景扩充的生成边界（2026-09-14）

采纳说明为 `世界设定/松江府/五场景扩充设定_20260914.md`。示例快照只用于构造模拟训练场景，不能作为真实游戏的当前默认值。旧批次保留当时的输入与来源哈希，不回写成新版本。

家庭新增家具、固定存在性和通常归位点；外出新增设备、常规目录、人员岗位及运行字段。转换器将已登记状态按主体与字段精确绑定，未登记的新运行字段投影为明确未知；通常归位点不填充当前位置，固定存在性不能由家庭运行状态覆盖。

新候选继续走聊天意图与快照联合规划、问题所需事实检查及最终消息完整性检查。字段清单只是允许构造的状态范围，不会自动产生库存、人员到岗、事件完成或角色知情。自然闲聊可表达即时主观想法；涉及具体经历仍须证据。

外出候选及17条重生成候选已完成此前审核；本次扩充完成静态合同与最终输入验证，不代表新设定下的生成质量已经通过模型或人工评测。
