# 混合候选 200 条隔离扩产

## 2026-09-15 失败回归修订（当前生效）

本节替代下文旧版本中关于零温度编剧、全局问句判重和只冻结当前快照的说明。当前版本为 `joint_scene_v4_frozen_history`。已完成的 `expanded200_b01_20260914` 是旧实现证据，保持原样；改版必须使用新输出目录，不能混用旧检查点。

旧批次有 200 个槽位、86 条格式有效回复，110 个槽位在回复前失败。其中 81 个最终因问句重复失败，25 个因历史证据审核失败，3 个因需求审核拒绝，1 个因需求审核输出截断；另有 4 条回复格式失败。历史审核失败含误判，不能把这些数字当成人工确认的内容错误率。

当前流程：场景/人物种子 → 话题与当前状态规划 → 过去事件规划 → 冻结当前快照和过去事件 → 历史及当前发言编剧 → 历史证据审核 → 完整上下文校验 → 问题所需事实审核 → 正式回复 → 风格/事实审核 → 疑点隔离。

1. 创作请求与审核请求分别配置。场景、事件、编剧使用 0.65 / 0.75 / 0.85 的有限重试采样，审核仍为零温度。以准确 schema 约束输出；语义拒绝不能强行改成通过。
2. 不向编剧提供“最近已用问法”原句列表。历史参照只用于代码侧查重。完整历史重复仍拒绝；相同短问句在话题、场景或事实状态真正不同的上下文中可以成立，不能仅靠改编号或时间绕过去重。本入口仍每条重新构建历史，严格于同历史最多四个变体的上限。
3. 对白生成前规划至多 3 条模拟过去事件，记录时刻、参与者、知情者及关联当前事实编号。事实任务至少规划 1 条，主观聊天允许 0 条；事件不一定对白可知，隐藏事件不能强行转成已知。事件只证明指定过去时刻，不证明持续未变、不倒推谁知道，也不覆盖当前状态。无可知事件时只能写有固定设定依据的历史或主观讨论、未实施计划和假设。事件不是回复生成后的补证，更不冒充实际游戏日志或真实向量召回。
4. 事件原始规划可含角色不知道的事实，但不可知事件仅保存在规划审计文件；角色可知事件同时进入编剧、历史审核、证据目录和最终 `GAME_REPLY_CONTEXT_V1` 的记忆证据区。规划允许旧会话和最近会话两个时段，以分别支撑过去经历和刚才观察；代码禁止用较晚事件证明较早对白。哈希冻结包含事件；完整消息校验检查事件原文与来源。事件的自洽性及对白是否被证据支持仍由模型审核，结构校验不等于语义证明。
5. 历史审核逐句输出 `checks`：主观/固定设定/当前事实/过去事件分类、证据编号、是否纯对白、是否被支持。代码拒绝以当前快照证明旧会话、无冻结事件的过去断言、动态事实冒充正典和动作旁白。问题审核先分别提取原主题和当前请求，再比较 `topic_check`，不允许靠场景中某个无关事实通过。审核明确区分计划和已完成动作，允许同一问题同时引用已知与明确未知。需求证据引用最多 8 个，拒绝理由最多 3 个且每条最多 160 字，避免枚举整份世界状态耗尽输出。审核截断和格式错误单独记录，不能作为语义拒绝或通过。上述语义分类仍可能出错，已有历史来源关键词疑点保留为人工复核入口，不能因模型通过而清除，也不能把关键词命中当作确定错误。
6. 正式回复使用只有 `reply` 的精确 schema；空值、截断、额外说明、序列化污染不得进入目标。仅格式/传输失败最多生成三次，各次原始响应留档。格式有效后不因审核不通过重写答案；审核失败保留原回复给人工判断。短回复可以合格，重复隔离是多样性疑点而不是事实判错。

验证入口：`tools/regress_expanded200_failures.py`。复用旧批次的四条回复格式失败输入、历史误拒案例、混合已知未知案例、截断案例以及两个离题负例，并选择三个重复失败槽位走完整新流程。原始记录不覆盖。此次不训练、不自动重跑整个 200 条，也不以少量回归通过宣称所有模型错误消失。

## 扩充正典后的新批次入口

用户已确认扩充五场景16条全部合格，并授权生成新的200条。新批次使用 `prepare_expanded_batch_seeds.py` 创建批次专属编号和可复现的日期、时段、天气、区域组合；每场景40条，20闲聊、5情绪、5打趣、10事实问答。主题调度是编剧输入，不是最终问句或历史，不允许把占位文本发布为训练样本。

随后调用正式 `run_mixed_candidate_batch.py --count 200 --seed-input ... --history-input ...`。聊天意图/世界状态、相关历史/当前发言、最终回复均由本地Qwen3.5 27B依次生成，Gemma4 12B负责审核。旧批次只供去重参考，不复制其答案或宣称其旧状态仍然有效。

批次冻结种子文件、去重参考文件及权威来源的哈希，续跑不允许改变来源。新旧批次的完整历史检查精确及近似重复，问句检查精确重复，回复重复作为多样性疑点隔离；这不是通用语义去重。每条重新编排独立历史，不用同一段历史凑四个改写。明确未知可以被询问并回答不知道，不应因没有具体值直接拦截这类样本。

先完成这一批，不自动扩大到1000或4000，也不启动训练。规划失败、格式失败、审核拒绝分别保留，实际有效回复数单独统计。人工审核页在本批完成后生成。

## 原有流程与边界

本流程沿用完整 GAME_REPLY_CONTEXT_V1 输入。只生产候选，不启动训练、不自动纳入训练集。用户已确认自然闲聊方向，不能再用状态问答冒充闲聊扩展。

入口为 tools/run_mixed_candidate_batch.py。五个场景各 40 个尝试槽位，共 200 个；100 条闲聊、25 条情绪交流、25 条轻松打趣、50 条事实问答。每条由 qwen3.5:27b 先设计独立的四条旧记忆发言、四条近期发言和当前男主发言，再通过正式生成入口获取白未晞回复。编剧输出是合成训练历史，不是实际用户记忆或向量召回结果；完整编剧请求与响应单独留档。

场景、角色、时刻、天气由程序提供。动态事实改为在对话前联合规划，废止事实槽位只注入一个状态的方式。规划器输出聊天意图以及支持它的一组模拟状态，只能使用注册字段，不能覆盖固定事实。便利店可组合库存、付款、店员在场和收银负责人；心愿的无员工设定不得被改写。编剧随后只扩展话题和对话链。扩产多样性仍需要人工抽检验证，不能仅凭不同编号认定合格。

当前规划版本为 joint_scene_v1，实现在 tools/joint_scene_planning.py。已知值与未知 null 严格区分；visible 表示本条模拟场景明确让角色可见或获知，hidden 值只保存在规划审计文件，转换后的组件、runtime_snapshot 和最终消息中仅保留未知。该来源是合成快照，不冒充真实游戏事件或用户报告。规划结果在对话生成前冻结并记录摘要，不能根据生成答案事后补证据。

对话生成后、回复生成前增加事实需求检查：审核模型从问题和前提提取所需事实，以精确主体/字段引用已知事实或显式未知项；代码再检查引用确实存在、known/intentional_unknown 与值一致。事实任务不允许空依赖；纯主观讨论可没有依赖。缺字段、已知未知错配、前提或状态冲突、审核异常均在回复调用前失败隔离。本版不会自动回填缺失字段或无限重新规划，失败保留原因，后续可据此重做独立候选。

语义需求提取和状态自洽性仍依赖审核模型，不能保证找出所有遗漏；程序保证已声明依赖的引用和值一致，不宣称通用语义正确。旧批次配置缺少 planning_version，禁止混用检查点续跑，必须使用新输出目录。

每条先校验结构和时间，检查历史精确及近似重复、当前问句重复，再重建正式模型上下文并做字段覆盖检查。相似度阈值是疑点筛选启发式，不是语义正确性的保证。当前设计为每条独立历史，比同历史最多四个变体更严格。

回复经过 Gemma4 12B 常规审核和另一次独立事实审核；二者是同一审核模型的两个请求，不是两套独立模型。事实审核单独检查已知拒答、虚构具体往事、计划变完成、人物观察混淆和上下文关联性。主观愿望、审美及假设不要求作为世界事实登记。任何审核失败、内容拒绝或输出重复均隔离，不直接丢弃原始证据。

候选全部留档，人工页包含按场景和聊天类型分层抽取的 32 条，以及全部隔离项（取并集，不重复）。因此疑点多时页面可能明显超过 32 条。规划失败槽位单独记录，不能将尝试 200 条报告为成功生成 200 条，也不自动无限重试补齐。

支持逐条检查点续跑。完成后写出候选全集、实际审核子集、摘要校验、统计及 review.html。自动批准只表示可供抽检，不等于事实已被验证。4000/10000 条扩产仍应等这批抽检和错误分布确认后再推进。

验证：200 槽位正式输入预检；历史重复不能靠更换 ID 绕过、空历史拒绝、32 条抽样覆盖全部场景和类型的测试；现有场景和权威投影测试。
