# 五层场景训练数据结构

实施状态澄清：下文是目标合同，不表示五层已全部被生产消费。连续会话以[连续对话链生成与验收](连续对话链生成与验收_20260912.md)为准；不能用结构字段存在代替最终模型输入验证。

生成器按“一组基础设定 + 一个场景正典 + 一个运行时快照生成一条训练样本”工作。每条样本必须携带以下五层：

1. `protagonist_profile`：男主稳定身份与偏好。当前已确认男主是四川人，四川口味、能吃辣、喜欢油腻。它是基础资料，不代表白未晞已经知道。
2. `female_character_profile`：白未晞的身份、性格、知识边界、能力边界和关系边界。稳定角色知识通过生产角色锚渲染；结构字段用于审计和生成器契约。
3. `scene_canon`：固定房屋与世界设定，例如松江府老城区六楼两室一厅、房间布局和长期存在的家电。它不会因一条样本而改变。
4. `runtime_snapshot`：本条样本的当前时间、天气、人物位置/情绪、物品与设备状态、当前世界事件和历史对话。不同快照可以产生同一问题的有效对照。
5. `known_by_baiweixi`：白未晞在当前时刻真正已知的男主偏好、记忆和事实。基础设定不自动进入这一层；没有证据就不能说“我记得”。

渲染顺序是：固定角色锚 + 五层结构投影 + 当前男主问题。训练数据保存结构化输入和最终模型可见消息；正式程序必须调用同一投影函数。`target_reply` 只监督白未晞实际说出口的回复，不把内部字段当作训练目标。

场景变体只修改 `runtime_snapshot`，例如只改时间、天气、钥匙位置或历史话题；不得修改男主基础设定、女主稳定设定或固定房屋正典。状态变化必须同步更新事实、未知列表和回答合同。第三方历史必须保留说话人、来源和原话。

## 连续对话构造顺序（2026-09-12 修订）

生成器必须先确定当前事实目标，再构造同主题的记忆对话，接着构造最近会话，最后由最近会话的未解决事项生成当前男主问题。禁止先生成问题、再按编号附加历史；禁止使用“与当前问题相关”这类没有具体原话的占位记忆。最终去重必须比较记忆、最近历史、当前问题和权威快照的组合指纹。
