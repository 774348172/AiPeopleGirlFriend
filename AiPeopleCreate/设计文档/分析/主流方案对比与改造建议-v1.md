# 主流数据生成方案对比与改造建议（v1）

> 2026-08-07 | 定位：**分析类文档**（不施工）
> 对比对象：AI 女友角色微调主流方案总结（SFT 5 种 + DPO 3 种 + 通用增强 3 项）vs 我们的通用生成器（data_gen_v4）

---

## 一、我们的定位

data_gen_v4 **本质 = 主题驱动直出法（Magpie 范式）**：池条目（topic/场景标签）→ prompt 直出多轮对话 → 内置过滤链路。

**结论：主方向正确**（Magpie 是角色微调最常用的方案），但对照完整方案清单存在 **2 个方向性缺口 + 4 个可改进点**。

## 二、逐项对比

### SFT 类（5 种）

| 方案 | 我们的现状 | 判定 | 差距评估 |
|---|---|---|---|
| ① 种子衍生法（Self-Instruct） | 池条目≈种子，但直接生成不做衍生 | ⚠ 部分对应 | 低——无需改，直出法更适合角色场景 |
| ② 主题驱动直出法（Magpie） | **完全对应（主架构）** | ✅ | 无 |
| ③ 进化指令法（Evol-Instruct） | 无难度梯度（池内场景平级） | ❌ 缺失 | **中**——复杂情绪/多轮拉扯场景缺失（评审 relationship 类落后与此相关） |
| ④ 公开语料改写 | 无（数据全 AI 生成） | ❌ 缺失 | 低——项目有历史语料（data/life_corpus/qwx_all.jsonl）可试，注意合规 |
| ⑤ 模板实体填充 | pool_variants（12 条变体注入）≈ 雏形 | ⚠ 部分 | 低——基础场景已覆盖，价值有限 |

### DPO 类（3 种）——**全部缺失，最大缺口**

| 方案 | 我们的现状 | 判定 | 差距评估 |
|---|---|---|---|
| ⑥ 同题双答直接配对 | 无 | ❌ | **高价值 + 零成本路径**（失败样本回收，见下） |
| ⑦ 多回答打分排序（RLAIF） | 无 judge | ❌ | 依赖更强评审模型（重构方案 L3 已规划） |
| ⑧ 正向样本反向改造 | 无 | ❌ | 中——改造 prompt 即可做 |

### 通用增强（3 项）

| 方案 | 我们的现状 | 判定 | 差距评估 |
|---|---|---|---|
| RAG 增强 | canon 事实库=注入式知识，但**全量注入不分场景** | ⚠ 部分 | 低——按池裁剪 FACTS（safety 池不需要童年事实） |
| 多模型混合 | 单一教师（deepseek-v4-flash） | ❌ | 中——依赖 aihub 其他模型可得性 |
| 三层质检 | 规则过滤 ✅（G0-G8）｜**近重复去重 ❌**｜模型打分 ❌ | ⚠ 部分 | **去重低投入立即做**；模型打分=重构 L3 |

## 三、改造建议（按优先级）

### P0：DPO 偏好数据生成（最大缺口，零成本启动路径）

**核心洞察：重试失败样本 = 现成人设崩塌样本（rejected）**

| 回收路径 | 说明 |
|---|---|
| **失败候选回收** | 被 P3/P4/G8 拦截的候选（身份朗读/冷漠/拍背吐水/属性不合时宜）→ 直接作为 DPO `rejected`；sqlite 中 gate_report 拒绝的候选文本仍可读（**零新增 API 成本**） |
| **同题双答** | 同一 topic：正常 prompt 生成 chosen + 引导崩塌 prompt（冷漠/说教/朗读身份）生成 rejected → 配对 |
| **配对质量** | 校验 chosen/rejected 差异度（过低丢弃） |

训练侧：LLaMA-Factory 原生支持 DPO ✅（MLX 的 DPO 亦支持）。
**组合价值**：SFT 打底人设 + DPO 优化情感体验——与主流推荐组合一致。

### P1：近重复去重（低投入高价值）

- 1000 条生成后无 SimHash/MinHash 去重——casual 489 条中预计 5-10% 高重复
- 工具层脚本（不动架构）

### P2：进化指令法（难度梯度）

- supportive/romance 池加 `difficulty` 字段（简单承接 → 复杂拉扯）
- 与评审发现的 relationship 类落后、长对话体验弱直接相关

### P3：小改进

- 按池裁剪 FACTS（减少无关事实干扰，顺带缓解属性不合时宜）
- 多模型混合（若 aihub 有其他教师模型）

## 四、与重构方案的衔接

| 本次发现 | 衔接点 |
|---|---|
| DPO 失败样本回收 | 重构方案的 **taxonomy 飞轮** 正好提供 rejected 样本分类 |
| DPO 多回答打分 | 重构方案 **L3 评审模型** = 打分排序的 judge |
| 近重复去重 | 独立工具，不冲突 |

**路线建议**：SFT 两阶段重构（进行中）→ 失败样本回收做 DPO rejected（零成本启动）→ 评审模型到位后升级多回答打分 DPO。
