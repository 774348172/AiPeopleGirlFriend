## 图片与现有模型的对应

现有模型的厨房、玄关、主卧、右上次卧、右下卫生间、下方阳台拓扑基本对应。墙体比例、局部转角和门洞是图生模型重建结果，不是原图的精确 CAD 复刻。本轮没有修改墙体或重建房屋。

餐桌已从客厅中央移到左下餐桌区；中央增加独立茶几、地毯，右侧布置朝左的三人沙发，电视低柜沿左墙布置。厨房已改为沿左墙和窗下组合的 L 形台面，并补上正典中的家电。主卧补被褥/床头柜，次卧补储物架和桌椅；卫生间补洗衣机、洗手台、镜子和淋浴外形；阳台两侧为盆栽，中部为空晾衣杆。

原图不同视图之间的纸箱位置有差异：左图看起来位于阳台右侧，右上图在窗边室内。右侧候选 `(1.9, 地面, -4.15)` 实测被主卧墙/关闭的门遮挡；沿窗侧扫描，`x=-0.6` 及更左的候选可看见入口。考虑阳台门口与角色净空，最终采用 `(-1.9, 地面+0.26, -4.15)`，位于阳台门左侧室内窗边。坐姿 0.95m/站姿 1.5m、六门全开/全关都检查至真实入户门表面，不忽略墙体或门叶。第一版失败证据保留在 `output/apartment-furnishing-layout/iteration-1/geometry-audit.txt`。

图中没有清楚画出的设施先列入细化项，不把想象位置当成原图内容。设备存在与是否正在运行继续分离；家具摆放不新增后端地点 ID，也不把次卧分配给白未晞。

## 已实施与重现

1. `ApartmentFurnishings` 只应用于导入房屋；保留餐桌表面、水杯、唯一纸箱、三个后端地点锚点。桌边交互站位移到 `(-3.05, 地面, -3.30)`，第一人称出生点避开新茶几。
2. 各家具组内按材质合并装饰网格；家具共 2,080 三角面、81 个有效渲染器，外壳保持 15,000 面。大件采用简化实体碰撞；地毯/装饰无额外碰撞，生成的 Mesh 在场景销毁时释放。
3. 修正餐椅、床头柜和洗衣机的穿墙间距。沙发/茶几向右调整 0.35m，使去阳台的路径绕开旧模型门槛凸起。阳台盆栽提升至落地高盆栽比例，避免成为角色可攀踩的栏杆旁台阶。
4. 家具调整后执行 `AiPeople.EditorTools.ApartmentFurnishingRefresh.Refresh`，更新导航与场景配置、几何审计和五张实际 Unity 预览。无需重新导入/减面外壳。
5. PlayMode 运行 `AiPeople.Tests.Apartment`、`RoomControlsTests`、`ChatUiServerTests`、`ChatWindowLatencyTests` 和 `ShellTests`。新增家具实体/设备、门扇扫掠和门口净空、外墙独立射线与生成网格释放检查；已有全屋连续行走、视线及镜头测试继续执行。外边界测试的接近点按实际过道调整，不取消边界阻挡验证。
6. `ApartmentShellImporter.BuildPreviewPlayer` 配合新的 `AIPEOPLE_BUILD_PATH` 构建 Windows 包。`python Tools/Apartment/verify_furnished_player.py <exe> --output <新证据目录>` 检查两次启动的图标下方挂载与 12 次门窗 API 转换，不注入输入或发送聊天内容。

下一步为正式家具美术替换、窗帘/玄关门垫与挂放区/卫生间细部；热水设备类型继续未定。不把本轮摆设当成电器运行或家务完成事实。验证结果与新包路径见 `output/apartment-furnishing-layout/RESULTS.md`。
