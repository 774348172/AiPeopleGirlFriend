# 女主角角色包需求

> 文档状态：当前有效需求合同  
> 适用产品：《猫咪女友》  
> 适用范围：所有现在与未来新增的女主角角色包  
> 当前 P0 激活角色：`baiweixi`（白未晞）

## 1. 目的

女主角不是项目框架的一部分，而是可以装载到同一个产品、同一个世界和同一个存档中的内容包。项目需求只定义通用能力；每位女主角的人设、经历、知识、声音、美术、训练资产和专属评测由各自角色包定义。

新增女主角不得要求复制一套运行时、创建另一个男主角或建立彼此隔离的世界存档。

## 2. 核心不变量

1. 每个女主角拥有全局唯一且永久稳定的 `character_id`。
2. 所有女主角共享同一个 `world_id`、同一个 `save_id` 和唯一男主角 `protagonist_id`。
3. 每位女主角分别拥有自己的当前身心、关系、记忆、自我时间线、欲望与知识边界。
4. 一位女主角不会因为事件写入同一存档，就自动知道另一位女主角的私密对话或私密经历。
5. 角色包只描述该女主角，不复制世界正典和主角正典；只通过 ID 和路径引用共享权威。
6. 角色包不得自行改变项目安全规则、运行时事务规则、游戏时钟规则或玩家主角的唯一性。
7. P0 只允许一个激活女主角参与当前对话，但数据结构从第一天起必须携带 `character_id`。

## 3. 标准目录

每个角色包至少采用以下结构：

```text
人物设定/<角色目录>/
  README.md
  角色设定定稿.md
  bible.yaml
  canon.json
  timeline.yaml
```

未来训练、美术、语音与评测资产可以位于独立资产目录，但 manifest 必须通过 `character_id` 关联，不得依赖中文目录名猜测角色身份。

## 4. 必填身份与引用

每个角色包必须声明：

```yaml
identity:
  character_id: baiweixi
  display_name: 白未晞
  role: heroine
  adult_status: 明确成年

shared_context_refs:
  world_id: songjiangfu
  world_canon: 世界设定/松江府/
  protagonist_id: protagonist
  protagonist_canon: 人物设定/主角/
```

约束：

- `character_id` 发布后不可复用或因改名而改变。
- `display_name` 可以在剧情中变化，但不能替代 ID。
- `world_id` 和 `protagonist_id` 必须引用当前共享权威。
- 角色包中若出现共享事实，只能作为“该角色如何看待或知道该事实”，不能成为共享事实的第二权威。

## 5. 角色正典合同

角色包必须覆盖：

- 身份、种族、成年状态和稳定外观。
- 出身、重要经历与当前时间线锚点。
- 核心性格、价值倾向、防御方式和情感表达方式。
- 说话风格、称呼策略、禁止表达和防止人格漂移的边界。
- 能力、代价、限制和明确未知项。
- 对主角的初始认知、初始关系和关系边界。
- 对共享世界的已知部分、未知部分和秘密披露规则。
- 角色专属地点、物品、习惯、目标与未解决剧情线。

`角色设定定稿.md` 面向人类审阅，`bible.yaml` 面向上下文和数据生成，`canon.json` 面向硬事实校验，`timeline.yaml` 面向事件顺序和记忆素材。四者冲突时必须停止生产并人工消歧，不能由模型自行选择。

## 6. 初始运行时状态

角色包必须提供可以创建新存档的初始状态模板，但初始模板不是运行中状态的永久权威。进入存档后，真实状态由事件账本和投影重建。

至少包括：

```yaml
initial_runtime:
  character_id: baiweixi
  living_mind:
    body: "..."
    emotion: "..."
    attention: "..."
    current_activity: "..."
    immediate_intent: "..."
  relationship:
    protagonist_id: protagonist
    stage: "..."
    trust: "..."
    unresolved_tension: "..."
  knowledge_boundary:
    known: []
    suspected: []
    unknown: []
```

每份运行时状态必须同时携带 `save_id`、`character_id`、状态版本和最后证据事件 ID。

## 7. 记忆与知识隔离

写入事件时至少记录：

```yaml
event_scope:
  participants: [protagonist, baiweixi]
  observers: []
  location_id: apartment
  visibility: private
  knowledge_eligible_for: [protagonist, baiweixi]
```

运行时为当前激活女主角召回记忆时，只能从以下集合选择：

1. 她亲自参与的事件。
2. 她在场观察到的事件。
3. 后续由可信主体明确告知她的事件。
4. 世界公开信息中她按正典有能力知道的部分。

禁止：

- 因另一角色与主角发生过私密事件，就让当前女主角自动知道。
- 把模型训练中见过的其他女主角设定当作当前角色知识。
- 把玩家 OOC 指令、调试信息或现实账户信息写入角色记忆。
- 在没有事件证据时伪造“我们以前说过”或“我亲眼见过”。

## 8. 角色专属资产合同

以下资产必须由 `character_id` 绑定：

- 训练数据与训练 manifest。
- LoRA、合并权重或其他角色适配资产。
- 角色专属提示词片段。
- 立绘、表情、动作和服装资源。
- 声线、TTS 参考音频和语音参数。
- 角色专属自动评测集与人工盲测表。

项目不得把某一角色的模型格式、声线、立绘规格或训练规模写成所有角色必须遵守的产品事实。

## 9. 评测合同

每个角色包必须通过两类评测：

### 9.1 通用产品评测

- 能自由理解并回应玩家。
- 不遗忘或无证据改变当前身体、心理、活动、位置与时间。
- 能在合理证据和时间流逝下自然改变状态。
- 记忆召回遵守参与者、观察者、可见性和知识资格。
- 不替玩家决定重大行动。
- 不混淆游戏内主角与现实玩家。

### 9.2 角色专属评测

- 身份与经历准确。
- 口吻、价值倾向和情感表达符合人设。
- 能力使用不越界。
- 关系推进速度符合角色设定。
- 未知项不被补写为确定事实。
- 与其他角色的语言和行为具有可辨识差异。

## 10. 版本与迁移

- 角色包使用独立 `package_version`。
- 正典变更必须声明是补充、修正还是破坏性迁移。
- 已有存档迁移不得静默重写玩家与角色已发生的历史。
- 角色包卸载后，存档中的历史事件仍保留；重新安装同一 `character_id` 后可以恢复。
- 历史废弃角色必须移入历史文档区，不得继续出现在当前角色注册表、训练入口或默认运行配置中。

## 11. 当前 P0 解释

P0 只验证：

- 同一存档中加载共享世界、唯一主角和一个激活女主角。
- 首个激活女主角固定为 `baiweixi`。
- 对话、状态、记忆、关系和时间链路都按 `character_id` 写入。

P0 不验证：

- 多位女主角同时在场生成回复。
- 女主角之间的自动对话。
- 多角色并发推理和群体场景调度。
- 复杂修罗场、竞争关系或跨角色自动剧情。

这些能力未来可以增加，但不得推翻本合同中的共享存档、知识隔离和角色 ID 设计。
