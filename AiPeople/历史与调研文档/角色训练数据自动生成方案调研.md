# 角色训练数据自动生成方案调研

> 性质：调研资料（非实施要求）。  
> 日期：2026-08-04。  
> 目的：调研业界"用 AI 自动生成虚构角色训练数据"的最新论文与开源方案，对照本项目（正典 + 强模型生成 + 一致性检查 → 微调 Qwen3-4B）找出可借鉴点。
> 核验说明：标 ✅ 的链接已逐个抓取核验为真实存在；标 ⚠️ 的为检索报告提供、未逐一打开核验。

## 0. 核心结论（先看这个）

**业界已收敛到与本项目几乎同构的范式**：

```
角色档案/正典 → 场景化/分段时间线 → 强模型(GPT-3.5/4 级)第一人称生成多轮对话
→ 质量过滤/一致性校验 → SFT 微调小模型
```

我们的 bible/canon/timeline 正典 + glm-5.2 生成 + consistency_check 路线**方向正确，没有重复造轮子**。缺的是四个细节工程（详见 §7 可落地建议）：

1. **置信度自评过滤**（RoleLLM Context-Instruct）：生成时让模型自报置信度+理由，低置信度丢弃
2. **Protective scenes 反幻觉数据**（Character-LLM）：专门生成"她不可能知道/不会做"的样本
3. **记忆驱动生成**（MemoryForge/RoleMemo）：先合成角色"自传体记忆库"再生成对话，细节一致性大幅提升
4. **防人设漂移**（SPASM）：多角色/长对话生成时用"视角投影"存历史

## 1. 第一梯队：与本项目最接近的方案

### 1.1 OpenCharacter（2025-01，最接近）✅
- 链接：https://arxiv.org/abs/2501.15427 ；数据：https://huggingface.co/datasets/xywang1/OpenCharacter
- 思路：不针对单角色，先大批量合成**角色档案**（从 Persona Hub 抽取 persona → GPT-4o 扩展为完整档案），再为每个角色生成第一人称对话，微调 LLaMA-3-8B 实现"角色泛化"。
- 数据生成双策略（可借鉴）：
  - **OpenCharacter-R（改写）**：把通用指令数据（LIMA/Alpaca）里已有的助手回答**改写成"该角色会怎么说"**，用户话术不变
  - **OpenCharacter-G（生成）**：直接按角色风格/经历/性格生成新回答
- 规模：2 万角色档案、30.6 万对话对。评估用 PersonaGym，8B 超过 GPT-4o 变体。
- **对我们的价值**：R 策略（任意问答 → 角色口吻改写）非常适合批量制造单角色语料；档案扩展 prompt 可直接照抄。弱点：论文承认没有独立自动一致性过滤——正是我们的强项。

### 1.2 Character-LLM：Experience Reconstruction（2023-10，EMNLP）✅
- 链接：https://github.com/choosewhatulike/trainable-agents ；论文：https://arxiv.org/abs/2310.10158
- 思路：不为角色写对话，而是先生成角色"经历过的事件场景"，再补全对话——让模型学到经验/性格/情感。平均每角色 1.6K 场景、13 轮/段、约 75 万字。
- 数据生成管线（与我们的 timeline 高度契合）：
  1. Profile Construction（档案）
  2. Scene Extraction（GPT-3.5-turbo 基于档案生成场景）
  3. Experience Completion（按场景生成多轮对话）
  4. **Protective Scene（保护性场景）**——生成"角色对超出设定的问题做出符合人设的拒绝/回应"的样本，**抑制幻觉/OOC** ⭐
  5. 转 SFT 格式（FastChat 全参微调 Llama-7B）
- 数据生成代码完全开源（run_api_gen_data.py 等）。限制：仅学术研究，禁止商用。

### 1.3 RoleLLM：Context-Instruct + 置信度过滤（2023-10）✅
- 链接：https://github.com/InteractiveNLP-Team/RoleLLM-public ；论文：https://arxiv.org/abs/2310.00746 ；数据：RoleBench（16.8 万条）
- 四阶段：角色档案 → Context-Instruct（抽取角色知识与"情节记忆"）→ RoleGPT（模仿说话风格）→ RoCIT（微调）。
- 关键细节（论文明确）：Context-Instruct 让 LLM 生成"问题-答案-**置信度分数（含理由）**"三元组，**置信度过滤 + 去重**；论文说"不加置信度会导致问题残缺或幻觉" ⭐
- RoleGPT 用 **BM25 检索档案中最相关的 top-5 对话对做 few-shot**，对话式 prompt。
- 对我们的价值：置信度自评过滤是"最有效的一致性保障机制、成本低、可立即加入检查流程"。

### 1.4 SPASM：稳定人设多轮对话合成（2026-04，ACL 2026 Findings）✅
- 链接：https://arxiv.org/abs/2604.09212
- 问题：LLM 互相对话生成合成语料时**人设漂移、角色混淆、互相回声**。
- 方案：persona 创建 → Client-Responder 双角色对话生成 → 终止检测三阶段；核心是 **Egocentric Context Projection (ECP)**——对话历史以"无视角"形式存储，生成前投影到每个 agent 的视角。4500 persona / 4.5 万条对话，消融显示 ECP 显著降低漂移、消除回声。
- 对我们的价值：我们正是"强模型扮演双方"生成数据——ECP 是现成防漂移方案；将来多角色共场（三女友）时必用。

### 1.5 Operation Veja：角色"内在世界"四要素（2025-12，NeurIPS 2025 workshop）✅
- 链接：https://arxiv.org/abs/2601.06039
- 观点：现有角色扮演模型"缺乏可信角色深度"的根因是训练数据缺**动态内在世界**。
- 提出 **VEJA 四要素**：Values（价值观）/ Experiences（经历）/ Judgments（判断）/ Abilities（能力）——做数据策划（curation）而非只靠合成。
- 对我们的价值：生成角色档案时不要只写外貌性格，要写价值观/经历/判断方式/能力边界——这些正是恋爱游戏角色区分度的来源。我们 bible.yaml 已含部分（价值观），可补"判断方式"维度。

### 1.6 Fixed-Persona SLMs with Modular Memory（2025-11）✅
- 链接：https://arxiv.org/abs/2511.10277
- 与"Qwen3-4B 成为一个人"几乎同构：为每个 NPC 微调固定人设的小模型（DistilGPT-2/TinyLlama-1.1B/Mistral-7B），运行时通过**可热插拔记忆模块**注入上下文与世界知识，消费级硬件跑游戏 NPC。
- 对我们的价值：验证了小模型+固定人设路线的可行性；"记忆模块可换"思路可做同一模型的多个角色版本或长期记忆注入设计（与我们双系统记忆的快轨对应）。

## 2. 记忆驱动生成（2026 年最活跃方向）

### 2.1 MemoryForge：从人设合成"终生记忆"（2026-06）✅
- 链接：https://arxiv.org/abs/2608.00007
- 用冻结 LLM 从简短人设**合成整套虚构人生记忆**（自传体记忆库），agent 按情境检索相关记忆再行动——**memory-based conditioning 取代静态文本人设**。
- 三组件：context generator（社会历史背景）、life organizer（发展连贯性）、multi-resolution simulator（时间摘要与具体经历平衡）。
- 对我们的价值：直接为秦未晞合成"人生记忆库"（timeline 已有素材），生成时注入"角色回忆"再产出第一人称语料——细节一致性和情感厚度自然提升。

### 2.2 RoleMemo + DualMem：事实记忆与人设化解读分离（2026-05）✅
- 链接：https://arxiv.org/abs/2605.25693
- RoleMemo 数据集：4 类任务，"同一事实必须通过人设解读"；DualMem 双流记忆（事实认知流 + 人设化洞见流）。4B 模型 SFT+RL 后持久人设保真度超过 DeepSeek-V3.2 零样本方案。
- 对我们的价值："同一事件不同角色反应不同"正是恋爱游戏卖点——其任务设计可直接转成数据生成模板。

### 2.3 斯坦尼斯拉夫斯基"情感记忆"范式（2026-03）⚠️
- 链接：https://arxiv.org/abs/2603.19313
- MRPrompt 提示架构（人设知识当 LLM 的"内心记忆库"）+ **MRBench 双语基准（含中文）** + MREval 细粒度评估。
- 对我们的价值：MRBench 可用来验收我们微调出的角色模型（中文可用）。

### 2.4 REVERIEMEM：角色视角受限记忆（2026-06）⚠️
- 链接：https://arxiv.org/abs/2606.25632
- 针对原著角色"越权知识"（factual overreach）问题，三层记忆架构限制知识边界，保真度提升 34.6 点。
- 对我们的价值：角色不能知道"不该知道的事"（如异世界秘密的边界），防世界观泄漏。

## 3. Self-play / 多智能体自演

| 方案 | 链接 | 思路 | 借鉴点 |
|---|---|---|---|
| MADS（2025-09）✅ | https://arxiv.org/abs/2510.05124 | 用户 agent（星座/MBTI 驱动）+ 对话 agent + 优化 agent 三类协同自演，无人工标注；转化率提升 22.4% | "玩家 agent（有性格偏好）+ 角色 agent + 质量裁判"结构可直接照搬 |

## 4. 数据蒸馏/生成框架（通用领域 → 可搬到角色域）

- **AgentInstruct**（2024-07）✅ https://arxiv.org/abs/2407.03502 ：种子素材 → 多 agent 协作 → 大规模合成（25M 对）。→ 用"角色世界观文档"作种子。
- **GLAN**（2024-02）✅ https://arxiv.org/abs/2402.13064 ：人工策划"知识分类树"，逐节点生成，覆盖广无污染。→ 为角色建"剧情事件分类树"（相识→暧昧→冲突→和解），保证各阶段语料均衡。
- **GroupPersona**（2026-06）⚠️ https://arxiv.org/abs/2606.07893 ：合成对话对齐"总体行为分布"（12 个行为属性 JS 散度降 24.4%）。→ 有少量目标风格样本时校准合成数据分布。

## 5. 评估基准与数据集资源（可直接拿来用）

### 评估基准
- **PersonaGym / PersonaScore**（2024-07）✅ https://arxiv.org/abs/2407.18416 ：动态人设评估框架，10 个 LLM / 200 人设 / 1 万问。→ 验收角色模型的现成工具。
- **CharacterEval**（2024-01）✅ https://github.com/morecry/CharacterEval ：中文基准，77 角色 / 1785 段多轮 / 23020 样本 + CharacterRM 奖励模型（人工评分训的小评估器，可本地跑省 API 费）。
- **MiniMax role-play-bench** ✅ https://huggingface.co/datasets/MiniMaxAI/role-play-bench ：**情境重现**评估法——不设唯一答案，比较"该角色最可能怎么回答"。→ 一致性检查可借鉴（多候选打分排序而非硬判对错）。

### 角色数据集（hf-mirror.com 可下载）
- OpenCharacter（2 万角色 + 30.6 万对话）✅
- RoleBench（16.8 万条）✅
- ChatHaruhi-Expand-118K ✅（context/target 格式，直接对接 LLaMA-Factory）
- Character-LLM 数据（1.6K 场景/角色）✅
- Evol-Character ✅（角色信息+多轮对话，带【动作/情绪】标注——与我们的标签系统同构）
- PIPPA ✅（真实用户-AI 角色扮演记录 10K-100K，Apache 2.0，混入可提升口语自然度）
- SoulChatCorpus ✅（中文真实共情对话 258K 段，隐私/质量已过滤）

## 6. 商业/大厂方案（公开信息有限）

- **Character.AI**：无公开技术论文。已知：模型 GPT-3.5~4 量级，训练数据以海量用户角色扮演对话 + 用户反馈 RLHF 为主。启示：**产品真实交互数据是最佳微调语料**（我们本地单机无此条件，但可用 SillyTavern 人工试玩采样）。
- **AI Dungeon**：在用户生成冒险文本上微调。同样是"用户生成内容反哺"模式。
- **智谱 CharacterGLM**（2023-11）✅ https://github.com/thu-coi/CharacterGLM-6B ：角色七属性（身份/兴趣/观点/经历/成就/社交关系/其他）+ 行为（语言特征/性格）；评估维度（一致性/拟人化/吸引力 + OOC/矛盾/重复错误分析）可直接用作我们的评分 rubric。开源版仅学术。
- **腾讯 Persona Hub**（2024-06）✅ https://arxiv.org/abs/2406.20094 ：从网络蒸馏 10 亿 persona，驱动任意 persona 条件生成。→ 角色档案生成底座，但我们是单角色不需要。
- **中文大厂**：百度/阿里/讯飞/腾讯均未公开人格化数据生成管线（调研确认），角色扮演多为提示词/插件形态。

## 7. 对秦未晞方案的可落地建议（按性价比排序）

| # | 建议 | 来源 | 成本 | 收益 |
|---|---|---|---|---|
| 1 | **Protective scenes 反幻觉数据**：为秦未晞生成"她不可能知道/不会做"的样本（如"异世界的真相"被追问时的反应、"你俩是不是情侣"的回应） | Character-LLM | 低（复用现有生成器，加一类 prompt） | 高——OOC/幻觉显著减少 |

| 4 | **MRBench / PersonaGym 验收**：训练后用它评测角色保真度（含中文） | MRPrompt / PersonaGym | 中 | 高——训练效果可量化 |
| 5 | **场景分类树**：建立恋爱剧情节点分类树，逐节点生成保证覆盖均衡 | GLAN | 中 | 中——防"日常多、冲突少"失衡 |
| 6 | **记忆库驱动生成**：先合成秦未晞"自传体记忆库"（timeline 已具雏形），生成时注入回忆再产出语料 | MemoryForge | 高 | 高——细节一致性/情感厚度质变 |
| 7 | **ECP 视角投影**：长对话生成时历史无视角存储、生成前投影，防人设漂移 | SPASM | 中 | 中——当前 4-8 轮不严重，扩到 20+ 轮时必需 |
| 8 | **多 agent 裁判过滤**：加一个"质量裁判 agent"对生成对话打分过滤 | MADS | 中 | 中——替代/增强规则检查器 |

## 8. 空白点（我们的差异化机会）

未发现 2025-2026 有公开论文专门做"**恋爱/亲密关系向、单角色深度绑定、本地小模型**"的方案——多为通用多角色或多智能体。我们在此位置有差异化空间；同时"剧情张力驱动的秘密管理"（如 Tricking LLM-Based NPCs into Spilling Secrets，https://arxiv.org/abs/2508.19288 ⚠️）提示：角色"秘密管理"要考虑对抗提示，Protective scenes 顺带覆盖。
