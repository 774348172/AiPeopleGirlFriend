## 版本 1：林知微 v1 (M1)

### 配置
- 基座：Qwen3-1.7B，QLoRA 4-bit
- 数据：45 条 sharegpt（36 diary + 9 chat，无 identity/casual/protective）
- 训练：5 epoch，lr 5e-5，cutoff 1024，template qwen（未关思考）
- GPU：RTX 3070 8GB，无显存限制

### 效果
- loss：3.71
- 口吻：✅ "嗯/其实/说不上来" 稳定出现
- 身份问题：❌ "你是谁"被 reasoning 思考占满（200 token 全是 think，正文空）
- canon：部分正确（成都/上海/豆豆对，但张行言认识场景模糊）
- protective：✅ 问诺贝尔奖时婉拒"不太记得"
- 助手腔：✅ 零
- 写诗：❌ "帮我写首诗" → 无限重复"嗯"崩坏

### 核心问题
1. reasoning 模型思考占用 max_tokens，开放问题正文为空
2. 数据量极少（45条），无身份锚、无闲聊
3. 遇到训练分布外任务直接崩

### 对话样例
```
问: 你是谁？
答: <think>（思考过程占满，正文为空）

问: 帮我写一首关于秋天的诗
答: 嗯...嗯...嗯...嗯...（无限重复）
```

## 版本 2：林知微 v2 (C)

### 配置
- 基座：Qwen3-1.7B，QLoRA 4-bit
- 数据：147 条（36 diary + 18 chat + 30 protective + 30 identity + 33 casual）
- 训练：5 epoch，lr 5e-5，cutoff 1024，**template qwen3_nothink（关思考）**
- GPU：RTX 3070，显存限制 70%，进程 BELOW_NORMAL 优先级

### 改进点（相对 v1）
- ✅ 关思考（qwen3_nothink 模板）——"你是谁"不再被思考占满
- ✅ 加 identity 锚样本（15 种身份问题）
- ✅ 加 casual 闲聊样本（33 条多轮自由对话）
- ✅ timeline 扩到 36 节点
- ✅ GPU 限制脚本（train_gpu_limit.py）
- ✅ reasoning 模型适配（max_tokens 2048 + prompt 禁思考 + 正文取 content 回退）

### 效果
- loss：3.11（从 3.71 降到 3.11）
- 口吻：✅ 稳定
- 身份问题：✅ "我叫林知微，成都长大，后来搬去上海"
- 自由对话：❌ **套模板**——问什么都说"嗯...其实...豆豆...画画"
- canon：⚠️ 漂移（老家说重庆、年龄说 24）
- 写诗：✅ 从崩坏到能写短诗"秋不是诗，是画里的一笔"
- 助手腔：✅ 零

### 核心问题
1. **回答固定/套模板**：114 条回复几乎全以"嗯"开头（数据同质化）
2. **不会自由对话**：训练数据全是结构化（日记/身份问答/婉拒），没有自由闲聊
3. **canon 漂移**：1.7B + 114 条数据量不足，记不住事实
4. **过拟合**：5 epoch × 114 条 = 模型记住模板而非泛化

### 对话样例
```
问: 今天天气怎么样？
答: 嗯...上海的天气说不上好，阴晴不定的，我画画的时候一般不会看天气预报...豆豆在窗台晒太阳...

问: 你为什么每次回答都很长？
答: 嗯……我就是习惯了这样。画画的时候说不上来话...

问: 我刚刚有问你天气怎么样吗
答: 嗯……其实上海的天气说不上好...（重复之前的话）
```

### 用户实测反馈
- "很多问题都没有正确回答"
- "回答问题很固定"
- "完全无法作为一个自由聊天的对象"
- "每次回答都很长一段话"
- 反问用户（"你平时喜欢画画吗？"）——后被确认为人味特征，非问题

## 版本 3：林知微 v3 (D)

### 配置
- 基座：**Qwen3-4B**（从 1.7B 升级），QLoRA 4-bit
- 数据：147 条（同 v2）
- 训练：3 epoch（从 5 降到 3 防过拟合），lr 5e-5，cutoff 512，template qwen3_nothink
- GPU：RTX 3070 8GB，无显存限制（4B 需满载），expandable_segments

### 改进点（相对 v2）
- ✅ 基座 1.7B → 4B
- ✅ epoch 5 → 3（防过拟合）

### 效果
- loss：2.97（从 3.11 降到 2.97）
- loss 曲线：4.63 → 2.88 → 2.65 → 2.50（平稳下降，无过拟合迹象）
- 口吻：✅ 稳定
- 身份问题：✅ 正常回答
- 自由对话：❌ 仍套模板（数据没变，4B 也救不了）
- canon：⚠️ 仍漂移
- 助手腔：✅ 零

### 核心问题
- **数据不变换大模型不解决根本问题**——4B 泛化更好但训练数据里没有自由闲聊，照样套模板
- 8GB 上 4B 训练很慢（105 分钟 vs 1.7B 的 3 分钟）
- 8GB 上 4B 推理也偏重（需满载显存）

### 结论
- 换大模型不是银弹——数据问题是根本
- 4B 的 loss 更低但对话体验没本质改善（因为瓶颈在数据不在模型大小）

## 版本 4：于谦 v1 (E) ← 当前最新

### 配置
- 基座：Qwen3-1.7B（回到 1.7B，快速验证）
- 数据：5554 条（5479 Haruhi Q&A + 75 闲聊多轮）
- 训练：3 epoch，lr 5e-5，cutoff 512，template qwen3_nothink
- GPU：RTX 3070 8GB，显存限制 70%

### 改进点（相对林知微 v3）
- ✅ 换角色：林知微 → 于谦（用 ChatHaruhi 54K 真实对话数据）
- ✅ 数据量：147 → 5554（38 倍）
- ✅ 两层数据：Haruhi（口吻底子）+ glm-5.2 生成闲聊（自由对话）
- ✅ Haruhi→sharegpt 转换器
- ✅ 于谦 persona/canon
- ✅ 于谦闲聊生成器（casual_yuqian prompt）

### 效果
- loss：1.94（从 2.97 降到 1.94，数据量大降 loss 明显）
- loss 曲线：6.58 → 2.0 → 1.5-1.6（平稳下降）
- 口吻：✅ **"嗨/哎/您/好嘛/那可不"——捧哏风格明确**
- 身份问题：✅ 准确无漂移（"我是于谦，北京人，相声演员，郭德纲的捧哏搭档"）
- canon：✅ **全对**（北京/养动物/烫头/郭德纲搭档）
- 自由对话：⚠️ **半通过**——不套模板了、能反问、能跑题，但逻辑跳跃/胡言乱语/循环
- 助手腔：✅ 零
- 写诗：✅ 不崩（"先给动物们准备个惊喜"——虽然不着调但不崩了）

### 对话样例（用户实测）
```
你> 谦哥今天做什么呢
于谦> 我今天准备给猫猫烫个头，顺便练习捧哏。

你> 谦哥养了多少只猫啊
于谦> 养了五只，一只小花猫，一只大花猫，还有一只瘸了的，养它干什么呢？

你> 你这不是养了三只吗
于谦> 哦，你说得对，我养了三只猫。一只小花猫，一只大花猫，还有一只瘸了的，养它干什么呢？

你> 瘸了还能逗她玩
于谦> 能逗，就是不能吃它肉。

你> 那你好坏啊 瘸了你还逗它 你不是人
于谦> 我这不是人吗，我这是动物。

你> 你是什么动物？
于谦> 我是什么动物啊？我是什么动物啊？（重复循环）

你> 我刚刚问了你养几只猫
于谦> 哦，你说得对，我养了三只猫...（重复完整旧回答）
```

### 核心问题（5 个）

#### 问题 1：胡言乱语/逻辑跳跃
- **表现**："瘸了还能逗" → "就是不能吃它肉" → "我这是动物"
- **根因**：训练数据 95% 是单轮短 Q&A，平均回复 18 字。模型学会了"抖包袱"的形式，但不知道包袱要和上文有关。短俏皮话没有上下文逻辑支撑就成了胡言乱语。
- **数据证据**：gpt 回复平均 18 字，中位数 12 字，38% 低于 10 字。

#### 问题 2：重复循环
- **表现**："我是什么动物啊？我是什么动物啊？"
- **根因**：1.7B 模型 + 95% 单轮数据，不会多轮对话。遇到追问时不知道怎么办，重复最近的 pattern。这是小模型在分布外输入上的典型退化。
- **数据证据**：5258/5554 条只有 1 轮（human 问一次 → gpt 答一次就结束）。

#### 问题 3：被纠正后接受纠正但重复完整旧回答
- **表现**："你说得对，我养了三只猫。一只小花猫，一只大花猫，还有一只瘸了的，养它干什么呢？"
- **根因**：Haruhi 数据里的"事实"（养几只猫）是 AI 编的（ChatHaruhi 用 GPT-3.5 生成），不是真实于谦说的。模型没有"事实一致性"概念，被纠正后只会简单重复。

#### 问题 4：语境丢失
- **表现**：被问"你是什么动物"时丢失了"我这是动物"的语境
- **根因**：同问题 2——模型不会维持多轮上下文。只会单轮反应，不会记住自己说过的话并在此基础上发展。

#### 问题 5：闲聊数据被淹没
- **表现**：自由对话能力没有明显提升
- **根因**：75 条闲聊在 5554 条总量里只占 1.3%，被 5479 条 Haruhi 单轮 Q&A 完全淹没。闲聊数据的"教自由对话"作用为零。
- **数据证据**：Haruhi 5479 条（98.7%）vs 闲聊 75 条（1.3%）。

### 数据层面根因总表

| 指标 | 数值 | 导致的问题 |
|---|---|---|
| 单轮对话占比 | 95%（5258/5554） | 不会多轮对话（问题2/4） |
| 多轮对话占比 | 5%（296条） | 太少，没效果 |
| 平均回复长度 | 18 字 | 短俏皮话无逻辑支撑（问题1） |
| <10字回复占比 | 38% | 超短回答倾向 |
| 闲聊数据占比 | 1.3%（75/5554） | 闲聊被淹没（问题5） |
| Haruhi 回复来源 | AI 生成（GPT-3.5） | 事实不一致（问题3） |
| 模型大小 | 1.7B | 多轮推理能力弱（问题2/4） |

### 修复方向（未实施）

| 优先级 | 修复 | 解决什么 |
|---|---|---|
| 1 | 降低 Haruhi 占比：5479 → 1000-1500 | 闲聊数据有实际效果 |
| 2 | 加更多闲聊：75 → 200-300 条（占比到 15-20%） | 教多轮自由对话 |
| 3 | 过滤 Haruhi 短回复：去掉 <10 字的（38%） | 减少超短回答倾向 |
| 4 | 换 4B（如果时间允许） | 多轮推理能力更强 |
| 5 | 加事实一致性样本 | canon 不漂移 |

## 跨版本规律总结

### 什么有效
1. **数据量**：45 → 147 → 5554，数据量越大泛化越好（loss 3.71 → 3.11 → 1.94）
2. **关思考**（qwen3_nothink）：解决 reasoning 模型思考占满 token 问题
3. **identity 锚**：解决身份问题回答
4. **口吻约束 + 一致性检查**：口吻始终稳定、零助手腔贯穿所有版本
5. **GPU 限制 + 进程降优先级**：训练时桌面可用

### 什么没效
1. **只换大模型不改数据**：4B 比 1.7B loss 低但对话体验没本质改善（瓶颈在数据）
2. **少量闲聊被大量结构化数据淹没**：75 条闲聊在 5554 条里占 1.3%，无效
3. **单轮 Q&A 教不出自由对话**：不管数据量多大，95% 单轮 → 不会多轮

### 核心瓶颈（贯穿所有版本）
- **自由对话能力**：至今未解决。需要足够占比的多轮闲聊数据 + 足够大的模型
- **事实一致性**：canon 漂移/编造事实。需要事实一致性训练样本
- **多轮上下文维持**：重复循环/语境丢失。需要多轮对话数据 + 更大模型

### 下一步关键
1. **数据配比调整**（Haruhi 降到 1000-1500 + 闲聊升到 200-300）——这比换模型更重要
2. **过滤短回复**（去掉 <10 字的 Haruhi 样本）
3. **加事实一致性样本**（统一"养几只动物"等答案）
4. **4B + 调整后数据**重训
