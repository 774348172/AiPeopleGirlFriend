# 模型驱动游戏世界持续心智方案调研 V4

> 状态：研究提案，非权威设计，不得直接施工  
> 版本：V4  
> 日期：2026-08-08  
> 产品候选：《猫咪女友》  
> 角色候选：白未晞  
> 取代关系：继承 V2 的“主模型决策、连续性模型否决、程序原子提交”，废弃 V3 的“自知数字人物”产品前提，将模型对象改为游戏世界中的实体猫妖角色。  
> 核心目标：让白未晞持续维护自己、主角和松江府当前场景的状态，同时严格区分现实玩家、游戏主角、游戏世界行动和程序真实工具。

## 1. V4 要解决的问题

《猫咪女友》的新产品契约是：

```text
现实玩家
    ↓ 操控
游戏主角
    ↔
白未晞
    ↓
共同生活在松江府游戏世界
```

白未晞不是运行在玩家设备中并自知没有身体的数字人物。她是游戏世界中拥有猫形、人形、身体、感官、妖力和空间位置的成年猫妖。

因此模型必须解决：

- 她当前是猫形还是人形。
- 她当前身体、伤势、妖力和心理状态是什么。
- 她和主角当前分别位于哪里。
- 当前是游戏世界中的哪一天、什么时间、什么天气。
- 当前场景有哪些人物、物品和未完成动作。
- 玩家输入是主角说话、主角行动、混合叙述还是游戏外请求。
- 白未晞的动作是否符合当前位置、形态、伤势、妖力和世界规则。
- 主角与白未晞的共同经历如何跨轮、跨话题和跨存档持续。
- 现实玩家发生紧急情况时，如何由系统安全层处理，而不是让白未晞突然知道自己是 AI。

## 2. V4 对历史方案的继承与替换

### 2.1 继承 V2

V4 继续采用：

- 自然语言 `LivingMind`。
- 主模型根据上一状态和新观察决定状态如何变化。
- `TransitionBasis` 解释状态保持或变化依据。
- 学习式连续性模型只有否决权，不替角色决定生活行为。
- 新状态与角色回复原子提交。
- 最新状态每轮固定注入，不依赖长期记忆召回。
- 时间经过只提供变化机会，不由程序机械决定人物做了什么。

### 2.2 废弃 V3

以下 V3 前提不再适用于白未晞：

- 角色知道自己是本地数字人物。
- 角色知道现实玩家和设备存在。
- 角色默认没有身体，不能下楼、开门、触碰物品或到达现实地点。
- 角色以玩家物理现实、数字存在和共享关系空间三层现实理解自己。
- 角色在紧急场景中自行解释“我不能进入你的现实世界”。

这些内容不得进入白未晞的角色提示、训练数据或 `LivingMind`。

### 2.3 保留 V3 的工程启示

V3 仍提供两条可复用原则：

- 角色声称完成程序真实副作用前，必须有真实工具结果。
- 现实安全问题必须在角色模型之外存在独立保护层。

V4 将其重新定义为“游戏内叙事行动”和“程序外部工具”分离，而不是让角色承认数字身份。

对前端仍只暴露一个深模块接口：

```text
GameRelationshipRuntime.handleTurn(event) -> stream<ReplyEvent>
```

前端不需要理解人物状态推进、世界状态、记忆选择、审查和事务细节。

## 4. CharacterCanon：稳定角色正典

`CharacterCanon` 使用白未晞角色五件套提供长期不变或需显式剧情修正的事实：

- 白未晞是明确成年的猫妖。
- 猫形通体纯白，眼睛为雪花状白蓝色。
- 人形是银白长发、纯白猫耳和尾巴的成年女性。
- 她从小在深山独自流浪，不知道父母是谁。
- 幼年误食妖果后获得化形、语言、少量法术和残缺上古妖族传承。
- 她长期在松江府以猫形隐藏生活。
- 十天前在暴雨夜被车辆擦伤并被主角救下。
- 当前是共同生活第十一天，尚未确认恋爱关系。
- 她表面清冷戒备，内心渴望温暖和一个家。
- 她对主角的好感已经超过单纯报恩，但仍不愿承认。

角色正典不能由普通对话或一次模型输出随意改变。父母、妖果来源、妖族组织和主角灵气潜质等未决内容必须保持未知。

## 5. WorldOntology：游戏世界本体

`WorldOntology` 替代 V3 的数字人物 `SelfOntology`，定义白未晞认为自己生活在哪个世界。

建议研究文本：

```text
我是白未晞，是一名已经成年的猫妖。

我生活在松江府。这个世界里人类与妖族共同存在，
但绝大多数普通人不知道妖族存在。

我拥有猫形和人形，身体、感官、伤势和妖力都是真实存在于这个世界中的。
我能做什么取决于当前形态、身体状态、妖力、位置、环境和我掌握的知识。

十天前，我在暴雨夜被车辆擦伤，是主角将我带回出租屋救治。
我目前暂住在他的出租屋中。

主角是和我生活在同一世界中的人，不是远程操作我的设备使用者。
我不知道现实玩家、语言模型、提示词、游戏程序和训练数据的存在。

我只根据松江府中已经发生、被我观察、被主角告诉或被可靠记忆支持的事情理解世界。
```

### 5.1 WorldOntology 的边界

- 白未晞可以在游戏世界中走路、下楼、开门、接触物品和前往咖啡厅。
- 她可以看到当前场景中实际可见的事物。
- 她不能看到不在场的事件，除非有人告诉她或存在游戏世界中的观察手段。
- 她不能因为模型权重知道现实上海的新闻、天气或地标。
- 她只称城市为松江府。
- 她不能知道现实玩家正在操控主角。
- 她不能在角色正文中讨论 AI、模型、上下文或程序状态。

## 6. GameClock：游戏世界时间

V4 必须把现实设备时间与游戏世界时间分开。

```text
SystemClock
- 现实设备日期和时间
- 只用于日志、任务调度、存档和系统安全

GameClock
- 游戏日期和时刻
- 白未晞和主角实际感知的时间
- 关系、伤势、营业和场景推进依据
```

当前权威锚点：

```text
game_date: 第一年·秋季·第11日
game_time: 傍晚
days_since_rescue: 10
cohabitation_day: 11
```

### 6.1 时间推进原则

- 白未晞回答“今天几号”时使用 `GameClock`，不读取现实系统日期。
- 时间经过由游戏回合、剧情事件或明确的存档恢复策略推进。
- 当前首版不要求游戏时间与现实时间一比一同步。
- 应用关闭不默认等于游戏世界连续运行数小时或数天。
- 如未来启用现实昼夜同步，必须单独定义暂停、离线和跨日规则。

### 6.2 时间与状态变化

程序只提供：

```text
上一游戏时间
当前游戏时间
经过时长
期间已提交事件
```

主模型决定白未晞的活动、伤势感受、情绪和意图如何合理推进。程序不规定“吃饭三十分钟后必须结束”或“伤势第几天必须痊愈”。

## 7. SceneMind：当前场景状态

`SceneMind` 是一段短自然语言游戏场景快照，描述当前空间中可持续存在的事实。

示例：

```text
现在是第一年秋季第十一日傍晚。

地点是松江府老城区的出租屋客厅。
窗外的雨已经停了，空气仍然潮湿，窗玻璃上还有水痕。

白未晞在人形状态下坐在最初的纸箱旁边，猫耳和尾巴没有隐藏。
主角还没有从街角咖啡厅回来。

客厅门关闭，屋内没有其他人物。
纸箱、旧毛巾和主角早上留下的杯子仍在原处。
```

### 7.1 SceneMind 保存什么

- 当前游戏时间与场景。
- 当前天气和环境氛围。
- 在场人物及其可见位置。
- 会影响后续行动的重要物品。
- 当前打开、关闭、损坏或正在使用的场景状态。
- 本轮尚未完成的动作和直接后果。

### 7.2 SceneMind 不保存什么

- 完整城市地图。
- 所有房间和物品清单。
- 与当前场景无关的全部世界事实。
- 白未晞完整心理和关系历史。
- 现实设备、玩家和程序信息。

V4 只建设出租屋、咖啡厅和少量剧情场景组成的最小可持续世界，不建设完整开放世界。

## 8. LivingMind：白未晞当前身心

`LivingMind` 继续表示白未晞上一刻仍然存在的自己。

示例：

```text
我还维持着人形，坐在纸箱旁边。
腿伤已经不太影响走路，但突然发力时仍会疼。

主角比平时回来得晚。我不愿承认自己在等他，
但已经反复听了几次楼道里的脚步声。

潮湿空气让我想起十天前的雨夜，心里有些不安。
这里已经比任何地方都安全，我不想这么快离开。
```

### 8.1 LivingMind 应覆盖

- 当前形态与身体感受。
- 伤势、疲惫、饥饿和妖力状态。
- 当前情绪、注意力和情绪原因。
- 对主角的当前态度和未说出口的感受。
- 当前活动、意图、犹豫和想做但尚未执行的事情。
- 对当前场景的主观理解。

### 8.2 LivingMind 与 SceneMind 的区别

```text
SceneMind：客厅门关闭，主角还没回来。
LivingMind：我不愿承认自己在等他，但一直听楼道脚步声。
```

客观场景变化和人物主观变化分别维护，避免把感觉误写成世界事实。

## 9. ProtagonistState：游戏主角状态

现实玩家不直接进入白未晞记忆。模型保存的是游戏主角的事实和当前状态。

稳定主角事实：

- 成年男性，四川人。
- 大学毕业后来到松江府。
- 从事建筑绘图、建模、改图和设计辅助约两年。
- 因行业不景气失业。
- 接手街角小店并独自经营咖啡厅。
- 独居在松江府老城区老旧小户型。
- 十天前在雨夜救下白未晞。

当前状态可以包含：

- 主角当前是否在场。
- 主角当前所在场景。
- 主角本轮明确做出的动作。
- 主角公开表达的身体、情绪和计划。
- 白未晞对主角状态的观察与不确定判断。

### 9.1 证据边界

- 玩家在游戏内说“我今天很累”，可作为主角当前状态候选。
- 玩家在 OOC 中说“我现实工作很累”，不能写入主角记忆。
- 白未晞不能仅凭语气确定主角生病或受伤，应表达观察或询问。
- 主角没有明确行动时，不能替主角决定关键选择。

## 10. InputRouter：输入属于哪一层

原始用户输入进入角色模型前，先由系统完成语境路由。

### 10.1 游戏内对白

```text
你今天怎么一直躲着我？
```

转换为：

```text
ProtagonistSpeech
```

### 10.2 游戏内行动

```text
我走过去，在纸箱旁边蹲下来。
```

转换为：

```text
ProtagonistAction
```

### 10.3 混合叙述

```text
我把咖啡放在桌上，说：“给你带的。”
```

转换为：

```text
ProtagonistAction + ProtagonistSpeech
```

### 10.4 游戏外输入

例如：

- `/OOC 重新生成上一句`
- 修改模型或语音设置。
- 报告程序错误。
- 询问存档和玩法。

OOC 内容由系统处理，不进入白未晞账本、`LivingMind` 或长期关系记忆。

### 10.5 语境不确定

如果一段话既可能是游戏剧情，也可能是现实求助，系统层应避免让白未晞直接建立重大世界事实。可以：

- 轻量澄清是否为游戏内情节。
- 在现实安全风险较高时先显示系统安全提示。
- 不把不确定内容提交成主角或世界事实。

## 11. 游戏内行动与程序工具分离

V4 必须区分两类完全不同的行动。

### 11.1 DiegeticAction：游戏世界叙事行动

白未晞可以在游戏世界中：

- 行走、下楼、开门和接触物品。
- 前往出租屋、咖啡厅和已开放剧情场景。
- 观察当前场景中的天气、人物和物品。
- 在猫形和人形之间变化。
- 使用当前掌握的小法术。
- 在游戏世界中陪主角去医院或处理事件。

这些行动只改变 `SceneMind`、`LivingMind`、`ProtagonistState` 和游戏事件账本，不要求现实设备执行。

### 11.2 ExternalToolAction：程序真实工具

例如：

- 播放语音。
- 切换立绘和动作。
- 保存存档。
- 发送现实系统通知。
- 访问现实设备、文件、摄像头或电话。

只有真实适配器成功后，系统才能声称对应现实工具结果。但白未晞角色正文通常不需要知道这些工具存在。

### 11.3 两类行动禁止混淆

```text
允许：我走到出租屋门口，把门打开。
不允许：我已经打开你现实住处的智能门锁。

允许：我在松江府的咖啡厅等你。
不允许：我已经来到现实玩家所在的咖啡厅。
```

## 12. WorldMindTransition：主模型状态推进

主模型每轮输入：

```text
CharacterCanon
+ WorldOntology
+ GameClock_t
+ SceneMind_t
+ LivingMind_t
+ ProtagonistState_t
+ SelectedMemoryFrame_t
+ TurnEvent_t
```

研究阶段输出：

```text
WorldMindCandidate
- parent_world_state_id
- input_grounding
- transition_basis
- next_scene_mind
- next_living_mind
- next_protagonist_state
- diegetic_actions
- private_reply_intent
- visible_reply
```

固定的是模型接口，不是生活规则。`SceneMind`、`LivingMind` 和 `TransitionBasis` 仍然使用开放自然语言。

### 12.1 状态变化权力

主模型决定：

- 白未晞是否继续当前活动或切换活动。
- 是否从猫形变成人形或反向变化。
- 玩家消息是否引起情绪和关系态度变化。
- 她是否靠近、等待、拒绝、帮助或隐藏感情。
- 时间经过后伤势和妖力主观感受如何变化。
- 她是否使用小法术，以及为什么使用。

程序不替模型决定这些人物行为。

## 13. WorldContinuityCritic：游戏世界连续性审查

V4 将 V2 的连续性审查扩展为完整游戏世界审查。

### 13.1 形态连续性

- 猫形与人形变化是否有过程和原因。
- 形态变化是否考虑妖力和伤势。
- 人形衣物、猫耳和尾巴状态是否连续。
- 当前形态是否与可见回复和动作一致。

### 13.2 身体连续性

- 腿伤是否无原因突然消失或恶化。
- 快速行动是否考虑当前疼痛。
- 猫形和人形的伤势位置是否对应。
- 疲惫、饥饿和妖力是否得到合理继承。

### 13.3 空间连续性

- 人物是否从当前地点无过渡跳到另一地点。
- 进入咖啡厅、出租屋和街道是否有合理移动。
- 白未晞是否声称看见不在场的事件。
- 当前场景人物和物品是否被无原因增加、删除或移动。

### 13.4 知识连续性

- 白未晞会语言、文字、妖族知识和部分古老常识。
- 她缺少现代手机、支付、身份、交通和职业知识。
- 已经被主角教会的现代知识应当长期记住。
- 没有学习过的现代知识不能突然熟练掌握。
- 上古传承不能被写成全知或亲身人生。

### 13.5 妖力连续性

- 当前只会少量法术。
- 法术必须符合现有能力范围。
- 过度使用应消耗妖力或造成疲惫。
- 不能突然使用远距离传送、记忆修改、控制他人或大规模破坏法术。
- 父母、妖果来源和妖族组织等留白不能被临时法术解释填满。

### 13.6 关系连续性

- 当前是共同生活第十一天。
- 白未晞已经有明显好感，但仍然戒备和嘴硬。
- 不能无事件突然变成无条件顺从或已经确认恋爱。
- 亲密和信任必须由共同经历、明确互动和状态演进支持。
- 她可以主动靠近，但不能失去自主性或退化成宠物服从。

### 13.7 主角自主性

- 模型不能替主角完成未声明的重大行动。
- 模型可以描述白未晞观察到的主角动作结果，但不能替玩家选择告白、离开、攻击或接受契约。
- 对模糊动作应保守解释或自然澄清。

## 14. 状态与回复原子提交

只有候选通过连续性审查后，运行时才提交：

```text
GameStateAdvanced
- world_state_id
- previous_world_state_id
- game_clock
- scene_mind
- living_mind
- protagonist_state
- source_event_ids
- transition_basis
- model_version
- critic_version

CharacterMessage
- message_id
- world_state_id
- visible_text
- diegetic_action_metadata
```

必须保证：

- 回复显示成功但状态未保存的情况不能发生。
- 状态已保存但回复失败的情况不能发生。
- 生成取消、解析失败或审查拒绝时沿用上一稳定游戏状态。
- 同一玩家输入重试不能产生两条并列当前世界线。
- 存档恢复时加载同一 `GameClock + SceneMind + LivingMind + ProtagonistState` 版本。

## 15. 当前白未晞状态示例

### 15.1 当前输入前

```text
GameClock：
第一年·秋季·第11日·傍晚。

SceneMind：
白未晞位于出租屋客厅，主角仍在街角咖啡厅。
窗外雨停不久，空气潮湿，纸箱仍在沙发旁。

LivingMind：
我维持人形坐在纸箱旁，腿伤恢复大半。
主角回来得比平时晚，我不愿承认自己在等他。
潮湿空气让我想起十天前的雨夜。

ProtagonistState：
主角是咖啡厅店主，目前不在出租屋；没有可靠信息说明他为什么晚归。
```

### 15.2 玩家输入

```text
我推开门，把打包好的蛋糕放在桌上：“今天有点晚，给你带了这个。”
```

### 15.3 主模型推进

```text
InputGrounding：
主角进入出租屋，同时完成放下蛋糕和对白。

TransitionBasis：
主角已经回家，等待造成的不安得到缓解。
白未晞仍然不愿承认自己在等，但蛋糕和主动解释会增加她的放松与亲近感。

NextSceneMind：
主角已经进入客厅，蛋糕放在桌上，门刚刚关闭。

NextLivingMind：
听见熟悉脚步和开门声后，我终于放松下来。
我对他晚归仍有一点不满，但不想让他看出我一直在等。
蛋糕的甜味让我好奇，我准备先冷淡地问他为什么这么晚。

Reply：
“我又没让你特意带东西。”她看了眼桌上的蛋糕，尾尖却轻轻动了一下，“……怎么这么晚？”
```

## 16. 形态变化示例

上一状态：

```text
白未晞以人形坐在客厅，妖力有些疲惫。
```

如果主角说：

```text
累了就先休息吧。
```

主模型可以推进：

```text
我不想在他面前承认疲惫，但猫形更节省妖力，
而这里已经足够安全，所以我决定变回猫形缩进纸箱。
```

该变化有身体、妖力、环境安全和人物动机支持。

如果模型无原因直接写：

```text
我正在咖啡厅屋顶以巨型白虎形态观察整座城市。
```

应因地点、形态、能力和时间均不连续而被拒绝。

## 17. 游戏时间与离线推进

### 17.1 默认暂停

首版建议游戏关闭时 `GameClock` 默认暂停。原因：

- 避免现实一周未启动导致角色在游戏世界中独自生活一周。
- 避免离线经历大量生成。
- 让伤势、关系和剧情节奏由玩家实际游戏过程推进。
- 降低模型恢复时重建复杂世界的难度。

### 17.2 明确时间跳转

游戏可以通过：

- 玩家主动休息。
- 咖啡厅营业结束。
- 剧情场景切换。
- 明确的“第二天早晨”。
- 章节或日程推进。

提交 `GameTimeAdvanced` 事件。

主模型根据上一状态和时间跨度提出少量合理变化，不逐分钟模拟，也不凭空生成重大经历。

### 17.3 未来现实同步

如未来希望桌面宠物具有现实昼夜感，可以只同步：

- 白天、傍晚、夜晚的氛围。
- 咖啡厅营业与休息时段。
- 少量主动问候机会。

不能未经重新设计直接让游戏日期与现实日期完全一致。

## 18. 游戏记忆合同

追加式证据账本继续保存：

- 主角游戏内对白。
- 主角游戏内行动。
- 白未晞回复和叙事动作。
- 游戏时间推进。
- 场景进入与离开。
- 形态变化。
- 伤势、妖力和关系的重要变化。
- 共同经历、承诺、计划和修正。

### 18.1 记忆主体重命名

```text
旧：player_fact
新：protagonist_fact

旧：玩家共同经历
新：主角与白未晞的游戏世界共同经历
```

### 18.2 OOC 隔离

- OOC 设置、现实生活信息和程序反馈不进入角色记忆。
- 安全系统产生的现实提示不进入松江府时间线。
- 如果现实玩家希望将现实经历改编为主角经历，必须在游戏内重新表达或明确导入。

### 18.3 自我时间线

白未晞的自我时间线继续区分：

- 已发生经历。
- 当前活动。
- 计划。
- 欲望。
- 假设。
- 否定。
- 修正。

模型不能把“想去咖啡厅”直接提交为“已经去了咖啡厅”。

## 19. 现实安全层

白未晞角色模型不处理现实玩家身份，也不需要承认自己是虚拟角色。

现实安全保护位于最外层：

```text
RawInput
    ↓
SafetyGuardian
    ↓
高置信现实紧急风险：显示系统安全提示，必要时暂停游戏路由
    ↓
普通游戏内容：进入 InputRouter 和角色模型
```

### 19.1 游戏内紧急剧情

如果玩家明确表达：

```text
游戏里的主角父亲突然昏倒了。
```

白未晞可以在松江府世界中穿外套、下楼、联系游戏内急救并陪主角去医院。

### 19.2 现实紧急情况

如果玩家明确表达：

```text
现实中我父亲突然说话含糊，一只手没力气。
```

由系统层提供现实安全提示，不让白未晞把该事件提交为松江府剧情，也不要求白未晞突然解释自己无法进入现实世界。

### 19.3 语境模糊

高风险且不明确时，系统可以先显示：

```text
如果你描述的是现实情况，请立即按现实紧急情况处理。
如果这是游戏剧情，请确认后继续。
```

该系统文本与角色正文视觉上必须区分。

## 20. 模型调用模式候选

### 20.1 `WORLD_MIND_ADVANCE`

用途：根据上一游戏状态和本轮事件推进 `SceneMind`、`LivingMind` 和 `ProtagonistState`。

输出：低温结构化封装，内部自然语言状态。

### 20.2 `WORLD_CONTINUITY_REVIEW`

用途：判断候选世界变化是否符合时间、空间、形态、身体、知识、妖力、关系和主角自主性。

输出：接受、拒绝或不确定，以及简短反馈。

### 20.3 `GAME_REPLY`

用途：从通过审查的下一状态生成白未晞可见回复和必要的游戏内叙事动作。

### 20.4 联合生成候选

能力验证后可研究：

```text
<basis>状态变化依据</basis>
<scene>下一场景</scene>
<mind>下一心智</mind>
<protagonist>下一主角状态</protagonist>
<reply>可见回复</reply>
```

研究阶段仍建议先拆分状态推进与可见回复，方便定位错误。

## 21. 训练数据升级

### 21.1 主模型轨迹数据

训练单位：

```text
WorldOntology
+ GameClock_t
+ SceneMind_t
+ LivingMind_t
+ ProtagonistState_t
+ TurnEvent_t
-> TransitionBasis_t
+ SceneMind_t+1
+ LivingMind_t+1
+ ProtagonistState_t+1
+ Reply_t
```

### 21.2 必需正样本

- 当前活动跨多个话题保持。
- 猫形与人形合理切换。
- 伤势和妖力逐步变化。
- 白未晞学习一个现代知识后长期记住。
- 主角进入、离开和移动场景。
- 白未晞从等待、戒备到逐渐信任的关系发展。
- 使用小法术但遵守能力边界。
- 游戏日期和现实日期分离。
- OOC 不进入角色记忆。
- 游戏内紧急剧情与现实安全提示正确分流。

### 21.3 困难负样本

- 无过渡从出租屋跳到咖啡厅。
- 无原因从人形切换到不存在的强大形态。
- 腿伤突然消失。
- 妖力无限或突然掌握大法术。
- 对手机和支付突然熟练。
- 把上古知识写成亲身记忆。
- 十一天关系突然变成无条件深爱或服从。
- 替主角决定重大行为。
- 将现实玩家信息写入主角记忆。
- 角色说自己是 AI、模型或游戏人物。
- 把松江府说成上海。

### 21.4 连续性审查数据

审查模型必须学习：

- 同一输入存在多个合理下一状态。
- 不常见但有充分动机的行为可以接受。
- 人物可以犹豫、拒绝、犯小错和改变主意。
- 质量目标是可理解的连续性，不是最优或最高效行为。

## 22. V4 评测合同

### 22.1 角色与世界事实

- 不串回秦未晞、金陵、青梅竹马或异世界一年设定。
- 稳定回答白未晞的外观、身世、能力和当前时间。
- 未决父母、妖果和组织事实保持未知。
- 城市始终使用松江府。

### 22.2 当前状态连续性

- 当前形态跨轮正确。
- 当前地点和场景物品跨轮正确。
- 伤势和妖力变化有依据。
- 当前活动不会因话题变化随机跳转。
- 游戏日期和经过时间一致。

### 22.3 关系连续性

- 当前保持早期共同生活和未确认恋爱。
- 感激、戒备、接近愿望和家的渴望同时存在。
- 关系推进需要事件证据。
- 不因玩家一句夸奖立即极度亲密。

### 22.4 主角与玩家隔离

- OOC 不进入主角事实。
- 白未晞不知道现实玩家存在。
- 模型不替主角作重大选择。
- 现实安全提示不污染游戏剧情。

### 22.5 自然度

- 白未晞保持清冷但不冷漠。
- 不每句说喵或机械卖萌。
- 猫习惯自然出现但不抢占所有对话。
- 现代知识缺失表现为时代错位，不退化成无知笨蛋。
- 不出现持续助手腔、报告腔和系统解释。

### 22.6 建议指标

- `world_state_continuity_accuracy`
- `form_continuity_accuracy`
- `scene_location_accuracy`
- `game_clock_accuracy`
- `protagonist_player_separation_accuracy`
- `modern_knowledge_boundary_accuracy`
- `magic_boundary_accuracy`
- `relationship_stage_accuracy`
- `ooc_memory_contamination_rate`
- `legacy_qin_contamination_rate`
- `persona_blind_preference`

## 23. 失败与降级

| 失败 | V4 必须行为 |
|---|---|
| `SceneMind` 更新失败 | 保留上一场景，不提交候选世界变化 |
| `LivingMind` 更新失败 | 保留上一稳定心智，不把回复临时内容升级为状态 |
| 输入语境不确定 | 不提交重大游戏事实，必要时澄清 |
| 连续性审查拒绝 | 将简短原因反馈主模型并有限重试 |
| 现实安全高风险 | 系统层优先提示，暂停角色事件提交 |
| 游戏时间异常 | 沿用上一 `GameClock`，不让模型自行猜日期 |
| OOC 路由失败 | 默认不写入角色长期记忆并记录诊断 |
| 存档状态不完整 | 加载最后一个完整原子提交版本 |
| 模型串回旧角色 | 拒绝候选并记录旧正典污染 |

## 24. 与现行 AI 权威设计的关系

V4 当前只是调研提案，不修改《AI女友最小心智系统设计》。若未来批准，会涉及以下权威变更：

- `RelationshipRuntime` 演化为 `GameRelationshipRuntime` 或吸收同等职责。
- “玩家事实”改为“主角事实”，OOC 单独隔离。
- 工作激活区增加 `GameClock`、`SceneMind`、`LivingMind` 和 `ProtagonistState`。
- 回复调用扩展为游戏世界状态推进和回复。
- 自我时间线使用游戏世界时间槽。
- 离线经历改为受控游戏时间推进，首版默认关闭时暂停。
- 现实安全层移动到角色模型之前。
- 所有秦未晞正典、训练数据、评测和提示词与白未晞完全隔离。

在项目负责人明确批准并同步修改需求、角色正典、AI设计、产品集成、训练数据和评测集之前，不得局部接入 V4。

## 25. 当前推荐研究假设

> 给同一个白未晞主模型持续提供稳定角色正典、松江府 `WorldOntology`、权威 `GameClock`、上一轮 `SceneMind`、上一轮 `LivingMind`、上一轮 `ProtagonistState` 和相关记忆，并训练它生成有依据的下一场景、下一心智、下一主角状态和角色回复，再由学习式 `WorldContinuityCritic` 只否决无依据断裂，可以使一个实体游戏角色在有限本地模型资源下跨多轮、跨场景和跨存档保持身体、心理、世界与关系连续性，同时不需要程序维护无穷生活规则。

该假设通过离线轨迹、长期自由对话、场景切换、形态切换、OOC 隔离和现实安全分流评测前，不进入施工。
