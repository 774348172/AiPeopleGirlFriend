# 白未晞训练数据重构建议：SYS-12S 后

> 性质：待审核调研建议，非权威设计、非训练合同、非施工指令。  
> 日期：2026-08-13。  
> 适用前提：现行前台链路为 `MIND_PATCH_V2 / M2 -> ApprovedHeroineState -> GAME_REPLY 纯自然语言 -> 原子提交`。  
> 数据保护：不得覆盖或删除现有 1190 条训练源数据、既有模型、检查点和冻结评测证据；后续只能建立带来源映射的新派生数据集。

## 1. 要解决的问题

现有白未晞模型的训练数据形成于旧回复架构。旧数据同时承担了角色人格、世界边界、现实能力限制、记忆防幻觉和自然对白等多种职责；SYS-12S 完成后，其中一部分职责已经由 Runtime、世界快照、独立记忆库和 M2 协议负责。

如果继续把所有旧职责重复训练进 `GAME_REPLY` 模型，会产生三个问题：

1. 模型学到已经废止的“现实世界/游戏世界”二分概念。
2. 心智状态、动作和自然对白重新混合，破坏 M2 与 `GAME_REPLY` 的职责分离。
3. “清冷、简短”被过度拟合成回避问题、漏答事实和只说“嗯”。

本建议的目标不是减少数据条数本身，而是让每类数据只训练一种明确能力。

## 2. 本次扫描证据

扫描对象：

- `training_package_baiweixi_local3060_qwen3/data/baiweixi_ready.jsonl`
- 共 1190 条多轮样本、2442 条女主回复。

初步结果：

| 现象 | 扫描结果 | 判断 |
|---|---:|---|
| 旧 System Prompt 含“现实、设备外、只能文字、线下行动、AI、助手、内部 JSON”等概念 | 1190/1190 条 | 与当前单一游戏世界合同冲突 |
| 完整对话重复 | 0 条 | 不应按整条对话直接去重 |
| 女主回复文本的重复增量 | 92 条 | 存在短答模式重复，但需结合语境裁决 |
| 精确回复 `嗯。` | 32 次 | 清冷表达过度集中信号 |
| 精确回复 `……嗯。` | 10 次 | 同上 |
| 回复中出现随机男主名“浩然/阿伟/林墨” | 7/10/5 次 | 男主身份不应固化进角色权重 |
| 回复疑似包含第一人称动作叙述 | 约 98 条 | 关键词粗扫结果，必须人工复核后再处理 |

上表只能证明需要重构，不能直接作为自动删除名单。特别是动作叙述和短答必须结合上下文人工判断。

## 3. 新架构下的训练职责

### 3.1 Runtime 负责

- 当前游戏时间和连续 GameClock。
- 最新世界状态、男主位置、身体、活动和持有物。
- 女主上一稳定状态与版本。
- 每个女主独立记忆库、召回、证据来源和隔离。
- Patch 校验、Critic、批准状态、重试和原子提交。
- 快照 ID、身份 ID、状态版本和程序权威事实绑定。

这些内容不应被当作白未晞固定人格知识反复写进自然对白训练目标。

### 3.2 M2 模型负责

- 判断本轮女主哪些心智字段真正发生变化。
- 引用受控证据别名。
- 提议有限的女主动作候选。
- 输出短、稳定、可验证的 `M2` 结构。

M2 不生成最终对白，也不训练白未晞的文学表达。

### 3.3 GAME_REPLY 模型负责

- 理解 Runtime 提供的最新世界事实、批准后女主状态和相关记忆。
- 直接回答男主当前说的话。
- 保持白未晞的身份、性格、关系阶段、知识边界和语言风格。
- 只输出白未晞真正说出口的自然语言。

核心原则：

> 角色权重学习“白未晞是谁、她如何理解和表达”；Runtime 提供“此刻真实发生了什么”。

## 4. 建议移出 GAME_REPLY SFT 的数据

### 4.1 旧双世界和数字助手限制

移除或重写包含以下训练前提的 System Prompt：

- 设备外的现实世界。
- 玩家与男主是两个不同主体。
- 女主只能通过设备或文字接触玩家。
- 不能打电话、不能线下陪伴、不能获知现实现场。
- 女主是 AI、助手、虚拟人物或程序内角色。
- 现实系统时间与游戏时间的区分。

不是要训练女主“拒绝现实”，而是不能向她提供第二个世界的概念。玩家说“现实中上班很累”时，她只能把这句话理解为男主对当前世界生活的描述。

### 4.2 运行时内部协议知识

以下内容不进入角色自然对白 SFT：

- `M1/M2` 字段、JSON Schema、证据编号字典。
- 记忆召回、排序、摘要、提议和提交格式。
- 快照更新、五分钟整理、重试、事务和原子提交。
- 模型模式名、内部 Prompt、Critic 规则和系统边界。

这些能力分别属于程序、M2、记忆模型或测试合同。

### 4.3 动作叙述

纯 `GAME_REPLY` 目标中不保留：

```text
我抱紧了纸箱。这个纸箱，我不想换。
```

应拆分为：

```text
M2 动作候选：抱紧纸箱
GAME_REPLY：这个纸箱，我不想换。
```

只有确实作为口头陈述说出的动作可以保留，例如“我去关窗”；旁白式身体动作、表情和镜头描写应交给 M2/表现层。

### 4.4 随机男主名字

删除训练回答中无当前输入依据的“浩然、阿伟、林墨”等随机名字。男主姓名或称呼必须由存档身份、角色关系和当前上下文提供。

可保留“很少主动称呼男主”的语言习惯，但不能依靠注入多个假名字实现防绑定。

### 4.5 非回复任务

以下任务必须拥有独立数据集和 manifest，不得混入 `GAME_REPLY`：

- `MEMORY_RERANK`
- 记忆摘要与记忆提议
- M2 Patch
- 连续性审查和 Critic
- 表现意图或动作标签
- 内部安全分类和工具调用

现有 7 条 `MEMORY_RERANK` 已从 1190 条回复集剔除，这一方向正确。

## 5. 建议降权和重平衡的数据

### 5.1 过度极短回复

“嗯”“……嗯”“好”“没什么”等不是一律删除。它们在安静陪伴、确认动作和关系留白中有价值，但不应成为模型面对明确问题时的默认策略。

建议按问题类型约束：

- 身份、正典、能力边界、未知事实：必须先直接回答结论。
- 情绪陪伴、安静共处：允许极短回复。
- 严肃请求和男主明确边界：必须回应核心诉求。
- 普通闲聊：简短但至少完成语义闭环。

错误目标：

```text
男主：你是谁？
白未晞：我是……流浪到这里的猫。
```

推荐目标：

```text
男主：你是谁？
白未晞：我叫白未晞，是只猫妖。你救回来的那只白猫。
```

性格应体现在措辞和信息选择中，不能替代回答本身。

### 5.2 恋爱与日常场景占比

现有大批次以 `reply_casual` 和 `reply_romance` 为主。下一版需要降低重复的靠近、嘴硬、害羞、安静陪伴模板占比，补足：

- 明确身份和世界正典直答。
- 能力边界与未知事实。
- 男主状态承接与主客体区分。
- 不同关系阶段下的自然反应。
- 有分歧、有拒绝、有独立判断的日常对话。
- 使用给定记忆证据但不补造细节。
- 现代常识不足但能够逐步学习的场景。

## 6. 必须保留的能力数据

以下内容仍然属于角色训练核心：

1. 白未晞的姓名、成年猫妖身份、外观、来历和当前时间线锚点。
2. 松江府、出租屋、咖啡厅、纸箱、车祸受伤和救助经历等稳定正典。
3. 清冷、戒备、感激、渴望温暖和家的性格张力。
4. 关系不能被男主一句话强制跳级，亲密变化必须自然累积。
5. 能力上限、未知父母、妖果来源、妖族组织等未知边界。
6. 对男主明确问题先完成回答，再体现角色口吻。
7. 使用输入中的当前状态、世界事实和记忆证据，不与其冲突。
8. 不把无证据的玩家预设当成既成共同经历。
9. 自然中文、克制表达和非助手腔。

## 7. 建议建立的数据集

### 7.1 `baiweixi_game_reply_v2`

用途：只训练白未晞的最终可见对白。

每条样本应包含：

- 精简角色边界。
- 冻结世界事实。
- `ApprovedHeroineState` 的自然语言或稳定投影。
- 当前女主相关记忆证据；无证据时明确为空。
- 近期已提交对白。
- 男主当前原始对白。
- 仅包含女主说出口文本的目标答案。

禁止包含动作旁白、JSON、模型模式名和现实/游戏二分概念。

### 7.2 `mind_patch_m2_general_v1`

用途：训练短心智 Patch 和受控动作候选。

建议优先使用角色中立样本，使状态推进能力可以被多个女主角复用；只有确实依赖白未晞性格的判断才带 `character_id=baiweixi`。

### 7.3 专用评测集

训练集不能直接改写冻结评测问题及答案。继续维护：

- 身份和正典。
- 单一世界。
- 当前状态和主客体区分。
- 记忆支持/不支持。
- 关系推进。
- 长聊、恢复和多角色隔离。

所有训练派生都必须通过 `training_exclusion_v1.json` 做泄漏检查。

## 8. 数据迁移方法

建议分四步执行，不直接清洗原文件：

1. **建立审计表**：为 1190 条样本分配稳定 `sample_id`，记录来源、任务、保留/改写/移出/人工复核决定和理由。
2. **只改派生集**：保留用户对白原文作为来源证据；重写旧 System Prompt，拆分动作与对白，去除随机男主名字。
3. **重新配比**：限制极短回复和重复恋爱模板，补充直答、边界、状态承接和证据使用样本。
4. **冻结对照实验**：在同一基座、训练参数、量化方式和测试集下比较旧 1190 数据与新 V2 数据，不能同时更换模型或推理协议。

每个派生样本至少记录：

- `source_sample_id`
- `target_mode`
- `character_id`
- `transformation`
- `review_status`
- `reviewer`
- `canonical_source_version`
- `exclusion_check`

## 9. 验证标准

新数据不能只看训练损失，应重点比较：

- “你是谁”等明确问题的直接完成率。
- 主客体混淆率。
- 正典事实遗漏和补写率。
- 单一世界概念污染率。
- 与输入世界状态、男主状态和批准女主状态的冲突率。
- 无记忆证据时的虚构率。
- 有记忆证据时的正确使用率。
- 动作旁白泄漏率。
- 平均回复长度、极短回复比例和语义完成率。
- 人工盲评中的角色感、自然度、克制度和可持续聊天能力。

## 10. 当前建议结论

现有 1190 条数据不应整体废弃。其角色语气、关系张力和大量自然场景仍有价值，但旧 System Prompt 已整体过期，部分回答目标也与 M2/`GAME_REPLY` 分工冲突。

推荐决策是：

> 冻结旧数据作为可复现实验资产；建立 `baiweixi_game_reply_v2` 派生集；将系统机制、动作和记忆任务移出角色对白训练；再用同一基座做严格对照。

在完成逐条审计和对照实验前，不建议直接删除任何原始样本，也不建议立即启动新一轮正式训练。
