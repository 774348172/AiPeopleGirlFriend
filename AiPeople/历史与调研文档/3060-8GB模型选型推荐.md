# 3060 8GB 玩家本地推理模型选型推荐

> 目标：玩家 3060 8GB，本地推理（不训练），和游戏共享 GPU。
> 需求：人格化 NPC 对话，口吻一致、能自由聊天、不联网。

---

## 显存预算（8GB 与游戏共享）

| 项 | 可用 |
|---|---|
| 总显存 | 8 GB |
| Windows 桌面/浏览器 | ~1.5-2 GB |
| 游戏渲染（中低画质） | ~3-4 GB |
| **留给 LLM** | **~2-3 GB** |

**关键约束：LLM 只能用 ~2-3 GB。** 这决定了模型大小。

---

## 推荐模型

### 首选：Qwen3-4B Q4_K_M（GGUF 4-bit）

| 项 | 值 |
|---|---|
| 权重大小 | ~2.3 GB |
| KV cache（2k 上下文，int8） | ~0.15 GB |
| 推理合计 | ~2.5 GB |
| 剩余给桌面+游戏 | ~5.5 GB |
| 和游戏共享 | ✅ 可行 |
| 人格质量 | 中等偏上（4B 够学口吻+canon，多轮推理偏弱） |
| 中文能力 | ✅ 强（Qwen 中文原生） |
| 推理速度（3060） | ~25-35 tok/s（够对话用） |
| License | Apache-2.0（可商用） |

**为什么选它**：
- 2.3GB 权重是 8GB+游戏共享下能装的最大"质量尚可"模型
- Qwen3 中文强、有 nothink 模式（关思考直接出正文）
- 4B 参数量够学人格口吻和 canon 事实
- int8 KV cache 把对话上下文占用压到 0.15GB
- 推理用 llama.cpp / Ollama，3060 原生支持

**局限**：
- 多轮推理偏弱（4B 参数量天花板，长对话可能循环/丢上下文）
- 不能同时跑太多 NPC（KV cache 叠加）

### 备选：Qwen3-4B Q3_K_M（3-bit，更省显存）

| 项 | 值 |
|---|---|
| 权重大小 | ~1.8 GB |
| 推理合计 | ~2.0 GB |
| 剩余给桌面+游戏 | ~6.0 GB |
| 人格质量 | 中等（3-bit 有轻微质量损失） |
| 和游戏共享 | ✅ 更宽松 |

**什么时候选 Q3**：游戏画质要求高（占 4-5GB），留给 LLM 只有 2GB 时。质量损失可接受（人格口吻不受影响，只是推理略差）。

---

## 不推荐的选项

| 模型 | 大小 | 为什么不推荐 |
|---|---|---|
| Qwen3-1.7B Q4 | ~1.2 GB | 能跑但人格质量低（之前验证过：多轮差、套模板） |
| Qwen3-7B Q4 | ~4.0 GB | 和游戏共享必 OOM（4+4=8GB 满载，桌面卡死） |
| Qwen3-8B Q4 | ~4.5 GB | 同上，更不可能 |
| Qwen3-14B Q4 | ~8 GB | 连单独跑都装不下 |
| Qwen3-32B 任何量化 | >10 GB | 完全不可能 |
| Llama3-8B Q4 | ~4.5 GB | 中文弱 + 显存同 8B |
| Phi-3-mini (3.8B) Q4 | ~2.2 GB | 中文弱，人格学习不如 Qwen |

## 推理部署方案

### 推荐用 llama.cpp / Ollama（不是 HF transformers）

| 方案 | 适合 | 理由 |
|---|---|---|
| **Ollama + GGUF** | 玩家分发 | 单 .exe，一行命令跑，自带并发管理 |
| llama.cpp server | 嵌入游戏 | C++ 库，可进程内调用，低延迟 |
| HF transformers | ❌ 不推荐 | Python + 大量依赖，显存占用更高，不适合游戏嵌入 |

### Ollama 部署步骤（玩家侧）

```bash
# 1. 装 Ollama（一次性，双击安装）
# 2. 拉模型（我们 ship 的 GGUF）
ollama create yuqian -f - <<EOF
FROM ./yuqian_4b_q4.gguf
SYSTEM "你是于谦，北京人，相声演员，郭德纲的捧哏搭档。1969年生。"
TEMPLATE "{{ .System }}\n{{ .Prompt }}"
EOF

# 3. 对话
ollama run yuqian
```

### 游戏 + LLM 共享显存的配置

```bash
# Ollama 限制显存使用（给游戏留空间）
# 方法1：环境变量限制
OLLAMA_GPU_MEMORY_FRACTION=0.3 ollama serve
# 方法2：Ollama 自动管理（默认会留出空间）

# 游戏 setting 里调中低画质，给 LLM 留 VRAM
```

## 训练端（H200）→ 部署端（3060 8GB）的工作流

```
H200 训练                        3060 8GB 推理
─────────                        ────────────
Qwen3-4B 全精度 LoRA SFT  →  导出 GGUF Q4_K_M  →  Ollama 加载
  (5554条于谦数据)              (~2.3GB)            (~2.5GB 显存)
  
可选：H200 上训 14B/32B       蒸馏到 4B           ship 4B 给玩家
      (高质量老师)              (学生 4B)           (玩家跑得动)
```

### H200 上训练时的关键决策

| 训练模型 | 训练可行性 | ship 方式 |
|---|---|---|
| Qwen3-4B 全精度 LoRA | ✅ 直接训 | 训完导 GGUF Q4 → ship |
| Qwen3-14B 全精度 LoRA | ✅ H200 够 | 蒸馏到 4B → ship 4B |
| Qwen3-32B 全精度 LoRA | ✅ H200 够 | 蒸馏到 4B → ship 4B |

**玩家端始终跑 4B Q4**（2.3GB），不管训练端用多大的模型。

## 结论

| 维度 | 推荐 |
|---|---|
| **模型** | **Qwen3-4B** |
| **量化** | **Q4_K_M（4-bit GGUF）** |
| **权重大小** | ~2.3 GB |
| **推理框架** | Ollama / llama.cpp |
| **推理显存** | ~2.5 GB |
| **和游戏共享** | ✅ 可行（留 ~5.5GB 给桌面+游戏） |
| **训练在哪** | H200（全精度 LoRA，可选 4B/14B/32B） |
| **ship 给玩家** | 4B Q4 GGUF（2.3GB 文件） |

**一句话**：3060 8GB 玩家本地推理的甜点是 **Qwen3-4B Q4_K_M GGUF**（2.3GB 权重，2.5GB 显存），用 Ollama 跑，和游戏共享显存可行。训练在 H200 上做（全精度，可选更大模型蒸馏到 4B），ship Q4 GGUF 给玩家。
