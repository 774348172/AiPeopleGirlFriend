# 乙女向恋爱游戏 —— 需求整理

> 性质：需求整理文档（非实施）。基于用户口述 + 之前所有研究结论，系统化梳理。
> 日期：2026-08-03。

---

## 0. 一句话描述

一个乙女向恋爱游戏，玩家与虚拟男友自由对话，男友根据对话内容/语气调用动作、语音等接口做出反应。模型跑在玩家本地（3060 8GB），不联网，保护隐私。

---

## 1. 核心需求

### 1.1 产品形态
- **类型**：乙女向（女性向）恋爱模拟游戏
- **核心玩法**：与虚拟男友自由文字对话 + 男友情感反馈（动作/语音）
- **平台**：PC 端（Windows）
- **分发**：游戏本体 + LLM 模型文件一起 ship 给玩家

### 1.2 硬性约束

| 约束 | 值 | 来源 |
|---|---|---|
| 玩家最低 GPU | RTX 3060 8GB | 用户指定 |
| 联网 | ❌ 不联网 | 隐私保护 |
| 隐私 | 对话数据不出本地 | 用户要求 |
| 训练 | 在 H200 上做（dev 端） | 不在玩家机器训练 |
| 推理 | 在玩家 3060 8GB 上跑 | 用户要求 |

### 1.3 用户体验目标

| 维度 | 目标 |
|---|---|
| 对话自由度 | 玩家可以自由输入任何话题，不限选项 |
| 人格一致性 | 虚拟男友有稳定人格、口吻、背景故事 |
| 情感反馈 | 根据玩家说话内容和语气，男友做出不同情绪反应 |
| 动作调用 | 根据对话/语气，调用预设的动作接口（表情/肢体/场景） |
| 语音 | 男友有语音输出（可选/可关） |
| 响应速度 | 文字回复 <2 秒，让对话流畅 |

## 2. 技术架构（基于之前研究）

### 2.1 训练端（H200）

```
H200 dev 机器
  └─ Qwen3-4B 全精度 LoRA SFT（虚拟男友人格）
     └─ 数据：人生语料 + 闲聊 + 身份锚 + 情感标注样本
     └─ 导出 GGUF Q4_K_M（~2.3GB）→ ship 给玩家
```

### 2.2 玩家端（3060 8GB）

```
玩家 PC (3060 8GB, Windows)
  ┌─ 游戏引擎（UE/Unity/Godot）
  │   ├─ 渲染场景 + 虚拟男友形象（Live2D/3D）
  │   ├─ 文字输入框
  │   ├─ 动作/表情系统（预设接口）
  │   └─ 语音播放系统
  │
  ├─ LLM 推理服务（Ollama / llama.cpp，localhost）
  │   ├─ 加载 yuqian_4b_q4.gguf（2.3GB, ~2.5GB 显存）
  │   ├─ 接收玩家输入 → 生成男友回复
  │   └─ 输出：回复文本 + 情绪标签
  │
  └─ 显存分配（8GB）
      ├─ LLM 推理：~2.5GB
      ├─ 游戏+桌面：~5.5GB
      └─ 语音模型（如需本地 TTS）：另算
```

### 2.3 关键数据流

```
玩家输入文字
  → 游戏引擎传给 LLM（localhost HTTP）
  → LLM 生成回复 + 情绪标签
  → 游戏引擎解析情绪标签
  → 调用动作接口（表情/肢体/场景切换）
  → 调用语音接口（TTS 合成语音）
  → 展示：文字 + 动作 + 语音
```

## 3. 虚拟男友设计（待定项）

### 3.1 角色设定（需你定义）

| 项 | 说明 | 状态 |
|---|---|---|
| 名字 | 男友叫什么 | 待定 |
| 年龄/外貌 | 人设 | 待定 |
| 性格 | 大五人格 + 特质 | 待定 |
| 背景故事 | 人生 timeline | 待定 |
| 口吻特征 | 说话风格/口头禅 | 待定 |
| 与玩家关系 | 初始关系（陌生人/青梅/同事/...） | 待定 |
| 情感发展 | 随对话深入关系变化（好感度系统？） | 待定 |

### 3.2 情绪/动作接口（需你定义）

LLM 需要输出情绪标签，游戏引擎据此调用动作。示例：

```json
{
  "reply": "嗯，今天确实有点累……不过听到你的声音就好多了。",
  "emotion": "tender",        // 情绪标签
  "action": "lean_in",        // 动作接口
  "expression": "soft_smile"  // 表情接口
}
```

情绪标签体系（需你定义）：

| 类别 | 可能标签 |
|---|---|
| 正面 | happy, tender, playful, shy, excited |
| 负面 | sad, angry, worried, tired, hurt |
| 中性 | calm, thinking, surprised, embarrassed |

动作接口（需游戏引擎侧定义）：

| 接口 | 说明 |
|---|---|
| expression | 面部表情（微笑/皱眉/脸红/...） |
| body | 肢体动作（靠近/转身/低头/...） |
| scene | 场景切换（换房间/天气/...） |
| voice | 语气语调（温柔/急切/低落/...） |

## 4. 训练数据需求（基于之前版本的经验）

### 4.1 数据类型

| 类型 | 说明 | 教模型什么 |
|---|---|---|
| 人生语料 | 男友的日记/回忆/经历 | canon 事实、自传记忆 |
| 身份锚 | "你是谁""你多大"等 | 身份问题不崩 |
| 自由闲聊 | 和玩家聊日常/情感/观点 | 自由对话（核心！） |
| 情感场景 | 不同情绪下的对话样本 | 情绪表达 + 动作标签 |
| 恋爱互动 | 调情/撒娇/吵架/和解 | 恋爱语境下的口吻 |
| 越界保护 | 政治/隐私/不当话题婉拒 | 不破人格不胡编 |

### 4.2 之前版本的经验教训

| 教训 | 对应措施 |
|---|---|
| 单轮 Q&A 教不出自由对话 | 闲聊数据占比 ≥30% |
| 短回复导致无逻辑 | 过滤 <10 字回复，保留有内容的长回复 |
| 少量闲聊被淹没 | 控制 Haruhi/结构化数据占比 |
| 1.7B 多轮弱 | 用 4B（H200 训练 → 4B Q4 ship） |
| canon 漂移 | 加事实一致性样本 |
| 套模板 | 多样化生成（不同温度/场景/prompt 变体） |

### 4.3 乙女游戏特有需求

| 特有需求 | 说明 |
|---|---|
| 恋爱语境 | 需要调情/暧昧/吃醋/撒娇/表白等场景的训练数据 |
| 情感发展 | 需要不同好感度阶段的不同说话方式（初期礼貌→后期亲密） |
| 情绪标签 | 训练数据需带情绪/动作标签，教模型输出结构化情绪 |
| 玩家自定义 | 玩家可能想自定义男友名字/性格（需考虑 prompt 锚 vs 权重） |
| 安全边界 | 恋爱游戏有尺度边界——亲密但不越界（需 Protective Scene） |

## 5. 语音方案（需决策）

| 方案 | 优点 | 缺点 |
|---|---|---|
| 本地 TTS（如 edge-tts/piper） | 不联网、免费 | 显存额外占用 ~0.5-1GB，音色固定 |
| 预录制语音（按情绪切片） | 零显存、可控 | 只能说预设台词，不能任意文字 |
| 混合（预录制常用 + TTS 兜底） | 平衡 | 工程复杂 |
| 不要语音（纯文字） | 最简单 | 体验降级 |

3060 8GB + 游戏 + LLM 已用 ~5GB，TTS 再占 0.5-1GB，可能到 6GB——还能跑（8GB 剩 2GB）。但需要测试。

## 6. 游戏引擎集成方案

### 6.1 LLM 与游戏引擎的通信

```
游戏引擎 ←→ LLM 推理服务（localhost HTTP API）

游戏引擎发: POST /chat {"message": "玩家输入", "history": [...]}
LLM 返回:    {"reply": "...", "emotion": "tender", "action": "lean_in"}
```

### 6.2 推理服务选择

| 方案 | 显存 | 并发 | 嵌入方式 |
|---|---|---|---|
| Ollama | ~2.5GB | ✅ 自带 | 游戏调 localhost:11434 |
| llama.cpp server | ~2.3GB | ✅ | 游戏调 localhost:8080 |
| NVIGI（进程内） | 最优 | 最优 | C++ 库直接嵌入（NVIDIA 方案） |

### 6.3 延迟预算

| 环节 | 预算 |
|---|---|
| 玩家输入 → LLM | <100ms |
| LLM 生成（~50 token） | ~1-2s（3060 4B Q4） |
| 情绪解析 + 动作调用 | <50ms |
| TTS 合成（如需） | ~0.5-1s |
| **总延迟** | **~2-3s**（可接受，恋爱游戏不需要实时） |

## 9. 与之前于谦/林知微的区别

| 维度 | 于谦/林知微（之前） | 乙女男友（现在） |
|---|---|---|
| 角色 | 真人/虚构普通人 | 虚拟恋爱对象 |
| 对话风格 | 捧哏/插画师口吻 | 恋爱语境（温柔/暧昧/撒娇/吃醋） |
| 情绪输出 | 无 | **有**（需带 emotion/action 标签） |
| 好感度 | 无 | **可能有**（分阶段说话方式） |
| 尺度 | 无限制 | **有边界**（亲密但不越界） |
| 语音 | 无 | **可能有** |
| 动作接口 | 无 | **有**（表情/肢体/场景） |
| 训练数据 | 相声/日记 | **恋爱对话 + 情绪标注** |

**最大区别**：乙女男友需要**情绪标签 + 动作接口**——LLM 不只输出文字，还要输出结构化的情绪/动作指令给游戏引擎。这需要在训练数据里加入带情绪标签的样本。
