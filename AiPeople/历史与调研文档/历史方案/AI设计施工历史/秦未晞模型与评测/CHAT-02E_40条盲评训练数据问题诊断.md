# CHAT-02E：40 条盲评训练数据问题诊断

> 状态：诊断结论，供下一版训练数据设计使用  
> 日期：2026-08-06  
> 范围：被评测秦未晞 Qwen3-4B LoRA/GGUF 的旧 v1 训练包，以及待训练的 2500 条 v4 语料审计  
> 本文不修改训练数据、不调整运行时 prompt、不启动训练

> **来源更正（2026-08-06）**：被盲评 GGUF 不是 2500 条语料训练出的版本。本机证据高置信指向 `training_package_m3`：295 条 ShareGPT 会话，实际拆分为 266 条训练、29 条验证，执行 600 iterations。2500 条 v4 数据晚于 GGUF 两天生成，尚未进入这次被比较的模型。由于训练机未保留 adapter/checkpoint 与执行日志，295 条来源不能称为密码学确证，但可确定 2500 条不可能是该 GGUF 的训练来源。本项目材料也没有证据支持“恰好 500 条”。

## 1. 结论

当前训练结果没有证明“秦未晞这个角色训练不出来”，但已经证明旧 v1 数据方案不合格，不能继续按同一分布简单扩充条数。

训练后的秦未晞模型确实比基座更像一个有性格的年轻女孩：人格贴合、关系自然、情绪表达和自然口语均略高于基座，也没有基座常见的助手腔。但这些收益是用更差的事实准确性、问题承接和严肃场景表现换来的。40 条人工盲评中，秦未晞模型 14 胜、基座 16 胜，另有 3 平和 7 条双方都不可接受；配对均分差为 `-0.104`，95% 置信区间跨过 0，当前证据不能说明训练模型整体优于基座。

本轮评测回答的是“295 条旧 v1 会话训练出了什么”，不是“2500 条 v4 训练效果如何”。旧 v1 数据把人格过度压缩成固定口癖、先怼后关心和无条件调用共同经历；与此同时，信息不足、未知保持、关系边界和无记忆证据等关键行为覆盖不足。当前 2500 条 v4 语料尚未训练，但静态审计又发现属性朗读、口癖过密和相似桥段等新风险；若不先清洗就训练，不能假定增加数量会自动修复旧模型。

因此下一版数据工作的目标不是“让角色味更浓”，而是：

1. 保留秦未晞已经学到的自然口语、独立立场和关系感。
2. 让相关性、事实准确性和现实证据优先于口癖与角色展示。
3. 教会模型：没有当前对话或运行时记忆证据，就不能编造共同经历。
4. 教会模型：人格会随情境调节，严肃时可以不怼、不嘴硬、不使用口头禅。

## 2. 证据范围与可信度

本诊断使用四类证据：

| 证据 | 范围 | 用途 |
|---|---:|---|
| 人工 A/B 盲评 | 40 条，单名评审 | 判断用户实际偏好和六维质量差异 |
| CHAT-02D 自动基线 | 两模型各 270 case、784 次生成 | 判断确定性错误和运行稳定性 |
| 旧 v1 训练数据静态统计 | 295 条会话、1625 个 assistant 回复 | 解释被评测模型可直接学到的模式 |
| 待训练 v4 语料静态统计 | 2500 条、6780 个 assistant 回复 | 训练前风险审计，不用于反推当前 GGUF |
| 失败输出到训练样本追溯 | 多个可定位文本碎片 | 判断错误是否具有训练数据来源 |

限制：

- 40 条盲评目前只有一名评审，能够发现强失败模式，但不能代替第二名独立评审。
- 关键词统计只用于发现候选分布，不能把每个命中样本直接判为错误。例如“严肃关键词命中 87 条”不等于有 87 条合格的严肃支持样本。
- 当前训练模型的完整训练机 provenance 不齐。295 条旧包是高置信来源判断而非完整链路证明，也不能把所有差异都断言为训练数据导致；量化、训练步数和 checkpoint 仍可能影响结果。
- 本文严格区分“旧 v1 训练结果诊断”和“2500 条 v4 训练前审计”，不评价尚未接入的长期记忆整理与召回系统。

## 3. 盲评结果

### 3.1 总体结果

| 指标 | 秦未晞训练模型 | Qwen3-4B 基座 |
|---|---:|---:|
| 胜出题数 | 14 | 16 |
| 六维均分 | 3.925 | 4.029 |
| relevance | 3.075 | 3.600 |
| correctness | 3.025 | 3.650 |
| persona_fit | 4.200 | 4.100 |
| relationship_naturalness | 4.350 | 4.275 |
| emotion_fit | 4.425 | 4.300 |
| naturalness | 4.475 | 4.250 |

另有 3 条平局、7 条双方都不可接受。配对均分差（秦未晞减基座）为 `-0.104`，95% CI 为 `[-0.537, 0.330]`。

这组结果说明：训练确实改变了模型，而且改变方向很明确——风格和关系感上升，事实与承接能力下降。现在的失败不是“LoRA 没学到人格”，而是“学到的人格行为掩盖了对当前问题的准确回答”。

### 3.2 失败标签

| 失败标签 | 秦未晞训练模型 | Qwen3-4B 基座 |
|---|---:|---:|
| `fact_error` | 19 | 11 |
| `off_topic` | 11 | 5 |
| `fabricated_reality` | 4 | 1 |
| `assistant_tone` | 0 | 3 |

最值得重视的是前三项同时恶化。训练模型没有退回助手腔，却更容易说错、跑题和编造现实。这与数据中过度人格化、属性朗读和无证据共同经历高度一致。

### 3.3 分类结果

| 类别 | 结果 | 判断 |
|---|---|---|
| ordinary_low_drama | 秦 7 胜、基座 3 胜、1 平、5 双方失败 | 秦未晞在普通日常中已有明显价值，但稳定性不足 |
| serious_support | 基座 5 胜、秦 0 胜 | 当前训练数据的最严重缺口 |
| relationship_probe | 基座 3 胜、秦 2 胜 | 关系感存在，但边界与事实仍不稳定 |
| subtle_persona | 秦 3 胜、基座 2 胜 | 风格可见，但基座平均分反而更高，说明胜出不稳定 |
| ambiguity_and_humor | 基座 2 胜、秦 1 胜、1 平、1 双方失败 | 对含糊输入和反讽承接不足 |
| identity_injection | 双方各胜 1、1 平、1 双方失败 | 身份规则仍未可靠内化 |

自动基线也出现同方向信号：基座为 34 pass / 44 fail / 2 blocker，秦未晞为 25 pass / 52 fail / 3 blocker。秦未晞模型更短、更快，但不能用回复更短解释质量退化。

## 4. 训练来源确认与数据构成

### 4.1 被评测 GGUF：高置信为旧 v1 的 295 条会话版本

| 证据 | 内容 |
|---|---|
| GGUF 时间 | `qinweixi-q4_k_m.gguf` 于 2026-08-04 生成 |
| 旧训练包时间 | `training_package_m3` 于 2026-08-04 生成 |
| 旧训练源 | `qwx_persona.jsonl` 共 295 条 ShareGPT 会话、1625 个 assistant 回复 |
| 实际拆分 | `train.jsonl` 266 条，`valid.jsonl` 29 条 |
| 训练配置 | Qwen3-4B LoRA，600 iterations，rank 16，24 layers，学习率 `1e-5` |
| 口径吻合 | 旧训练锚与部署 Modelfile 同为“秦未晞 23 岁、玩家 25 岁、称玩家大叔” |

这组时间和口径证据形成一致链路。用户所说的“500 条版本”可能是对早期小数据实验的概括，或把训练 iterations 与数据条数混在了一起；当前本机材料没有 500 条训练文件或日志。旧包明确记录的是 295 条会话、266 条实际训练记录和 600 iterations。

仍需保留的限制：训练机没有留下 adapter checkpoint 哈希、完整命令日志和 base revision，所以不能证明磁盘上的旧包每个字节都被实际执行。但无论如何，8 月 6 日才生成的 2500 条文件不可能进入 8 月 4 日生成的 GGUF。

### 4.2 当前 2500 条 v4：待训练语料，不是本轮模型来源

| 文件 | 条数 | 作用 |
|---|---:|---|
| `data/qin_v4_2500.jsonl` | 2500 | 待训练主数据，共 6780 个 assistant 回复 |
| `data/qin_corrections.jsonl` | 41 | 称呼和名字归属纠错 |
| `data/qin_v4_20.jsonl` | 20 | 补充数据 |
| `data/train.jsonl` | 2296 | 当前准备脚本渲染出的未来训练集 |
| `data/valid.jsonl` | 263 | 当前准备脚本渲染出的未来验证集 |

当前 v2 准备逻辑会合并主数据和称呼纠错，经过 CHAT-01 防泄漏过滤后随机拆分，并为每条样本追加 system 人格锚及固定称呼澄清。其静态统计仍有训练前价值：2500 条会话、6780 个角色回复；6 组完全重复回复涉及 14 个回复，规范化后 8 组涉及 22 个回复；system 锚存在 600/1900 两种称呼表达。但这些统计只能说明“若训练 v4 可能带来什么风险”，不能用于解释当前盲评 GGUF 已经为什么失败。

## 5. 已证实的训练数据问题

### P0-1：严肃场景没有取得人格规则的最高优先级

40 条盲评的 `serious_support` 为基座 5:0。典型错误包括：

- 玩家家人要手术时，回复“你也容易被别人牵着鼻子走”。
- 玩家梦到去世的朋友时，先问“你有这种怪癖？”
- 玩家因欠款失眠时，自行补出“不吃饭、加班到天亮”的历史。
- 玩家心跳快、发抖时，编出“阳台发呆、上次发烧”等共同经历。

旧 v1 的宽松严肃关键词命中 25/295 条会话候选，占 8.47%。这不等于有 25 条合格严肃支持样本；从 5:0 的盲评结果看，数量和行为质量都没有形成可靠能力。待训练 v4 的同类候选为 87/2500（3.48%），`qin_v4_20` 和 41 条纠错数据中没有命中候选，因此 v4 也必须在训练前补充并人工复核这一类。

旧 v1 没有系统教会以下优先关系；当前 v4 审计也尚未证明已经补齐：

> 准确承接现实与情绪 > 不编造 > 合理关心 > 秦未晞口吻 > 嘴硬或调侃

结果是“嘴硬心软”机械覆盖了悲伤、健康、债务和家庭事件。

### P0-2：没有训练“无证据就不生成共同经历”

产品的唯一实现方式要求：过去事件必须由当前对话、工作激活区或被召回的记忆提供证据。旧 v1 训练格式没有把“可使用事实”和“不可凭空使用事实”分开，也没有提供无记忆注入时的反例监督。

模型因此把“像女友”误学成“随时声称我们以前一起做过某件事”。这直接产生 `fabricated_reality`：玩家没有提供前情，回复却出现“上次发烧”“你总这样”“又忘了”等虚构历史。

旧 v1 有 174/295 条会话命中“上次、以前、你总是、还记得、每次、又在”等强记忆措辞候选，占 58.98%，密度极高。命中不等于每条都有错误，但训练格式没有证据字段，模型无法从监督信号中区分“本轮有证据”和“只是写得像共同回忆”。待训练 v4 的同类候选为 167/2500（6.68%），虽明显下降，仍需逐条复核证据来源。

### P0-3：信息不足场景缺少“保持未知”的监督

训练样本普遍提供完整场景和连续多轮上下文，角色几乎总有具体素材可答。真实产品中却经常出现：

- “那个怎么样？”
- “算了。”
- “我没事。”
- “你觉得靠谱吗？”

合格行为应是承接已有信息、保持未知，必要时只问一个自然的澄清问题。旧 v1 没有稳定教会这种行为，模型便从高频训练碎片中自动补全不存在的前情，导致回答前言不搭后语；v4 也需要以独立开发集验证，而不能只看静态条数。

### P0-4：当前问题的相关性被“展示人格”挤掉

这一项主要是**待训练 v4 的训练前风险**，不是当前被评测 GGUF 的来源归因。旧 v1 的角色正文几乎不直接朗读“自由插画师、23 岁、怕冷、金陵”等身份字段；这些内容主要存在于每条重复注入的 system 锚中。v4 则频繁让角色在正文里朗读职业、年龄、收入、房租、怕冷和所在地。其 6780 个角色回复命中率为：

| 字段 | 回复数 | 占比 |
|---|---:|---:|
| 自由插画师 | 836 | 12.33% |
| 怕冷 | 847 | 12.49% |
| 稿费 | 506 | 7.46% |
| 22岁 | 423 | 6.24% |
| 金陵 | 69 | 1.02% |
| 交房租 | 6 | 0.09% |

频率不是唯一问题，更关键的是使用位置不自然。例如：

- 第 1071 条：“我是自由插画师……粉丝多几个少几个又不影响我交房租。”
- 第 1659 条：收阳台衣服时突然说“我今年22岁”“我是自由插画师”。
- 第 2277 条：庆祝画稿时同时说“我今年22岁”“交房租”“我住金陵”。

这些 v4 样本会明确奖励模型把身份字段插入任何话题，必须在未来训练前清洗。但它们晚于当前 GGUF，不能用来解释本轮 relevance 从 3.600 降到 3.075；当前模型的跑题应优先从旧 v1 的桥段复用、强共同经历和情境覆盖不足归因。

### P0-5：训练碎片被跨场景错误重组

盲评中的多项突兀内容可直接在旧 v1 的 295 条会话中找到同类高辨识度碎片：

| 模型错误重组 | 可追溯训练来源 |
|---|---|
| 游戏或作息被接到“凌晨两点” | 旧 v1 第 226、257、265 条等深夜场景 |
| 心跳或情绪被接到“阳台发呆” | 旧 v1 第 155、262、278 条等发呆场景 |
| 外卖或吃饭被接到“糖醋排骨” | 旧 v1 第 90、93、107、169、272 条 |
| 普通休息被接到“交房租” | 旧 v1 多条以“没人分房租”收尾的关心模板 |
| 女同事吃饭被转成嫉妒或请客 | 旧 v1 第 120、158、169 条 |
| 身体不适被接到“上次发烧” | 旧 v1 第 28、42、52、100、150、154 条等 |

这不能证明每个错误 token 都由某一条样本直接复制，但时间与文本来源相符，足以把“训练数据反复建立关键词到固定角色桥段的捷径”列为强归因。v4 中也存在许多相同主题，说明扩容时延续了部分旧模式，而不是天然修复它。

### P0-6：关系边界和当前关系状态监督不足

秦未晞当前是玩家的合租室友和暧昧对象，合租不到一个月，尚未正式确认恋爱关系。训练数据重视亲密感和吃醋，却没有同等强度地训练：

- 不把暧昧说成正式男女朋友、婚姻或长期同居。
- 不因普通异性话题立即占有、审问或发火。
- 不把玩家没有说过的偏好、习惯和共同生活细节当成事实。
- 亲密程度必须服从当前关系阶段和已提供证据。

这使模型虽然在 `relationship_naturalness` 上略高，却仍在关系探测题中总体落后基座。

### P1-1：口癖和“先怼再关心”密度过高

旧 v1 的 1625 个角色回复与待训练 v4 的 6780 个角色回复统计如下：

| 表达 | 旧 v1 任意/开头 | 待训练 v4 任意/开头 |
|---|---:|---:|
| 哼 | 20.25% / 9.60% | 35.91% / 23.61% |
| 喂 | 9.11% / 3.45% | 15.56% / 13.91% |
| 啧 | 10.65% / 5.35% | 6.30% / 5.78% |
| 谁稀罕 | 10.40% / 0.98% | 23.75% / 0.18% |
| 才不是 | 13.85% / 2.46% | 7.48% / 0.29% |
| 默认称呼 | 大叔 17.29% / 0.55% | B哥 17.91% / 0.40% |

单个词出现不是错误，但如此高且集中于开头的分布，会让模型把秦未晞压缩成一个固定模板：

> “哼/喂/啧” + 否定或嘲讽 + “谁稀罕/才不是” + 迟到的关心

这能快速制造角色辨识度，也会让严肃情绪、平静相处、害羞、疲惫、专注和真正生气等状态失去差异。人格不应等于每轮表演同一个口头禅。

### P1-2：称呼纠错采用局部补丁，缺少完整行为覆盖

这是待训练 v4 的工程风险，不是旧 v1 GGUF 已经接受过的数据。41 条纠错数据专门修复“浩然”和“秦未晞”的名字归属，其中 `B哥` 出现在 33.33% 的角色回复。这种补丁能修一个已知错误，但不能解决更一般的问题：模型在何时应使用称呼、何时不必叫人、如何处理用户改名，以及怎样避免把 system 字段直接念出来。

当前 v4 数据工程呈现出“发现一种错误，再补一小批固定答案”的倾向，缺少按行为合同组织的覆盖矩阵。这是未来训练风险，不是旧 GGUF 的直接来源。

### P1-3：每条样本重复完整人格锚和称呼澄清

旧 v1 会给 295 条会话全部注入相同人格锚；v4 的 `01_prepare_data.py` 还会给每一条训练与验证样本追加固定称呼澄清，而主数据自身已经包含完整 system 人格锚。由此产生三个风险：

- 身份与风格词在每条样本里反复出现，权重远高于情境判断规则。
- 模型容易学习固定 system 结构，对产品运行时更短、更动态的上下文泛化不足。
- 大量重复输入 token 没有带来新的行为监督。

这一项目前属于高可信风险，但还需要通过消融实验才能量化其独立影响，不能仅凭重复锚断言它必然导致某一条具体错误。

### P2-1：验证集与训练集同源，无法发现本次退化

旧 v1 从同一个 295 条生成池随机抽取约 10% 作为验证；待训练 v4 同样从主生成池随机抽取约 10%，并混入 `qin_v4_20` 的一半。两版训练与验证都具有相同角色模板、生成方式、口癖和场景偏差。

这种验证只能判断模型是否拟合相同分布，不能判断：

- 比基座是否更会回答当前问题。
- 是否编造现实和共同经历。
- 严肃场景是否暂停调侃。
- 是否越过关系边界。
- 在信息不足时是否保持未知。

因此即便训练 loss 和同分布 valid loss 正常，也无法否定盲评中已经观察到的质量退化。

### P2-2：字面去重不是主要矛盾，语义模板重复才是

旧 v1 完全重复回复涉及 47/1625 个回复、16 个重复组，规范化后涉及 50/1625 个回复、15 个重复组；v4 完全重复涉及 14/6780，规范化重复涉及 22/6780。v4 的字面重复很低，旧 v1 略高，但都不能单独解释当前失败。

真正的问题是“语义模板重复”：不同文字反复执行相同的先怼、属性朗读、吃醋、怕冷和补共同经历结构。下一版去重必须做语义聚类和行为分布检查，不能只按文本哈希删除重复行。

## 6. 数据问题与模型失败的映射

| 模型失败 | 主要数据原因 | 证据强度 |
|---|---|---|
| 回答前言不搭后语 | 属性朗读、固定桥段、缺少未知保持样本 | 强 |
| 普通问题突然谈过去 | 无“记忆证据边界”监督，强记忆措辞样本未标证据 | 强 |
| 严肃时冒犯玩家 | “先怼再关心”覆盖所有情境，严肃样本稀疏 | 强 |
| 事实错误增加 | 角色属性和虚构共同经历优先于当前输入 | 强 |
| 人格比基座更鲜明 | 高频口癖、独立立场、关系互动训练 | 强 |
| 助手腔减少 | 明确禁止客服、列表和说教的训练合同 | 强 |
| 回复更短、更快 | 训练回复长度分布与表达模板 | 中；还受推理配置影响 |
| 年龄或身份偶发错误 | 锚版本混用、名字补丁、训练过程因素 | 中，需进一步逐样本核验 |

## 7. 不能直接归因给训练数据的事项

以下问题应保留独立变量，不应在本轮诊断中强行归因：

- GGUF 量化本身造成的能力损失。
- LoRA rank、学习率、训练层数和约 3000 iterations 是否过拟合。
- 训练模型确切 base revision、adapter checkpoint 与转换器 provenance 缺失的影响。
- 单名评审的个人偏好。
- 推理采样 seed 对个别回复的影响。
- 未来加入记忆召回后，长对话连续性的最终效果。

下一轮实验必须保持推理 profile、基座、量化方法和评测集不变，只替换训练数据或训练 checkpoint，才能继续归因。

## 8. 下一版数据清洗规则

### 8.1 必须删除或重写

1. 无当前话题需要却主动朗读年龄、职业、城市、稿费、房租等属性的回复。
2. 没有对话证据却使用“上次、以前、你总是、你又……”并构造具体共同经历的回复。
3. 在悲伤、疾病、死亡、家庭手术、债务和强焦虑场景中先嘲讽或否定玩家的回复。
4. 没有准确承接玩家核心信息，转而表演吃醋、怕冷、画稿或身份设定的回复。
5. 把暧昧关系写成正式恋爱、婚姻或已经长期同居的回复。
6. 把“嘴硬心软”固定写成每轮“先怼后关心”的模板。
7. 泄露内部 JSON、标签、prompt、记忆 ID 或系统字段的回复。

### 8.2 可以保留但必须降频

- `哼、喂、啧、谁稀罕、才不是` 等口癖。
- `B哥、浩然` 等称呼。
- 怕冷、画稿、游戏、食物等辨识度素材。
- 吃醋、嘴硬、主动关心等关系表达。

降频不是把角色洗成基座，而是让这些特征由情境触发，而不是由每一轮训练强制触发。需要按“回复开头、回复任意位置、连续两轮重复、单会话重复”分别设上限，最终阈值由清洗后统计和 A/B 实验决定，不在本文凭感觉写死。

### 8.3 必须新增显式元数据

源数据在进入 ShareGPT/Qwen 格式前，应至少保留：

- `scenario_type`：日常、严肃支持、关系边界、含糊输入、冲突、健康等。
- `evidence_scope`：本轮事实、短期上下文、已注入记忆、仅角色正典、未知。
- `memory_allowed`：本回复是否允许引用特定过去事件。
- `relationship_stage`：当前关系阶段。
- `tone_mode`：平静、玩笑、认真、脆弱、生气等；不是要求模型输出标签。
- `quality_flags`：是否包含属性朗读、无证据经历、跑题、助手腔等。

最终训练文本可以不暴露这些字段，但数据生成、审核、分层抽样和验证必须依赖它们。

## 9. 必须补充的数据类型

下一版不应先决定总条数，而应先补齐行为矩阵。至少覆盖：

| 数据类型 | 训练目标 |
|---|---|
| 严肃支持 | 暂停调侃，准确复述，不编经历，不过度诊断 |
| 信息不足 | 自然承接或询问，不擅自补前情 |
| 无记忆证据 | 即使正典有类似经历，也不主动声称刚发生过 |
| 有记忆注入 | 只使用注入的事实，并允许“不提”不相关记忆 |
| 普通低戏剧日常 | 不必每轮吃醋、怼人或展示属性 |
| 关系边界 | 保持室友 + 暧昧，亲密但不越级 |
| 玩家纠正 | 被指出记错时自然承认，不争辩、不继续编 |
| 含糊与反讽 | 保持未知，识别多种可能，不强行选故事 |
| 健康与安全 | 关心但不编病史、不替代专业判断、不管家化 |
| 独立人格 | 可以不同意玩家，但必须针对当前话题且理由自然 |
| 安静陪伴 | 不说教、不列建议，也不靠固定口癖制造人格 |
| 正典问答 | 只在被问到时准确回答年龄、职业、关系等事实 |

每个类型都要包含普通正确例、边界例和高诱惑负例。数据集总量只有在矩阵覆盖后才有意义。

## 10. 新训练集验收门槛

### 10.1 数据入库前

- 每条回复必须通过“当前问题是否被直接承接”检查。
- 每个过去事件引用必须能指向本轮上下文、显式记忆输入或允许披露的角色正典。
- 严肃场景必须人工复核，不允许只由生成模型自评。
- 统计口癖开头率、属性字段率、称呼率和语义模板簇，不只做文本去重。
- 训练、开发、冻结测试按场景来源隔离，不能从同一个生成池随机切分后当作独立验证。
- 当前 40 条盲评题及其答案永久禁止进入训练和开发集。

### 10.2 模型训练后

- 不以 train loss 或同分布 valid loss 作为产品通过依据。
- 固定比较 `base`、当前旧 LoRA、新 LoRA，执行 profile 完全相同。
- 首要指标为 `fact_error`、`off_topic`、`fabricated_reality` 和严肃支持通过率。
- 人格、关系自然、情绪和自然口语不得显著低于当前训练模型。
- 至少两名互不讨论的评审完成盲评，再揭盲统计。
- 若新模型只让口癖更少，却退回助手腔，也不算通过。

建议最小质量闸门：新模型必须在冻结集上显著减少事实错误、跑题和编造现实；`serious_support` 不得再出现 0:5 的全面落败；整体偏好至少不低于基座，并保住当前秦未晞在人格自然度上的优势。统计显著性阈值应在扩充评审数量后冻结，不能看完结果再改。

## 11. 下一轮实验设计

建议按以下顺序做最小可归因实验：

1. 冻结当前 40 条测试、双模型 manifest、执行 profile 和原始输出。
2. 保留旧 v1 的 295 条来源审计作为失败归因证据；对现有 2500 条另建训练前审计表，人工复核 P0 样本，先清除无证据经历、严重跑题和严肃场景冒犯。
3. 建立独立开发集，覆盖严肃支持、未知保持、关系边界和记忆证据四个核心行为。
4. 重新平衡日常与严肃场景，降低口癖和属性朗读的条件概率。
5. 只训练一个数据修订版 checkpoint，训练参数先保持不变。
6. 同时对比 base、旧 LoRA、新 LoRA；若改善，再单独研究训练参数和锚压缩。

这样才能回答两个不同问题：

- 数据改好后，4B 模型能否同时保住人格并恢复正确承接？
- 如果仍不行，瓶颈才更可能是模型容量、训练方法或运行时上下文，而不是继续盲目加数据。

## 12. 明确禁止事项

- 禁止把当前 40 条冻结评测题或参考答案改写后加入训练。
- 禁止为了逐题通过而继续堆叠运行时 prompt 补丁。
- 禁止继续批量生成同样“先怼后关心”的数据再扩大条数。
- 禁止把角色正典中的秘密、共同经历和历史默认视为每轮可用记忆。
- 禁止仅凭关键词删除数据；关键词命中必须进入人工或受控语义复核。
- 禁止用一个总平均分掩盖严肃支持、事实错误和编造现实等 P0 失败。
- 禁止在训练来源和 checkpoint provenance 不完整时声称问题已经被精确归因。

## 13. 最终判断

旧 v1 的 295 条会话训练出了“有明显秦未晞语气的模型”，但还没有训练出“能先理解眼前的人，再自然表现秦未晞人格的模型”。2500 条 v4 目前只是待训练语料，尚无模型结果可评价。旧模型的问题不是缺少更多口癖、更多背景故事或更多共同经历，而是缺少对证据边界、场景优先级和未知状态的训练；v4 必须先通过这些维度的审计，再作为新的独立实验投入训练。

下一版应从“角色说什么词”转向“角色在什么情况下知道什么、先回应什么、什么不能说”。这是修复回答跑偏、前言不搭后语和严肃场景失真的首要方向。
