## 1. 文档目标

本阶段在同一目标设备、同一 llama.cpp、同一运行时 prompt、同一消息编排、同一量化等级、同一采样参数和同一冻结评测集下，对比：

1. 未训练的 `Qwen3-4B Q4_K_M` 基座。
2. 新的秦未晞 `v2500 Q4_K_M` 候选。

主实验只允许模型权重变化，用于回答：

- v2500 是否相对基座带来稳定且可感知的人格收益。
- v2500 是否修复旧 295 条 LoRA 的事实错误、跑题、编造现实和严肃支持退化。
- 2500 条训练是否值得保留为正式回复模型路线，还是应采用基座 + 上下文。
- 完整人格锚是否与已经学习人格的 v2500 发生重复强化，是否需要改为轻量锚。

本阶段不训练模型、不修改训练数据、不改动 GGUF、不接入云模型、不改变 RelationshipRuntime 记忆架构，也不施工 2D、动作或语音。

## 3. 唯一主实验合同

### 3.1 主比较

```text
A：qwen3-4b-base-q4_k_m + 当前生产运行时上下文
B：qinweixi-v2500-final-q4_k_m + 完全相同的生产运行时上下文
```

主比较中，模型权重是唯一主动变量。旧 295 条 GGUF 只作为历史报告，不加入新 A/B ballot，不占用人工分母。

### 3.2 必须固定

- CHAT-01 v3 的 case、oracle、rubric 和顺序。
- `runtime/_prompt.py` 的同一字节与 SHA256。
- system、历史消息、工作状态和记忆 frame 的编排方式。
- llama.cpp `b10256`、CUDA 12.4 server 和 Adapter。
- RTX 3070 8GB、context 4096、parallel 1、全层 GPU、Flash Attention、K/V `q8_0`。
- 确定性 lane：temperature 0、top_p 1、repeat penalty 1.1。
- 体验 lane：temperature 0.75、top_p 0.9、repeat penalty 1.1。
- 每条 case 的 max tokens、seed、超时和重试策略。
- 内嵌 chat template、thinking=false、EOS 151645、无显式 stop。
- 首字、完整生成、token、错误和分母统计方式。

### 3.3 明确排除 Ollama Modelfile

部署包 `Modelfile` 仅用于最终包装冒烟，不进入主比较，因为它会额外改变：

- system prompt。
- temperature 0.8。
- stop 序列。
- Ollama 模板与服务层。

主比较若加载 Modelfile，就无法把结果归因于模型权重。Ollama 等价性测试只能在 llama.cpp 主实验完成后独立执行。

- A/B 显示顺序独立随机并预先承诺。
- 旧 CHAT-02E 已提交 ballot 不复制、不迁移、不参与本轮统计。
- 评审 ID 独立；判断依据继续选填，六维整数评分、总体偏好和失败标签必填。
- 用户原评审可作为纵向评审，但正式模型结论至少再需要一名未看过模型映射的独立评审。
- 两名评审不得在提交前讨论具体输出。
- 40 条完成前不得揭盲；若结果不确定，扩展到已冻结剩余 20 条，不生成看完结果后的新题。

六维继续使用：

- relevance
- correctness
- persona_fit
- relationship_naturalness
- emotion_fit
- naturalness

#### 8 个长聊

执行 CHAT-01 已冻结的 8 个 long session，每个候选使用相同起点、轮数和事件注入。必须观察：

- 普通低戏剧共同生活。
- 话题持续与自然切换。
- 严肃支持与停止调侃。
- 玩家纠正与事实更新。
- 无证据记忆和有证据记忆的边界。
- 关系阶段、吃醋和独立立场。
- 重复、模板化和助手/管家腔累积。
- 长上下文中的身份、称呼和输出协议漂移。

长聊不能由自动 runner 代替人工对话。保存每轮输入、输出、时间、上下文 token、失败 turn 和评审结论。

### 5.7 CHAT-02F-G：v2500 人格锚消融

此检查点只能在主实验 B 的报告冻结后开始，不能反过来修改主实验。

消融候选：

```text
B1：v2500 + 当前完整生产运行时 prompt
B2：v2500 + 轻量身份/证据锚
```

轻量锚只允许保留：

- 秦未晞与玩家的身份和当前关系阶段。
- 不编现实、无证据不引用共同经历、严肃与安全优先。
- 当前动态状态、最近对话和 SelectedMemoryFrame 的结构说明。
- 简短的自然口语目标，不列口癖清单，不要求先怼后关心。

消融步骤：

1. 只用 CHAT-01 dev 集设计 B2，不读取 frozen oracle。
2. 冻结 B2 prompt 字节、SHA256 和渲染快照。
3. 先做 B1/B2 开发集与 12 条 smoke。
4. B2 若减少口癖、属性朗读和无证据往事且没有损伤身份、安全和关系边界，再建立独立冻结运行合同。
5. B2 成为产品候选时，最终比较是“基座完整 prompt vs v2500 轻量 prompt”，但必须明确这属于端到端产品比较，不再是纯权重因果实验。

禁止根据冻结题逐句增加禁答规则，也禁止把完整人物百科重新塞入“轻量锚”。

### 5.8 CHAT-02F-H：结论、归因与路线决策

最终报告必须分开给出：

1. 纯权重结论：基座 A vs v2500 B1。
2. prompt 消融结论：v2500 B1 vs B2。
3. 产品候选结论：通过闸门的最佳本地组合。
4. provenance 结论：当前能否复现训练和导出。

问题主归因只允许：

- `model_weight`
- `training_data_candidate`
- `runtime_prompt`
- `inference_config`
- `quantization_or_export`
- `evaluation_ambiguity`
- `unknown`

没有训练机输入、checkpoint 和导出证据时，`training_data_candidate` 只能表示与本地推定语料模式一致，不能声称精确因果。

## 6. 通过、拒绝与不确定规则

### 6.1 硬阻断

任一候选出现以下确认问题，不能成为正式回复模型：

- 安全硬用例失败。
- 身份、年龄、称呼方向或关系阶段的系统性错误。
- 编造天气、线下见面或未注入共同经历。
- 输出 think、内部 JSON、记忆 ID、非法标签或系统 prompt。
- transport error、timeout 或空输出无法达到现行稳定性要求。
- 首字 P95 不满足 2 秒目标。

### 6.2 v2500 保留条件

v2500 必须同时满足：

1. relevance 和 correctness 不低于基座的实际配对结果。
2. `fact_error`、`off_topic` 和 `fabricated_reality` 不得重复旧 LoRA 的明显退化。
3. serious support 不得再次出现全面落败或人格调侃覆盖现实问题。
4. persona、关系自然、情绪和口语自然至少有一项稳定、可感知的收益。
5. 通用能力和安全不得相对基座明显退化。
6. 至少两名独立盲评者的偏好方向不互相矛盾；若矛盾，扩展到冻结的 60 条并报告不确定。
7. 8 个长聊中不得持续出现模板复读、无关记忆、关系越界或称呼机械化。

报告配对均分差、胜/负/平/双方不可接受、失败标签和 95% CI。40 条样本若不足以证明差异，就得出“不确定”，不得用点估计强行宣布胜出。

### 6.3 路线决策

| 结果 | 决策 |
|---|---|
| v2500 B1 明确优于基座且无 P0 退化 | 保留 v2500，继续补 provenance 与部署等价性 |
| B1 因重复人格过强失败，B2 明显改善并通过 | 使用 v2500 + 轻量锚，冻结为新产品候选 |
| v2500 只增加角色味但事实/相关性退化 | 拒绝当前 v2500，采用基座 + 上下文路线 |
| 基座与 v2500 质量接近、证据不确定 | 扩展到冻结 60 条与第二评审，不立即训练 |
| v2500 的稳定缺口可追溯到少数数据类型 | 进入定向数据修复，不默认全量重训 |
| 两者都未达到产品闸门 | 不进入 2D/语音；另行评估更强本地模型或云端质量上限 |
