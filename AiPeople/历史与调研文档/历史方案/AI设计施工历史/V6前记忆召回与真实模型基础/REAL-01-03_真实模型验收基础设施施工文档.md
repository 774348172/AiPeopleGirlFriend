## 1. 连续施工范围

本施工段连续完成真实模型产品验收之前的三项基础设施：REAL-01 冻结指标和共享全局池评测，REAL-02 验真本地 BGE、Qwen3-Reranker 与 Qwen3.5 GGUF 资产，REAL-03 用断网 adapter 将三类资产组合到现有长期记忆在线主链。

本段不下载或训练模型，不生成、清洗或修改训练数据，不导出 GGUF，不覆盖任何旧冻结 manifest。没有真实资产时只验证合同和失败路径，Fake/injected backend 不产生质量、P95 或显存结论。

## 2. REAL-01：升版验收合同

旧 RECALL-04 v1 每个案例只有 4 条候选，而指标检查 Top32，因此无法形成有区分度的语义门。本段新增 v2 evaluator：所有案例共享同一个大于 32 条记忆的全局池，统一报告 `Recall@1/@5/@10/@32` 与 MRR，并拒绝未知、重复、缺失或超过 32 个候选 ID。

随仓库冻结的 8 案例、40 记忆集合仅用于工程 smoke，明确禁止据此宣布产品质量通过。正式产品集要求至少 200 个冻结案例、1 万条共享有效记忆，并分离 validation、test_frozen 和 long_memory_e2e。test_frozen 不得用于调整阈值。

预注册门槛固定为：

- `global_recall_at_32 >= 0.98`；
- `natural_recall_accuracy >= 0.90`；
- `no_memory_false_activation_rate <= 0.05`；
- `hard_negative_rejection_rate >= 0.90`；
- `selected_memory_precision >= 0.90`；
- 相对未微调 reranker 的成对 bootstrap 95% CI 下界严格大于 0。

性能门保持 selector P95 严格小于 300ms、回复首字 P95 严格小于 2 秒、GPU 总峰值严格小于 5120 MiB，以及至少一小时无持续显存增长。

## 3. REAL-02：真实资产验真

`LocalBgePackage` 要求显式 `bge_manifest.json`，固定 `BAAI/bge-small-zh-v1.5`、revision、512 维、512 token、mean pooling、Runtime L2、CPU 和禁止联网。必须列出并校验全部模型文件 SHA256，路径不能绝对或包含 `..`，整包使用 canonical SHA256。

既有 `LocalRerankerPackage` 继续要求 `Qwen/Qwen3-Reranker-0.6B`、固定 activation threshold、128 pair tokens、yes/no logits、部署 profile 和文件/整包 SHA256。本段为其增加严格 JSON Schema，并将正式部署 profile 限定为 CUDA BF16、FP16、INT8 或 NF4。

`LocalQwen35Package` 要求 `reply_manifest.json`，固定 `Qwen/Qwen3.5-4B`、base revision、角色、部署 profile、GGUF、量化、chat template、thinking=false、禁止联网及所有 SHA256。在线栈只接受 `qinweixi_candidate`，未训练基座仅用于对照。

`LocalRealAssetBundle` 使用显式绝对路径绑定三类包和 llama.cpp runtime manifest，并再次核对三个 component artifact SHA256。缺失、路径漂移、身份漂移或文件篡改均在加载模型前失败。

## 4. REAL-03：断网 adapter 与组合入口

`ManifestBgeEncoder` 使用本地 `torch + transformers` 在 CPU 执行冻结的 attention-mask mean pooling；所有加载均为 `local_files_only=True`、`trust_remote_code=False`。查询仍每轮只编码一次，记忆向量仍只由后台增量同步或全量重建。

`LocalQwen3Reranker` 将同一 Top32 批量编码到最多 128 tokens，读取 yes/no token logits 并输出逐 memory ID 激活概率。支持 CUDA BF16、FP16、INT8 和 NF4 加载配置；未知 profile 明确失败，不切换 CrossEncoder。推理在线程中执行，继续受现有 250ms 超时和 fail-closed 校验保护。

`build_real_memory_stack` 验证 Qwen3.5 GGUF 路径和 llama runtime manifest 与 bundle 完全一致，再组合：

```text
ManifestBgeEncoder
  -> MemoryVectorStore / SelectorQuery
  -> exact global Top32
  -> LocalQwen3Reranker
  -> SelectedMemoryFrame
  -> LlamaCppReplyModel
  -> MemoryAwareReplyModel
```

它不自动在玩家关键路径重建向量，不增加第二次 REPLY，不绕过追加式账本，也不改变既有故障降级。
