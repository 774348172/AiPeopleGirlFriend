## 0. 本次整合的关键变更（相对初版）

初版基于 audit 修订，但**尚未反映后续三个决策**。本整合版修正：

1. **ABCD 决策（砍运行时训练）**：原"慢轨离线固化闭环"被 ABCD 取代——发版后**零权重训练**，成长靠记忆，深层质变靠剧情 gated 预烘 LoRA。
2. **8GB 地板模型选型**：8GB 与游戏共享 → **1.7B**（不是 4B）；12GB → 4B；**按显存自适应**。
3. **方案 C 简化为 8GB 地板版**：原 C1-C6 精巧流程（三分量 LLM 评分/mem0 DECIDE/反思流水线）→ 数据卫生 + 零 LLM 评分 + 模型生成时判断。
4. **差异化定位修正（诚实）**：原"反射→权重闭环"差异化随 ABCD 砍掉（见 §2）。

## 1. 路线决策：ABCD（一句话）

| | 内容 | 训练? |
|---|---|---|
| **A** | 发版冻结权重 + per-player 记忆成长（玩家设备本机、实时、私密、免费） | 发版一次，之后零 |
| **B** | 反思**写记忆**而非写权重（反思是推理级调用，不是训练） | 零 |
| **C** | 记忆层做扎实——**8GB 地板版**（数据卫生 + 零 LLM 评分） | 零 |

**明确砍掉 E**（任何发版后权重训练：运行时 on-device、dev-time 周期、集中训练所有玩家数据）——成本/隐私/8GB 可行性都不可接受。

**满足"实时新记忆"硬需求**：快轨（A 的记忆层）在玩家设备实时；权重内化（原慢轨）改为记忆驱动 + 剧情离散，不上权重。

## 2. 差异化定位（诚实修正）

初版差异化 = "反射→权重闭环"（OSS 空白）。**ABCD 砍掉该闭环**后，运行时成长 = 记忆驱动（行业标准，Letta/mem0/AIRI/ACE 都这么做），**该差异化消失**。这是受成本/隐私/8GB 可行性约束的 **scope 收敛**，诚实承认。

**新差异化**（不再是"权重级成长"）：
1. **8GB 地板可行性**——多数 game-AI 假设云或大卡；在 8GB 最差地板上把本地多 NPC 跑通是真硬约束、真工程。
2. **hero LoRA + 剧情 gated LoRA**——市面量产几乎全 prompt+memory（无 per-NPC 权重）；我们给少量 hero 烘权重 + 剧情阶段 LoRA，在 8GB 地板上做。
3. **零 LLM 记忆卫生（C 8GB 版）**——为 8GB 地板调的、几乎不耗 LLM 的记忆层。

**诚实边界**：1.7B + 这套方案能做到"记得、引用、因过往而变、剧情阶段切换"；**做不到"无剧情开关的平滑底层性格渐变"**——那需权重持续训练（已砍）或更强基座（8GB 上不了）。接受此上限。

## 3. 市面对比与选型

| 系统 | 人格 | 记忆 | 本地? | 借鉴 |
|---|---|---|---|---|
| NVIDIA ACE/NVIGI | 共享基座+RAG | Game Agent SDK RAG | 进程内 | GPU 共享解法 + tiering 哲学 + Qwen3.5-4B 基座 |
| Inworld/Convai | session/多段配置 | Knowledge Bank vs Memory | 云 | 多段 persona card + 静态/情景记忆二分 |
| AIRI | CCC card | pgvector per char | 本地可换 | character card 规范 + provider 抽象 |
| AstrBot | PersonaManager | FAISS+BM25+压缩 | 单进程异步 | 异步总线串行化 NPC 轮次 + 上下文压缩 |
| Smallville | per-agent 记忆流 | 三分量+反射 | 独立模拟服务 | 独立模拟服务拓扑(引擎无关) |

**市面最重要发现**："一个基座 + per-agent prompt + per-agent 记忆"是量产主流，per-NPC 权重罕见——**我们的 hero LoRA 是差异化，background tier 契合主流**。

**选型（union of what ships）**：拓扑 **Smallville**（独立模拟服务 over OpenAI 兼容本地端点）+ 记忆 **二分量+反思写记忆**（砍 mem0，见 §6）+ 运行时 **AstrBot 异步总线+压缩** + GPU 纪律 **NVIGI tiering 哲学** + 我们 **hero/剧情 LoRA**。

## 4. 目标架构（整合后）

```
游戏引擎(UE/Unity/Godot)
  └─ NPC 调度器（错峰；只附近/参与 NPC 生成；NPC_id→tier→服务方式）
       原则：N 常驻，K≪N 同时说话（8GB 地板 K=1-2，12GB K=2-3）
       ├─ 模拟服务（独立进程，Smallville 式，OpenAI 兼容）
       │     ├─ 异步事件总线（AstrBot 式，串行化前台 NPC 轮次，避免并发爆显存）
       │     ├─ per-NPC 状态：persona card(多段) + 记忆层(分区) + 当前上下文
       │     └─ 上下文压缩（长对话压历史，保 persona 锚）
       ├─ Hero tier（2-3）：NPC_id→专属 LoRA + 剧情阶段 LoRA
       │     ├─ 共享基座(roleplay-SFT, 自适应1.7B/4B, 4bit) + LoRA 服务
       │     ├─ 记忆层 C（8GB 版：二分量+valid+latest-wins+启发式importance）
       │     └─ 权重：发版烘好（基础LoRA + 剧情阶段LoRA），发版后零训练
       ├─ Background tier（其余）：NPC_id→persona card（无权重）
       │     ├─ 共享基座 + 多段 card(Convai 式) + 记忆层 C(轻量)
       │     └─ 无任何权重
       ├─ 记忆二分（Convai 式）：Knowledge Bank(静态世界观) + Memory(情景对话)
       └─ 服务栈：llama.cpp(原生Win, 单LoRA热换) / vLLM多LoRA(WSL2) / NVIGI(进程内,RTX)
```

## 5. 模型与显卡（8GB 地板）

**两类卡瓶颈相反**：
- 8GB（3070/3060-8G）瓶颈显存 → 与游戏共享**必须 1.7B** + int8 KV + 限画质 + 预留显存。
- 12GB（3060-12G）瓶颈算力 → **4B 甜点**（显存富余），8B 慢、14B 不行。

**自适应发版**：启动检测 VRAM → ≥12GB 用 4B，8GB 用 1.7B。hero LoRA 要为两尺寸准备（或 1.7B 档全 background card、4B 档才给 hero LoRA）。

**同时说话**：8GB 3-5（1.7B），12GB 2-3（4B，算力卡）。靠"N 常驻 K 说话"错峰调度。

**GPU 共享无银弹**：优先 NVIGI（进程内 CiG 协同，8GB 起荐 12）；否则 1.7B + 预算 + 限画质；或推理卸 CPU/NPU（慢但无争用）。

## 6. 方案 C：8GB 地板版记忆层

**原则**：8GB 地板上 LLM 调用最贵（与游戏+生成抢算力），1.7B 反思弱。C 目标 = **用最少 LLM 调用保数据卫生**，不是模拟人脑。

**按 LLM 成本切分**：

| 模块 | 处置 | LLM 成本 |
|---|---|---|
| 结构化存储（含 valid/superseded_by） | **保留** | 零 |
| 二分量检索（recency+relevance） | **保留**（砍 importance 的 LLM 评分） | 零 |
| valid 失效过滤 + 严格小预算（~300 token） | **保留** | 零 |
| latest-wins 去重 | **替代 mem0 DECIDE** | 零 |
| 评分衰减遗忘 | **保留** | 零 |
| importance | **启发式**（涉及玩家+5/情绪+3/环境+1） | 零 |
| 热路径抽取 | **规则优先**，抽不到才 1 次轻调用 | 0-1 |
| 反思 | **降为可选单次摘要**，罕见、仅前台 | 1（可选） |

**每轮 LLM 调用 0-1 次**（原版 1+ 次 + 冷路径多次 DECIDE + 反思多次）。

**有效性边界（诚实）**：C 的价值在**保数据卫生**（零 LLM、必要），不在模拟成长——成长靠发版烘进权重的人格 + 干净记忆即时检索。1.7B 反思封顶，C 突破不了。

**两档配置**：8GB 地板（1.7B，零 LLM 为主）+ 12GB 舒适（4B，可解锁偶尔 LLM 评分/低频去重），均不默认全开，看 ablation 收益。

---

## 7. 方案 D：剧情 gated 预烘人格 LoRA

- 发版时为每个 hero 烘**几个阶段 LoRA**（如创伤前/创伤后/救赎），随包 ship。
- 剧情节点**切换加载**哪个 LoRA（推理级，不训练）。
- 与 C 接缝：切 LoRA **不重置记忆**（记忆连续，"变了一个人但记得过去"成立）；切阶段时写一条高 importance 状态记忆重锚情绪基线，配合新 LoRA。
- 解决"深层人格质变"，**零运行时训练**。

## 8. 与现有代码的关系（复用 vs 新增 vs 砍）

**复用**（不浪费）：
- `data_gen/`（life_generator/consistency_check/to_sharegpt/prompts）→ 每个 hero 的语料管线，逐 NPC 跑。
- `persona/` → 每个 hero 一套 + 新增"世界正典"管跨 NPC 一致。
- LLaMA-Factory config → **共享基座 roleplay-SFT + hero 基础 LoRA + 剧情阶段 LoRA**（发版一次训练）。
- `eval/personality_fidelity.py` → hero 人格保真评测。

**新增**：
- `memory/` 8GB 版：schema/store/retriever(二分量)/latest_wins/可选 summarizer——**砍掉原 mem0 DECIDE/store_writer**。
- `sim_server/`：异步总线 + per-NPC 状态 + 上下文压缩 + OpenAI 兼容客户端。
- `scheduler/`：tier 路由 + 错峰 + 前台/后台循环。
- `serving/`：llama.cpp 热换脚本 / vLLM 多 LoRA / NVIGI 适配。
- 剧情 LoRA 切换器（D）。
- 自适应选型（启动检测 VRAM 选 1.7B/4B）。

**砍掉**：
- ❌ `consolidate/`（离线固化闭环）——ABCD 后不需要发版后训练。
- ❌ mem0 DECIDE + graph 记忆栈。
- ❌ 运行时/on-device/发版后任何权重训练（E）。

## 9. 关键技术决策（整合）

1. **记忆**：二分量（recency+relevance）+ valid 过滤 + latest-wins + 启发式 importance。砍 mem0、砍三分量 importance 的 LLM 评分。
2. **权重**：发版**一次训练**（共享基座 + hero 基础 LoRA + 剧情阶段 LoRA）；发版后**零训练**（ABCD）。
3. **服务**：v1 = llama.cpp 单 LoRA 热换（原生 Win）；多 hero 并发 → vLLM 多 LoRA(WSL2)；GPU 共享瓶颈 → NVIGI(进程内,RTX)。
4. **GPU 共享**：NVIGI 优先；否则 1.7B + 显存预算 + 限画质。
5. **路由**：确定性 `NPC_id → adapter`(hero) / → card(background)。不学路由器。
6. **persona**：Convai 式多段 card（identity/traits/state）。
7. **基座**：roleplay-SFT 一次，自适应 1.7B/4B，4bit + KV 量化。

| MR | 内容 | DoD |
|---|---|---|

## 12. 风险（整合更新）

1. **命门未实锤**：合成语料一致性未在真实模型验证；多 NPC 放大（N 人设 + 世界正典）。MR0/MR1 先验证。
2. **8GB 与游戏共享无银弹**：NVIGI 集成重（C++/D3D12/RTX）；不集成则掉帧或降 1.7B。
3. **1.7B 反思封顶**：C 突破不了；深度成长放弃（scope 收敛，诚实承认）。
4. **NVIGI 接受自训基座/adapter 未核实**：后端无关且 ACE 列 Qwen3.5-4B，plausible，commit 前确认。
5. **多 LoRA 服务**：llama.cpp 单 LoRA 热换在多 hero 频繁切换有 ms 开销；要并发上 WSL2+vLLM。
6. **scope 收敛风险**：放弃运行时权重成长后，项目从"创新闭环"变"8GB 地板工程化"——定位要诚实传达，勿再宣传"权重级成长"。

## 13. 不做什么（明确砍掉）

- ❌ mem0 DECIDE + graph 记忆栈（过度工程）
- ❌ 运行时 on-device 持续 LoRA 训练（8GB 不可行）
- ❌ 发版后任何权重训练 / dev-time 周期固化 / 集中训练所有玩家数据（E，全砍）
- ❌ 反射→权重闭环（原差异化，随 ABCD 砍）
- ❌ 自学 LoRA 路由器（确定性查表即可）
- ❌ 自建 model soup 工具（mergekit/一行）
- ❌ 全 NPC per-NPC 权重（仅 hero）
- ❌ LMDeploy 原生 Windows 假设（更正为 llama.cpp）

## 14. 一句话总结

中间路线 = **Smallville 拓扑 + 二分量记忆(砍mem0,8GB版) + 2-3 hero LoRA + 剧情 gated 预烘人格 LoRA + 其余 card + 发版后零训练(ABCD) + llama.cpp/vLLM/NVIGI 服务 + 8GB 地板自适应 1.7B/4B**。整合砍掉了原路线的"运行时权重成长闭环"（改为记忆驱动 + 剧情离散，诚实 scope 收敛），保留了合理核心（tiering、数据卫生记忆层、确定性路由、共享 roleplay 基座）。新差异化是 **8GB 地板可行性 + hero/剧情 LoRA + 零 LLM 记忆卫生**，不再是权重级成长。现有 data_gen/LF SFT/eval 直接复用为 hero 管线（MR1），不浪费。
