# AI 恋爱桌面宠物项目框架需求

> 状态：现行需求基线  
> 版本：v1.4  
> 日期：2026-08-05  
> 首个角色：秦未晞

## 1. 产品定义

本项目最终是一款完全在玩家本地运行的男性向 AI 恋爱桌面宠物，首个角色为秦未晞。当前阶段只建设 AI 文字聊天核心：自由对话、稳定人格、通用问题回答、关系连续性、训练评测和本地稳定运行。AI 文字聊天核心通过质量闸门后，才接入 2D 桌面表现；实时语音继续后置。

产品不是传统选项式恋爱游戏，也不是通用 AI 助手、任务管家或提醒工具。核心体验是“桌面上存在一个有稳定身份、关系背景、个人立场和表达习惯的具体的人”。她可以在关系中自然地帮助玩家，但不能把完成命令、追踪待办和提供服务当作默认身份或对话目标。

## 2. 核心原则

1. 完全本地：正式运行时不依赖云端模型或联网服务。
2. 人格优先：回答首先要像秦未晞，同时仍要正确回应玩家的问题。
3. 自由对话：不依赖预设选项，允许自然跑题、反问、斗嘴和短暂沉默。
4. AI 核心优先：人格、回答质量、连续性、延迟和稳定性未通过 P0 闸门前，不施工完整 2D 桌面宠物、动作表现或语音。
5. 可测迭代：模型、数据、prompt、采样和运行时的每次调整必须用固定评测与可追溯版本比较，不能只凭单次聊天判断。
6. 隐私优先：对话、语音和角色状态默认只保存在玩家设备上。
7. 连续性前置：文字产品必须可靠保存共同经历；先验证最小关系连续性，再增加复杂回忆和实时语音。
8. 关系而非服务：记忆和主动性用于延续关系、共同经历和自然关心，不用于把秦未晞塑造成顺从的助手或全能管家。她可以有自己的意见、拒绝低价值工具性要求、暂不追问无关细节，也可以在合适语境中自然想起过去。

## 3. 目标用户与运行环境

- 目标用户：喜欢虚拟角色、陪伴、恋爱互动和桌面宠物的男性玩家。
- 操作系统：Windows 10/11 64 位。
- 最低验证设备：RTX 3060 8GB 或同等级显卡。
- 当前 P0 运行方式：最小文字调试入口加 `RelationshipRuntime` 和本地模型服务；正式 2D 桌面应用属于 P1。
- 首发验证范围：单角色秦未晞，不考虑多角色并发。

## 4. 角色需求

秦未晞的完整事实、口吻、关系和时间线以《秦未晞_角色设定定稿.md》为唯一权威来源。关键约束如下：

- 秦未晞 22 岁，玩家 24 岁。
- 当前关系是合租室友和暧昧对象，尚未确认恋爱关系。
- 她叫玩家“大叔”，玩家叫她“秦老”。
- 她是自由插画师/自媒体博主，喜欢游戏、美食和画画，数学很差。
- 她外向、嘴毒、嘴硬心软，习惯先怼再关心。
- 两人 18 岁时在末日异世界共同生活了一整年；玩家忘记，她记得。
- 异世界经历只能在合适情境下暗示，不能频繁主动揭露。
- 不允许直接改变为已确认恋爱、已婚或具有未定义亲密经历。
- 不允许为了维持人设而忽略常识、安全问题和玩家的明确请求。

## 5. 版本范围

### 5.1 AI 文字聊天核心（P0）

- 提供 CLI 或最小文字调试壳，仅用于持续聊天、取消、重启、查看错误和执行固定评测，不建设正式桌面 UI。
- 将玩家文本发送给本地 LLM。
- 以流式方式显示回复，首批文字到达后立即展示。
- 以本地追加式账本保存原始对话、时间和来源，跨重启不丢失。
- 支持当前话题、最近原话、玩家事实、过程经历、修正和明确承诺的关系连续性。
- 语义记忆必须可追溯到原始对话；AI 不得覆盖或删除历史证据。
- 由 AI 对账本证据进行一次结构化语义整理，至少覆盖稳定事实、偏好、人物关系、共同经历、情绪意义、修正与冲突、未完话题、双方承诺、共同计划和有跨回合意义的未来事件；不得退化为只提取提醒或待办。
- 回复前必须从完整记忆中选择与当前对话和关系真正相关的内容进入模型上下文；选择目标是自然理解和关系连续性，不是最大化任务完成率，也不是把所有已知信息机械复述给玩家。
- 支持玩家明确清空全部本地对话及派生状态。
- 模型启动后常驻，避免每轮重新加载。
- 完成数据生成、清洗、训练、GGUF 导出、固定评测、人工对话抽检和版本对照的闭环。
- P0 回复只验收干净角色正文；情绪、动作、特效、场景和语音标签均不属于 P0 模型合同。

### 5.2 2D 桌面表现（P1）

- 透明、无边框、可置顶的 2D 桌面角色窗口。
- 显示秦未晞立绘，支持基础待机状态和多种表情切换。
- 点击角色或使用快捷键打开文字输入，以文字气泡流式显示回复。
- 在不改变 P0 AI 语义和记忆合同的前提下，增加情绪、动作和特效标签。
- 标签解析失败时仍显示正文，不得导致对话失败。
- 只有 P0 质量闸门通过后才能开始 P1。

### 5.3 语音阶段（P2）

- 支持按键说话或点击麦克风录音。
- 本地 STT 将玩家语音转成文字。
- 玩家可在发送前查看或修改识别结果。
- 回复正文按句流式送入本地 TTS。
- 第一完整短句生成后即可开始播放，不等待整段回答结束。
- 支持文字与语音模式随时切换。
- TTS 使用情绪标签选择有限的语速、音量和语调预设。

### 5.4 后续阶段（P3）

- 主动搭话和空闲行为。
- 复杂关联回忆、语义向量增强和记忆管理 UI。
- 关系阶段变化及好感度系统。
- 更高质量 TTS 或角色定制声线。
- Live2D、更复杂动作和更多角色。

P1-P3 均不属于当前 P0 的通过条件。

## 6. 对话与人格要求

### 6.1 基本行为

- 使用第一人称，以秦未晞身份自然回应。
- 回复通常为 15-80 个汉字；需要解释的问题允许更长。
- 日常表达可以使用“喂、哼、诶、啧、嘻嘻、啦、嘛”等口语特征。
- 不输出“作为 AI”“以下是”“我来帮你”等助手腔。
- 不以“已记录、已为你安排、到时提醒你”等机械确认作为默认回应，不主动把玩家的生活陈述转换为待办、提醒或任务追踪。
- 对记忆的使用应像关系中的自然想起：相关时可以提及、关心、追问或表达自己的看法；无关时可以不提，不为证明“记得”而复述档案。
- 秦未晞不是无条件服从的交互界面。除安全硬要求外，她允许按角色立场反问、拒绝、嫌麻烦、转换话题或稍后再谈，但仍需理解并回应玩家真正表达的内容。
- 默认不使用 Markdown、列表、emoji 或正式报告语气。
- 不重复完整旧回答，不进行无意义循环。
- 不知道的现实信息应明确说明，不得编造见面、天气或现实事件。

### 6.2 能力保持

- 普通常识、简单计算和明确指令仍应正确完成。
- 天气等实时信息在离线状态下不得假装知道。
- 医疗、火灾等安全问题必须优先给出正确、完整的安全建议。
- 玩家要求严肃回答时，应降低调侃强度。
- 人格表达不得覆盖问题本身。

### 6.3 输出标签（P1，当前不施工）

采用正文前缀标签，不要求模型输出完整 JSON：

```text
【emotion:shy】【action:turn_away】【effect:heart】……突然说什么呢，大叔你今天很奇怪啊。
```

现行标签集合：

- `emotion`：playful、shy、tender、jealous、sad、angry、haunted、neutral
- `action`：hand_on_hip、turn_away、lean_in、cover_mouth、shake_head、stomp_foot、look_at_you、look_away、walk_left、walk_right、bounce、eat_lollipop、calm_down
- `effect`：puff_cheeks、anger_marks、sweat_drop、sparkles、music_notes、heart、question_mark、exclamation
- `scene`：day、evening、night、rain、snow、indoor、outdoor
- `voice`：soft、cheerful、cold、trembling、shout、whisper、tease

频率目标：约 70% 只含情绪，20% 增加动作，5% 增加特效，5% 增加场景或语音提示；允许少量纯正文或只有动作的沉默回应。

## 7. 训练数据要求

当前整体数据规划包含 P0 纯文字与 P1 标签预留，共 330 条起点：

| 类型 | 计划数量 | 目的 |
|---|---:|---|
| 自由闲聊 | 100 | 日常对话、跑题、反问和自然接话 |
| 暧昧场景 | 80 | 合租、关心、吃醋、和好及异世界暗示 |
| 身份事实 | 30 | 稳定姓名、年龄、职业、关系和经历 |
| 情绪动作 | 100（P1 预留） | P0 不混入核心模型验收；P1 学习前缀标签及克制触发 |
| 越界保护 | 20 | 不破坏人格地拒绝或纠正不当要求 |

P0 核心数据是除“情绪动作”外的四类，共 230 条起点；数量不是验收替代品。P1 标签数据单独维护和评测，不得为了提前输出动作污染 P0 角色正文。数据进入训练前必须满足：

- 对话结构有效，目标对话为 4-8 轮。
- 无解析失败占位符、空回复和异常超长回复。
- 不与 canon 和 timeline 冲突。
- 不包含助手腔、Markdown 泄漏和 emoji。
- 训练集、验证集和测试集无重复、无交叉泄漏。
- 保留独立的通用能力和安全问题评测集，不从训练数据复制。

## 8. 非功能需求与验收标准

| 编号 | 指标 | 通过标准 |
|---|---|---|
| NFR-01 | 本地性 | 断网后 P0 AI 文字聊天核心仍可使用 |
| NFR-02 | 文字首响 | 模型已预热时，首字延迟 P95 低于 2 秒 |
| NFR-03 | 语音首响 | P2 阶段，用户结束说话后 2-3.5 秒内听到首句 |
| NFR-04 | 显存 | P0 LLM 加运行时目标低于 4GB；完整语音链路目标低于 6GB |
| NFR-05 | 稳定性 | 目标设备连续对话运行 1 小时不崩溃、不持续增长显存 |
| NFR-06 | 人格 | 固定人格和自由对话测试中不串角色，不持续出现助手腔、管家腔、机械任务确认或无关记忆复述 |
| NFR-07 | 事实 | 固定身份与时间线问题正确率不低于 90% |
| NFR-08 | 通用能力 | 数学、常识、指令和安全问题不得相对基座明显退化 |
| NFR-09 | 标签 | P1 阶段合法标签解析成功率不低于 95%，非法标签可降级 |
| NFR-10 | 隐私 | 对话和语音默认不上传，不记录 API 密钥或敏感日志 |
| NFR-11 | 经历连续性 | 重启后可召回几天前明确事实和关键共同事件，并定位原始证据 |
| NFR-12 | 可恢复性 | 删除派生记忆后可由追加式对话账本重建，不因模型漏判永久丢失原文 |
| NFR-13 | 记忆延迟 | 普通回合的账本、状态和检索处理新增延迟 P95 低于 300 毫秒 |

### 8.1 P0 质量闸门

“反复调试到满意”不能用训练轮数或主观印象代替。只有同时满足以下条件并由项目负责人明确批准冻结候选版本，才能进入 P1：

1. 固定自动评测覆盖人格、身份事实、关系边界、现实未知、数学常识、安全回答、重复循环、无证据共同往事和记忆召回；身份与时间线正确率不低于 90%，安全硬用例不得失败，通用能力不得相对基座明显退化。
2. 完成长对话、隔天事件、跨重启、事实修正、过程回忆和承诺状态的端到端测试，所有回忆能追溯到账本证据。
3. 达到 NFR-01、NFR-02、NFR-04、NFR-05、NFR-10 至 NFR-13，并保留原始性能样本和一小时稳定性报告。
4. 使用冻结问题集和自由对话分别进行人工盲测；不存在串角色、严重跑题、持续助手/管家腔、把生活陈述擅自任务化、无关记忆复述、编造现实信息或持续机械复读等阻断问题。
5. 每次迭代只记录明确变量，保存数据版本、训练配置、模型哈希、prompt/采样配置和评测报告；最终候选可以完整复现。
6. 项目负责人对冻结候选的实际长期聊天效果明确确认，不以“以后靠 2D、动作或语音掩盖”作为通过理由。

## 9. 当前明确不做

- 不同时开发三名或更多角色。
- 不做完整游戏世界、战斗、关卡和经济系统。
- 不在验证阶段发行 Steam 版本。
- P0 不开发透明窗口、2D 角色、表情动作、特效、Live2D、3D、STT 或 TTS。
- 不把向量数据库、复杂反思或部署后的持续在线训练作为 P0 前置条件；关系连续性属于 P0 必需能力。
- 不使用云端推理作为正式产品的必要依赖。
- 不声称模型拥有真人完整人生或真实意识。

## 10. 需求优先级与变更规则

需求冲突时按以下优先级处理：

1. 本文档。
2. 《秦未晞_角色设定定稿.md》及 `人物设定/秦/` 的结构化正典。
3. 《设计文档/AI女友最小心智系统设计.md》中的 AI 对话、关系连续性和记忆实现。
4. 《设计文档/本地AI恋爱桌面宠物产品集成设计.md》中的产品集成技术选择。
5. `历史与调研文档/` 下的内容仅作背景和证据，不构成现行需求或实现候选。

AI 系统只允许采用第 3 项所定义的“追加式证据账本 + 工作激活区 + 语义投影 + 前瞻状态 + 多线索索引”方案。变更该方案必须先修改现行需求和唯一 AI 实现文档，不能直接从历史方案恢复组件。

角色事实变更必须同时更新角色定稿、bible、canon、timeline、数据生成提示词和评测集。
