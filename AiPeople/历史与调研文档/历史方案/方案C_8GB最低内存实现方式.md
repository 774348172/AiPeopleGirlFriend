# 方案 C 重新分析：8GB 最低内存下的实现方式

> 性质：分析文档（非代码）。在"8GB 是最低地板"约束下，重新判定方案 C（记忆层）该怎么实现。
> 日期：2026-08-01。前置：见《玩家显卡与模型负载分析》《权重NPC与快轨NPC对比分析》。
> 背景：原方案 C（《中间路线实现方案》§C1-C6）被指繁琐、且低估模型能力。本文件按 8GB 地板重新裁剪。

---

## 0. 8GB 地板改变了什么

8GB 最低地板（如 3070 8GB / 3060 8GB，与 3A 游戏共享）的实际工况：

- **模型**：Qwen3-1.7B 4-bit（4B 装不下或挤死游戏）→ **模型小、判断/反思能力弱**。
- **上下文**：1-2k（游戏抢显存，KV 紧）→ **能喂给模型的记忆窗口极小**。
- **算力**：每次 LLM 调用都和游戏渲染 + NPC 生成抢 GPU → **每个 LLM 调用都贵**。

这三个约束**根本性地重塑 C**：C 的设计目标从"模拟人脑整理机制"变成"**用最少的 LLM 调用，保证喂给小模型的记忆是干净、不矛盾、装得下的**"。理由：小模型 + 短上下文 + 贵算力下，"精巧的记忆整理流程"既跑不起、模型也用不动；而"数据卫生"反而更关键（小模型自己处理脏数据的能力更弱）。

**核心原则（8GB 地板）**：C = **数据卫生 + 零/低 LLM 的便宜评分 + 模型在生成时做判断**；不是"用工程模拟成长"。

---

## 1. 按"是否消耗 LLM 调用"重新切分 C 模块

这是 8GB 地板下看 C 的正确视角——**LLM 调用是最贵的资源**。

| 模块 | 原 C 设计 | LLM 成本 | 8GB 地板处置 |
|---|---|---|---|
| C1 结构化条目 | 全字段 | 零 | **保留**（零成本） |
| C2 写入-抽取 | 每轮 LLM 抽取 | 中（每轮 1 次） | **降级**：规则抽取优先，LLM 仅兜底 |
| C2 写入-DECIDE 去重 | LLM 判 ADD/UPDATE | 高（每条多次） | **砍掉/规则化** |
| C3 检索-三分量 | recency+importance+relevance | importance 需 LLM 评分 | **改二分量**：recency+relevance，importance 用启发式不调 LLM |
| C3 失效过滤+预算 | valid 过滤 + 预算 | 零 | **保留** |
| C4 遗忘 | 评分衰减 | 零 | **保留** |
| C5 反思 | 3 问→检索→5 洞察流水线 | 高（多次 LLM） | **降级**：周期性单次摘要，罕见，仅前台，可选 |
| C6 上下文拼装 | 预算分账 | 零 | **保留**，预算更激进 |

**规律**：零 LLM 的全保留；低 LLM 的节俭保留；高 LLM 的全砍或降级。**砍掉的全是"用 LLM 替模型做判断"的部分——这些在小模型上本来收益也低。**

## 2. 8GB 地板版 C 的逐模块设计

### C1' 结构：保留，importance 用启发式不调 LLM
- 全字段保留（id/timestamp/type/content/embedding/valence/last_accessed/valid/superseded_by）。
- **importance 不用 LLM 评**，用规则：涉及玩家的 +5、涉及情绪/冲突的 +3、纯环境观察 +1。零 LLM 成本。小模型评 importance 本来也不可信。

### C2' 写入：热路径规则抽取 + 冷路径 latest-wins（无 LLM DECIDE）
- **热路径**：本轮对话用规则/关键词抽 1-3 条候选（"玩家叫…""我答应…"这类模式匹配），append。**不调 LLM**；抽不到就跳过（宁缺勿滥）。
- **冷路径（罕见）**：不跑 mem0 式 LLM DECIDE。改 **latest-wins 规则**：新事实与旧事实同 `concept` 时，标旧 valid=false、superseded_by 指向新。**零 LLM**。
- 代价：偶尔有冗余重复条目（没检索到旧的）。**冗余可容忍，矛盾不可容忍**——latest-wins + valid 过滤保证矛盾不出。

### C3' 检索：二分量 + 严格小预算
- **score = recency + relevance**（α=1，归一化）。砍 importance（已是启发式存着的，可选加权，但不为它调 LLM）。recency 零成本（时间戳），relevance 零成本（余弦）。
- **valid-only 过滤**：只取未失效的，避免喂矛盾。
- **严格小预算**：8GB 地板上下文 1-2k，记忆预算 ~300-500 token（3-5 条）。**少而精**——小模型本就消化不了太多上下文。

### C4' 遗忘：评分衰减（零 LLM）
- 低分（旧+琐碎）记忆 recency 衰减趋零，自然沉底不检索。
- valid=false 的不检索（但存储在，剧情回看可复活）。
- 不硬删。**零 LLM**。

### C5' 反思：降级为"周期性单次摘要"（可选）
- **砍掉** 3 问→5 洞察流水线（多次 LLM，1.7B 也产不出高质量洞察，得不偿失）。
- 改：每"游戏天"或每 N 轮，**对前台 NPC 做一次单调用摘要**——"把最近这些记忆用一两句话总结成一条高 importance 记忆"。1 次 LLM，罕见，仅前台，可选。
- 这是 C5 在 8GB 地板的下限形态：成本最低的"压缩"。质量浅，但比塞满原始流水账强。

### C6' 上下文：激进压缩 + 固定锚
- 1-2k 上下文分账：人格锚 ~150 + 检索记忆 ~350 + 近期对话 ~800-1000 + 摘要 ~150。
- 超预算优先丢低分记忆和旧对话原文（旧对话靠 C5' 摘要替代）。
- hero 人格在权重不漂；锚只管"我是谁、今天哪天"，固定占位不被压。

## 3. 8GB 地板版 C 的运行节奏（LLM 调用记账）

| 路径 | 频率 | LLM 调用 | 内容 |
|---|---|---|---|
| 热路径 | 每轮 | **0-1**（规则抽不到才 1 次轻调用，或直接 0） | 规则抽取+append、二分量检索、生成 |
| 冷路径 | 稀有 | **0** | latest-wins 标失效、评分衰减 |
| 摘要 | 每 N 轮/前台 | **1**（可选） | 单次总结近记 |

**对比原 C**：原 C 热路径每轮 1+ 次、冷路径多次 DECIDE、反思多次 → 8GB 地板上算力顶不住。新版每轮 **0-1 次 LLM**，重活儿几乎全零 LLM。

---

## 4. 与"舒适档"（12GB / 4B）的关系

C 设计为**两档配置**：

| 模块 | 8GB 地板（1.7B） | 舒适档（12GB/4B） |
|---|---|---|
| importance | 启发式（0 LLM） | 可选偶尔 LLM 评 |
| DECIDE | latest-wins 规则 | 可选低频 LLM 去重 |
| 检索 | 二分量 | 三分量 |
| 反思 | 单次摘要（可选） | 可选稍复杂反思 |
| 上下文预算 | ~300 token | ~800 token |

**原则**：8GB 地板配置是**保底下限**；玩家卡更好时按档位解锁更多 LLM 辅助，但**不默认全开**——是否启用仍看 ablation 实测收益（见 §5）。

## 5. 有效性边界（诚实）

8GB 地板版 C 的**有效部分**：
- **数据卫生（存/检/不矛盾/不爆）**——零 LLM、必要、模型再弱也要。这是 C 真正不可砍的核心。
- **便宜评分（二分量）+ 启发式 importance + latest-wins**——零 LLM、廉价、能把脏数据管到"可检索、不矛盾"。有效。

8GB 地板版 C 的**天花板**（不是"没效果"，是"上不去"）：
- **反思质量封顶**：1.7B 的"总结"很浅，C5' 给不了深度洞察——这是模型小决定的，C 再精巧也突破不了。
- **成长深度有限**：1.7B + 这套 C 能做到"记得、引用、因过往而变、简单总结"；做不到"深层自我演化"。这超出 8GB 地板能力，要更强基座或上云——但你要求不联网 → **接受这个上限**。

**核心判断**：8GB 地板上 C 的价值在"保数据卫生"，不在"模拟成长"。成长主要靠**发版时烘进权重的人格 + 这套卫生的记忆层**，模型在生成时拿干净记忆做即时判断。别指望 1.7B + C 产出 70B 那种深度成长。

## 6. 对原 C 繁琐设计的修正总结

| 原 C | 问题 | 8GB 地板修正 |
|---|---|---|
| 三分量（含 LLM 评 importance） | importance 要 LLM，贵 | 二分量 + 启发式 importance |
| mem0 DECIDE（LLM 去重） | 每条多次 LLM，8GB 顶不住 | latest-wins 规则，零 LLM |
| 反思 3 问 5 洞察流水线 | 多次 LLM + 1.7B 产不出 | 单次摘要，可选 |
| 失效链/superseded_by | 保留（零 LLM，廉价） | 保留 |
| 上下文预算分账 | 8GB 更紧 | 更激进（~300 token 记忆） |

**砍掉的全是"高 LLM 成本 + 小模型收益封顶"的部分；保留的全是"零 LLM + 数据卫生"的部分。**

---

## 7. 一句话

8GB 地板上 C 的正确形态是**"数据卫生 + 零/低 LLM 的便宜评分 + 模型生成时做判断"**：保留结构化存储、二分量检索（recency+relevance）、valid 失效过滤、latest-wins 去重、评分衰减遗忘、严格小上下文预算——**这些全零 LLM、廉价且必要**；砍掉/降级 importance 的 LLM 评分、mem0 DECIDE、反思流水线——**这些在 1.7B + 贵算力下要么太贵要么收益封顶**。C 的价值回到"保数据卫生"本职，不奢望在 1.7B 上模拟人脑成长——成长主要靠发版烘进权重的人格 + 干净记忆层的即时检索。
