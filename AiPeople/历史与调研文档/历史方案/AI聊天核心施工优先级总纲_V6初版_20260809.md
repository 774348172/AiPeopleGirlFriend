# 《猫咪女友》V6 实时世界持续心智系统施工总纲

> 文档状态：当前唯一施工排序  
> 生效日期：2026-08-09  
> 上游需求：`需求文档/项目框架需求.md`  
> 上游设计：`设计文档/AI设计/当前权威设计/AI女友最小心智系统设计.md`  
> 当前角色：白未晞（`character_id=baiweixi`）

## 1. 施工目标

将现有“固定秦未晞 Prompt + conversation 账本 + 全局长期记忆选择器”升级为：

```text
同一 SaveRuntime
+ 连续 GameClock
+ LiveWorldState
+ 程序权威 ProtagonistLiveState
+ WorldStateProjection / getLatestSnapshot()
+ HeroineRuntime[character_id]
+ HeroineMemoryRepository[character_id]
+ 模型驱动回合心智推进
+ 回答后与五分钟模型整理
+ 连续性审查
+ 状态与回复原子提交
```

现有追加式账本、事务、epoch、记忆表示、证据校验、Embedding、TopK、Reranker、后台任务和 llama.cpp 适配可以复用，但必须服从 V6 的单一世界、程序权威事实、实时状态和女主独立记忆合同。

## 2. 施工原则

1. 先完成身份和角色包中立，再进入实时世界施工。
2. 实时程序事实与模型心智状态分层，不能由模型修改男主位置和时间。
3. 玩家聊天文字唯一表示男主对白，不建设输入分类和程序命令路由。
4. 先用 FakeModel 跑通最新快照和原子回合，再接真实模型。
5. 每位女主角从第一天使用独立 Memory Repository，不做全局搜索后过滤。
6. 五分钟整理以模型为主，程序只实现极少量硬不变量。
7. 不原地修改旧 MEM/RECALL/CHAT 冻结哈希；V6 建立新的 WMR 冻结链。
8. 未通过当前阶段闸门，不进入依赖它的下一阶段。

## 5. WMR-01：身份、存档与角色包

### 5.1 目标

让 Runtime 知道当前存档、世界、唯一主角、激活女主角和角色包来源。

### 5.2 合同

- `SaveIdentity`
- `CharacterPackageManifest`
- `RuntimeSessionIdentity`
- `active_character_id`
- 角色包版本和正典哈希

### 5.3 Runtime 修改

- `TurnRequest` 携带 `save_id` 和会话身份。
- `RuntimeConfig` 增加世界、主角和角色包注册表。
- 替换 `QIN_WEIXI_REPLY_SYSTEM`。
- Prompt 由 `WorldCanon + ProtagonistCanon + CharacterPackage` 动态装配。
- 真实模型 manifest 从秦未晞固定角色改为 `character_id` 绑定。
- 缺失白未晞角色包时明确失败，不回退旧人格或通用助手。

### 5.4 闸门

- FakeModel 白未晞最小对话 smoke 通过。
- Prompt 不包含秦未晞、B哥、浩然和旧世界设定。
- 错误世界、主角、角色 ID 和包版本明确失败。
- 合成第二角色包可注册但 P0 不激活。

## 6. WMR-02：实时世界与连续时钟

### 6.1 目标

建立程序权威实时事实层：

- `LiveWorldState`
- `GameClockAnchor`
- `ProtagonistLiveState`
- `ActiveSceneState`
- 程序事件流

### 6.2 不变量

- 程序运行时 `GameClock` 连续变化。
- 聊天不推动、暂停或重置时间。
- 男主位置、动作、持有物和程序身体状态由程序最终控制。
- A 点到 B 点等变化按帧或事件立即更新。
- 模型没有 `game_clock_patch` 和 `protagonist_patch` 权限。

### 6.3 测试

- 无聊天运行十分钟，读取时间正确前进。
- 连续聊天不按轮数增加固定时间。
- 男主到达 B 点后状态立即可读。
- 应用关闭和重启按 P0 暂停策略恢复。
- 重复事件和版本冲突不会产生两份位置事实。

## 7. WMR-03：投影、快照与 FakeModel 原子回合

### 7.1 目标

建立：

- `WorldStateProjection`
- `ModelReadableWorldState`
- `WorldStateProvider.getLatestSnapshot()`
- `TurnWorldSnapshot`
- 前台回复事务锁
- 原子回复缓冲和提交

### 7.2 快照合同

- 每轮回复前只 GET 一次最新状态。
- 快照包含当前游戏时间、场景、男主状态和激活女主状态。
- 回复期间实时世界继续运行。
- 当前回复始终使用同一 `snapshot_id`。
- 下一轮读取新版本。

### 7.3 FakeModel 轨迹

- 男主正在吃面，回复不能说男主正在画画。
- 男主从客厅进入厨房，下一轮女主读取厨房位置。
- 生成期间男主再次移动，当前回复保持旧快照一致，下一轮读取新位置。
- 持久化失败时不显示未提交回复。

### 7.4 闸门

FakeModel 可以完成：最新快照读取、女主状态 Patch、硬校验、回复缓冲、原子提交和下一版本恢复。

## 8. WMR-04：女主独立记忆 Repository

### 8.1 目标

建立：

- `HeroineMemoryRepository[character_id]`
- 独立事件投影
- 独立语义记忆存储
- 独立向量索引
- 独立工作激活区
- 独立自我时间线

### 8.2 迁移

- 现有 conversation-scoped memory 增加 `save_id` 和 `owner_character_id`。
- 删除普通召回中的全局跨角色候选宇宙。
- 召回入口必须先打开当前角色 Repository，再执行向量召回和重排。
- `WorldEventLedger` 只作为客观证据，不允许直接作为女主记忆查询。

### 8.3 合成第二角色测试

- 白未晞私密事件不进入第二角色 Repository。
- 第二角色私密事件不进入白未晞 Repository。
- 同一共同事件可以分别形成两份角色语义记忆。
- 角色切换不串 Prompt、记忆、索引和时间线。

## 9. WMR-05：真实回合心智与最终回复

### 9.1 模式

- `TURN_MIND_ADVANCE`
- `WORLD_CONTINUITY_REVIEW`
- `GAME_REPLY`

### 9.2 合同

- `TURN_MIND_ADVANCE` 只修改激活女主角心智。
- 男主程序状态、游戏时间和客观场景只读。
- 默认 `keep`，`update` 必须提供依据。
- Critic 先审查，再从批准状态生成回复。
- 最终回复不能出现现实玩家、第二世界和设备系统时间。

### 9.3 闸门

- 白未晞能自然理解男主对白并保持当前活动。
- 回复遵守最新男主状态和游戏时间。
- 模型不能通过对白修改男主客观事实。
- 连续性审查能阻止活动、身体、关系和知识无依据跳变。

## 10. WMR-06：回答后与五分钟模型整理

### 10.1 模式

- `POST_REPLY_WORLD_MIND_RECONCILE`
- `FIVE_MINUTE_WORLD_MIND_RECONCILE`

### 10.2 WorldUpdateCoordinator

- 实时世界不因模型任务暂停。
- 回答期间到期的心智整理任务排队。
- 回答结束后重新 GET 最新世界状态。
- 多个积压五分钟任务合并。
- 下一轮前完成标记为 required 的整理。

### 10.3 程序硬规则边界

程序只校验：

- 身份和角色权限。
- 模型不可修改男主状态和时间。
- 父版本、Schema、引用 ID 和幂等。
- 原子事务和崩溃恢复。

程序不实现吃饭时长、疲劳变化、情绪变化、关系好感和记忆重要性的生活规则。

### 10.4 闸门

- 无事件五分钟允许模型 `keep`。
- 有事件时模型能自然更新活动、身体、情绪、注意力和意图。
- 模型任务失败不停止 `GameClock` 和实时世界。
- 回答后整理不推动时间，不重写刚显示回复。

## 11. WMR-07：长期轨迹、自我时间线与恢复

### 11.1 轨迹

- 50～100 轮自由对话与实时世界混合轨迹。
- 男主多次移动、活动切换和场景变化。
- 女主持续吃饭、休息、受伤恢复、情绪和关系变化。
- 五分钟整理、回答后整理和前台回复交错。
- 崩溃、重试、版本冲突和跨重启恢复。

### 11.2 闸门

- 当前状态不依赖完整聊天记录常驻上下文。
- 世界实时变化和回复快照不存在撕裂。
- 女主长期状态自然变化但不漂移。
- 独立记忆不串角色。
- 事件和投影可重建。

## 12. WMR-08：真实工件、性能和冻结

### 12.1 目标

- 冻结真实主模型模式与 Schema。
- 完成 Embedding、Reranker 和独立 Repository 性能验证。
- 完成前台回复、后台整理和实时世界并发测量。
- 完成显存、延迟、一小时稳定性、取消和恢复测试。
- 输出 P0 冻结 manifest 与验收报告。

### 12.2 关键测量

- `getLatestSnapshot()` 延迟。
- 前台首字和完整回复延迟。
- 五分钟模型整理平均和 P95 用时。
- 后台整理对前台回复的干扰。
- 独立记忆召回 P95。
- 一小时内显存峰值和失败恢复。

## 13. 旧实现复用边界

### 13.1 可直接复用

- 追加式事件账本。
- SQLite 事务、幂等和崩溃恢复。
- 记忆证据校验和语义物化基础。
- Embedding、TopK、Reranker 和真实模型适配基础。

### 13.2 改造后复用

- conversation-scoped memory 改成 save + heroine Repository。
- 全局选择器改成 Repository 内召回。
- 后台调度改成前台优先、任务合并和下一轮屏障。
- Prompt 和真实模型 manifest 改为角色包动态绑定。

### 13.3 不得继续使用

- 秦未晞固定 Prompt、路径、角色名和模型角色。
- 角色聊天输入分类、OOC 和现实安全分流主干。
- 双时钟和聊天轮数时间策略。
- 模型生成男主客观状态 Patch。
- 全局跨角色记忆先搜索后过滤。
- 大量程序生活规则。

## 14. P0 完成定义

P0 只有同时满足以下条件才完成：

1. 白未晞角色包动态加载且无秦未晞回退。
2. 实时世界、连续 GameClock 和程序男主状态稳定运行。
3. 每轮回复读取最新完整世界快照。
4. 白未晞只访问自己的记忆 Repository。
5. 回合状态推进、Critic、最终回复和原子提交通过。
6. 回答后和五分钟模型整理通过长轨迹验收。
7. 实时世界、前台回复和后台任务并发无状态撕裂。
8. 跨重启恢复最后完整状态。
9. 合成第二角色包验证 Prompt、记忆和状态隔离。
10. 目标硬件性能和稳定性通过冻结标准。
