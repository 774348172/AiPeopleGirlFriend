## 1. 需求补充一：文字转语音 + 实时对话

用户需求：不只是文字聊天，要能**实时语音对话**——玩家可以说话（语音输入），未晞也能用语音回复。要有"在和真人打电话"的感觉。

### 1.1 技术链路（实时语音对话）

```
玩家说话
  → 麦克风录音
  → STT（语音转文字）—— 本地 Whisper 或系统 STT
  → 文字送 LLM
  → LLM 生成回复 + 情绪标签
  → TTS（文字转语音）—— 本地 TTS，用未晞的声线
  → 扬声器播放
  → 同时触发动作/表情/特效

全链路延迟目标：<3s（说话到听到回复）
```

### 1.2 STT 方案（玩家说话 → 文字）

| 方案 | 本地? | 显存 | 中文 | 延迟 | 推荐 |
|---|---|---|---|---|---|
| **Whisper.cpp（小模型）** | ✅ 本地 | ~0.3-0.5GB | ✅ 强 | 0.5-1s | ✅ 首选 |
| Whisper.cpp（tiny/base） | ✅ 本地 | ~0.1-0.2GB | ⚠️ 小模型中文一般 | 0.2-0.5s | 备选（速度优先） |
| Windows SAPI | ✅ 本地 | 0 | ✅ | 快 | 可选（质量一般） |
| 云端 STT（百度/讯飞） | ❌ 联网 | 0 | ✅ 强 | 0.3s | ❌ 用户要求不联网 |

**推荐 Whisper.cpp（small 模型）**：
- 本地、不联网、中文质量够用
- small 模型 ~480MB、显存 ~0.3-0.5GB
- 延迟 0.5-1s（取决于句子长度）
- 和 Ollama/llama.cpp 同生态（C++ 推理）

### 1.3 TTS 方案（文字 → 未晞的语音）

| 方案 | 本地? | 显存 | 音色可定制 | 延迟 | 质量 | 推荐 |
|---|---|---|---|---|---|---|
| **Piper TTS** | ✅ 本地 | ~0.3GB | ⚠️ 有限（预置模型） | 0.1-0.3s | 中 | ✅ 首选（轻快） |
| **GPT-SoVITS** | ✅ 本地 | ~1-2GB | ✅ 可定制音色 | 0.5-1s | 高 | ⚠️ 8GB 偏紧 |
| **edge-tts（微软）** | ❌ 需联网 | 0 | ✅ 多音色 | 0.5s | 高 | ❌ 联网 |
| **Coqui TTS** | ✅ 本地 | ~0.5GB | ✅ 可微调 | 0.3-0.5s | 中高 | 可选 |
| 预录制切片 | ✅ | 0 | ✅ | 0 | 高 | 补充（常用台词） |

**推荐 Piper TTS（验证期）**：
- 本地、不联网、轻量（~0.3GB 显存）
- 延迟极低（0.1-0.3s）——对实时对话最关键
- 有中文模型
- 音色固定但验证期够用
- 后期可升级 GPT-SoVITS（定制未晞专属声线）

**GPT-SoVITS（后期升级）**：
- 可以用 3-10 秒未晞的参考音频定制音色
- 质量高、情感表达好
- 但显存 1-2GB，8GB 上偏紧（LLM 2.5 + 游戏 1 + STT 0.5 + TTS 1.5 = 5.5GB，还能跑）
- 适合后期 3D 升级时一起换

### 1.4 显存总预算（3060 8GB，实时语音）

| 组件 | 显存 |
|---|---|
| LLM（Qwen3-4B Q4） | 2.5 GB |
| STT（Whisper.cpp small） | 0.5 GB |
| TTS（Piper） | 0.3 GB |
| 桌面宠物 + 2D 立绘 | 0.3 GB |
| 系统/桌面 | 1.5 GB |
| **合计** | **~5.1 GB** |
| **剩余** | **~2.9 GB**（够用） |

**结论：3060 8GB 上实时语音对话可行。** Whisper + Piper 都很轻，加上 LLM 总共 5.1GB，留 2.9GB 给系统。

### 1.5 延迟预算（实时语音对话）

| 环节 | 耗时 | 说明 |
|---|---|---|
| 玩家说完 → STT 转文字 | 0.5-1s | Whisper.cpp small |
| LLM 流式生成首字 | 0.2-0.4s | TTFT |
| LLM 生成 ~50 token | 1-2s | ~25-35 tok/s |
| TTS 合成首句 | 0.1-0.3s | Piper 极快 |
| 表情/动作切换 | <0.01s | 立绘图层切换 |
| **总延迟** | **~2-3.5s** | 说完到听到回复 |

**比真人打电话慢一些**（真人 0.5-1s 响应），但比文字聊天好得多——有"声音对话"的感觉。后期用更快的模型/更小的 Whisper 能再压。

### 1.6 流式语音（边生成边说）

进阶优化：LLM 流式输出文字 → 按句切分 → 每句立刻送 TTS → 边生成边说：

```
LLM 生成: "喂！你是不是又迟到了？我等了你好久了好不好……"
  → 生成到第一个逗号/句号 → 立刻送 TTS
  → TTS 0.2s 出音频 → 播放
  → 同时 LLM 继续生成后半句
  → 生成完 → 送 TTS → 播放

体感延迟: STT(0.8s) + TTFT(0.3s) + TTS首句(0.2s) = ~1.3s 开始听到回复
```

**1.3s 听到首句**——接近真人电话体验。

## 2. 需求补充二：动作/特效/调用系统

用户需求：不只是聊天——AI 要在对话中**主动判断**调用预设的动作、特效、表情、场景变化。有"真人在面前"的感觉，不是一个对话器。

### 2.1 设计思路

LLM 不只输出文字和情绪，还要输出**动作指令**——告诉前端"该做什么"：

```json
{
  "reply": "哼，你又迟到了！",
  "emotion": "playful",
  "actions": [
    {"type": "expression", "value": "hands_on_hips"},
    {"type": "body", "value": "turn_away"},
    {"type": "effect", "value": "puff_cheeks"},
    {"type": "scene", "value": "change_to_evening"}
  ]
}
```

### 2.3 LLM 输出格式（前缀标签法）

训练数据教 LLM 在回复前输出标签：

```
【emotion:playful】【action:hand_on_hip】【effect:puff_cheeks】
喂！你是不是又迟到了？我等了你好久了好不好……哼，算了不跟你吵了，走吧。
```

前端解析逻辑：
1. 正则提取 `【emotion:xxx】` `【action:xxx】` `【effect:xxx】` `【scene:xxx】` `【voice:xxx】`
2. 去掉标签得到正文
3. 正文送 TTS
4. 标签依次触发表情→动作→特效→场景→语音语调
5. 动作/特效可以多个（逗号分隔）：`【action:hand_on_hip,puff_cheeks】`

### 2.4 动作触发的时机

不是每句话都触发所有系统——LLM 自己判断"这句话需要做什么动作"：

| 情况 | LLM 输出 |
|---|---|
| 正常聊天 | 只有 emotion + 正文 |
| 吵架/怼人 | emotion + action(叉腰/转身) + effect(鼓腮/生气符号) |
| 撒娇/暧昧 | emotion + action(靠近/捂嘴) + effect(爱心/闪亮) |
| 场景转换 | emotion + scene(夜晚/下雨) |
| 喊叫 | emotion + voice(shout) + action(跺脚) |
| 沉默/思考 | 只有 action(不看你/看窗外)，正文可以很短或没有 |

### 2.5 "真人感"的关键设计

不是每个标签都可用——LLM 需要学会**克制**，像真人一样不是每句话都手舞足蹈：

| 真人感原则 | 训练数据怎么教 |
|---|---|
| 大部分时候只有表情，不夸张动作 | 70% 的样本只输出 emotion + 正文 |
| 动作只在情绪强烈时出现 | 20% 的样本有 action |
| 特效只在特殊时刻（惊讶/暧昧/暴怒） | 5% 的样本有 effect |
| 场景变化很少 | 5% 的样本有 scene |
| 有时候只有动作没话说 | 少量样本：`【action:turn_away】……`（沉默但转身） |
| 有时候什么标签都没有，就是说话 | 少量纯文字样本 |

**真人感 = 克制 + 不规律 + 有时候什么都不做。** 越不像预设动画的越像真人。

### 2.6 训练数据格式示例

```json
// 正常聊天（只有情绪）
{"from": "human", "value": "你今天吃了吗"},
{"from": "gpt", "value": "【emotion:playful】吃了吃了，你又不是我妈，怎么比我亲妈还操心？"}

// 吵架（情绪+动作+特效）
{"from": "human", "value": "我迟到了五分钟而已"},
{"from": "gpt", "value": "【emotion:angry_pout】【action:hand_on_hip】【effect:puff_cheeks】五分钟？！你知道五分钟能发生多少事吗？万一我……算了，不跟你说了。"}

// 暧昧（情绪+动作+特效）
{"from": "human", "value": "你今天……挺好看的"},
{"from": "gpt", "value": "【emotion:shy】【action:turn_away】【effect:heart】……突然说什么呢，你又犯傻了吧。才、才没有开心呢。"}

// 沉默（只有动作）
{"from": "human", "value": "你是不是生气了"},
{"from": "gpt", "value": "【action:look_away】……没有。"}

// 场景变化
{"from": "human", "value": "天都黑了"},
{"from": "gpt", "value": "【emotion:tender】【scene:night】嗯……天黑了啊。那，你今天不走了吧？……我什么都没说！"}
```

### 2.7 前端预设接口规范

前端（用户自己的游戏引擎）需要实现以下接口供 LLM 标签调用：

```python
# 前端需要实现的接口
def set_expression(expr: str):    # smile/blush/pout/...
def play_action(action: str):     # hand_on_hip/turn_away/...
def play_effect(effect: str):     # puff_cheeks/heart/sparkles/...
def change_scene(scene: str):     # day/night/rain/...
def set_voice_tone(tone: str):    # soft/cheerful/cold/...

# LLM 返回解析后，前端按顺序调用
response = call_llm(user_input)
tags, reply = parse_tags(response)
for tag in tags:
    if tag.type == "expression": set_expression(tag.value)
    elif tag.type == "action": play_action(tag.value)
    elif tag.type == "effect": play_effect(tag.value)
    elif tag.type == "scene": change_scene(tag.value)
    elif tag.type == "voice": set_voice_tone(tag.value)
display_text(reply)  # 显示文字
play_tts(reply, voice_tone)  # 播放语音
```

## 3. 更新后的完整链路

```
玩家说话（语音）
  → 麦克风 → Whisper.cpp STT（0.5-1s）
  → 文字送 Ollama LLM
  → LLM 流式生成：【标签们】+ 正文（0.3s TTFT + 1-2s 生成）
  → 解析标签 → 触发表情/动作/特效/场景/语音语调（<0.01s）
  → 正文按句切分 → 送 Piper TTS（0.1-0.3s/句）
  → 扬声器播放 + 立绘切换 + 特效触发
  → 体感首句延迟 ~1.3-2s

文字模式（不用语音）：
  → 玩家打字 → Ollama LLM → 流式输出文字气泡 + 立绘切换
  → 延迟 ~0.5-2s
```
