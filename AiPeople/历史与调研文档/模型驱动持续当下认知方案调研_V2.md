# 模型驱动持续当下认知方案调研 V2

> 状态：研究提案 V2，非权威设计，不得直接施工；已由《模型驱动持续当下认知方案调研 V3：自知数字人物》扩展取代  
> 版本：V2  
> 日期：2026-08-08  
> 取代关系：细化并取代《模型驱动持续当下认知方案调研》；其状态变化权力和连续性设计继续被 V3 继承，最新研究方向以 V3 为准。  
> 研究目标：主要依靠模型维护秦未晞连续存在的当前身体、心理和情境状态，同时只让程序承担感知、持久化、安全和事务职责，避免扩张为无穷的生活规则库。

## 1. V2 结论

V2 将状态变化中的三种权力彻底分开：

```text
MindTransition 主模型
决定秦未晞如何理解新情况、是否改变状态、改变成什么
                    ↓
ContinuityCritic 连续性模型
只判断候选变化是否前后连贯，不替秦未晞选择生活行为
                    ↓
RelationshipRuntime
只执行保存、拒绝、重试和恢复，不解释人物生活
```

核心原则是：

> 主模型拥有状态变化的决定权，连续性模型只有否决明显不连续候选的权力，程序只有事务提交权。

因此系统不会为“吃饭多久”“弹琴时能否聊天”“一句话应该生气多少”持续增加确定性规则。人物状态由模型根据上一刻的自己、新观察、时间、人格、意图和相关经历自然推进。

## 2. 需要解决的根问题

普通角色聊天近似执行：

```text
persona + history + selected_memories + user_message -> reply
```

即使上下文中出现过“我正在吃饭”，模型下一轮仍可能把它当作普通文本，而不是当前仍在持续的现实。因此它可能在若干轮后无过渡地声称自己正在弹琴。

V2 将模型改造成递归状态转换器：

```text
LivingMind_t
    + PerceptionPacket_t
    + SelectedMemoryFrame_t
        ↓
LivingMind_t+1
    + TransitionBasis_t
    + Reply_t
```

`LivingMind_t+1` 会作为下一轮固定输入继续传递，不依赖长期记忆召回，不因为当前话题改变而消失。

## 3. 关键对象

### 3.1 LivingMind：上一刻仍然存在的自己

`LivingMind` 是由模型维护的一段短自然语言内部状态。它描述秦未晞此刻认为自己正在经历什么，而不是一张由开发者枚举的状态表。

示例：

```text
我还坐在餐桌前吃面，已经吃了一半。今天整体心情不错，
注意力在饭和浩然的对话之间来回。他刚才没有说什么让我不舒服的话，
我暂时没有离开餐桌的打算。
```

它允许表达：

- 同时存在的活动、感受和注意力。
- 混合、隐瞒或尚未说出口的情绪。
- 当前倾向、犹豫和未形成行动的想法。
- 对世界事实的知道、不知道、猜测和误解。
- 状态仍在持续的原因或可能结束的条件。

它不要求固定列出地点、姿势、情绪数值、活动枚举或兼容矩阵。训练目标要求模型只保留当前真正活跃、会影响后续理解和回复的内容。

### 3.2 PerceptionPacket：模型这一刻实际看见的东西

程序只提供模型无法自行获得的观察，不解释这些观察意味着什么：

```text
PerceptionPacket
- observation_time
- timezone
- elapsed_since_last_mind
- user_message
- application_events
- trusted_external_observations
- unavailable_observations
```

示例：

```text
观察时间：2026-08-08 20:15:32
时区：Asia/Shanghai
距离上一状态：42秒
玩家消息：你今天开心吗？
外部观察：无
当前无法观察：天气、玩家实际位置
```

程序只声明当前时间和观察来源，不直接下结论：

```text
错误：因为过去42秒，所以秦未晞仍在吃饭。
正确：过去42秒，是否仍在吃饭由主模型理解。
```

### 3.3 SelectedMemoryFrame：当前可能自然想起的过去

长期记忆仍按现行全局选择机制进入本轮。它提供过去经历、计划、关系和修正，但不能替代 `LivingMind`。

两者区别：

```text
LivingMind：我这一刻正在经历什么，每轮固定存在。
SelectedMemoryFrame：过去什么事情与本轮相关，可以为零。
```

“正在吃饭”一旦成为当前状态，就不依赖记忆选择器在后续每轮重新选中。

### 3.4 TransitionBasis：主模型为什么改变或保持状态

主模型每轮生成一段简短的内部依据：

```text
没有发生足以结束吃饭的事件，只过去了不到一分钟。
浩然的问题改变了我的注意力，但没有改变当前活动。
```

或者：

```text
我上一刻已经快吃完，而且一直惦记没弹顺的旋律。
现在过去了十五分钟，吃完并回到钢琴前是前一意图的自然发展。
```

`TransitionBasis` 不展示给玩家，也不是固定原因枚举。它用于让连续性模型检查主模型是否真的基于上一状态和新观察完成了推理，而不是无依据重写人物。

## 4. 谁决定状态是否改变

### 4.1 主模型拥有决定权

`MindTransition` 主模型决定：

- 当前活动是否继续、结束、暂停或转移。
- 新消息是否引起情绪、注意力或态度变化。
- 时间经过后人物自然做了什么。
- 秦未晞是否自主形成新想法或行动倾向。
- 某个变化如何符合秦未晞的人格、欲望和当前处境。
- 回复中应该公开多少内部感受。

例如上一状态是“正在吃面”，二十分钟后主模型可以选择：

```text
我已经吃完，正在慢慢喝水。
```

也可以选择：

```text
我还没吃完，刚才一直和浩然说话，吃得比较慢。
```

两种都可能自然。程序和连续性模型不能替人物规定唯一答案。

### 4.2 连续性模型只有否决权

`ContinuityCritic` 不决定秦未晞应该做什么，只检查候选是否满足一般连续性：

1. 未被新观察影响的上一状态是否得到继承。
2. 明显变化能否从新消息、时间经过、上一意图、身体感受或外部观察得到支持。
3. 变化幅度是否与原因和经过时间相称。
4. 候选状态是否区分事实、感受、猜测、计划和未知。
5. 可见回复是否与候选新状态一致。

它可以说：

```text
从吃面直接跳到弹琴缺少过渡和动机，候选不连续。
```

但不能说：

```text
秦未晞现在应该继续吃面十分钟，然后洗碗。
```

### 4.3 程序只有提交权

`RelationshipRuntime` 不理解吃饭、弹琴和情绪。它只执行：

```text
if critic_verdict == accept:
    原子提交 next_living_mind + reply
else:
    保持 previous_living_mind
    将审查意见交给主模型重试
```

程序不能添加“吃饭最长三十分钟”“弹琴不能聊天”等生活规则。

## 5. 三类状态变化来源

### 5.1 外部观察造成的变化机会

外部系统可以确定提供：

- 当前绝对时间和时区。
- 距离上一轮经过多久。
- 玩家真实发送的消息。
- 应用启动、恢复或交互事件。
- 存在可信来源的天气、日历或设备观察。

这些观察是事实，但它们对秦未晞的影响仍由主模型决定。

例如程序提供“过去了两个小时”，但不直接把人物状态改成“已经吃完”。主模型可能判断她吃完了，也可能结合特殊原因判断她中途离开后刚回来继续吃。

### 5.2 玩家消息引起的内部变化

玩家消息不会通过固定规则映射情绪。主模型结合人格和上一心理状态决定：

- 生气、受伤、调侃或不在意。
- 情绪是否立即改变或延迟显现。
- 是否只改变内心，不在回复中直接承认。
- 是否改变当前活动或只是改变注意力。

连续性模型只检查这种变化是否有语境支持，不规定唯一情绪。

### 5.3 秦未晞自主产生的变化

人物可以在没有玩家指令时自主：

- 完成、放弃或切换当前活动。
- 因疲惫、饥饿、灵感、犹豫或欲望改变行为。
- 对之前的对话产生后续情绪。
- 选择不行动、继续等待或改变下一轮态度。

自主变化应优先来自上一 `LivingMind` 中已经存在的感受、注意力、倾向、未完活动和欲望，而不是每轮随机产生全新的生活剧情。

## 6. 单轮完整流程

### 6.1 输入准备

运行时读取：

```text
1. 固定角色正典与关系边界
2. 最新已提交 LivingMind_t
3. PerceptionPacket_t
4. SelectedMemoryFrame_t
5. 当前玩家输入
```

`LivingMind_t` 和 `PerceptionPacket_t` 是强制上下文，不能因为 token 预算或记忆相关性被删除。

### 6.2 主模型生成候选

研究阶段建议主模型一次产生完整内部封装：

```text
MindCandidate
- parent_state_id
- transition_basis
- next_living_mind
- private_reply_intent
- visible_reply
```

这里固定的是模型调用接口，不是人物生活 schema。`next_living_mind` 仍然是开放自然语言。

### 6.3 连续性审查

连续性模型输入：

```text
previous_living_mind
perception_packet
selected_memories
transition_basis
next_living_mind
visible_reply
```

输出：

```text
ContinuityVerdict
- verdict              accept | reject | uncertain
- continuity_score
- evidence_support_score
- temporal_plausibility_score
- reply_alignment_score
- concise_feedback
```

分数用于训练、分析和阈值实验，不表示程序掌握了人物生活规则。

### 6.4 原子提交

只有候选状态和回复同时通过，才提交：

```text
MindStateAdvanced
- state_id
- previous_state_id
- perception_event_ids
- selected_memory_ids
- transition_basis
- living_mind_text
- model_version
- critic_version

CharacterMessage
- message_id
- mind_state_id
- visible_text
```

必须保证：

- 回复已显示但状态未保存的情况不能发生。
- 状态已保存但回复生成失败的情况不能发生。
- 生成取消、模型崩溃或审查失败时继续沿用上一稳定状态。
- 同一玩家消息的重试不能产生两条并列当前状态。

## 7. “正在吃饭”如何跨多轮保持

### 7.1 第一轮建立状态

玩家问：

```text
你在干嘛？
```

主模型候选：

```text
TransitionBasis：当前处于晚饭时间，上一状态已经准备去弄吃的，
经过时间足以完成准备，因此现在正在吃饭是自然推进。

LivingMind v1：我坐在餐桌前吃面，刚吃了一部分，
可以一边吃一边和浩然说话。

Reply：在吃饭呢，怎么了？
```

审查通过后，`LivingMind v1` 成为唯一当前状态。

### 7.2 第二轮继续传递

玩家问：

```text
吃的什么？
```

模型固定收到 `LivingMind v1`，不需要从长期记忆召回“吃饭”。

候选：

```text
TransitionBasis：只过去几十秒，没有发生结束吃饭的事件。

LivingMind v2：我仍在餐桌前吃面，注意力部分转向浩然的问题。

Reply：随便煮了点面，冰箱里也没什么东西了。
```

### 7.3 话题改变但状态仍保持

玩家问：

```text
你觉得人工智能以后会怎么样？
```

候选：

```text
TransitionBasis：问题改变了谈话主题，没有改变当前活动。

LivingMind v3：我仍然坐在餐桌前吃面，谈话已经转向人工智能，
我可以边吃边认真回答。

Reply：这个问题挺大的。真要我说的话……
```

回复没有必要主动提到吃饭，但下一轮仍会收到 `LivingMind v3`。

### 7.4 合理结束状态

二十五分钟后再次收到消息，主模型可以生成：

```text
TransitionBasis：上一状态已经吃了一段时间，当前又过去二十五分钟，
没有需要中断进餐的事件，结束晚饭并开始收拾是自然推进。

LivingMind v4：我已经吃完面，正在把碗筷收进厨房，
心情仍然比较轻松。
```

“正在吃饭”不是被遗忘，而是经过明确状态转移后结束。

## 8. 从吃饭变成弹琴的判断

### 8.1 无依据跳变

```text
上一状态：正在吃面。
经过时间：20秒。
玩家消息：你觉得这个游戏怎么样？
候选新状态：我正在钢琴前练琴。
```

连续性模型应拒绝，因为：

- 没有描述停止吃饭。
- 没有支持离开餐桌和走到钢琴前的新观察。
- 玩家消息与活动变化无关。
- 候选没有提供人物自己的动机。

### 8.2 有人物动机的快速变化

```text
上一状态：我正在吃面，但脑子里一直转着刚才没弹顺的旋律。
经过时间：20秒。
候选依据：那段旋律的解决办法突然清晰起来，
我不想让灵感消失，所以立刻放下筷子回到钢琴前。
候选状态：我暂时停止吃饭，已经坐回钢琴前试刚想到的改法。
```

这种变化虽然快速，但可能符合上一状态、人物动机和明确过渡，连续性模型可以接受。

因此连续性模型判断的不是“吃饭能不能转成弹琴”，而是：

> 这个具体的秦未晞，在这一刻，基于上一状态和新观察，是否能够自然成为下一状态。

## 9. 时间经过与离线状态推进

时间不是状态机触发器，而是模型的新观察。

```text
错误：吃饭超过30分钟，程序自动切换为吃完。
正确：程序报告过去30分钟，主模型结合上一状态决定发生什么。
```

### 9.1 短时间经过

短时间通常要求强继承。除非玩家消息、外部事件或上一状态中的强烈动机支持变化，否则主模型应保留主要活动和心理背景。

### 9.2 长时间经过

长时间允许更大变化，但模型不能借机生成大量具体经历。离线推进应只恢复当前需要知道的结果和少量关键过程：

```text
可以：晚饭已经吃完，现在在客厅休息。
谨慎：吃完后练了一会儿琴，当前已经停下。
不可以：临时编造与朋友外出、事故、购买物品等大量新经历。
```

具体、可长期引用的离线经历仍需服从现行自我时间线和证据提交要求。

### 9.3 应用未运行

没有进程时不存在实时心智计算。应用恢复后，运行时提供：

- 上一稳定 `LivingMind`。
- 最后更新时间。
- 当前时间。
- 已知计划和外部事件。

主模型完成一次恢复性 `MindTransition`，生成当前状态候选。它不是逐分钟模拟过去，而是从上一状态合理推进到现在。

## 10. 一次调用与两次调用

### 10.1 两次主模型调用

```text
MIND_ADVANCE -> next_living_mind
REPLY -> visible_reply
```

优点：

- 心智推进和说话分离，容易定位错误。
- 连续性模型可以先审查状态，再允许生成回复。
- 适合研究阶段收集状态轨迹和失败样本。

缺点：

- 每轮增加一次 4B 生成调用。
- 回复首 token 延迟增加。
- 两次调用之间仍需保证人格和意图一致。

### 10.2 一次联合调用

```text
<basis>变化依据</basis>
<mind>下一LivingMind</mind>
<reply>玩家可见回复</reply>
```

优点：

- 同一次生成中先形成自己，再从这个自己出发说话。
- 降低主模型重复加载和调度成本。
- 状态与回复共享同一推理链。

缺点：

- 连续性审查发生在完整候选生成以后。
- 未进入 `<reply>` 前不能向玩家显示正文。
- 需要稳定的格式训练和流式解析。

V2 推荐：

- 离线研究和能力验证先采用两次调用，确认状态推进能力本身成立。
- 若效果成立，再验证一次联合调用是否能保持质量并降低延迟。

## 11. 连续性模型的训练职责

连续性模型需要学习一般状态演进，而不是生活规则列表。

### 11.1 正样本

- 活动保持但话题变化。
- 有明确过渡的活动切换。
- 玩家消息引发不同但均合理的情绪变化。
- 长时间后活动自然完成。
- 短时间内由强烈动机引发快速行动。
- 不知道外部事实时继续保持未知。
- 回复不公开全部内部情绪，但不与内部状态冲突。

### 11.2 困难负样本

- 语言流畅但无依据切换当前活动。
- 无原因大幅改变情绪。
- 把欲望写成已经执行。
- 把计划写成已经完成。
- 把玩家的话误写成客观事实。
- 把未知天气或现实事件写成已知。
- 新 `LivingMind` 正确但可见回复与其冲突。
- 回复正确但内部状态悄悄增加不存在的经历。

### 11.3 评估器不能过度否决

如果连续性模型只学习常见行为，它可能压制人物自主性。因此训练集必须包含：

- 不常见但有充分动机的合理变化。
- 同一输入下多个不同但合理的下一状态。
- 允许不行动、等待、犹豫和改变主意。
- 允许人物做出不高效、不理性但符合人格的决定。

质量目标不是让人物行为最合理，而是让行为具有可理解的连续来源。

## 12. 主模型的轨迹训练

训练单位从单轮问答扩展为：

```text
LivingMind_t
+ PerceptionPacket_t
+ SelectedMemoryFrame_t
-> TransitionBasis_t
+ LivingMind_t+1
+ Reply_t
```

重点能力包括：

- 没有变化理由时保持当前核心状态。
- 只修改受到新观察影响的部分。
- 用自然语言保存复杂和混合状态。
- 将内部感受与可见表达分开。
- 让活动、心理、意图和回复共同演进。
- 面对时间跨度时形成少量、克制的状态推进。
- 正确区分观察事实、自己感受、推测和未知。

训练集必须包含连续多轮轨迹，而不是把每轮拆成互不相关的单轮样本。

## 13. 重试与失败处理

### 13.1 审查拒绝

连续性模型拒绝后，将简短反馈交回主模型：

```text
候选没有解释如何从正在吃面转为正在弹琴；
当前消息和经过时间也不足以支持该跳变。
请继承旧状态，或明确形成有动机的过渡。
```

主模型最多进行有限次数重试。不能无限循环，也不能由程序直接修改自然语言状态。

### 13.2 审查不确定

对 `uncertain` 可研究三种策略：

- 保守拒绝并重试。
- 让主模型进行一次自我澄清。
- 接受候选，但标记为需要后台复核。

具体策略必须通过误拒绝与漏判实验决定，V2 不预设最终阈值。

### 13.3 模型或解析失败

- 沿用上一稳定 `LivingMind`。
- 不提交候选状态。
- 不把半截心智文本当作当前状态。
- 如回复未显示，可安全重试；如已显示则必须保证与提交事务一致。

## 14. 状态版本与防漂移

每个状态形成单链：

```text
LivingMind v1 -> v2 -> v3 -> v4
```

系统始终只有一个当前有效指针。新状态必须声明 `parent_state_id`，防止并发消息或重试产生两条分叉当前现实。

防止逐轮漂移主要依靠：

- 最新状态每轮固定注入。
- 主模型专项轨迹训练。
- `TransitionBasis` 暴露变化原因。
- 连续性模型比较前后状态，而不是只看新状态。
- 原始状态变化和对应观察全部追加保存。
- 定期用账本轨迹做离线重建和漂移评测。

不建议依赖不断扩展的字段 schema 防止漂移。

## 15. 程序必须保留的窄硬约束

模型驱动不表示模型可以创造真实传感器或执行真实副作用。程序仍必须保证：

- 系统时间、时区和应用事件来源真实。
- 外部数据不存在时明确标记不可观察。
- 模型不能伪造已经调用天气、摄像头、定位或日历。
- 原始玩家消息和角色回复不可被模型删除或静默修改。
- 文件、网络、通知、支付和设备控制必须经过真实权限。
- 状态和回复采用原子事务提交。
- 崩溃后能够恢复上一稳定状态。

这些是模型的感官、身体和存储条件，不是人物生活规则。

## 16. 研究验收问题

V2 是否值得进入权威设计，至少需要回答：

1. 连续十轮改变话题后，当前活动保持正确的比例是多少。
2. 时间经过后，模型能否自然结束活动而不是永久保持或随机跳变。
3. 同一上下文下，模型能否产生多个不同但合理的状态发展。
4. 连续性模型能否拒绝无依据跳变，同时接受有动机的少见行为。
5. 心理状态是否比情绪标签更自然，并且不会逐轮夸大。
6. 模型是否能稳定区分世界事实、角色感受、推测与未知。
7. 4B 模型在两阶段和联合调用中的准确率、首 token 延迟和总延迟分别是多少。
8. 跨重启恢复最新 `LivingMind` 后，人物是否仍能自然继续当前处境。
9. 状态链发生错误时，能否定位是哪次观察、主模型推进或连续性审查造成。

## 17. 与 V1 的主要区别

| V1 | V2 |
|---|---|
| 提出模型维护 `LivingMind` | 明确谁决定、谁否决、谁提交 |
| 泛化描述学习式检查 | 定义连续性模型只有否决权 |
| 未完全说明状态变化来源 | 区分外部观察、玩家影响和人物自主变化 |
| 未完整说明跨轮保持 | 明确 `LivingMind` 每轮强制传递且不参与记忆淘汰 |
| 未完整说明吃饭到弹琴 | 定义无依据跳变与有动机快速变化的差异 |
| 简述持久化 | 定义父状态单链、原子提交、重试和恢复 |
| 推荐联合生成 | V2 建议先用两阶段验证能力，再评估联合生成 |

## 18. 当前推荐研究假设

V2 最需要验证的不是某个字段或提示词，而是以下完整假设：

> 同一个秦未晞主模型能够把最新自然语言 `LivingMind` 当作上一刻持续存在的自己，根据新观察和相关经历自主生成有依据的下一状态；一个独立学习式连续性模型能够只否决无依据断裂而不替人物做决定；运行时能够将通过审查的新状态与回复原子提交，使当前活动、身体心理状态和世界认知跨多轮、跨话题、跨时间和跨重启持续存在。

该假设通过离线轨迹和长期对话评测前，不进入施工。

## 19. 与现行权威设计的关系

本文不修改当前权威设计。现行 AI 实现仍以《AI女友最小心智系统设计》为准。

若未来 V2 实验通过并获得项目负责人批准，可能涉及：

- 将工作激活区中的简单 `mood_state` 深化为模型维护的 `LivingMind`。
- 增加 `MIND_ADVANCE` 或联合心智推进调用模式。
- 增加学习式 `ContinuityCritic`，但不增加生活规则库。
- 让 `RelationshipRuntime` 保存心智状态单链并执行原子提交。
- 重新定义时间经过和应用恢复时的内部状态推进。

在正式批准前，本文只作为后续讨论、数据设计和离线实验的研究依据。
