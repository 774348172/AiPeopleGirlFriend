## 1. 盲评前提解读（最容易误读的一点）

CHAT-02E 盲评比较的**不是**"纯基座 vs LoRA"，而是：

```
Qwen3-4B 基座 + 同一人格锚   vs   旧秦未晞 LoRA + 同一人格锚
```

关键数字：

| 指标 | 基座+锚 | 旧LoRA+锚 |
|---|---:|---:|
| persona_fit | 4.100 | 4.200 |
| relevance | 3.600 | 3.075 |
| correctness | 3.650 | 3.025 |

**结论**：基座通过 prompt 已能表现出接近 LoRA 的人格（-0.1），同时保留明显更好的承接与事实能力（+0.5/+0.6）。在旧 v1 数据方案下，训练是净负收益。

**注意**：盲评为单轮评测，长对话人格保持未测——不能把单轮结论外推到长对话。

## 2. "不训练"判断的两个层次（必须分开）

| 层次 | 结论 | 理由 |
|---|---|---|
| 否定旧 v1 数据方案 | ✅ 成立 | 数据问题 P0-1~P0-6（口癖密度/无证据经历/严肃稀疏/属性朗读）已证 |
| 否定所有微调 | ❌ 不成立 | 数据错误 ≠ 训练动作错误；高质量小数据最小 LoRA 仍是候选 |

训练替代不了的三件事（prompt 的软约束局限）：

1. **权重内化**：人格锚不必每轮重复注入 → 省上下文、省首字延迟（本地 4B 的关键）
2. **长对话抗漂移**：prompt 50 轮后角色淡化，权重是硬约束
3. **多角色低成本切换**：三女友 = 三 adapter，而非三个巨型 prompt

## 3. 三路线成本速查

假设：每轮 1500 token 输入 + 200 token 输出；每天 50 轮；每月 1500 轮。

| 路线 | 成本形态 | 量级 |
|---|---|---|
| 本地 4B/8B | 玩家自备硬件（3060 8G 两者都能跑），边际成本 ≈ 0 | 一次性 |
| GPT-5.6 API | 输入 ≈ 2.25M token/月 + 输出 ≈ 0.3M token/月 | **$5-10/月/玩家**；1000 玩家 = $5000-10000/月 |
| 混合（本地默认+云增强） | 本地 ≈0 + 云仅增强模式 | 取决于增强使用率 |

要点：**云端成本随玩家数线性增长**，与 Steam 买断制天然冲突（除非改订阅/内购——那是产品战略变更）。

## 4. 本地 8B 候选（主比较文档未覆盖）

| 项 | Qwen3-4B Q4 | Qwen3-8B Q4 |
|---|---:|---:|
| VRAM | ≈2.5GB | ≈4.5GB（3060 8G 可跑） |
| 理解/事实能力 | 基准 | 显著更强 |
| 基座+prompt 人格上限 | 已测 4.1 | 未测（预计 ≥4.1） |
| 成本 | 0 | 0 |

**意义**：8B 基座 + 最小上下文很可能同时拿到"人格 4.2 + relevance 3.6"，是"不训练也够用"的最可能路径，且零成本。建议并入四路实验为**候选 E**。

## 5. 必须实测才能决策的项（当前证据缺口）

| 项 | 为什么必须实测 |
|---|---|
| 长对话人格保持（100 轮） | 单轮盲评不覆盖；prompt 漂移 vs 权重硬约束的分水岭 |
| 8B 基座+prompt 的严肃支持 | 4B 基座 serious 已明显优于旧 LoRA，8B 预计更好，需确认 |
| GPT-5.6 同题实测 | "很可能更好"≠ 实测；恋爱角色非通用榜单任务，可能过于圆滑/安全策略显眼 |
| 相同冻结输入四路对比 | 控制变量：同正典/同记忆帧/同输出格式/固定 reasoning effort |

## 6. 决策速查（调用时直接参考）

```
Q: 现在要不要训练 2500 条 v4？
A: 暂停。先做基座+上下文基线（含 8B 候选），测出稳定缺口再最小 LoRA。

Q: 能不能直接用 GPT-5.6 当正式回复模型？
A: 不能（违反本地/断网/隐私 + 运营成本线性增长）。
   定位：质量上限 / 教师 / 评审器（立即采用，价值最高）。

Q: 哪条路能同时保住人格和事实？
A: 最可能：本地 8B 基座 + 最小人格/证据上下文 + RelationshipRuntime。
   其次：高质量小数据最小 LoRA 补明确缺口。

Q: 无论选哪条路都不能删什么？
A: RelationshipRuntime（本地证据账本）。模型越强越需要正确记忆输入；
   云端也不会自动拥有玩家本地账本。

Q: 什么情况下必须训练？
A: 基座长对话人格稳定漂移 / 助手腔在更强 prompt 下仍无法消除 /
   固定 prompt 导致上下文过长拖慢首字延迟 / 多角色需要低成本切换。
   原则：只训练已测出的稳定缺口，不把整个角色人生灌进权重。
```
