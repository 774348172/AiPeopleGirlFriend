## 目标（§20 阶段 4）
1. 注册 `relationship-runtime-v1` 默认 ProtocolBundle（三 mode，非核心硬编码）
2. 对齐生产 prompt 顺序与三 mode 监督规则（§10.5 renderer 合同）
3. 建立跨 profile 的协议 fixture 与 sealed suite（§16.2：协议能力不是记住某个角色事实）
4. 验证计划状态没有混入 MEMORY_PROPOSE（§10.3）

## 交付物

### 1. 默认协议包（`data_gen_v4/packages/protocols/relationship-runtime-v1.yaml`）
- `protocol_bundle_id: relationship-runtime-v1`；三 mode 注册：
  - `REPLY` → mode.reply.v1，引用 `schemas/mode_v4/reply_{input,target}.schema.json`，render_profile `reply-runtime-v1`
  - `RECALL_PLAN` → mode.recall_plan.v1，引用 recall_plan schema
  - `MEMORY_PROPOSE` → mode.memory_propose.v1，引用 memory_propose schema
- 与 fixture 协议包（protocol.fixture.rel）并存：bundle 是配置资产，核心不硬编码任何 bundle

### 2. 生产 renderer（`adapters/modes/renderers.py`，~100 行）
按 §10.5 合同实现 `ProductionRenderers`：
- `reply_system_anchor(profile, facts)`：固定身份锚（姓名/关系/关键边界）→ 输出协议（长度/标签/禁 emoji/markdown/助手腔），顺序与运行时 §11 合同一致
- `reply_training_record(candidate, package_set)`：静态对话监督全部 assistant（runtime-grounded 只监督末条的逻辑留接口，阶段 5 用）
- `protocol_system_anchor(mode)`：mode discriminator + grammar 约束
- `ReplyModeAdapter.render_training` 改用生产 system_anchor（替换现在的 `package_set.get("system_anchor")` 占位）

### 3. 跨 profile 协议 sealed suite（`tests/stage4/fixtures/sealed_protocol_suite.json`）
- 8-10 组与角色无关的协议 fixture：RECALL_PLAN（search/NO_OP/ask_clarification）+ MEMORY_PROPOSE（propose/NO_OP/correction），每组含 model_input + oracle_state + 期望行为类别
- 证明：同一 suite 在 Alpha 与 Beta 上都能消费（协议能力不依赖角色事实）

### 4. 测试（`tests/stage4/`，约 18 项）
- `test_default_bundle.py`：bundle 可加载且三 mode 注册；schema refs 文件存在；compiler 用默认 bundle 编译 Alpha/Beta 均成功（与 fixture bundle 并行可用）
- `test_production_prompt_order.py`：reply system anchor 顺序（身份锚→输出协议）；监督索引规则（REPLY 全部 assistant；协议只 JSON 条）；协议训练记录顺序（discriminator → 输入 → target）
- `test_cross_profile_protocol_suite.py`：suite 结构完整；StrictTestModelAdapter 按 suite 输出，Alpha/Beta 双 profile 全流程（protocol adapter）均通过；协议 target 不含任何角色事实词
- `test_no_plan_smuggling.py`：memory_propose_target schema 的 claim_type ⊆ {fact, preference, relationship, episode, correction}（schema 层已保证 + 显式断言）；模型输出 plan/promise 类候选被拒（schema_error）；输入 schema 无 plan 字段
