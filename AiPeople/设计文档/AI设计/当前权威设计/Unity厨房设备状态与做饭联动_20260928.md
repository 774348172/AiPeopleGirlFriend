# Unity 厨房设备状态与做饭联动（2026-09-28）

本轮承接《Unity场景事实覆盖审计与显存优化_20260928.md》的家电缺口。权威场景设定中的设备存在，不等于已知运行、门、内部温度或内容状态。游戏只上报程序实际管理的状态，模型不能从三维外观推断未接入的信息。

## 施工范围

- Unity 快照 schema 4 登记六件厨房设备：燃气灶、抽油烟机、冰箱、微波炉、电饭煲、电热水壶。每件有稳定 ID、名称、位置和运行状态。导入房屋中靠外墙的水壶由已登记的厨房节点归属厨房，不放宽房间区域的通用判定。
- 燃气灶和抽油烟机有实际开关、场景指示和状态变化；其余四件仅确认存在，运行状态为 `unknown`。冰箱门和内部温度也保持未知。没有把贴图、模型存在或对白当成传感器。
- 小窗“房间”增加“厨房设备”页；未知设备不可操作。第一人称可通过场景按钮操作两件可控设备。`/ui/device` 的命令在 Unity 主线程执行，过期请求不会延后改变场景。
- 白未晞到达厨房开始做饭时自动打开灶台和油烟机；完成或失败后，仅恢复由本次动作自动开启且没有被玩家再次操作的设备。做饭途中人工关灶会失败，不生成面碗。后端从完整快照构建设备事实，阻止自由场景字段冒充设备及实体状态。

## 验收

- Unity 图形模式 PlayMode：62/62 通过，包括设备状态、做饭中断、房间小窗按钮与超时保护、30 轮契约桩流式协议。契约桩仅验证接口，不代表真实模型质量。
- 后端相关测试：48/48 通过，覆盖设备唯一性、不可虚报状态、连续快照变化和场景字段约束。
- Windows 正式构建：`UnityClient/Builds/CatGirlfriend-KitchenDevices-20260928/CatGirlfriend.exe`。联调使用独立副本、独立存档 `kitchendevices20260928` 与独立 SQLite。
- 真实 Unity → 后端 → Unity 联调：六件设备可从快照和小窗状态接口读取；人工开灶后模型答“燃气灶开着。冰箱里的温度我不知道。”，关灶后答“不在运行了。”；做饭运行时灶台和油烟机均为运行，人工关灶得到 `failed` 回执，未生成 `bowl`，自动开启的油烟机恢复关闭。
- 首次真实流式提问出现一次“服务返回错误”，没有提交模型回复；随后同一快照的直接后端请求及两次真实小窗提问成功。此短测不证明首轮生成失败已消除，也不构成八小时稳定性验收。

## 后续边界

微波炉、电饭煲、电热水壶、冰箱尚无真实开关、门或温度传感状态，不能回答具体运行、内容和温度。电视、其他装饰窗、锁和人体状态仍按各自事实缺口推进；不得用本轮厨房设备登记宣称全屋事实已闭环。模型动作授权和训练权重均未改动。
