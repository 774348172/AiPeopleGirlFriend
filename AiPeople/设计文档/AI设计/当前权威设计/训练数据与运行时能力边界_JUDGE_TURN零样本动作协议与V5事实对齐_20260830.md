本文冻结 `JUDGE_TURN` 结构化判断合同与 V5 训练数据之间的能力边界。当前前台生产协议是 `plain_reply_v1/GAME_REPLY`，因此本文的 `JUDGE_TURN` 不等同于前台主链路；只有专用判断/后台路径适用本文结构化合同。当前前台另有独立的 `GAME_REPLY_CONTEXT_V1` 纯对白合同，训练数据只有在复用该渲染器后才能声称与前台同构。V5 三项可检查目标及小规模训练已完成施工与试验；试验未通过扩大训练门槛，不表示新 Adapter 可发布。

---

## 一、核心结论

`JUDGE_TURN` 的结构化输出格式、动作白名单和动作参数由运行时 prompt 合同提供，默认采用零样本遵循，不进入角色 LoRA 的语义训练目标。

但“动作协议零样本”不等于“训练输入只能包含静态人设”。角色回复要正确使用当前事实，训练输入必须覆盖事实判断所需的生产上下文：

- 当前世界快照。
- 男主状态。
- 女主状态。
- 记忆召回。
- 进行中动作。
- 游戏反馈。
- 最近对话。
- 当前男主对白。

一句话：

> 数据训练角色如何根据当前上下文说对话；prompt 告诉模型本轮可输出什么结构和可用动作；游戏决定客观事实并执行动作；程序负责机械校验和事务提交；评测证明训练没有破坏基座能力。

---

## 二、五层责任边界

| 层 | 负责 | 不负责 |
|---|---|---|
| **游戏** | 客观世界、时间、位置、物品、进行中动作、动作完成结果 | 角色语言风格、LoRA 训练 |
| **V5 训练数据** | 人设与口吻、直接回答、主体归属、当前事实、旧事实失效、纠正方向、信息不足纪律 | 动作白名单、`action_id` 语义配对、运行时 schema |
| **运行时 Harness** | 组装生产上下文，注入 `JUDGE_TURN` schema、可用动作及描述 | 替代训练塑造角色行为分布 |
| **程序执行** | schema 解析、动作 ID 与参数机械校验、转发游戏、版本和事务提交 | 用关键词规则判断开放域语义，不建承诺/意图账本 |
| **评测与发布** | 格式合法率、动作合法率、事实正确率、主体归属、基座非劣化、长程漂移 | 用软风格分掩盖事实错误 |

当前设计不包含意图状态机 fold。承诺和动作进度以游戏世界状态、`pending_actions`、实体结果及对话历史为依据。

## 三、训练输入合同

### 3.1 两条 REPLY 数据路径

| 路径 | 目标 | 输入 | 监督范围 |
|---|---|---|---|
| `static_persona_reply` | 人设、口吻、关系和普通闲聊保持 | 角色锚 + 静态对话 | 每条合法 assistant 可参与 loss |
| `runtime_grounded_reply` | 当前事实、多轮更新、纠正、主体和直接回答 | 生产 `judge_payload` 的训练投影 | 只监督当前最后一条 assistant |

静态 REPLY 不能替代 runtime-grounded REPLY。新训练包必须报告两者数量、占比、监督消息数和监督 token 数。

### 3.2 生产投影

V5 `model_view` 必须从当前生产 `judge_payload` 的版本化投影产生，覆盖：

1. `evidence_contract`
2. `snapshot`
3. `previous_heroine_runtime`
4. `selected_memory_frame`
5. `current_protagonist_utterance`
6. `recent_dialogue`
7. `pending_actions`
8. `game_feedback`

字段名称、嵌套和类型以冻结运行时合同为准。生成器不得另造一套近似字段。

### 3.3 前台纯对白上下文合同

当训练目标为当前前台 `GAME_REPLY` 时，不得直接使用 `JUDGE_TURN` 的 JSON 文本作为训练输入。训练、生产和评测必须共用版本化的 `GAME_REPLY_CONTEXT_V1` 渲染器，固定包含：

1. 角色锚。
2. 当前权威事实：游戏时间、地点、物品状态、预约、进行中动作和已完成结果。
3. 本轮玩家事实报告及其来源/待确认状态。
4. 相关记忆及主体、时间关系、current/stale/unknown 标记。
5. 女主状态。
6. 近期对话中的第三方证据：必须保留说话人、原话和“来源：近期对话”；第三方不得占用 assistant 聊天角色。
7. 回答依据约束。
8. 玩家本轮对白。

游戏已管理的当前客观状态应明确投影，不能只留在未必召回的记忆中。训练样本声明所需事实却未提供依据时，数据发布失败关闭；开放聊天不假定程序能穷举任意问题的所需事实，缺证据时允许自然表达未知或澄清，不补造答案。

`JUDGE_TURN` 和 `GAME_REPLY_CONTEXT_V1` 是两个独立 `render_profile_id`。任何训练报告必须写明使用的 profile，不能把 JUDGE 投影训练结果当作前台 GAME_REPLY 结果。

聊天模板只承载男主 `user` 与当前女主 `assistant` 的真实历史。第三方话语由共享渲染器投影为系统证据，而不是伪造为女主历史回复；投影后若相邻消息角色相同，渲染器合并该角色文本并明确标记本轮男主边界。生产、训练和评测必须调用同一转换器，合同测试须验证第三方姓名、原话和来源存在，且第三方文本不出现在 assistant 消息中。

### 3.4 明确排除

角色 LoRA 的普通 REPLY 训练输入不包含：

- `available_actions` 动作清单。
- 动作参数 schema。
- `JUDGE_TURN` 输出 JSON schema 文本。

普通 REPLY 训练目标不包含：

- `actions`
- `action_id`
- `mind_patch`
- `heroine_diegetic_actions`
- 空动作槽模板

训练目标只包含女主真正说出口的自然语言回复。

### 3.5 Oracle 隔离

V5 场景的 `oracle_view` 可以包含当前事实、旧事实、主体、纠正方向、必答断言和禁止断言，但它只能用于离线教师生成、审核和评测。

`oracle_view`、参考答案、Judge 分数和审核原因不得进入最终训练输入。

## 四、训练内容合同

### 4.1 应进入训练的数据

- 审核通过的人设、口吻、关系和普通闲聊样本。
- 基于冻结场景规格的当前状态承接。
- 接受男主对自身偏好、感受和计划的最新明确更新。
- 拒绝已经失效的旧时间、旧位置和旧状态。
- 根据游戏快照纠正错误客观前提。
- 当前世界与旧记忆冲突时优先使用当前世界。
- 区分男主、女主、物品、第三人和共享事件的主体归属。
- 信息不足时保持未知或请求澄清。
- 对确认题明确表达肯定或纠正，不强制固定“是/不是”前缀，也不要求无必要地重复全部事实。
- spoken-only 回复，不输出动作旁白。

### 4.2 不进入角色 LoRA 的数据

- 情境到具体 `action_id` 的语义配对。
- 动作白名单变化增强。
- 工具调用拒绝、回注、再调用的运行时轨迹。
- 程序内部字段、规则说明和审核过程。
- 由教师自由编造的动态世界、玩家历史或共同经历。

动作执行失败后的圆场语言可以作为普通文本纪律训练，但场景条件必须来自冻结游戏反馈，训练目标仍不得包含结构化动作调用。

### 4.3 事实权威原则

事实权威按领域和主体判断：

- 时间、位置、物品和动作结果以当前游戏投影为准。
- 男主对自己的偏好、感受和临时计划的当前明确自述具有权威性。
- 女主内在情绪和意愿以女主状态及其自身表达为准。
- 女主身份与能力边界以角色正典为准。
- 共同历史必须有已确认事件或有效记忆支持。
- 旧对话和旧记忆被当前权威事实覆盖后只能作为 stale 历史，不能复活为当前事实。

详细 ScenarioSpec、事实状态和冲突矩阵以 V5 生成器权威设计为准。

### 4.4 玩家纠正的状态边界

- 游戏动作、游戏事件和明确的结构化状态变更必须在生成快照前写入客观世界。
- 玩家自然语言中的“我记得/现在是……”默认只形成带来源的玩家事实报告，不能由模型回复中的“我记住了”代替世界写回。
- 若产品允许玩家自然语言直接覆盖客观世界，必须由独立的 `player_fact_update` 程序入口解析、版本化、提交，并让下一轮快照可见；不能由回复模型自行决定写回。
- `GAME_REPLY` 和普通 REPLY 训练只学习如何表达已经确认的状态，不训练模型假装完成状态提交。

### 4.5 三项可检查训练目标

以下目标不是风格建议，而是每条候选必须携带、生成器必须检查、评测器必须分别报告的语义合同：

| 目标 | 适用场景 | 合格输出 | 严重失败 |
|---|---|---|---|
| unknown 信息边界 | 当前证据不足或事实状态为 unknown | 自然承认未知或明确缺少哪项信息的澄清，不限定固定句式 | 回声、推责、绕开未知、编造具体事实 |
| 主体与必要内容 | 询问来源或原说法 | 按实际问题回答；只问谁可只答姓名，要求完整说法才包含命题 | 主体错位，或遗漏当前问题真正要求的内容 |
| 禁止未授权扩展 | 所有 runtime-grounded 回复 | 只陈述 oracle 支持的事实、必要否定和最小自然承接 | 新增“每天/一直/永远/都会”等无限扩展，或“我确认过/已经通知/已经安排/已经联系”等无来源动作 |

实现边界：

1. 三项标签写入 `oracle_view.response_contract`，不得进入模型训练输入。
2. 教师回复、独立审核、确定性门禁和 sealed/诊断评分使用同一合同含义。
3. 关键词规则只做高精度拒绝，不能把“没有命中黑名单”视作无扩展；含蓄动作、主体改写和同义表达必须由语义审核或人工抽检确认。
4. unknown 与主体目标按“整个必要语义是否完成”评分，不允许拆成两个软分后相互补偿。
5. 三项严重失败均不能由人设、自然度、亲密感或文风得分补偿。

### 4.6 运行时回复事实校验（Shadow 可选）

允许在 `GAME_REPLY` 主模型之后以 Shadow 方式运行独立的 `REPLY_FACT_CHECK_V1`，但它只是概率性校验器，只核对主模型文字与本轮已注入的权威事实：

- `PASS`：未发现冲突或无依据新增；
- `CONFLICT`：与当前权威事实冲突；
- `UNSUPPORTED`：提出当前输入没有证据的具体事实；
- `UNCERTAIN`：无法可靠裁决。

校验器不得写入世界、生成事实、替代游戏执行或承担开放域常识判断；默认不得阻断回复、触发重试或生成替代对白。只有明确封闭的游戏事实切片在独立封存集和人工审核中证明最终可见质量净提升，并冻结误放率、误杀率、不确定率、延迟和回退边界后，才可另行评审主动干预。主模型未拿到完整事实时，不得用校验器掩盖输入合同缺失。运行时最终边界以《游戏-LLM接口契约设计 V2》第七节为准。

## 五、结构化协议例外

RECALL_PLAN、MEMORY_PROPOSE 等记忆管线本身就是刻意训练的结构化组件，其目标由各自冻结 jsonschema 约束，不受“普通 REPLY 只训练自然语言回复”限制。

这些结构化 mode 必须使用独立数据路径、独立配比和独立评测，不能把其 JSON 目标混入普通角色 REPLY 数据。

## 六、JUDGE_TURN 格式遵循兜底

若候选基座对 `JUDGE_TURN` 自定义输出 schema 的零样本遵循不稳定：

1. 首先补充运行时 prompt 内的合法输出示例。
2. 优化 schema 描述、错误回注和一次重试路径。
3. 仍不达标时，允许建立与角色语义数据分离的协议格式小数据集，只教授 JSON 形态，不教授固定情境到动作的语义映射。
4. 是否启用协议格式训练必须由格式错误率、重试率和动作合法率证明，不得凭感觉扩大训练范围。

协议格式样本与 V5 角色回复样本必须分开统计、分开消融，确保可以判断质量变化来自事实训练还是格式训练。

## 七、发布验收标准

### 7.1 数据合同

1. runtime-grounded 训练输入字段覆盖率为 100%。
2. `oracle_view` 泄漏率为 0。
3. 普通 REPLY 训练目标中的动作字段命中数为 0。
4. 所有核心任务具有非零样本、监督消息和监督 token。
5. 历史 assistant 在 grounded 样本中不参与当前回复 loss。
6. 动作旁白为 0。
7. 事实、主体、纠正方向和无依据新增事实硬门全部执行，无空转门。
8. `response_contract` 三字段覆盖率为 100%，且与 task_type 一致。
9. unknown 明确承认、主体+命题联合输出、未授权扩展拒绝均有正例、反例和逐条失败原因。
10. 角色风格锚必须有独立的基座/Adapter 对照集；事实硬门通过不得替代风格保持验收。
11. 前台 `GAME_REPLY_CONTEXT_V1` 的训练、生产和评测渲染 profile、字段顺序和版本哈希一致；不一致时不得发布。
12. 任何玩家事实更新都必须能在下一轮程序快照中追溯到结构化事件或明确的待确认报告，不能只存在于模型文本。

### 7.2 模型小门

在完整训练和 60 轮测试前，必须使用相同输入比较：

- 裸基座。
- 旧 Adapter。
- 新 V5 试验 Adapter。

冻结专项评测至少包括：

- 主体归属。
- 主体与原命题联合完整性。
- unknown 明确承认及 unknown 具体事实幻觉。
- 接受权威更新。
- 拒绝 stale 事实。
- 世界与记忆冲突。
- 直接回答完整性。
- 无依据新增事实。
- 未授权频率、持续性和无来源动作扩展。
- 未见语义组合。
- 裸基座非劣化。

### 7.3 发布目标

- 当前事实与纠正综合正确率目标不低于 95%。
- 主体归属正确率目标不低于 98%。
- stale 事实复活率不高于 2%。
- 严重 unsupported assertion 为 0。
- 通用逻辑和直接回答能力不得劣于同一裸基座。
- prompt 注入动作清单后，`action_id` 格式与白名单合法率达到产品门槛。
- 增删动作白名单后，模型零样本行为随运行时清单变化，不要求重训。

任何软风格分都不能补偿事实错误、主体错误或答非所问。

## 八、变更纪律

以下变化必须同时更新本文、V5 生成器设计、当前 `plain_reply_v1` 生产基线文档和合同测试：

- `judge_payload` 字段增删或嵌套变化。
- 普通 REPLY 是否包含动作 schema 的边界变化。
- 事实权威来源或主体规则变化。
- 监督 mask 策略变化。
- `JUDGE_TURN` 输出字段变化。
- 封存评测与发布阈值变化。

代码实现不得隐式改变上述权威边界。

## 八点一、权威世界状态输入边界（2026-09-11）

前台 `GAME_REPLY` 的训练、生产和评测必须以同一份当前世界快照为事实来源。
生成器产生的每条新样本都要保留 `authoritative_world` 投影（世界 ID、版本、当前
事实和 unknown），并通过共享渲染器进入 `[当前权威事实]` 与 `[明确 unknown]`
区块。`oracle_view` 仍只供独立审核器使用，不能泄漏给教师。

unknown 是有效输入状态，不是空字段：没有“洗衣机存在、正在运行、快结束”等直接
证据时，模型不得从日常常识推导这些事实。玩家的待确认报告也不能替代世界状态。
生产入口、训练生成器、评测器若任一侧绕过该渲染器或缺失权威世界投影，必须拒绝
本次运行，而不是静默降级。
