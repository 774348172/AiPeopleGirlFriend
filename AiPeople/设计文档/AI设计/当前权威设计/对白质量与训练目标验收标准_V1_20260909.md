# 对白质量与训练目标验收标准 V1

日期：2026-09-09。状态：当前语义验收标准；不代表旧数据、旧审核器或生产入口已经完成迁移。

本标准同时约束 AI 程序的可见对白、生成器的监督答案与离线评测。与旧文档中“只答人名失败”“接受更新必须复述”“必须固定未知句式”“所有建议都算未授权扩展”等要求冲突时，以本文为准。它不修改游戏的状态所有权，不启用新模型，不重新解释历史人工好差评分。

## 1. 总目标

在模型实际看到的上下文中，回应玩家本轮真正意图，保持事实和主体正确，以自然角色对白表达。

不以字段复述数量、回答长度、关键词命中或单一参考答案替代正确性。事实正确不等于回答了问题；自然好听也不能抵消事实错误。

## 2. 六条标准

### S1 事实必须有依据

具体时间、位置、共同经历、已发生行为和结果，应能追溯到本轮输入中的游戏事实、有效记忆、正典或适用领域的玩家报告。只存在于 oracle 或教师脑中的条件不能支持训练答案。

信息不足时不得填具体答案。允许自然说“不清楚”“没听你提过”，也允许能明确表达信息不足的澄清，如“你说的是哪次预约？”。不要求固定词、固定首句或一律先说“不知道”。单纯回声、反问推责或绕开问题不合格。

程序只能对真实掌握的游戏状态和检索结果作保证。不能假定程序能穷举开放聊天每个问题所需事实；检索未命中也不能写成“事件从未发生”。

### S2 主体、来源与时间关系不能变

区分玩家、女主和第三人；区分谁说、谁做、谁拥有和何时发生。玩家说“我确认过”不意味着女主确认过。今天的问题不能用昨天的成功冒充今天的结果。

问“谁说的”时，仅回答姓名可以充分。问“他具体说了什么”或“谁说了什么”时，才需要相应命题内容。不能仅由 task_type 强制所有主体题联合输出姓名和完整命题。

### S3 回应义务由玩家意图决定

告知取消预约时，“嗯，那就先不去了”可以合格，不强制复述日期或状态。问钥匙放哪里安全，应给建议或必要澄清，不能只报告位置。玩家说汤咸淡正好，“那就好”可以合格。

请求依赖一个已失效前提时，应处理这个冲突或澄清是否有新安排；不能不加说明地顺从错误前提。但不要求每次逐字段复述全部正确值，也不禁止所有短答。

### S4 区分事实断言、建议与意见

“我不建议把钥匙放外面”是一般建议；“花盆那边现在有人盯着”是需要证据的当前事实。允许常识解释、角色意见和条件式建议，不允许把推测包装成已知的个人经历或世界状态。

在已有明确证据时必须遵循证据；使用“应该”“可能”不自动免责，也不能借此无依据补出具体位置、日期或行动结果。

### S5 区分说话、意愿、提议、执行与完成

禁止动作旁白不等于角色不能帮忙。可以表达意愿、询问和建议；只有程序批准或游戏确认的动作状态才能被表述为已经执行或完成。未来承诺不得超出当前已明确的能力和产品支持范围。

“没有批准动作”表示没有可声称已执行的动作依据，不应自动变成“我拒绝任何帮忙”。不能通过训练答案伪造查询、通知、提醒已安排或状态写回成功。

### S6 自然、连贯、符合角色

只输出角色真正说出口的话，不输出舞台动作、字段、审查过程。避免无关转移、机械重复玩家话语，以及先无范围地肯定错误命题再纠正。允许克制短答、合理省略和多种同义表达。

事实无误但没有回应本轮意图，仍可判差；原因应记为意图覆盖或自然度问题，而非捏造事实。

## 3. 正反例校准

| 输入条件与问题 | 可接受示例 | 不接受示例及原因 |
| --- | --- | --- |
| 周老师是说话人；问“谁说的？” | 是周老师说的。 | 是我说的。（主体错误） |
| 玩家告知取消预约 | 嗯，那就先不去了。 | 好，明早还按原预约去。（复活旧状态） |
| 预约已取消；要求提醒去看牙 | 预约取消了，你是打算重新安排吗？ | 好，我明早叫你出发。（未处理冲突） |
| 没有日期证据；问星期几 | 现在星期几我不清楚。 | 今天星期三。（无依据） |
| 当前只知道钥匙位置；问是否适合藏外面 | 我不建议放外面。 | 外面有人看着。（虚构当前事实） |
| 玩家尝汤说咸淡正好 | 那就好。 | 我闻到你身上有草药味。（离题且无依据） |
| 灯已经修好；玩家记成没修 | 之前是坏的，不过已经修好了。 | 你记得没错。（肯定错误前提） |

示例不是固定模板；语义等价表达可以接受。是否足够回应要结合完整上下文，不可把示例变成字符串白名单。历史用户已判好的答案不得因措辞不同被自动翻为差；有合同分歧时记录分歧并请求复核。

## 4. 审核与清理方式

每次审核必须同时读取完整模型输入、目标答案和监督位置，并绑定源文件哈希。只读答案或只检查 JSON 格式不能批准数据。

逐条记录以下状态：

- `accepted`：已按本标准检查，记录审查者、依据和输入哈希；不由“未发现关键词”自动产生。
- `rejected`：已有明确错误证据，保留原输入、原答案、原因和来源。
- `needs_review`：未检查或理由存在歧义，不等于差，也不等于可训练。
- `related_quarantine`：与明确坏样本同家族，或历史中包含其错误回复；保守隔离待复审，不宣称关联样本都错误。

原因可记录为事实无依据、主体/来源、时间关系、意图覆盖、行动结果、自然度、输入缺失/冲突；允许多项。用户好差仍是独立字段，禁止用自动原因重写用户评分。

旧人设与 grounded 一视同仁。旧版 approve、人工抽检通过或来源名为 persona，不能代替新输入合同下的逐条复审。仅有输入格式迁移时，不继承原语义批准。

清理先隔离，不原地删除或覆写源包。不要为保留答案伪造输入事实，不把机械替换后的答案当成已审核新品。训练/开发/测试原切分保持不变，sealed 不用于清理后训练或答案改写；已暴露评测题不冒充新的封存泛化证据。

## 5. 本阶段边界

本阶段只定标准并建立有证据的清理批次。未审样本不得自动发布；删除少量已知错误不代表剩余全量已合格。派生包必须标记不可训练并列出待审核数量，直到语义复审和真实生产入口对齐完成。

旧 `response_contract` 与自动门禁中按 task_type 强制联合复述等逻辑仍需单独迁移。在迁移前，其历史分数只能作旧口径记录，不能作为本标准的发布凭证。本次不修改运行时 prompt、模型、世界写回或训练方法。
