# Unity 场景事实覆盖审计与显存优化（2026-09-28）

本轮落实后端显存优化、当前可读取场景状态的正式输入，并审计剩余事实缺口。上游仍为《游戏-LLM接口契约设计_20260827.md》和《程序施工计划_权威状态闭环_V1_20260911.md》；后者 A 块仅部分完成，不能标成完整状态/动作闭环已验收。

## 显存优化及实测

1. 正式 V3 manifest 的注意力实现由 eager 改为 SDPA，允许的配置与 JSON schema 同步更新并重新计算运行包摘要。基础模型、Adapter 文件及其校验值未修改，6144 上下文上限和 96 输出 token 配置未缩减。
2. 同步与流式生成工作线程结束后释放未使用 CUDA 缓存；仍保留模型权重。释放在串行工作线程内执行，不在请求超时/取消时抢先释放正在工作的资源。
3. 对四个相同输入比较 eager / SDPA：三份 V3 输入回复逐字相同；预约纠正题措辞不同但日期时间均正确。未重跑全量 dev60 质量评测。
4. 4726 token 输入的 PyTorch 活跃显存峰值约 11.984 → 9.016 GiB，保留显存峰值约 15.160 → 9.500 GiB。清理后单独主模型进程对应的整卡占用约 9.708 GiB。这是主模型诊断，不含正式后端全部检索组件。

RTX 4090 上正式后端与新 Windows 程序同跑的结果：

| 指标 | 前次联调 | 本轮优化后 |
|---|---:|---:|
| 连续对话后整卡待机显存 | 15.471 GiB | 11.086 GiB |
| 对话生成阶段采样峰值 | 约 15.49 GiB（前次全程） | 12.068 GiB |
| 后端待机专用显存 | 13.881 GiB | 9.494 GiB |
| Unity 场景 + 小窗专用显存 | 约 0.38 GiB | 约 0.41 GiB |

整卡待机下降约 4.39 GiB，约 28%。本轮推理采样 GPU 利用率峰值 100%，功耗峰值 214.28 W。采样间隔约 1.6 秒，可能漏掉瞬态峰值；前后是不同短对话样本，不能用此表推导所有工作负载的固定收益。优化后的完整栈仍未通过 12GB 显卡验收，长上下文、大批记忆重排和八小时稳定性不在本轮结论范围。

## 已接入的事实

Unity 每次提交对白时在主线程生成独立 `scene_facts` 数组；后端验证标签、长度、唯一性及保留字段，再整体替换当前场景事实，进入持久化快照和现有 V3 渲染器。最多 10 个额外标签，每个标签 40 字符、值 160 字符，不增加不受限自由文本入口。旧客户端不传该字段仍可用。

- 厨房门、主卧门、次卧门、浴室门、过道门、阳台移窗：真实开/关、打开中、关闭中、受阻未完成。读取 `ApartmentDoor`；不以 `TargetOpen` 当完成结果。
- 室内灯光：读取 `SceneAtmosphere.LightOn`。导入房屋不再上报旧占位窗状态；无真实控制组件的其他窗户不冒充已同步。
- 男主手持物：实际 `HeldItemLabel` 同步到结构字段及可读事实，放下后明确为空；修复离开位置锚点时丢失手持物、桌面模式手持字段始终为空的问题。
- 白未晞实际移动：行走中、等待通路、未在行走。只描述移动，不推断坐着、躺着、已经到达或动作已经完成。
- 去掉锚点场景文字中固定的灯亮、门关、窗外安静等动态断言，避免与实时事实互相冲突。
- 后端比较连续结构快照，给变化/撤销事实生成“旧记录已失效，当前值为……”说明；这是结构值比较，不是从玩家自由对白抽取或确认事实。说明只在对应变化回合出现，不积累为常驻历史。
- 修复状态查询取字典第一个值当场景的问题：明确读取 `场景` 标签，并返回结构化 `scene_facts`。

本轮没有把自然语言回复写回世界。保留模型错误不能污染世界的边界。

## 验收

- 后端 44 项相关测试通过，包括已有 V3 网关、资产完整性、超时串行、工作线程结束后释放、场景字段约束、状态撤销和编码往返测试。
- Unity 8 项新增测试通过：开关/过渡/阻挡六种状态、真实导入门关闭及灯光同步与 JSON 往返、无锚点时持杯/放杯。
- Windows 新构建成功：`UnityClient/Builds/CatGirlfriend-MemoryFacts-20260928/CatGirlfriend.exe`。测试运行其副本，saveId 为 `memoryfacts20260928`，使用独立 SQLite，正式存档不变。
- 首轮 9 次真实 Unity → 后端 → Unity 对话中，六处门窗、灯光、空手、移动状态和未知电视频道均获得相应反馈；其中厨房门首次重开曾错误沿用旧回复。数据库确认该轮当前快照已经是打开，不能把该错误归为传输失败或隐去。
- 增加程序状态变更说明后，复测厨房门两次关闭/重开及阳台移窗打开/关闭，6/6 语义正确，回复耗时 3.279–4.038 秒。此短测不证明模型永远能抵抗旧对白。
- 本轮总计 15 次真实模型回复；当前仍为完整 reply JSON 解析后一次正文输出，并非逐 token 流式。
- 壁纸挂载日志校验通过；Player 日志无异常。本轮小窗外观未另做截图验收。

## 剩余事实缺口与施工顺序

后续进展：人物实际位置、动作执行器回执和有限物品实体联合快照已部分落地，见[Unity人物位置动作回执与实体快照_20260928.md](Unity人物位置动作回执与实体快照_20260928.md)；厨房设备状态与做饭联动见[Unity厨房设备状态与做饭联动_20260928.md](Unity厨房设备状态与做饭联动_20260928.md)。下表保留本次审计时的原始缺口；最新范围与验收以后续记录为准，A 块仍未全量完成。

| 优先级 | 事实类别 | 现状 / 风险 | 所需来源与验收 |
|---|---|---|---|
| P0 | 人物实际房间与位置 | 男主桌面模式固定为餐桌旁；第一人称只有餐桌/厨房/门口三个锚点，无锚点时位置 ID 仍回退门口。白未晞动作提交即把目标写成位置，不能当物理到达 | 建房间区域与实际 Transform 归属；分离当前位置、目标位置、到达事件，门挡路时不能提前报到达 |
| P0 | 动作阶段、失败、完成 | 正式聊天服务仍未接入 `RemoteGameWorld`。当前计时完成与物理行走/实体生成并非同一确认点 | 接入进行中/受阻/取消/拒绝/完成投影，完成由执行器确认；不得把“答应做饭”当已完成 |
| P0 | 物品实体、位置、所有者 | 仅玩家单一水杯状态可靠接入；中文持有标签的机器 ID 仍可能都退化为 `item`。做饭产物/拾取效果未完整接入正式模型快照 | 稳定实体 ID、所在房间/容器/桌面、持有人、生成/移除事件、库存；避免“桌上”和“手里”同时出现 |
| P0 | unknown / stale / 来源版本 | 新数组支持当前值和旧值失效，但不是完整 A 块快照协议；没有每项采集版本/时间与正式 unknown 投影 | 与权威 A 块合同统一，传版本/来源/已知性，缺失不是自动关闭或不存在；断线/重连不沿用过期事实 |
| P1 | 统一时间、天气、环境 | 后端 GameClock 已进入上下文，但动作计时由 Unity deltaTime 推进。天气由场景文字关键词回推，装饰天空/粒子不是独立气象真相 | 单一游戏时钟、昼夜/天气/室内温度等明确状态；动画仅消费该状态，禁止反向把画面猜成事实 |
| P1 | 人物活动与身体状态 | 男主身体/站坐多为固定默认值；女主心智活动/身体来自初始正典及后端状态，与当前动作表现可能不一致 | 程序管理站坐躺、睡眠、饥饿/疲劳/伤势等真实实现的数值/枚举；未实现项保留未知，不从动画/默认台词推断 |
| P1 | 家具与家电 | 三维家具存在不等于已登记实体；电视、灶台、冰箱等尚无完整开关/运行/内容/温度状态 | 先实体注册，再实现能改变的设备状态；电视无频道系统时仍回答不知道，不以贴图猜频道 |
| P1 | 每扇窗、锁与通行条件 | 六处控制对象已覆盖，其他装饰窗户、入户门锁、钥匙、遮帘等未形成实际控制合同 | 每个可交互对象拥有独立状态；锁定与关闭分开、通行与视觉姿态分开，不能扩展“阳台窗关闭”为全屋窗关闭 |
| P1 | 空间可见性、在场人物 | 当前默认主角和白未晞均在场，没有房间隔离、视线/听力范围或第三方出入的正式投影 | 区分存在、同房、可见、可听；人物不知道隔墙细节时应有明确边界 |
| P2 | 预约、任务、业务状态和玩家报告 | 对应权威计划已有设计，但正式提交/确认/纠正/失效 API 未全部落地 | 结构化业务入口或确认流程；保留 reported/confirmed/unknown/stale，聊天提问不能覆盖事实 |
| P2 | 长期记忆与后台维护 | 正式服务后台仍 queued_only；记忆队列存在不等于已写入长期记忆 | 另行验收同模型空闲消费及纠错，不能从本轮短历史成功推断跨会话记忆已完整 |

建议下一块先做“房间/人物实际位置 + 动作完成回执 + 物品实体”的联合快照，沿用权威 A 块合同，随后再做时间天气和身体/家电。不要继续堆更多固定场景描述，也不在本轮擅自启用模型动作或后台任务。

后端显存后续重点是更长上下文与 Qwen3 重排候选批次；当前重排器整批计算完整位置 logits，值得单独做同评分对照后优化。尚未为省显存把重排器迁移到 CPU，以免把显存问题变成交互延迟。
