# 动作执行闭环施工方案（2D 游戏前提版）（2026-08-27）

> 状态：**权威设计（施工依据，2D 游戏前提）** | 日期：2026-08-27
> 依据：《Harness组装与单次判断设计_20260827.md》（管线部分以该文为准）、《游戏-LLM 接口契约设计_20260827.md》（本方案为接口契约在 runtime 侧的细化）
> **前提修正（2026-08-27）**：产品为 2D 游戏，出租屋世界由程序构建，世界拥有面等实体、可执行动作与当前状态——**执行权与事实源归游戏**。LLM runtime 不再自建执行器/事件表/到期扫描，只做投影、校验与转发。
> 本版取代旧版（工具调用模式版）中"runtime 自建执行器"的机制部分；枚举白名单、模型判断语义、训练边界等结论继续有效。
> **无意图记账（2026-08-27）**：承诺跟踪由世界状态承担（进行中动作 + 实体即账本），runtime 不建承诺表（详见 Harness 设计 §二）。

## 一、问题与前提

**问题**：她说"我去做饭"——在 2D 游戏世界里，这句话必须真的变成"她在厨房煮面、面实体生成"。以前的设计让 runtime 自建"做饭物理引擎"（事件表、倒计时、效果写入），既重复造轮子又容易出错。

**前提**：游戏拥有完整世界——实体、位置、动画、动作执行、进行中动作。LLM runtime 的角色是**神经层**：模型判断（大脑）、游戏执行（身体）、runtime 翻译与投影（神经）。

## 二、目标与边界

**目标**：模型提议动作 → runtime 校验 → 游戏执行 → 游戏状态投影回上下文 → 模型基于真实状态叙述。玩家在 2D 世界里看到"她真的在煮面、面真的出现在桌上"。

**边界**：
- runtime **不模拟任何动作**（不建事件表、不倒计时、不写效果——这些是游戏的活）；
- runtime 的动作白名单**从游戏导出**，不自造；
- 语义判断（冲突/打断/顺序）仍归模型，不做规则代码；
- **不做意图记账**——进行中动作与实体结果（世界状态）即承诺账本。

## 三、改动点（runtime 侧，4 项）

### 3.1 动作清单 = 游戏导出

- `action_manifest.py` 不再自造，改为**消费游戏导出的动作定义**（接口契约 §四）：每个动作含 `action_id / description / duration_game_seconds / effects / params`；
- 动作描述仍含语义约束文本（占用什么、可不可打断），由模型读取判断；
- 单一来源：训练评测与运行时看到同一份动作清单。

### 3.2 白名单校验（机械，不变）

- `action_id` 必须存在于游戏导出清单；`params` 结构校验；
- 非法动作 → 拒绝并回注下一轮上下文（不转发给游戏）。

### 3.3 提议转发（新增通道）

- 判断契约 `actions` 字段 = 模型提议 → 校验通过 → **转发给游戏执行**（接口契约 §四 转发通道）；
- 被游戏拒绝（如玩家正占用厨房/资源冲突）→ 拒绝原因回注下一轮上下文，模型自然圆场。

### 3.4 状态投影（取代自建执行器）

- `pending_actions`（进行中动作 + 剩余时间）、`current_activity`、`item_states`、位置等**全部读游戏世界状态**（接口契约 §五）；
- 游戏完成煮面（面实体生成）→ 下一轮快照自然出现"桌上有一碗面" → 模型基于事实叙述"饭好了"；
- **到期完成由游戏模拟循环负责**，runtime 无扫描逻辑。

## 四、与游戏的分工表

| 层 | 管什么 |
|---|---|
| 游戏 | 世界状态（实体/位置/动画）、动作执行（时长/效果）、玩家操作、进行中动作、到期完成 |
| 模型 | 要不要做、冲突/打断判断、叙述、收口 |
| LLM runtime | 白名单校验、提议转发、状态投影进上下文、对话管线 |

**不写任何语义规则代码**；动作语义约束通过描述文本传递（模型读取），执行物理由游戏承担。

## 五、验收标准

1. 动作清单来自游戏导出，runtime 与游戏定义一致（单一来源校验）；
2. 模型提议合法动作 → 转发游戏 → 游戏状态变化 → 下一轮上下文可见；
3. 非法/被游戏拒绝的动作 → 回注 → 模型下轮自然圆场；
4. 游戏完成煮面后，上下文出现面实体，模型基于事实承接（"饭好了"）；
5. 回归：chat01/02/diagnostic120 无回归。

## 六、不做（本轮边界）

- runtime 不建动作事件表 / fold / 到期扫描（游戏内部实现）；
- 不做意图记账/承诺表（世界状态即账本）；
- 不做游戏引擎本身（2D 世界、动画、实体系统为产品侧）；
- 不做多角色泛化。
