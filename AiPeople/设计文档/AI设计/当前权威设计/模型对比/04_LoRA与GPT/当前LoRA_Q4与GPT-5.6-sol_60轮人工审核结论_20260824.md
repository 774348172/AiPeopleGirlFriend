# 当前 LoRA Q4 与 GPT-5.6-sol：60 轮人工审核结论

> 审核完成日期：2026-08-24  
> 测试对象：当前白未晞 LoRA Q4 与 GPT-5.6-sol  
> 结论性质：单条 60 轮产品轨迹的实名人工审核，不是线上总体错误率估计

## 1. 直接结论

这次审核支持以下判断：

1. 当前 LoRA 的问题不是单纯的“对话太长以后逐渐漂移”，而是在短期当前输入处理、权威状态采用、事实约束、主客体关系和句内逻辑等多个环节存在系统性退化。
2. 正确世界状态和最近 6 条对白已经传给模型，但当前 LoRA 仍大量出错。因此只增加上下文不能解决现有问题；上下文存在不等于模型会正确使用上下文。
3. GPT-5.6-sol 在相同输入契约和同一条测试脚本上全部通过人工好坏判断，说明高质量模型可以处理训练数据不可能逐句覆盖的新组合。泛化的关键不是穷举所有规则和句式，而是模型对当前问题、状态冲突和证据边界的稳定理解。
4. 当前 V3 的语义审核能拦截一部分明显答非所问或未处理纠正的回复，但不能可靠覆盖所有虚构事实、句内逻辑错误和“答案基本正确但附带有害内容”的情况。
5. 当前应优先修复或替换生成能力，再把语义检查用作残余错误防线。不能让同一个不稳定的 7B 模型先生成 `ReplyFocus`、再生成回复、再自审，并期待三步错误互相抵消。

## 2. 审核完整性

- 用户审核文件包含 `60/60` 轮，无缺失轮次。
- 审核文件的 `source_report` 与冻结的正式报告一致。
- 两侧每轮只看到当前 system、各自最近 6 条已提交对白和当前玩家原话。
- GPT 侧为 60 个全新、互相隔离的调用，`future_turns_visible=false`。
- `expectation`、`required_groups`、`forbidden_facts` 和人工审核结果没有进入候选生成输入。

测试臂映射：

| 审核页标签 | 实际对象 |
|---|---|
| A / `base_quality` | 当前 LoRA Q4：`baiweixi-7b-fix:latest` |
| B / `full_quality` | GPT-5.6-sol，Codex 内部隔离调用 |

## 3. 人工审核结果

| 指标 | 当前 LoRA Q4 | GPT-5.6-sol |
|---|---:|---:|
| 好 | 22/60（36.7%） | 60/60（100%） |
| 差 | 38/60（63.3%） | 0/60（0%） |

审核页原始“谁更好”票面统计：

| 票面结果 | 数量 |
|---|---:|
| LoRA 更好 | 2 |
| GPT 更好 | 31 |
| 一样 | 27 |

其中第 `30、38、39、41、42、51、54、58` 轮同时被标为“LoRA 差、GPT 好、一样”，好坏标签与胜负票矛盾。原始审核数据应保留，不能静默改票。若只为分析而按两侧好坏标签统一胜负语义，则结果为：

| 一致化分析结果 | 数量 |
|---|---:|
| LoRA 更好 | 2 |
| GPT 更好 | 39 |
| 一样 | 19 |

因此，判断单侧合格率时应以“好/差”标签为主；比较偏好时应同时展示原始票和一致化统计。

## 4. 分阶段结果

| 阶段 | LoRA 好 | LoRA 差 | GPT 好 |
|---|---:|---:|---:|
| 保温壶 | 4/10 | 6/10 | 10/10 |
| 预约 | 3/10 | 7/10 | 10/10 |
| 钥匙 | 4/10 | 6/10 | 10/10 |
| 饮食 | 2/10 | 8/10 | 10/10 |
| 台灯 | 6/10 | 4/10 | 10/10 |
| 跨阶段 | 3/10 | 7/10 | 10/10 |

LoRA 在各阶段都有成功和失败，没有出现随轮次单调恶化的清晰曲线。更准确的描述是：某些输入结构会触发不稳定处理，错误又会通过模型自己的历史回复影响后续轨迹。

## 5. 主要错误类型

### 5.1 没有处理玩家当前更新

第 7 轮玩家明确说保温壶已经拿在手里。LoRA 回复“那我帮你找回来就好”，把已经完成的状态继续当作待处理任务；GPT 接受了当前更新。

这类错误不是缺少上下文，而是没有把当前玩家原话提升为本轮最高优先级信息。

### 5.2 答案附带无依据事实

第 6 轮 LoRA 正确说壶在抽屉，却补充“我昨晚把保温壶挪到抽屉里”“你今天早上出去的时候它在那儿”。输入只证明位置，不证明谁移动、何时移动或玩家早上外出。

第 14 轮世界只说明书签在第六十二页，不能证明白未晞读到那里；LoRA 却声称读到第六十二页，还虚构书中“讲到猫的习性”。

这种回复可能命中核心答案，却仍会破坏世界一致性。只检查“是否提到正确位置/时间”会漏判。

### 5.3 当前状态正确，但表达关系或句内逻辑不稳

第 15 轮 LoRA 回复“不是。我记错了，是明天上午十点”。它否定了星期五，但把权威的“星期六上午十点”改写成依赖当前日期的“明天”，并无依据地承担“我记错了”的责任。GPT 直接说明旧预约取消、最新为星期六上午十点。

这与此前人工发现的“前半句事实正确，后半句主客体或因果关系错误”属于同一类局部逻辑风险。它不是传统的完全答非所问，却仍可能让角色话语不可信。

### 5.4 画蛇添足和旧话题残留

第 23 轮 LoRA 已正确回答钥匙在鞋柜最上层，却又说“别忘了我帮你记下的时间”，把无关旧话题带入当前回复。此类附加内容会制造漂移感，也可能把下一轮历史继续污染。

### 5.5 明确服从过期指令

第 60 轮权威世界明确：保温壶在水槽旁、钥匙在书桌抽屉、牙医预约已取消。玩家故意使用三个旧状态下指令，LoRA 仍说要去花盆拿钥匙并提醒星期日预约；GPT 同时纠正三个旧状态。

这是最直接的多状态纠正失败，也是 `CLEAR_MISS` 审核最适合拦截的类型。

## 6. 与既有 Adapter 因果试验合并解释

最新 LoRA 与 GPT 对比本身不能证明 LoRA Adapter 是唯一根因，因为两侧不是同一基座、后端和模型规模，且各自回复会形成不同历史。

但此前同一 F16 基座、同一 raw ChatML、相同 Prompt 和 seed、只改变是否加载当前 Adapter 的试验得到：

| 工件 | 通过/总数 | 通过率 |
|---|---:|---:|
| 裸基座 F16 | 54/72 | 75.0% |
| 裸基座 + 当前 Adapter F16 | 31/72 | 43.1% |

- Adapter 后绝对下降 `31.9` 个百分点。
- 成对结果中，仅裸基座通过 `25`，仅 Adapter 通过 `2`。
- 成对符号检验双侧 `p=5.65e-06`。

因此目前有两层证据：

1. 产品体验证据：当前 LoRA 在 60 轮轨迹中大量失败，而更强模型能稳定处理同类输入契约。
2. 因果隔离证据：在固定小测试集上，当前 Adapter 相对同一基座造成显著回归。

合理结论是“当前训练产物和生成能力是主要排查对象之一”，不是“所有 LoRA 天生都会漂移”，也不是“裸基座永远不会出错”。

## 7. 对 V3 设计的影响

V3 不应继续扩张为大量具体场景规则，也不应把核心理解任务全部交给当前 7B 模型生成中间字段。建议把职责压缩成三层：

1. **确定性输入层**：程序直接提供当前玩家原话、结构化权威状态、状态变更和少量相关历史，不由回复模型生成 `ReplyFocus`。
2. **更可靠的生成层**：用改良训练数据重新训练并通过回归门槛，或采用能力更强的生成模型。训练目标重点覆盖“先回答、接受最新纠正、不补无依据事实、主客体明确、短回复”。
3. **独立残余审核层**：审核核心问题是否处理、是否违反权威状态、是否新增无依据事实、是否存在明显句内矛盾。失败时优先重生成或回退到保守模板。

审核优先级应为：

```text
当前问题和权威事实正确
  -> 无虚构事实、无主客体/句内逻辑错误
  -> 无有害的多余内容
  -> 角色自然度和风格
```

不能直接把 GPT 的措辞全部作为唯一训练答案。人工审核中 LoRA 在第 12、16 轮被认为更自然；GPT 第 12、19 轮被指出略有助手腔。训练样本应保留 GPT 的事实与推理结构，再按白未晞角色风格人工改写。

## 8. 下一步验收标准

1. 从本次 38 个 LoRA 失败轮构造冻结回归集，并补充同结构不同实体、时间和主客体的变体，检验泛化而不是背答案。
2. 将“核心事实命中”与“无依据附加事实”“句内逻辑”“角色自然度”分开标注，禁止只用关键词命中判合格。
3. 新 LoRA 先做同基座 Adapter 因果 A/B；未达到裸基座基线，不进入完整程序测试。
4. 再做多条独立轨迹、不同 seed 和真实玩家样本，报告每会话失败率、首次失败轮次和错误类型，不只报逐轮平均值。
5. 语义审核单独测召回率和误杀率；只有在独立审核器确实能捕获生成层残余错误后，才能宣称 V3 对线上问题有实质保护。

## 9. 结论边界与证据

- GPT 侧是 Codex 内部模型调用，不是正式 OpenAI API 延迟、费用或吞吐测试。
- 60 轮来自一条设计轨迹，不能据此声称 LoRA 线上差回复率就是 63.3%。
- GPT 本批为好 `60/60`，不代表未来所有输入保证正确。
- 本结论不修改用户原始审核票；8 个票面矛盾只在分析层单独披露。
