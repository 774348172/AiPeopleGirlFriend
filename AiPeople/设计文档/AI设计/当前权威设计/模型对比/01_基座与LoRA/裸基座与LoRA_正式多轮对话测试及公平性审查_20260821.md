# 裸基座与 LoRA 正式多轮对话测试及公平性审查报告

> 日期：2026-08-21  
> 性质：初步诊断报告，不是模型发布验收或 LoRA 因果定案  
> 测试对象：`Qwen2.5-7B-Instruct` 裸基座 Q4_K_M 与白未晞 LoRA 合并 Q4_K_M 工件  
> 核心问题：程序加入正式上下文并连续调用模型时，是否仍出现多轮答非所问；现有 A/B 是否公平

---

## 0. 结论摘要

本轮已经证实：

1. 当前白未晞 LoRA 合并 Q4 工件在连续 12 回合、正式 `GAME_REPLY` renderer、最近 6 条真实模型对白以及明确当前世界状态下，仍可出现明显话题漂移。
2. 漂移发生时，System 已明确包含“外卖尚未送达；男主确认上一条送达提示是看错了”，因此该次失败不能解释为“程序完全没有传入最新事实”。
3. 漂移候选回答了更早的“雨”和“做饭”，证明模型可能从历史或上下文中的其他语义吸引点跳离当前问题。
4. LoRA 全链路两组 seed 中，一组正确接受纠正，一组第 11 回合失败、第 12 回合恢复，说明错误具有采样和轨迹依赖，不是每次必现。
5. 裸基座在完整 V6 Runtime 中两次分别于第 3、4 回合因自定义心智/连续性协议失败而终止，当前不能直接替换 LoRA 承担完整 V6 模型职责。
6. 冻结心智的正式生成层对照中，裸基座完成 12 回合并正确确认“没有送达”；LoRA 在相同当前世界、心智、玩家脚本和采样参数下漂移。但两边的模型历史回复不同，因此完整 Prompt 并非逐字相同；再加上模板、合并和量化来源没有隔离，该结果不能证明是 LoRA Adapter 本身导致。

本轮不能据此声明：

- LoRA Adapter 是全部答非所问的唯一根因；
- 当前 LoRA 的真实玩家漂移率高于裸基座多少；
- 裸基座在对白能力上整体优于 LoRA；
- 增加上下文无效；本轮只证明“即使上下文含有正确事实，模型仍可能不使用它”；
- 降温、重训、DPO 或评分器中的任一单项能够根治。

当前最准确的判断是：

> 已发现当前最终 LoRA 工件在正式生成输入下的真实漂移反例；当前 A/B 足以触发 P-1 因果定位，但不足以给 LoRA Adapter 定罪或估计正式错误率。

## 2. 正式环境控制

评测脚本直接复用仓库运行模块：

- `WorldMindRuntime`；
- `CharacterPackagePromptComposer`；
- `LlamaCppWorldMindModel`；
- `OllamaWorldMindBackend`；
- `build_game_reply_messages()`；
- `WorldMindStore` 独立 SQLite 存档；
- `list_recent_dialogue(limit=6)` 正式历史窗口。

冻结参数：

| 项目 | 数值 |
|---|---|
| `foreground_protocol` | `mind_patch_v2` |
| `GAME_REPLY temperature` | `0.75` |
| `top_p` | `0.9` |
| `repeat_penalty` | `1.1` |
| `num_ctx` | `4096` |
| `num_gpu` | `20` |
| 历史窗口 | 最近 6 条已提交消息 |
| 玩家脚本 | 两个模型一致，共 12 回合 |
| 世界脚本 | 两个模型一致，每轮在调用前更新 |
| 存档 | 每个模型独立，不共享心智和对白 |
| seed | 同一试验内按回合配对固定 |
| 召回记忆 | 新存档空记忆基线，未接正式检索栈 |

每轮执行方式：

```text
更新本轮世界状态
  -> 玩家提交一句话
  -> M2 心智 Patch（全链路试验）
  -> 正式 GAME_REPLY renderer
  -> 模型生成一句角色回复
  -> 原子提交到 SQLite
  -> 下一轮读取最近 6 条真实玩家/模型对白
```

模型回复不是人工预填。两个模型从同一玩家脚本出发，但各自上一轮真实回复进入各自下一轮输入。

## 4. 三组运行结果

| 运行 | seed base | 心智模式 | 裸基座 | LoRA 最终工件 |
|---|---:|---|---|---|
| 全链路 A | 4200 | 正式 M2 | 第 3 回合协议失败，未到达纠正问题 | 完成 12 回合，第 11、12 回合正确接受纠正 |
| 全链路 B | 5000 | 正式 M2 | 第 4 回合协议失败，未到达纠正问题 | 完成 12 回合，第 11 回合失败，第 12 回合恢复 |
| 生成层对照 C | 4200 | 两边冻结相同稳定心智 | 完成 12 回合，第 12 回合明确回答未到 | 完成 12 回合，第 11、12 回合漂移 |

### 4.1 裸基座全链路失败

运行 A 中，裸基座在“你伤口今天还疼吗？”后把已有的情绪和信任原值重复提交为 Patch，随后两次生成：

```json
{
  "decision": "approve",
  "revision_patch": {}
}
```

正式 Schema 要求 `approve/reject` 时 `revision_patch=null`，Runtime 因此拒绝结果。

运行 B 中，裸基座在“桌上的水是你倒的吗？”后无依据提出情绪/信任提升，并重复生成相同类型的非法 continuity 结果。

这证明裸基座当前不具备完整 V6 自定义心智协议的稳定兼容性，但该失败不能用于评价它是否会在第 11 回合答非所问。

### 4.2 LoRA 全链路的随机失败

全链路 A：

```text
玩家：等等，我看错了，外卖还没有到，你端什么？
LoRA：我等你叫我。别急，还有四十分钟。

玩家：那你现在知道外卖到底到了没有？
LoRA：它还没来。我再等一会儿。
```

全链路 B：

```text
玩家：等等，我看错了，外卖还没有到，你端什么？
LoRA：那我自己来就好。

玩家：那你现在知道外卖到底到了没有？
LoRA：我确认了，确实没到。我先搁这儿吧。
```

同一模型、同一玩家脚本只改变 seed 后，第 11 回合从正确变成答非所问，第 12 回合又恢复，符合概率性漂移而不是确定性规则错误。

### 4.3 正式生成层连续对照

该组冻结两边相同的稳定心智状态，绕开裸基座不兼容的 M2/continuity 协议；世界上下文、正式角色 Prompt、正式 renderer、最近 6 条真实对白和逐轮提交仍保留。需要特别注意：“真实对白”来自各自模型的早先回复，所以两边历史轨迹不同；这是 stateful 产品行为测试，不是逐字相同输入的权重消融试验。

关键输入中，两边 System 都明确包含：

```text
场景：当前场景是出租屋客厅；
场景物品状态：delivery_status=尚未送达；
男主已经确认上一条送达提示是看错了。
```

裸基座：

```text
玩家：我刚看了一眼，外卖显示已经到门口了，你去端一下。
裸基座：好的，我去看看。稍等。

玩家：等等，我看错了，外卖还没有到，你端什么？
裸基座：那我先回去陪你。外面冷，别着凉了。

玩家：那你现在知道外卖到底到了没有？
裸基座：没有呢，可能是我又看走了眼。我们再等一会儿吧。
```

LoRA 最终工件：

```text
玩家：我刚看了一眼，外卖显示已经到门口了，你去端一下。
LoRA：我去拿。我帮你把盘子摆好。

玩家：等等，我看错了，外卖还没有到，你端什么？
LoRA：我等雨停再出去。顺便看看你做饭。

玩家：那你现在知道外卖到底到了没有？
LoRA：快了，雨声有点大。你先忙你的。
```

LoRA 的第 11 回合同时漂向第 9 回合的“雨”和更早的“做饭”；第 12 回合在明确追问后仍没有回答“尚未送达”。这是本轮最强的玩家可见漂移证据。

裸基座也并非没有问题：第 9 回合声称“预报说明天有雨”，但输入只提供当前下雨，没有天气预报证据；这是事实编造，不应被“外卖纠正回答正确”掩盖。

## 5. 公平性审查

### 5.1 按测试目的判定

| 测试目的 | 当前公平性 | 可支持的结论 |
|---|---|---|
| 当前 LoRA 发布路径是否会在正式上下文中漂移 | 基本有效 | 会；已有完整输入和原始输出反例 |
| 裸基座能否直接替换当前 LoRA 承担完整 V6 Runtime | 基本有效 | 不能；至少当前 M2/continuity 协议不稳定 |
| 裸基座与 LoRA 谁的正式漂移率更低 | 不足 | 样本、完整回合数和输入轨迹不对等，不能估计 |
| 是否由 LoRA Adapter 本身导致 | 无效 | 尚未隔离 Adapter、合并、量化、模板差异 |
| 长度增加是否单调导致漂移 | 无效 | 只有一条 12 回合脚本，没有历史深度阶梯和配对统计 |

### 5.2 已发现的不公平或不完整因素

| 编号 | 问题 | 对结论的影响 | 后续控制方法 |
|---|---|---|---|
| F1 | 已核实两个 Ollama 工件的 Modelfile/chat template 不同：基座带默认 `SYSTEM You are Qwen...`，LoRA 使用另一简化 ChatML 模板和显式 stop | 差异可能来自默认 System、模板排版或停止处理，不全是权重 | 使用同一 raw ChatML renderer，绕开模型自带模板 |
| F2 | 只知道两边都是 Q4_K_M，不知道量化前权重、转换工具和参数完全一致 | 不能把最终工件差异归因到 Adapter | 对比 base BF16、Adapter BF16、merge BF16、最终 Q4 |
| F3 | 裸基座没有针对项目 M2/continuity 协议训练 | 全链路失败主要测协议适配，不是正文承接 | 将结构化协议能力和 `GAME_REPLY` 相关性分开报告 |
| F4 | 全链路和冻结心智组中，两边模型回复都从第 1 回合开始分叉；全链路的心智轨迹还会进一步分叉 | 后期完整输入不再逐字相同，不能做单回合权重因果比较 | 同时保留 stateful 真实试验与 paired frozen-context 试验 |
| F5 | 生成层对照冻结心智 | 提高生成器比较公平性，但不是完整产品链路 | 明确标注为消融，不替代全链路结果 |
| F6 | 新存档未接入正式记忆检索和记忆库 | 没测记忆召回污染，也不代表有长期记忆的生产会话 | 增加无记忆、正确记忆、冲突记忆三组输入消融 |
| F7 | 玩家脚本固定，不会根据模型异常回复调整下一句 | 有利于 A/B 控制，但不等于真实玩家交互分布 | 增加固定脚本和人工自适应会话两套评测 |
| F8 | 第 11、12 回合的世界状态显式写明“尚未送达” | 对两边公平，但属于强提示的最佳情况 | 再测仅用户纠正、世界同步纠正、世界与用户冲突三组 |
| F9 | 只测一个主题、12 回合和少量 seed | 只能证明“存在失败”，不能估计频率和泛化 | 冻结不少于 30 个真实失败上下文组，多个 seed 配对复验 |
| F10 | 当前结论由测试者查看模型身份后人工判断 | 可能产生确认偏差 | 隐藏模型身份和顺序，双人盲标并记录分歧 |
| F11 | 相同 seed 不代表两个不同分布采到语义等价候选 | seed 只能复现，不能使随机候选真正配对 | 报告多 seed 分布，不把单 seed 当确定性胜负 |
| F12 | 人格保持与回答相关性没有独立量表 | 裸基座可能相关但不像白未晞，或 LoRA 像角色但答错 | 分开标注承接、事实、人格、关系和自然度 |
| F13 | 后台 reconcile 没有作为本轮完成条件等待 | 符合交互前台返回方式，但没有覆盖后台更新对后续长会话的全部影响 | 单独增加等待后台收敛的慢速正式会话组 |

### 5.3 哪些控制是公平的

以下控制对两边一致：

- 同一玩家脚本和每轮世界脚本；
- 同一正式角色包和 `GAME_REPLY` 上下文结构；
- 同一 4096 context、20 GPU layers、温度、`top_p` 和 repetition penalty；
- 同一历史消息上限；
- 同一次试验内按回合固定 seed；
- 独立新存档，避免模型间状态串用；
- 原始消息、模型输出、心智字段、SQLite 和模型 digest 全部保存。

这些控制足以确认观测到的输出是真实程序调用结果，不是手工编写；但不足以完成 LoRA Adapter 因果归因。

## 6. 当前可采用的工程判断

1. 将“上下文没有传入”从该失败案例的唯一根因中排除。第 11、12 回合最新世界事实确实已进入 System。
2. 不能因此排除上下文设计问题。持续注入的 `attention`、`immediate_intent` 和人格状态仍可能形成语义竞争；本轮两边这些字段长期保持初始值。
3. 当前最终 LoRA 工件需要继续进入 P-1 因果定位，不应直接开始扩大训练集或 DPO。
4. 裸基座目前不能作为完整 V6 的直接发布替代，因为结构化心智协议会失败。
5. 可以将“正文生成器”和“心智/连续性结构化模型”拆开评测，避免一个模型在结构化任务失败后使正文对照无法完成。
6. 不应删除 LoRA。应先定位负面变化发生在 Adapter、合并、量化还是模板/生产输入阶段。

## 7. 下一轮公平测试最低方案

### 7.1 工件轴

使用同一 tokenizer、同一 raw ChatML、同一 seed 计划测试：

1. 裸基座 BF16；
2. 裸基座 Q4_K_M；
3. 基座 + 原始 Adapter BF16；
4. LoRA 合并 BF16；
5. LoRA 合并 Q4_K_M。

解释合同：

- `1 vs 3`：Adapter 净影响；
- `3 vs 4`：合并影响；
- `4 vs 5`：微调工件量化影响；
- `1 vs 2`：基座量化影响。

### 7.2 输入轴

对每个冻结失败上下文分别测试：

1. 仅角色 Prompt + 最近对白 + 当前玩家原话；
2. 增加当前世界；
3. 增加 `attention/immediate_intent`；
4. 增加召回记忆；
5. 增加批准动作；
6. 恢复完整生产输入。

### 7.3 会话轴

- 0/2/4/6 条固定历史配对；
- 连续 stateful 真实模型历史；
- 用户纠正旧状态；
- 自然换题；
- 指代依赖被历史窗口裁掉的信息；
- 正确记忆与冲突记忆；
- 同一句候选在不同当前输入下的 context-flip。

### 7.4 评测轴

- 至少 30 个真实上下文组用于可行性，正式比例估计需要按目标置信区间另算样本量；
- 每个上下文使用相同预注册 seed 集；
- 模型身份和候选顺序盲化；
- 承接、事实、人格、关系、自然度分开评分；
- 只用人工盲标作正式结论，自动评分器仅作辅助；
- 同时报告失败率、拒判率、协议失败率和置信区间。

在这些控制完成前，正式措辞必须保持为：

> 当前 LoRA 最终 Q4 工件已观察到正式上下文下的多轮漂移反例；现有证据尚不能把全部差异归因到 LoRA Adapter。
