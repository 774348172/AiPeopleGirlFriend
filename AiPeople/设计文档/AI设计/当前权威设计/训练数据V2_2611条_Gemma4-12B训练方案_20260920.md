## 1. 基座结论

本轮固定使用当前生产路线的干净基座 `google/gemma-4-12B-it`，本地 revision 为 `707f0a3b8a3c7ad586ed01e27eafbad8a27dd0f7`，采用 NF4 QLoRA。不得改用 Qwen3.5-4B，也不得从当前或历史白未晞 Adapter 续训。

选择该基座是为了和当前生产模型保持同一基础能力、tokenizer、聊天模板和推理栈，使“裸基座 vs 新 Adapter”成为可解释的因果对照。Qwen3.5-4B 是另一条离线资产路线，不属于本次训练。

## 3. 训练包施工

先建立不可变训练包，不直接让训练脚本读取会继续变化的 V2 目录。

1. 固定 V2 manifest、训练文件、metadata、Gemma 基座 revision 和 tokenizer/chat template 哈希。
2. 使用 Gemma 4 普通模式模板，关闭思考，逐行渲染完整消息。
3. 按对话 family 或共享历史连通分量分组切分，禁止同一长对话的连续窗口跨 train/dev。metadata 未完整保存 family 时，从发布审计源记录恢复，或按共享 memory/recent turns 建图分组；禁止随机按行切分。
4. 建议约 90% train、10% dev。封存泛化测试应使用未参与生成和调参的独立题集，不能从已看到目标答案的 2611 条中冒充封存测试。
5. 只监督最后 completion。prompt 中的历史 assistant 对白是证据上下文，不是本条目标；旧训练包“监督所有 assistant”的规则不适用于当前 prompt/completion 数据。
6. 逐行验证 prompt token 是完整训练序列的严格前缀；只放开最后 JSON 回复正文及轮次结束 token，system、历史对白和当前 user 全部标为 `-100`。
7. 禁止截断，禁止 packing。输出 split manifest、源哈希、family 分布、场景/任务分布、token 分布、监督 token 数和重复检查报告。

## 4. 首轮参数

| 项目 | 参数 |
|---|---|
| 基座 | 干净 `google/gemma-4-12B-it`，固定 revision |
| 方式 | bitsandbytes NF4 4-bit QLoRA |
| 最大长度 | 9216，禁止截断 |
| LoRA | rank 8，alpha 16，dropout 0；该值启用 Unsloth 快速 LoRA 路径 |
| 目标层 | Gemma language_model 的 q/k/v/o/gate/up/down；冻结视觉和音频分支 |
| batch | micro batch 1，gradient accumulation 8 |
| 学习率 | `1e-5` 起步，cosine，warmup 5% |
| epoch | 最多 1 epoch；先过按 step 小门 |
| 精度 | bf16，TF32 可启用 |
| 优化器 | `adamw_bnb_8bit` |
| attention | PyTorch SDPA；eager 最坏样本超过 33 分钟未完成，禁止用于正式训练 |
| seed | 固定并记录；正式晋升结论至少复验 3 个 seed |

历史 Gemma 训练使用 `5e-5`、1280 tokens，并出现 Adapter 能力回归。新数据虽与运行上下文更接近，但上下文约扩大五倍、监督答案很短，因此先用 `1e-5` 控制对裸基座能力的扰动。

## 5. 分阶段训练

### 阶段 A：数据审计与单步探针

- 建立 completion-only 构造器和逐 token mask 测试。
- 只跑 1 个优化步骤，验证 9216 tokens 下无 OOM、无 NaN/Inf、目标 token 非零、非语言分支未进入 LoRA、Adapter 可保存和重载。
- 记录整机显存、PyTorch allocated/reserved、单步耗时和实际 attention 后端。
- 单步失败时停止，不自动降低上下文长度。

### 阶段 B：小步检查点

- 依次保存 step 25、50、100、200。
- 每个检查点先跑静态同输入 A/B：干净 Gemma 裸基座与该 Adapter 使用完全相同 messages、模板、解码和 seed。
- 事实、未知、主体、旧新状态、意图覆盖或自然度出现显著回归时停止增加步数，不能用更低训练 loss 覆盖质量失败。

### 阶段 C：最多一轮候选

- 只有阶段 B 至少一个检查点通过小门，才允许完成最多 1 epoch。
- 不默认选择最终 checkpoint；按开发集和封存门选择候选。
- Adapter、合并权重和最终 NF4/Q4 部署形态分别复测，量化或合并造成的退化单独报告。

## 6. 晋升门

至少比较三臂：干净 Gemma 4 12B 裸基座、新 Adapter、当前生产 Gemma Adapter。GPT 可作为外部质量参考，但不能替代同基座因果对照。

1. 静态同输入集：当前事实、旧新冲突、未知、多事实、主体与来源、尚未完成的行动。
2. 自然对话集：闲聊、情绪回应、建议和意见，防止机械复述、过度拒答和角色味丢失。
3. 连续对话：至少一套 60 轮产品轨迹；静态同历史与各臂自历史分开报告。
4. 人工盲审：分别判断事实、意图覆盖、无依据扩展和自然度，不以关键词命中代替质量。
5. 新 Adapter 的关键能力不得低于 Gemma 裸基座，并须相对当前生产 Adapter 有明确改善；未通过则保留现网，不发布。

## 7. 明确禁止

- 不改用 Qwen3.5-4B。
- 不从旧 Adapter 续训。
- 不随机按行切分连续窗口。
- 不监督 prompt 中的历史 assistant 对白。
- 不把 8641-token 样本截断到 8192、4096 或 1280。
- 不因训练 loss 下降直接发布。
- 不直接启动 DPO、RLHF 或 RPO；当前 V2 是正样本 SFT 数据，不是可靠的同输入成对偏好集。

## 8. 下一施工项

训练包已经冻结：train 2332、dev 279，最长 8641 tokens，训练/验证泄漏组交叉为 0。SDPA 单步最坏样本探针用时 38.31 秒，整机显存峰值 23935 MiB，loss 2.4008，328 个语言 LoRA 模块，Adapter 成功保存。PyTorch allocated/reserved 统计超过物理显存，说明 Windows WDDM/Unsloth 存在统一内存或梯度卸载，正式训练仍须按小步门推进。

首次阶段 B 使用 micro batch 1、梯度累积 8，在第 1/25 步后发生 CUDA OOM，没有产生 step 25 检查点。单步探针未覆盖不同长度样本的连续反向传播和梯度累积，不能再作为阶段 B 的唯一显存门禁。

2026-09-22 使用相同冻结输入、干净 Gemma 基座、9216、NF4、SDPA 和累积 1，独立固定顺序测试 4553、6632、7492、8559、8641、8641 tokens。6/6 步完成，无 OOM，约 656 秒；整机 GPU 峰值 24068 MiB。第 3–6 步耗时分别为 166、157、145、121 秒，存在严重显存贴边后的吞吐下降。该结果仅证明这组连续样本和累积 1 能跑通，不证明整个 2332 条训练集可长期稳定运行，也不授权直接重启阶段 B。

对 2611 条输入按原有标题进行 Gemma tokenizer 独立分段计数：完整序列平均 6408 tokens；`[明确未知]`平均 2265、稳定角色知识 1919、`[当前权威事实]`1403，三段合计约 5587 tokens；`[相关记忆]`271，其他对话与目标回复仅约 48。最长样本中前三段分别为 3566、1919、2287 tokens。分段独立 token 化与完整 chat template 有少量边界差异；报告仅供容量归因，不是修改或裁剪训练输入。

下一步先决定训练内存路线：累积 1 需要重新定义有效 batch、学习率与步数，并通过更长连续、跨场景的稳定性及吞吐门；或设计生成、训练、运行时一致的确定性上下文投影，重新冻结数据。禁止直接截断旧包到 4096，也禁止将本次 6 步探针当作全量训练通过。
