# Unity 统一游戏时钟与动作计时（2026-09-28）

本轮承接《Unity快照有效性与重连恢复_20260928.md》。Unity 为正式游戏时间源，后端使用随本轮世界一起提交的时间；不再让 Unity 动作倒计时和正式对白各自推进一个时钟。仍不启用模型动作或后台记忆消费，不改训练权重。

## 实现

- 新 `GameTimeline` 使用未缩放帧间隔，按选定倍速推进一次，导演移动和做饭倒计时消费同一游戏时间增量；Unity 全局 timeScale 同步暂停/倍速供动画和其他已有表现使用，不在动作上重复乘倍速。
- 支持暂停和 0.1–8 倍速。暂停时不开始/推进/完成导演动作，白未晞实际移动投影为 idle；当前动作事实注明游戏已暂停。倒计时到期仍须执行器生成真实实体后确认，暂停不制造完成回执。
- `game_snapshot` 升级为 schema 3，包含 `game_clock`：ready、elapsed_seconds、time_scale、paused。历元沿用正式后端的游戏初始时间 `0001-10-11 18:00:00`，与现实 UTC 无关；快照有效期和 HTTP 超时仍使用现实时间，暂停不会让旧请求永不过期。
- 后端收到合法快照后，世界状态和时钟数据随同一 `unity_observations` 事务提交。正式运行时、世界变更时间、模型输入时间读取该时刻，后端不再独立外推 Unity 存档时间。非法/未就绪/非有限数值/超范围/时间倒退均被拒绝。
- Unity 启动先取后端存档时间，与按 saveId 隔离的本地时钟记录比较，使用较新记录，再开放导演动作推进。网络未就绪会等待并重试，不能默默从零开始推进正式动作。
- 本地每 5 秒、暂停/倍速改变和正常退出时保存时钟；保存包含暂停与倍速。重开不累加程序关闭期间的现实时间。只初始化一次，后续查询旧服务端状态不会拉回正在运行的本地时间。
- 开发/迁移入口仍支持原后端时钟，修复其 pause 后查询自动重启问题，新增显式 resume；暂停可跨后端重启保留，重复 resume 不丢失此前已流逝时间。正式 Unity 存档不能由后端 pause/resume 建立第二个控制源。

本轮没有新增设置界面按钮。受已有本地 HTTP 请求保护的控制入口为 `POST /game/clock`，参数 paused 与 time_scale；控制在 Unity 主线程执行。对白本身不能调用此入口或改变倍速。

## 当前边界

- 后端展示的是最近一次已接收快照的游戏时刻，不在客户端失联或快照过期后继续自行走时；`game_observation` 仍标明 current/stale/unknown。恢复对白时会重新采集。当前无时钟后台心跳，不把旧的采集时刻冒充实时钟表。
- 当前保存的是时钟，不是全屋世界存档。程序重启不会自动恢复未完成做饭、持有物、角色位置或旧动作；不因时间恢复而补发旧完成事件。
- 异常强杀可能损失最近一次本地保存之后的时间（通常最多约 5 个运行现实秒乘倍速），与服务端最后接受记录取较新值避免倒退到已确认时间。正常退出和控制改变即时保存。本轮不承诺完整崩溃恢复。
- 昼夜美术、天气、饥饿疲劳、预约调度尚未接入此时钟；它们需要真实程序状态后再逐项施工。几何测试仍可独立创建不带 Timeline 的导演，正式 App 总是绑定统一时钟。
- 按用户要求未做八小时测试。本轮未提交或推送 Git。

建议下一步补齐家具家电的结构化实体与最小可交互状态，优先厨房设备；不要把装饰模型或贴图直接当成已经运行的设备。
