# Unity 人物位置、动作回执与实体快照（2026-09-28）

本轮承接《Unity场景事实覆盖审计与显存优化_20260928.md》的下一块，落实实际位置、执行结果和有限实体注册表的同轮输入。上游仍为《游戏-LLM接口契约设计_20260827.md》和《程序施工计划_权威状态闭环_V1_20260911.md》。这是 A 块的部分落地，不代表完整权威状态协议或模型动作闭环已完成。

## 实现范围

- Unity 在主线程一次采集两个人物实际 Transform、移动阶段、已注册实体、进行中动作和最近回执，随对白提交 `game_snapshot`。保留旧 `scene_facts` 输入兼容。
- 快照包含 `save_id`、`world_id`、本次 Unity 实例 ID 和递增序号。后端拒绝跨存档输入、同一实例非递增序号、不一致的持有人房间、重复实体/动作 ID、错误的动作阶段及非有限坐标；手持物使用稳定实体 ID。
- 七个房间使用已校准房屋坐标的保守内部区域。墙边/门口未覆盖处明确上报“出租屋内（具体房间未确认）”，不把目的地或最近锚点当当前位置；未改变房屋尺寸、碰撞阈值。
- 动作依次执行，区分排队、行走、受阻、执行、等待确认及成功/失败/拒绝。移动仅在物理到达后完成；做饭抵达后开始计时，实际生成面碗后才确认；计时器不能独立宣告成功或写入物品。
- 实体目前仅登记水杯、纸箱和运行时生成的面碗。拾取检查真实实体、可拾取标记、所有者、距离和通路，转移实体后才回执成功。生成面碗使用唯一 ID，注册表上限 32，回执保留最近 8 条。没有把全部家具冒充已登记。
- 正式聊天通过 `SubmittedGameWorld` 绑定本轮快照，进入已有运行时投影与持久化快照；不在同一轮另取一个时刻的远端状态。状态查询的写入/初始化与聊天共用锁，普通只读查询不等待生成锁。
- 模型仍只生成对白。模型动作及玩家事实报告确认通道未启用；本轮实测动作由测试程序通过已有游戏动作接口提交。

## 验收

1. 后端相关测试 **41/41** 通过，包括结构校验、同轮隔离、稳定持有 ID、跨存档/过期拒绝，以及状态写入不能插入聊天的锁检查。
2. Unity 初轮 **19/19** 通过（含启动）；拾取修复后 **18/18** 回归通过（不含启动项）。覆盖七个房间、未知门口、真实到达、门阻挡/恢复、缺失目标、实体生成、真实拾取和重复确认。之后增加存档/世界标识及旧活动字段同步，最终 Windows 构建成功，并完成以下实机复测。
3. 最终 Windows 包：`UnityClient/Builds/CatGirlfriend-GameSnapshot-20260928/CatGirlfriend.exe`。运行副本使用独立 `gamesnapshot20260928` 存档和证据目录内 SQLite；未更改正式存档。应搭配本轮更新后的后端代码使用。
4. 首轮真实拾取暴露空目标位置 ID 导致行走状态提前结束：实体未转移、失败回执正确，模型也没有虚报成功。修复为使用动作实例 ID 作为无位置 ID 动作的行走标记，并延长拾取测试距离，验证先移动再转移。
5. 最终 **8/8** 次 Unity → 正式 Gemma 4 12B + V3 step2332 → Unity 回复语义正确：

| 厨房门关闭，前往厨房受阻 | 还没到厨房，我还在客厅。 |
| 开门后实际进入厨房 | 到了，我在厨房。 |
| 白未晞在厨房、男主在客厅 | 我在厨房，你在客厅。 |
| 水杯成功转移给白未晞 | 水杯在客厅，我拿着。 |

最终脚本强制断言水杯 owner 为 `baiweixi`，拾取回执为 completed 且结果实体为 water_cup。数据库也核对到受阻活动、真实房间和持有事实；不只是 UI 文本正确。回复耗时 3.281–4.781 秒。两轮共 16 次真实回复，首轮拾取失败证据保留。短测不代表模型永远不会受旧对白影响。

## 显卡采样

同机 RTX 4090、完整后端与 Unity 场景/小窗同时运行，继续使用 SDPA、6144 上下文上限和 96 输出 token；未更换模型或训练权重。

| 指标 | 最终复测 |
|---|---:|
| 连续对白后整卡待机显存中位数 | 11.071 GiB |
| 生成阶段整卡采样峰值 | 12.169 GiB |
| 后端待机专用显存峰值 | 9.514 GiB |
| 后端生成专用显存采样峰值 | 10.627 GiB |
| Unity 场景 + 小窗专用显存 | 约 0.385 GiB |

整卡值包含桌面和其他进程；采样间隔约 1.6–1.7 秒，可能漏掉瞬态峰值。生成采样 GPU 利用率峰值 99%。本轮不构成 12GB 显卡或长上下文验收，按用户要求未做八小时稳定测试。壁纸挂载日志校验通过，未另做外观截图验收。

测试副本先于模型加载完成启动，日志有两次后端未监听时的连接失败；服务就绪后上述 8 轮均成功，无 Unity 执行异常。完成后已正常退出本轮测试玩家及后端、停止采样，整卡显存回落到 1207 MiB；未终止用户其他程序。

## 仍未完成与下一步

后续进展：整份快照的有效期、来源、防回放与重启恢复已继续施工，最新范围和验收见[Unity快照有效性与重连恢复_20260928.md](Unity快照有效性与重连恢复_20260928.md)。以下保留本轮完成时的缺口记录。

- 版本目前用于同一实例顺序校验；尚非每项事实的完整 source/observed_at/known/unknown/stale 合同，也没有完整断线过期、旧实例重放隔离或 Unity 世界跨重启恢复。
- 房间位置同步不等于视线/听力权限已实现。站坐躺、身体状态、天气、设备运行仍需各自真实程序来源，不能从当前快照推导。
- 做饭仍使用 Unity deltaTime，后端 GameClock 仍独立；当前实体效果为占位表现，拾取没有完整手部动画，暂未提供女主放下物品或完整容器/库存系统。
- 最近回执是历史结果，不代表人物仍在该目标房间或物品仍由同一人持有。
- 未实现取消动作、模型动作授权、预约确认和后台长期记忆消费；未上传/提交 Git。

建议下一块优先补齐**快照的来源、有效性与断线/重连处理**，使旧游戏状态不会在客户端断线或重启后继续冒充实时事实，再统一游戏时钟并扩展设备与身体状态。
