## 四、M1 阶段 A 桥接（步骤 5–11，核心）

### 步骤 5：契约核对 + 开发桩（可选）
- 开工当天核对（见 §十一 清单）：端点行为、NDJSON 事件、`WorldInput` 字段与默认值、5 个点位词汇、无对外历史接口（历史由客户端本地保存，与 web 端 `localStorage` 语义一致）。
- 后端模型资产不可用时的替代：本地契约桩（复刻三端点与事件序列的**开发用**最小服务），仅解锁前端开发，**不得用于验收结论**。
- 验收：核对清单逐项打勾并记录；桩与真实服务行为差异记录在案。

### 步骤 6：`DialogueClient`
- HTTP 客户端 + NDJSON 增量解析：`{"type":"delta","text"}` 追加；`{"type":"done","value"}` 定稿；`{"type":"error"}` 展示错误行。
- 取消与超时：生成中允许取消（断开连接即放弃本轮显示，不做本地半提交）；`chat` 失败**不自动重发**（由用户重发）；`health/status` 允许有限重试。
- 验收：解析器单测（含跨包边界、半行、错误行）；手动 3 轮真实对话。

### 步骤 7：`GameStateModel`
- 拉取时机：进入场景、每轮对话 `done` 后、手动刷新；不做高频轮询。
- 缓存：`game_time`、`world`（version/location/activity/scene）、`heroine.living_mind`、`heroine.relationship`、队列计数。
- 降级：请求失败保留上次状态并提示"数据未更新"，不阻塞输入。
- 验收：断网状态不崩溃、恢复后自动转正常。

### 步骤 8：点位映射与 `PlayerController`
- 首版点位（与后端 `location_id` 词汇对齐，仅出租屋三类先做）：

| location_id | label | 场景点位 |
|---|---|---|
| `apartment_table` | 出租屋餐桌旁 | 餐桌区锚点 |
| `apartment_kitchen` | 出租屋厨房 | 厨房区锚点 |
| `apartment_door` | 出租屋门口 | 门厅锚点 |
| `lane_corner` | 巷口 | M4（场景外，暂不可达） |
| `coffee_shop` | 咖啡厅 | M4 |

- 第一人称移动 + 靠近锚点自动切换当前点位；合成并上报 `WorldInput`（`location_id/location_label/activity/body/held_item/scene`），字段集与默认值以 `baiweixi_chat_app.py::WorldInput` 为准。
- 验收：走动到各锚点，上报字段与场景一致；越界不可达点位不可误报。

### 步骤 9：`ChatUI`
- 输入框（长度限制对齐后端 1000 字）、消息列表、**生成中占位行**、`done` 后替换定稿、错误行样式。
- 本地历史：按 `save_id` 键持久化（与 web 端同语义；它是显示缓存，不是事实源）。
- 验收：生成期间显示"正在说"；中途失败不留半截为她说的话；重启客户端历史仍在（本地缓存）。

### 步骤 10：`Apartment` 场景 blockout + `CharacterActor` 占位
- 必备陈设：门、窗、餐桌椅、厨房与锅具、床、**纸箱**（不可移除道具）；暖灯与阴雨氛围；第一人称相机。
- 角色占位：静态模型入场 + 呼吸/轻微摆动微动（禁用其未经验证的动画假设）；也可用立绘卡片过渡。
- 验收：场景内可自由走动；纸箱存在且不可被玩家移除；角色可见且不穿模。
