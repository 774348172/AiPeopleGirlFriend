## 1. 文档性质与权威关系

本文件不是新的 AI 架构，也不替代 V6 权威设计和现有施工总纲。

本文件只解决一个施工排序问题：在白未晞模型角色质量尚未收敛的情况下，如何继续把已经设计完成的 V6 AI 系统建设成可冻结、可恢复、可测量的正式工程系统。

发生冲突时按以下顺序执行：

1. `项目框架需求.md`。
2. `AI女友最小心智系统设计.md`。
3. `本地AI恋爱桌面宠物产品集成设计.md`。
4. `AI聊天核心施工优先级总纲.md`。
5. 本施工执行分册。

本文件中的 `SYS-09～13` 是 `WMR-08` 未完成系统工程的内部施工编号，不创建第二套心智主干，也不改变 `WMR-00～08` 的历史结论。

## 2. 本轮施工决策

### 2.1 现在优先完成

- 正式本地 Embedding 与 Reranker 检索栈。
- 五种 WorldMind 模式及独立 `MEMORY_PROPOSE` 模式的结构协议可靠性。
- 模型失败时的保守回退、重试、取消、幂等和原子事务保护。
- 一小时真实模型运行、并发世界更新、崩溃和跨重启恢复。
- 发布推理栈、模型生命周期、KV Cache、模型切换、显存和延迟。
- 独立的 `system_engineering_gate` 系统工程冻结。

### 2.2 明确延期但不删除

- 白未晞 89 个自动质量案例的角色质量收敛。
- 已确认的角色失败和联合失败修复。
- 4 个人工长会话验收。
- 白未晞 V2 训练、数据修订和再次训练。
- 白未晞正式基础模型、checkpoint 和量化版本的最终选择。
- 角色语言自然度、恋爱感、口吻和长期人格质量结论。

延期项必须保留原始案例、报告、输入输出和归因，不能因为本轮不施工而改成“已通过”。

### 2.3 允许使用的模型

本轮可以使用以下任一模型作为工程探针：

- 当前白未晞模型。
- 秦未晞历史模型。
- 未经角色训练的原始 Qwen3-4B 或后续明确登记的本地模型。

工程探针只证明真实模型调用、结构协议、事务、调度、恢复和性能采集链路。它不能证明白未晞角色质量，也不能成为隐式产品角色回退。

每次测试必须在报告中冻结：

- 模型名称与用途。
- 原始工件路径或来源。
- 工件 SHA256 或服务 digest。
- 量化、上下文和推理参数。
- 该模型被允许证明和禁止证明的结论。

确定性 FakeModel 仍可用于故障注入和单元测试，但不能单独证明真实模型适配、真实延迟、真实显存或一小时真实模型稳定性。

## 6. 施工大块 A：真实检索与模型协议

### 6.1 `SYS-09`：正式 Embedding 与 Reranker

> 状态：已完成（2026-08-12）。正式检索报告：`eval/world_mind_p0/sys09_retrieval_report.json`。

#### 目标

把当前女主独立 Repository 的真实链路闭环为：

```text
当前女主 Repository
-> 正式 Embedding
-> 库内向量候选
-> 稳定 TopK

```

当前候选可继续实测 `bge-small-zh-v1.5` 与 `Qwen3-Reranker-0.6B`，但只有实测通过并进入正式 manifest 后才成为发布工件。

#### 施工内容

- 下载或整理可离线发布的正式模型工件、tokenizer 和必要配置。
- 为 Embedding 与 Reranker 分别建立正式 manifest，冻结工件哈希、维度、最大长度、精度、设备和运行后端。
- 把正式工件接入已有 `local_bge`、`qwen3_reranker` 和 `HeroineMemoryRepository`，不复制第二套召回实现。
- 启动时校验模型维度、manifest、索引代际和角色 Repository 身份；不一致时明确失败，不静默降级为测试替身。
- 保持“先打开当前女主 Repository，再在库内召回”的顺序，禁止先做跨角色全局召回再过滤。
- 冻结中文记忆检索工程集，覆盖直接相关、间接相关、同义表达、时间线、修正关系、无关记忆、空库、跨存档和跨女主隔离。
- 对 CPU、GPU 或混合执行方案分别测量，不预设 Reranker 必须常驻 GPU。
- 保留确定性替身作为单元测试依赖注入，不允许进入发布配置。

#### 内部测试

- 正式工件冷启动、热启动、重复加载和关闭释放。
- Embedding 维度、归一化、空文本、超长文本、中文标点和批处理。
- Reranker 分数稳定性、相同分数稳定排序和候选截断。
- 记忆修正后旧事实不重新成为最终选择。
- 同一公开事件可在两个女主 Repository 中形成不同私有表示，但互不读取私有内容。
- 跨 `save_id`、跨 `character_id`、跨索引代际读取全部拒绝。
- 重启后向量索引可验证或重建，结果不因数据库遍历顺序随机漂移。
- 前台召回到来时，低优先级批量索引能够暂停或让出资源。

#### 交付物

- 正式 BGE manifest 与工件清单。
- 正式 Reranker manifest 与工件清单。
- 冻结检索工程集及其 manifest。
- 冷热启动、召回正确性、隔离和 P50/P95 报告。
- 发布配置中“正式工件”和“测试替身”的强制分界。

- 跨存档和跨女主私有记忆泄漏为 `0`。

- 普通记忆选择新增 P95 小于 `300 ms`，并明确包含真实 Embedding、候选搜索和真实 Reranker。

### 6.2 `SYS-10`：结构协议、重试与保守回退

> 状态：已完成（2026-08-12）。联合验收报告：`eval/world_mind_p0/sys09_sys10_completion_report.md`。

#### 目标

让真实模型偶发超时、截断、无效 JSON、Schema 错误或语义越权时，系统仍保持一致、可诊断、可重试，不提交错误状态，也不伪造角色已经说过的话。

#### 协议范围

V6 实际包含五种 WorldMind 模式和一个独立记忆提议模式：

| 调用模式 | 系统职责 |
|---|---|
| `MIND_PATCH_V2 / M2` | 只提出本轮女主心智变化和受控动作，不生成回复正文 |
| `WORLD_CONTINUITY_REVIEW` | 审查越权、断裂和关系跳变 |
| `GAME_REPLY` | 从批准状态生成纯自然语言唯一角色回复 |
| `POST_REPLY_WORLD_MIND_RECONCILE` | 整理刚提交回合的持续含义 |
| `FIVE_MINUTE_WORLD_MIND_RECONCILE` | 整理时间段内的心智变化和遗漏 |
| `MEMORY_PROPOSE` | 为当前女主独立记忆库提出长期记忆候选 |

不得因为现有工程预冻结只统计“五种模式”，而从本阶段的协议和长稳测试中漏掉 `MEMORY_PROPOSE`。

#### 施工内容

- 对结构化模式收紧 JSON Schema：字段长度、数组数量、枚举、必填项、`additionalProperties` 和版本身份必须有界；`GAME_REPLY` 不使用 JSON Schema 包装正文。
- 同时保留 provider 原生 JSON Schema 约束和 Runtime 二次解析校验，不能只依赖 Prompt 要求模型“输出 JSON”。
- 建立统一模型调用结果和失败码，至少区分服务不可达、超时、取消、token 截断、空输出、JSON 解码、Schema、硬不变量、Critic 拒绝、快照漂移、版本冲突和提交失败。
- 重试必须绑定同一个 `request_id`、冻结快照和候选状态版本，不得在重试中偷偷读取新世界状态并混成同一回合。
- 记录每次尝试的模式、输入版本、模型工件、token、延迟、失败码和最终处理，不记录无法控制的模糊“模型失败”。
- 为结构失败建立有限重试和最小上下文重试，禁止无限生成。
- 把模型协议失败与角色语言质量分开统计。

#### 保守回退合同

| 失败位置 | 允许的系统处理 | 禁止行为 |
|---|---|---|
| `MIND_PATCH_V2 / M2` | 有限重试；仍失败则本轮无提交 | 根据关键词硬写情绪或活动，或绕过 Patch 直接回复 |
| `WORLD_CONTINUITY_REVIEW` | 有限重算；仍失败则不批准候选 Patch，使用 `keep` | 未审查候选直接入库 |
| `GAME_REPLY` | 有限重试；仍失败则本轮状态与对白均不提交并提供重试入口 | 程序拼一条假角色回复、提交已批准 Patch 或提交半条对白 |
| 回答后整理 | 保留已提交回复，任务去重后重试 | 回滚已经正式显示的回复 |
| 五分钟整理 | 保持上一稳定心智，合并积压后重试 | 阻塞 GameClock 或程序世界更新 |
| `MEMORY_PROPOSE` | 不产生记忆，任务去重后重试 | 用程序关键词直接制造长期记忆 |

#### 内部测试

- 每种模式注入截断 JSON、错误枚举、超长字段、额外字段、缺失版本、错误角色、错误快照和非法动作。
- 在模型生成、Critic、事务写入和提交确认各阶段执行取消与崩溃注入。
- 验证同一请求重试和 completed replay 不产生重复对白、重复状态转换或重复记忆。
- 使用至少一个真实工程探针覆盖全部六类调用；FakeModel 只承担故障形状覆盖。
- 验证日志能把“模型未遵守结构”与“Runtime 接受了非法结构”区分开。

#### 交付物

- 六类调用的协议矩阵和冻结 Schema 清单。
- 统一失败码、重试策略和模式级指标。
- 故障注入测试集与真实模型协议压力报告。
- 结构失败、保守回退和原子性审计报告。

#### 闸门

- 所有非法输出均在正式提交前被拒绝，非法提交数为 `0`。
- 所有失败路径均不会显示未提交回复，不会留下部分世界状态或跨角色记录。
- 六类模式至少各有真实模型成功证据，不能只由 FakeModel 证明。
- 固定工程压力轨迹中不得出现无限重试、队列永久占用或不可恢复卡死。
- 若工程探针持续无法满足必要结构合同，应记为“模型协议兼容失败”；系统运行时保护可以通过，但真实模型适配闸门不能通过。

## 7. 施工大块 B：真实长稳与发布推理栈

### 7.1 `SYS-11`：一小时、并发、崩溃与恢复

> 状态：已完成（2026-08-12）。真实模型长稳报告：`eval/world_mind_p0/runs/sys11-20260812-143630/SYS-11验收报告.md`；机器报告：`eval/world_mind_p0/runs/sys11-20260812-143630/report.json`。

#### 目标

把 `WMR-07` 的模拟长轨迹升级为真实模型参与的可重复稳定性测试，证明系统在世界持续运行、前后台模型任务交错和故障发生时不会撕裂世界线。

#### 冻结工作负载

建立固定一小时工作负载，至少包含：

- `GameClock` 连续运行，不因聊天、模型调用或后台整理暂停。
- 50～100 轮前台对白，包含短回复、80 token 和 160 token 档位。
- 男主位置、活动和场景由程序在回答前、回答中和回答后多次改变。
- 回答后整理在每次正式提交后触发。
- 五分钟整理按运行时间触发，积压时合并而不是逐次追赶。
- `MEMORY_PROPOSE`、物化、Embedding、Reranker 和召回穿插运行。
- 重复请求、取消、版本冲突、模型超时和结构失败。
- 进程终止、应用重启、投影删除后重建和最后完整世界线恢复。
- 同存档合成第二女主的状态、Prompt、记忆和后台任务隔离。

#### 并发重点

- 回答开始后世界继续变化，但当前回复只使用开始时冻结的 `TurnWorldSnapshot`。
- 下一轮重新 GET，必须看到程序已经准备好的最新男主位置、活动、场景和游戏时间。
- 前台回复优先于后台整理、索引和低优先级维护。
- 同一存档只有一条心智状态提交队列；不同角色的私有任务槽互相隔离。
- 崩溃恢复只恢复已提交事实，不把生成草稿当成已经发生。

#### 观测指标

- 完成、失败、取消、重试和恢复的事务数量。
- 重复事务、悬挂事务、半提交和投影版本漂移数量。
- 前后台队列长度、等待时间、合并次数和最大积压。
- 每种模型模式成功率、结构重试率和不可恢复失败率。
- 进程 RAM、GPU 显存、句柄、线程和数据库体积趋势。
- 世界快照、女主状态、记忆证据和最终回复的一致性。

## 9. 故障归因矩阵

| 现象 | 主归因 | 对系统闸门的处理 |
|---|---|---|
| 世界快照时间、位置或男主活动不是 GET 时最新值 | 系统 | 失败 |
| 回答期间读取了新状态并撕裂本轮快照 | 系统 | 失败 |
| 未召回本应进入候选的已提交记忆 | 检索系统 | 失败 |
| 记忆已进入 `SelectedMemoryFrame`，模型仍忽略 | 模型/角色 | 记录，不直接归为检索失败 |
| 跨存档或跨女主读取私有记忆 | 系统 | 失败 |
| 模型返回无效 JSON，但 Runtime 拒绝且无部分提交 | 模型协议事件 | 系统保护通过；真实模型兼容率单独判定 |
| Runtime 接受无效结构或留下半提交 | 系统 | 失败 |
| 模型看到正确快照仍把男主吃面说成自己吃面 | 模型语义或联合 | 角色质量延期；若硬校验本应阻止却显示，则系统同时失败 |
| 人设、口吻、关系节奏或城市称呼不正确 | 角色质量 | 不阻塞独立系统闸门，阻塞角色质量闸门 |
| 模型服务启动、健康检查、取消或关闭失控 | 发布集成系统 | 失败 |
| 性能或组合显存超标 | 发布配置/模型组合 | 失败 |
| 评测器误杀正确回答 | 评测系统 | 修正评测，不修改模型迎合错误规则 |

归因原则：

- “Runtime 正确拒绝了坏输出”证明保护机制有效，但不证明所选真实模型适合发布。
- “模型偶然输出了正确 JSON”不证明协议稳定，必须经过固定压力轨迹。
- “角色说错了”不能自动算成系统失败；“系统把可检测的越权错误正式提交了”也不能全部推给模型。
- 不能通过增加生活场景关键词规则把模型语义失败伪装成系统成功。

## 10. 双闸门与发布边界

后续报告固定保留三个结论：

```json
{
  "system_engineering_gate": "pending | passed | failed",
  "character_quality_gate": "deferred | passed | failed",
  "formal_p0_gate": "pending | passed | failed"
}
```

规则如下：

- `system_engineering_gate` 可以在角色训练质量延期时独立通过。
- `character_quality_gate` 在本计划期间保持 `deferred`，不得写成 `passed`。
- `formal_p0_gate` 只有系统工程和白未晞角色质量都通过后才能通过。
- 系统工程冻结后可以继续更换和训练角色模型，但更换工件必须重跑模型协议兼容、性能和必要回归。
- 当前阶段可以宣布“V6 系统工程冻结通过”，不能宣布“白未晞正式质量通过”或“产品 P0 通过”。
