## 二、施工步骤（最终版，6 步）

### 步骤 0：意图记账代码残留清理（纯删除，无行为变化）

- 删除 `intention_resolutions`：schema 属性、`_intentions_from_value` 解析、`IntentionResolution` 类型、`JudgeResult` 字段及校验、测试用例；
- 删除 `unresolved_intentions`：`TurnWorldSnapshot` 字段及校验、`judge_payload` 渲染；
- JUDGE_TURN 边界文本删"④对未收口意图的处理"及对应纪律句。
- 验收：全库 grep 无 `intention_resolutions` / `unresolved_intentions`；单测全绿。

### 步骤 1：动作清单接游戏导出（已有基础，待游戏侧）

- `action_manifest.py` 由自造改为**消费游戏导出的动作定义**（接口契约 §四）：id/描述/时长/效果/参数；
- 校验 id 集合与字段结构与游戏定义一致（单一来源）。
- 验收：runtime 与游戏动作定义一致；单测覆盖。

### 步骤 2：游戏投影（依赖游戏接口，可桩联调）

- 快照构建时读游戏状态：`pending_actions`（进行中动作+剩余秒数）、`current_activity`、`item_states`、男主/女主位置（接口契约 §五）；
- 实体投影**只有存在性**，不设来源属性（来源由记忆+推理承担，接口契约 §五）；
- 游戏接口未就绪时用 mock 游戏状态桩联调。
- 验收：桩状态下投影正确；游戏完成煮面后，下轮上下文出现面实体。

### 步骤 3：动作转发 + 回注通道（依赖游戏接口，可桩联调）

- 判断契约合法动作 → 校验 → 转发游戏执行；游戏拒绝（资源冲突/打断）→ 拒绝原因写入下一轮上下文固定字段（回注）；
- 验收：被拒动作回注后，模型下轮能基于原因自然圆场（评测用例）。

### 步骤 4：Critic 可选开关

- judge_v1 下默认不跑 Critic；配置开关开启时（actions 非空或 patch 变化大）跑定向审查，加"叙述游戏投影中不存在的事实"审查维度。
- 验收：开关开/关两态可用；默认关。

### 步骤 5：评测与回归

- 新增用例：格式遵循率（14B 实测）、动作闭环（提议→游戏→投影可见）、冲突场景（泡脚中被喊去跑步）、拒绝回注；
- 回归：chat01/02/diagnostic120 在 `mind_patch_v2`（默认回退）下无回归；`judge_v1` 下跑通主用例；
- 决策点：格式遵循率达标 → 默认协议切换 `judge_v1`。

## 三、明确不做（本轮边界）

- runtime 不做动作模拟（事件表/倒计时/到期扫描——游戏内部实现）；
- 不做意图记账/承诺表（已删除，世界状态即账本）；
- 不做实体来源属性（谁/何时/用什么——记忆+推理承担）；
- 不做心情量化与规则（模型自管，自由文本）；
- 不做 Critic 默认启用；
- 不做多角色泛化/插件系统；
- 不删除旧协议（保留为配置回退）。
