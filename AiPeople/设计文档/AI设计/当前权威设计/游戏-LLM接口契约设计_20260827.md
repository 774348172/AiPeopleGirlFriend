# 游戏-LLM 接口契约设计 V2

> 状态：当前权威架构设计
> 生效日期：2026-09-11
> 文件名保留 `20260827` 仅为兼容既有引用；正文版本与日期以本页为准。
> 取代：2026-08-27 版《游戏-LLM 接口契约设计》。旧版完整副本已归档至 `历史设计/游戏-LLM接口契约设计_V1_归档_20260827.md`。
> 适用范围：游戏、LLM runtime、当前 `plain_reply_v1/GAME_REPLY` 前台、状态写回、动作转发和可选回复审查。
> 不授权事项：本文不自动启用新模型、回复拦截器、重试、模板回复或新的训练。

## 一、修订结论

本版保留“游戏是世界唯一事实源、模型负责开放语义与自然表达”的主架构，同时删除一种不成立的期待：程序不能靠有限规则准确理解无穷自然语言，也不能因为权威事实已经进入 Prompt，就宣称模型最终回复一定正确。

系统将可靠性分为三层：

| 层 | 例子 | 责任与保证边界 |
|---|---|---|
| 结构化世界 | 实体位置、预约状态、动作是否完成 | 游戏负责；可做确定性校验 |
| 文本到结构 | “我放回老地方了”指什么 | 模型或人工参与；属于概率判断，不得伪装成确定事实 |
| 结构到对白 | 把“预约已取消”自然说出来 | 回复模型负责；可能出错，只能实测降低错误率 |

因此，P0 生产目标不是“程序判断所有对白对错”，而是：

1. 模型错误不得静默改写权威世界；
2. 结构化游戏事件必须稳定进入下一轮上下文；
3. 自由文本产生的候选事实必须保留来源和确认状态；
4. 任意模型校验器都只能被视为概率组件；
5. 开放对白允许残余错误，不宣称有限训练或有限规则能覆盖全部未来表达。

## 二、不可违反的边界

### 2.1 游戏拥有客观世界

- 游戏保存实体、位置、时间、人物外显状态、进行中动作、动作结果和业务状态；
- runtime 只读取冻结快照，不维护第二套客观世界；
- 模型回复、模型记忆和模型生成的 JSON 都不能直接改写权威世界；
- 权威状态的改变只能来自游戏事件、明确的结构化业务入口，或经过产品规定确认流程的文本报告；
- 动作是否完成以游戏执行结果为准，不以模型说“已经做了”为准。

### 2.2 程序只做封闭、机械判断

程序可以确定性检查：

- schema、字段类型、版本号和事务原子性；
- `entity_id`、`action_id` 和参数是否存在且合法；
- 游戏报告的动作状态是未开始、进行中、完成还是失败；
- 结构化事件是否成功写入以及下一轮快照是否可见；
- 训练、评测和生产是否使用相同渲染器及版本哈希。

程序不得用有限 `if/else`、关键词或正则宣称准确判断：

- 玩家真正意图；
- 代词、隐喻、反问、玩笑和“老地方”等开放指代；
- 任意自然语言回复是否完整、合理或符合角色；
- 文本中所有事实、主体、时间和来源是否正确。

关键词可以用于日志、候选召回或高精度风险提示，但“命中”不等于确定错误，“未命中”也不等于正确。

### 2.3 模型负责开放语义，但没有事实所有权

模型负责理解玩家自由文本、选择回应重点、生成白未晞自然对白，并可在专用协议中提出候选心智变化或动作。模型的任何判断都可能出错：

- 模型不能把一句“我记住了”变成世界写回；
- 模型不能凭旧记忆覆盖游戏当前状态；
- 模型不能把未检索到解释成“从未发生”；
- 模型或校验模型的 `PASS` 不构成真实性证明。

## 三、当前前台主链路

当前前台保持单模型、纯对白主链路：

```text
玩家输入（来自游戏）
  -> 冻结当前游戏快照
  -> 召回相关记忆和近期对白
  -> GAME_REPLY_CONTEXT_V1 唯一渲染
  -> Gemma + 白未晞 Adapter 生成纯对白
  -> 空文本、长度、协议边界和事务机械校验
  -> 提交并流式展示对白
  -> 后台记忆整理入队
```

这一主链路不要求模型生成 `ReplyFocus`、隐藏推理链、事实裁决 JSON、`JUDGE_TURN`、`mind_patch` 或动作 JSON。后台或专用结构化协议不得静默混入前台训练与推理。

普通聊天与自由表达不增加程序语义路由。若未来增加语义路由，必须作为概率模型单独评测，不能按规则命中率自证正确。

## 四、GAME_REPLY_CONTEXT_V1

训练、评测和生产共用同一版本化渲染器。前台输入固定包含：

```text
[角色锚]
[当前权威事实]
[本轮玩家事实报告]
[明确 unknown]
[当前世界]
[你此刻的状态]
[进行中的游戏动作]
[相关记忆]
[第三方对话证据]
[允许表达的动作]
[回答依据约束]
[玩家本轮对白]
```

合同要求：

1. 游戏已管理且与本轮相关的当前状态不能只存在于记忆中；
2. 旧事实必须标记为 `stale` 或带清楚的时间关系，不能与当前事实并列冒充有效状态；
3. 第三方话语保留说话人、原话和来源，不得渲染成白未晞的 `assistant` 历史；
4. `unknown` 表示当前证据边界，不表示事件永远不存在；
5. 玩家本轮原话必须完整保留；
6. 训练、评测和生产的字段顺序、角色锚、聊天模板及版本哈希必须一致；
7. 上下文完整只表示模型获得了证据，不表示模型一定正确使用证据。

## 五、玩家输入与状态写回

玩家输入分为三种来源，不能混为一种。

### 5.1 游戏操作事件

玩家通过游戏界面移动物品、取消预约或触发动作时，游戏直接产生结构化事件。事件成功后写入权威世界，下一轮从游戏快照投影给模型。

```json
{
  "actor_id": "protagonist",
  "action_id": "move_item",
  "object_id": "spare_key",
  "destination_id": "desk_middle_drawer",
  "status": "completed"
}
```

该路径不需要模型解释，属于最可靠路径。

### 5.2 结构化业务入口

预约、提醒、交易或其他产品功能若有明确 UI/API，由对应业务系统提交结构化变更。模型只能表达结果，不能代替业务系统完成操作。

### 5.3 玩家自由文本报告

玩家说“我把钥匙放回老地方了”时，系统不得仅靠关键词直接覆盖世界。自由文本首先是带来源的对话证据；需要进入世界时，必须形成候选更新并区分：

- `reported`：玩家原话报告，尚未成为游戏确认状态；
- `confirmed`：由结构化操作、明确确认或产品允许的确认流程提交；
- `unknown`：信息不足或指代不明；
- `stale`：曾经成立但已被当前状态取代。

候选抽取可由模型完成，但抽取结果仍是概率结果。存在主体、对象、位置或时间歧义，且该更新会影响后续世界时，应自然澄清；不能静默猜测。产品若允许某类明确玩家陈述直接生效，必须按具体业务入口限定范围，并保留原话、来源、模型版本和可纠正记录，不能扩展为“所有玩家陈述自动写入”。

## 六、动作闭环

```text
游戏导出动作清单
  -> 模型提出动作或玩家直接操作
  -> runtime 机械检查 action_id 和参数
  -> 游戏判断并执行
  -> 游戏返回 accepted/running/completed/failed
  -> 下一轮快照投影真实结果
```

- runtime 不自建第二套物理执行器；
- 模型负责开放语义上的提议，不拥有执行权；
- 游戏可以因资源、位置或状态拒绝动作；
- 模型提出动作不等于动作已经执行；
- 模型对白中对动作状态的错误表述不会改变游戏状态。

## 七、回复事实校验的定位

`REPLY_FACT_CHECK_V1` 保留为可选实验组件，默认只能运行在 Shadow：

```text
权威事实 + 玩家原话 + 模型回复
  -> 概率性校验器
  -> PASS / CONFLICT / UNSUPPORTED / UNCERTAIN
  -> 只记录，不修改世界，不阻断当前回复
```

它不得：

- 被称为确定性事实裁判；
- 使用有限关键词覆盖开放语义；
- 把 `PASS` 当成回复正确证明；
- 修改世界、记忆或玩家原话；
- 在未测误放和误杀时触发重试、替换或模板回复；
- 用校验器掩盖上游状态缺失和错误召回。

只有满足以下全部条件，某个狭窄、版本化切片才可以单独评审主动干预：

1. 输入范围是明确的封闭游戏事实，不是任意开放聊天；
2. 独立封存集和真实人工审核报告误放率、误杀率及不确定率；
3. 最终玩家可见好回复率相对基线有统计意义的净提升；
4. 人格、自然度、首字延迟和事务可靠性不退化；
5. 不确定、超时和模型故障默认不修改权威状态；
6. 干预范围、阈值、模型、版本和回退路径全部冻结。

一次重试或确定性事实核心只能是该专项切片通过后的产品策略，不能作为当前全局默认设计。由明确结构化 UI 事件触发的状态展示可以直接使用游戏数据，但不能把这条能力外推到任意自由文本问题。

## 八、LoRA 与训练边界

LoRA 主要负责：

- 白未晞语气、措辞和关系表达；
- 常见场景下先回应玩家本轮意图；
- 减少动作旁白、机械复述和无依据扩展；
- 提高使用当前事实、接受纠正和自然表达未知的概率。

LoRA 不承担确定性保证：

- 不能证明所有未来输入都已覆盖；
- 不能保证主体、事实、unknown 和多项回答永不出错；
- 不能替代世界状态、动作执行和事务边界；
- 训练损失下降不能证明产品正确率单调提高；
- 针对一个失败簇重训后必须检查能力迁移和新增回归。

继续训练必须有预先冻结的失败假设、训练目标和新封存集。若新 Adapter 只修复部分旧题同时新增同量错误，不得因训练已完成而升级生产版本。

## 九、记忆边界

- 当前客观状态来自游戏，不依赖记忆召回；
- 记忆保存共同经历、玩家报告、来源和时间关系，但不是第二套世界数据库；
- 玩家自由文本候选事实不得在记忆摘要中丢失 `reported/confirmed/unknown/stale` 区别；
- 后台模型整理不阻塞前台回复，也不得把猜测升级为确认事实；
- 召回失败表示本轮没有取到证据，不表示事实不存在。

## 十、故障与降级

| 故障 | 默认行为 |
|---|---|
| 游戏快照失败 | 不伪造当前事实；返回可重试错误或明确数据未更新 |
| 模型生成失败 | 不写世界；本轮不形成半提交 |
| 模型输出错误事实 | 不改变世界；记录人工或 Shadow 证据，允许玩家纠正 |
| 文本候选状态抽取不确定 | 保持 `reported/unknown`，必要时澄清 |
| 动作被游戏拒绝 | 保留真实失败状态并在下一轮回注 |
| 校验模型超时或不确定 | 默认不干预当前回复，不修改状态 |
| 后台记忆失败 | 前台已提交对白不回滚，任务继续入队或记录失败 |

这里的“安全”首先指世界状态不被污染，不等于玩家永远看不到错误对白。开放自然语言回复仍是概率结果，必须如实接受和度量残余错误。

## 十一、验收标准

### 11.1 确定性合同

以下项目应由自动测试做到全通过：

1. 游戏事件成功写入后，下一轮快照必然可见；
2. 模型对白不能直接改写世界；
3. 非法动作 ID 和参数不能转发给游戏；
4. 动作完成、失败和取消以游戏结果为准；
5. 事务失败不留下半轮对白或半个状态更新；
6. 训练、评测和生产渲染器版本一致；
7. 第三方对白不会变成白未晞历史回复；
8. `reported` 不会被后台摘要静默升级为 `confirmed`。

### 11.2 概率质量

以下项目只能通过冻结测试和人工审核报告，不能写成确定性保证：

- 答非所问率；
- 主体错位率；
- 当前事实使用率；
- unknown 编造率；
- 机械复述率；
- 白未晞角色自然度；
- 多轮状态纠正后的可见回复质量。

一次 60 轮轨迹不能估算全部玩家分布。发布至少要保留多条封存轨迹，并分别报告旧错修复、新增回归、双方共同失败和人工口径。

## 十二、明确不施工

本设计不授权：

- 为开放自然语言建立无限意图、话题或回答类型规则；
- 用正则、关键词和有限模板宣称覆盖所有玩家表达；
- 让小模型成为最终事实真理或自动修改世界；
- 让主模型的自然语言承诺代替游戏执行；
- 每轮强制多模型串行审核；
- 未经 Shadow 和人工净收益验证就拦截或改写回复；
- 为追求固定测试集满分而反复全量训练；
- 声称任意有限数据或单个生成模型可以保证开放域 100% 正确。

## 十三、与其他权威文档的关系

- 本文是游戏、runtime 和模型责任边界的最高层接口契约；发生冲突时，本文件关于事实所有权、自由文本状态写回和语义校验定位的条款优先；
- 《Harness组装与单次判断设计》仅约束后台/专用 `JUDGE_TURN` 路径，不是当前前台输入合同；
- 《动作执行闭环施工方案》继续有效，但“模型提议”不等于游戏执行；
- 《Gemma4全量混合Adapter生产基线与回退接入》继续约束模型工件和前台部署，回复事实校验须按本文第七节执行；
- 《训练数据与运行时能力边界》继续约束训练目标，运行时语义校验须按本文第七节执行；
- 《对白质量与训练目标验收标准 V1》继续作为人工语义口径，不得把其自然语言标准编译成无限程序规则。
