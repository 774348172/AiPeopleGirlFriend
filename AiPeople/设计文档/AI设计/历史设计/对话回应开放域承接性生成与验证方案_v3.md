## 0. 决策摘要

用户人工体验确认当前对白存在较多答非所问。这个问题不能通过以下任一单点方案完整解决：

- 扩充固定回应类型或逐话题规则；
- 只增加高质量 7B 训练样本；
- 让同一个 7B 先生成 `ReplyFocus`、隐藏意图或推导链，再相信它按自己的计划回答；
- 把“评分器没有发现错误”写成“已经证明回复正确”；
- 同 Prompt 换一次 seed，并把再次失败称为“已经修复”。

V3 接受一个不可回避的边界：

> 有限数据和有限模型无法对任意未来自然语言提供无分布假设的零错误保证。开放域、每轮必须输出角色对白、答非所问率为零，三者不能同时保证。

因此，V3 不承诺穷尽所有语义场景，而是把系统职责分成两个概率问题和一个确定性提交合同：

1. **生成概率**：7B 尽量提高正确候选在前 `K` 次生成中出现的概率。
2. **检测概率**：独立 0.6B 评分器只高精度识别“明显答错对象”，不负责给正常回复排名或证明充分承接。
3. **提交合同**：正式拦截模式不提交高置信明显错位候选；候选耗尽后不提交角色台词。

首版正式拦截目标链路保持最短：

```text
冻结的 GameReplyRequest
        ↓
7B 生成候选 R1
        ↓
既有硬门 + 独立 0.6B 明显错位检测
  ├─ 非 CLEAR_MISS：按发布策略决定提交或拒判
  └─ CLEAR_MISS：生成候选 R2
                         ↓
               同一套硬门 + 评分
                 ├─ 非 CLEAR_MISS：按发布策略决定提交或拒判
                 └─ CLEAR_MISS：本轮零提交并返回可重试系统状态
```

首版离线试验上限暂定 `K = 2`。这不是发布常数；只有完整管线的人工 `recovery@K`、最终风险、终止率和延迟证明第二候选有净收益，线上才启用 `K = 2`，否则保持 `K = 1` 或不发布。

本方案不引入 `ReplyFocus`。7B 只生成角色候选；0.6B 只判断候选是否构成高置信明显错位。二者都不能自证正确。

在进入上述候选链路前，必须先完成基座、LoRA、合并、量化和生产输入的因果定位。评分器只能降低残余坏回复的玩家可见概率，不能替代对生成链路根因的修复。

## 1. 问题、目标与硬边界

### 1.1 要解决的产品问题

V3 只聚焦以下用户可见缺陷：

> 角色回复流畅、可能符合部分场景或人格，但没有实质处理玩家当前表达，回答了旧问题、另一个问题、已被纠正的状态，或者输出了与当前交流没有可恢复关系的内容。

代表性失败包括：

| 公开上下文 / 玩家当前原话 | 错误候选 | 缺陷 |
|---|---|---|
| 玩家询问感情态度：“你喜欢我吗？” | “我还没打算走。” | 缺少公开桥接时回答了去留，而不是态度确认 |
| 旧回复声称外卖已到；玩家纠正：“外卖都还没有到，你端什么？” | “我把糖醋排骨端开一点。” | 继续使用已被否定的旧状态 |
| 玩家提出陌生知识问题 | “……雨停了。” | 回到场景或旧话题，没有处理当前求知请求 |
| 玩家明确追责 | 只复述玩家关键词或用万能拒绝 | 表面相关但没有可观察承接 |

### 1.2 不把训练数据误解为场景覆盖表

训练数据的职责不是列出未来所有问题，而是提高以下关系在未见上下文中的泛化概率：

```text
玩家当前贡献发生不兼容变化
              ⇒
合格回复的语义指向也应相应变化
```

例如，同一历史下：

```text
U1：外卖到了，你去端一下。
R1+：嗯，我去拿。

U2：外卖还没到，你端什么？
R2+：……是我记错了，还没送到。
```

将 `R1+` 放到 `U2`、将 `R2+` 放到 `U1`，可形成同口吻、同人物、同表面主题但当前指向不兼容的困难负例。这种数据训练的是上下文依赖，不是“外卖规则”。

即使如此，训练后的 7B 和 0.6B 仍可能在新表达、长上下文、隐喻、反讽、方言、歧义或分布漂移下失败。V3 只能通过高置信拦截、有界重采样和可选终止降低残余风险，不能把泛化当作保证。

### 1.3 不可能同时满足的三项要求

以下三项不能同时承诺：

1. 任意未来开放域输入都适用；
2. 每个请求都必须显示一句角色对白；
3. 显示的对白永远不答非所问。

若产品要求每轮必须输出角色对白，V3 只能声明 `best-effort` 降错，不能声明选择性风险保证。若产品要求显著降低玩家可见答非所问，则必须允许少量请求以非角色层技术状态结束，并由 UI 提供重试。

### 1.4 可声明与不可声明的保证

可以声明：

- 在冻结、近似部署分布的独立人工测试集上，已提交回复的答非所问风险及置信上界；
- 完整 `K` 候选管线的覆盖率、终止率和净修复量；
- `PRECISION_FIRST` 与 `STRICT_SELECTIVE` 结构上不提交已被高置信判为明显错位的候选；
- 模型、阈值、输入投影、采样计划和评测集均版本化可审计。

不可以声明：

- 任意自然语言上的零错误；
- 模型内部真实理解或真实因果；
- 多 seed 候选彼此独立；
- 0.6B 高置信度等于语义证明；
- `NOT_CLEAR_MISS` 等于事实、安全、人格、关系和总体质量全部通过。

### 1.5 基座与 LoRA 的因果边界

不加载 LoRA 的 `Qwen2.5-7B-Instruct` 也可能在多轮对话中答非所问。模型支持较长上下文，只表示输入可以被接收，不表示任意位置的相关信息都能被稳定利用。7B 的能力上限、历史裁剪、Prompt 冲突、旧记忆干扰和采样随机性都可能使裸基座回答旧问题或忽略本轮纠正。

LoRA 可能改变或放大该风险，但未经同条件对照，不得声明“当前问题就是 LoRA 导致”。至少存在以下相互独立的故障来源：

1. 裸 Instruct 基座本身的多轮承接能力不足；
2. LoRA 数据分布、训练强度或目标模块导致指令跟随退化；
3. Adapter 合并过程改变输出；
4. GGUF 转换或 Q4/Q5 量化放大退化；
5. chat template、停止符或推理参数不一致；
6. 生产输入裁掉必要历史，或注入与玩家当前原话冲突的状态、意图和记忆。

因此，“裸基座正常、LoRA 异常”只能证明故障位于两条实际推理链路的差异集合中。只有继续控制合并、量化、模板和输入后，才能把因果缩小到 Adapter 本身；即使确认 Adapter 有负面影响，也必须把“相关性退化”和“人格增强”分开测量。

外部研究只支持以下较弱结论：长上下文模型对相关信息位置的利用并不稳定；持续指令微调可能发生遗忘；LoRA 通常比全参数微调遗忘更少，但并非不会改变基座能力。它们不支持“LoRA 必然破坏基座”或某个固定学习率、回放比例能够保证根治。

### 1.6 独立问题：回复内部逻辑不连贯

人工体验还发现一种不能归入“答非所问”的缺陷：回复处理了当前话题，单句或相邻分句却没有成立的逻辑关系。该问题必须与承接性分开记录，否则一个候选可能被标为 `NOT_CLEAR_MISS`，但玩家仍会觉得它语义混乱。

2026-08-21 新构造的记忆纠正轨迹中，当前权威状态为“布包在书桌右侧抽屉，不在衣柜”，Adapter 回复：

> 我确认过了，它确实没有被放进衣柜。你放抽屉里的时候，我没看见。

这段回复处理了布包位置，因此不属于明显答错对象；但包含两个独立缺陷：

1. `UNSUPPORTED_EPISTEMIC_CLAIM`：输入没有“白未晞亲自确认过衣柜”这一事件，回复自行建立了确认经历。
2. `LOCAL_LOGIC_BREAK`：后句“没看见放进抽屉”不能支持前句“不在衣柜”，也没有解释角色凭什么确认最新位置；两个分句可以分别成立，但当前排列缺少因果、转折或证据桥接。

内部逻辑首版单独标注为 `COHERENT / LOCAL_LOGIC_BREAK / UNCERTAIN`，不得复用 `CLEAR_MISS / NOT_CLEAR_MISS`。至少覆盖：同句命题互相矛盾、结论与所给依据无蕴含关系、因果方向颠倒、主语/宾语或指代中途断裂、连接词与真实语义关系不符。无依据经历、感知或确认另记 `UNSUPPORTED_EPISTEMIC_CLAIM`；它可以与内部逻辑失败同时出现，也可以独立出现。

这个新增维度目前只有人工样例，尚不能据此声称“LoRA 普遍破坏句内逻辑”。必须在相同 Prompt 的裸基座/Adapter 冻结测试集上盲标比较，才能定位是否由当前 Adapter 放大。

## 2. V3 相对 V2 的关键修正

| V2 设计 | V3 决策 | 原因 |
|---|---|---|
| `substantive_address_score` 试图覆盖锚定、充分度、覆盖度和空前沿自然延续 | 将线上目标收窄为冻结评审人群对“明显答错对象”的判断概率 | 高精度负向检测更不容易奖励直白、长篇或客服式回复 |
| 全量冻结自由文本会话前沿 `F_t` | `F_t` 仅可作为少量失败分析备注，不进入主训练合同 | 昂贵且未进入生产损失，容易形成循环解释 |
| 可继续研究动态前沿或隐藏计划 | 明确不引入 `ReplyFocus`、隐藏推导链或候选自证 | 同一个 7B 的理解错误会同时污染计划和回复 |
| 低分 R1 只换 seed 生成一次 R2 | 改称有界拒绝采样；R2 策略必须通过真实恢复率实验冻结 | 换 seed 只提供另一个候选，不等于定向修复 |
| R2 未通过时保留已知 `fail` 的 R1 | 任一正式模式禁止提交已知 `CLEAR_MISS`；严格模式还拒绝 `UNCERTAIN` | 不把已识别失败继续交给玩家，同时显式暴露覆盖率代价 |
| Shadow 主要人工复核低承接分 | 对所有结果区间分层随机抽样 | 必须发现最危险的 `NOT_CLEAR_MISS` 漏检 |
| 先建 0.6B 在线链路，7B 优化放到可选 P4 | 7B 生成训练与 0.6B 评分训练并行验证；部署由完整策略净收益决定 | 生成与选择解决不同问题，不能预设单一路线 |
| 评分数据可有条件转 DPO | 评分数据和生成器总体偏好数据分开 | 承接成立不等于人格、自然度和关系体验更好 |

V3 保留 V2 的以下正确基础：

- 不枚举回应形式或问题类型；
- 使用同上下文困难对、独立绝对标签和 context-flip；
- 公开语境与私有状态边界；
- 独立 0.6B 业务合同；
- Shadow、版本化阈值和风险覆盖评测；
- 候选共享冻结快照，最终只提交一次；
- 不拼接候选、不由程序编造角色兜底台词；
- 事实、安全、能力、关系、人格和自然度继续由独立维度负责。

## 3. 唯一线上学习目标

### 3.1 目标定义

定义：

- `C_full_pub`：完成当前回合判断所需的完整玩家可见公开语境，用于人工真值；
- `C_score`：评分器实际收到的、版本化且可能裁剪的公开投影；
- `U`：当前玩家原始自然语言；
- `A_visible`：与候选同步展示给玩家的本轮已批准原子动作；没有可见动作时为空；
- `R`：一个完整候选回复；
- `H`：预先冻结口径的目标人工评审人群。

评分器只学习明显错位概率：

```text
P_miss*(C_full_pub, U, A_visible, R)
  = Pr[h ~ H 认为 (A_visible, R) 明显没有处理当前玩家贡献]
```

人工问题固定为：

> 知道全部玩家可见语境，并能看到本轮同步动作的普通玩家，是否会认为这组动作与台词明显答错了对象：回答了另一个问题、沿用了已被纠正的旧状态，或与当前交流没有可恢复的公开关系？如果存在合理的含蓄回应、动作呼应、自然转场或真实歧义，请不要标为明显错位。

这个定义是冻结评审人群的经验规范，不是文本上的客观语义真理，也不声称识别 7B 内部是否真正理解。`NOT_CLEAR_MISS` 仅表示“未达到明显错位阈值”，不表示回复充分、正确或总体优质。

### 3.2 不训练回应形式

下列内容只能作为数据切片或错误来源，不能成为线上类型树：

- 问题、请求、纠错、追责、陈述、情绪、玩笑、隐喻；
- 直接回答、含蓄回答、拒绝、澄清、短确认、沉默、主动开题；
- 旧话题固着、主体错位、极性错位、关键词复述、无依据转移。

模型只学习 `(C_score, U, R)` 是否构成明显错位，不输出上述类型。

### 3.3 检测结果的责任边界

`NOT_CLEAR_MISS` 只表示评分器未发现高置信明显错位，不表示总体合格。候选仍必须通过现有或新增的独立门禁：

| 维度 | 示例 |
|---|---|
| 事实与正典 | 编造共同经历、人物身份错误 |
| 程序世界与能力 | 声称已经转账、删除记忆或完成未发生动作 |
| 安全 | 危机问题给出危险建议 |
| 关系与同意 | 相关但关系跳级、越界亲密 |
| 人格与自然度 | 客服腔、模板腔、过度解释、强制直答 |
| 多轮体验 | 连续拒绝、持续回避、角色失去主动性 |

明显错位检测器的 `NOT_CLEAR_MISS` 不得覆盖其他门禁失败；其他门禁也不得把答非所问伪装为合格。

## 4. 最短运行时状态机

### 4.1 候选结果合同

评分器生产输出保持最小：

```json
{
  "clear_miss_probability": 0.93,
  "decision": "CLEAR_MISS",
  "reason_code": "THRESHOLD_CLEAR_MISS",
  "failure_scope": "NONE",
  "scorer_id": "reply-clear-miss-scorer-v3",
  "input_schema_version": "reply-clear-miss-input-v3",
  "threshold_version": "reply-clear-miss-threshold-v3",
  "deployment_profile": "baiweixi-q4-reply-v3",
  "artifact_identity": {
    "base_revision": "<revision>",
    "base_sha256": "<sha256>",
    "adapter_sha256": "<sha256>",
    "renderer_sha256": "<sha256>",
    "calibrator_sha256": "<sha256>"
  },
  "projection_complete": true
}
```

`decision` 只有四种运行结果：

| 结果 | 含义 |
|---|---|
| `CLEAR_MISS` | 在冻结校准域内达到高置信明显错位阈值 |
| `NOT_CLEAR_MISS` | 在冻结校准域内明显错位概率足够低，但不等于回复已被证明正确 |
| `UNCERTAIN` | 分数处于中间区，或输入超出已冻结校准包络 |
| `UNSCORABLE` | 输入残缺、版本不兼容、超时或非有限输出；由 `failure_scope` 区分候选局部与全局故障 |

`UNCERTAIN` 与 `UNSCORABLE` 不能自动解释为候选质量低。前者是语义证据不足或已知 OOD，后者是输入或系统不能评分；二者必须携带机器可枚举 `reason_code` 并分开统计。

`failure_scope` 只能是 `NONE / CANDIDATE / REQUEST / DEPLOYMENT`。它只描述故障影响范围，不描述回复语义；非 `UNSCORABLE` 结果必须为 `NONE`。

### 4.2 正式拦截候选循环

```text
冻结 GameReplyRequest = G
候选上限 K = K_policy

for i in 1..K:
    Ri = 7B.generate(G, candidate_attempt_id=i, frozen_sampling_plan[i])

    if Ri 未通过确定性前置门禁：
        记录并继续下一候选

    Di = ReplyClearMissScorer(C_score(G), U(G), A_visible(G), Ri)

    if Di == UNSCORABLE 且 failure_scope != CANDIDATE：
        终止本请求，不消耗下一个语义候选

    if Di == CLEAR_MISS：
        记录并继续下一候选

    if 当前发布策略允许 Di 且 Ri 通过全部其他正式门禁：
        原子提交 Ri，并结束

    记录并继续下一候选

候选耗尽（仅 PRECISION_FIRST / STRICT_SELECTIVE）：
    不提交玩家轮、角色台词、状态 Patch 或记忆作业
    返回 retryable 的 reply_candidate_exhausted
```

只有预算实际耗尽才返回 `reply_candidate_exhausted`。请求/部署级 `UNSCORABLE` 必须返回对应的版本不兼容、投影失败或检测器不可用 failure code，不能伪装成“7B 没生成好”。

确定性前置门禁只包括现有确实能验证的输出协议、非空、快照/状态版本和预携带断言。事实、安全、关系、人格与自然度等正文语义门禁若尚未实现，必须记为仓库缺口，不能用“既有硬门”假设它们已经存在。无论门禁放在评分前还是评分后，所有适用门禁都必须在唯一提交前完成。

关键合同：

- 候选按生成顺序检查，提交第一个通过全部门禁的候选；
- 不在多个非明显错位候选之间最大化分数，避免表达越来越直白；
- 不从多个 `CLEAR_MISS` 或无法裁决的候选中挑一个“相对最好”的提交；
- 不拼接、摘句或程序改写候选；
- 不把分数、阈值、判官理由或失败标签写入角色心智与记忆；
- 候选耗尽时返回系统层技术状态，不生成假的角色拒绝、澄清或占位台词；
- `known_clear_miss_commit_rate` 在 `PRECISION_FIRST` 和 `STRICT_SELECTIVE` 中由状态机结构保证为零。

### 4.3 运行模式与唯一转移矩阵

V3 区分四种发布阶段，不能混用其结论：

| 模式 | 玩家可见行为 | 能否声称解决已识别失败 |
|---|---|---|
| `SHADOW` | 始终按旧路径提交 R1，评分与虚拟候选只记录 | 不能 |
| `SOFT_PILOT` | `CLEAR_MISS` 时尝试 R2；全部候选仍失败时可保留硬有效 R1 | 不能，只能测恢复率和伤害 |
| `PRECISION_FIRST` | `NOT_CLEAR_MISS` 或 `UNCERTAIN` 可提交；`CLEAR_MISS` 不提交；局部 `UNSCORABLE` 尝试下一候选，耗尽或全局故障终止 | 可报告本策略实测的终态风险、覆盖率和降幅；不能说每个提交都取得了承接资格 |
| `STRICT_SELECTIVE` | 只有校准域内 `NOT_CLEAR_MISS` 且通过全部门禁的候选可提交 | 可报告更严格选择下的实测风险与覆盖率，仍不能声明开放域零错误 |

推荐顺序是 `SHADOW -> SOFT_PILOT -> PRECISION_FIRST`。它把干预限制在高置信明显错位，最不容易误杀含蓄、短答和自然转场。只有当 `UNCERTAIN` 中的人工坏回复率不可接受，且严格模式的覆盖率、终止率和体验非劣效都已达标，才升级 `STRICT_SELECTIVE`。

`SOFT_PILOT` 保留已知坏回复的行为不得被写成正式解决方案。`PRECISION_FIRST` 接受不确定回复是一项明确的连续性取舍，也不得包装成语义保证。

这四项是互斥的发布配置，不是同一请求依次经过的四个组件。首个正式线上配置 `PRECISION_FIRST` 实际只编译成三个动作：`PASS_THROUGH`（`NOT_CLEAR_MISS/UNCERTAIN`）、`REJECT_AND_NEXT`（`CLEAR_MISS` 或候选局部不可评分）和 `SYSTEM_TERMINATE`（全局故障或预算耗尽）；`STRICT_SELECTIVE` 在自身切片门槛通过前只保持 Shadow。

候选级动作必须按下表实现。`NEXT` 表示还有候选预算时生成下一个候选；预算耗尽时，`SOFT_PILOT` 转 `LEGACY_R1`，两个正式拦截模式转 `TERMINATE`。`LEGACY_R1` 只允许提交已经通过全部非错位门禁的原始 R1：

| 模式 | `CLEAR_MISS` | `NOT_CLEAR_MISS` | `UNCERTAIN` | `UNSCORABLE` |
|---|---|---|---|---|
| `SHADOW` | `LEGACY_R1` | `LEGACY_R1` | `LEGACY_R1` | `LEGACY_R1` |
| `SOFT_PILOT` R1 | `NEXT` | `COMMIT_R1` | `COMMIT_R1` | `LEGACY_R1` |
| `SOFT_PILOT` R2...RK | `LEGACY_R1` | `COMMIT_Ri` | `COMMIT_Ri` | `LEGACY_R1` |
| `PRECISION_FIRST` | `NEXT` | `COMMIT_Ri` | `COMMIT_Ri` | 局部 `NEXT`；全局 `TERMINATE` |
| `STRICT_SELECTIVE` | `NEXT` | `COMMIT_Ri` | `NEXT` | 局部 `NEXT`；全局 `TERMINATE` |

补充转移合同：

- `SHADOW` 的 live path 只有 R1；虚拟 R2...RK 只能离线记录，评分结果不改变玩家路径；
- `SOFT_PILOT` 只有在保存了通过其他全部门禁的 R1 时才能 `LEGACY_R1`；不存在该 R1 时转 `TERMINATE`；
- `PRECISION_FIRST` 或 `STRICT_SELECTIVE` 达到 `K_policy` 后仍为 `NEXT` 的结果统一转 `TERMINATE`；
- `UNSCORABLE` 的 `CANDIDATE_OVERSIZE` 或候选局部渲染失败可转下一个语义候选；`PROJECTION_INCOMPLETE`、`CURRENT_UTTERANCE_OVERSIZE`、Schema/工件/阈值不兼容、检测器不可用、超时或非有限评分属于请求/部署故障，应先走同一次评分的受限技术重试，仍失败则正式拦截模式立即 `TERMINATE`，不得浪费后续语义候选；
- 门禁失败的候选本身永不提交：有预算时转 `NEXT`；预算耗尽时，`SOFT_PILOT` 若另有已保存且通过全部非错位门禁的 R1 则转 `LEGACY_R1`，否则 `TERMINATE`；两个正式拦截模式始终 `TERMINATE`；
- `LEGACY_R1` 是实验性 fail-open，不受 `known_clear_miss_commit_rate = 0` 约束，必须单独计数；
- `COMMIT_Ri` 均表示通过所有适用门禁后的唯一原子提交。

### 4.4 候选生成不是独立事件

R1、R2 来自同一 7B、同一上下文和相近采样分布，错误高度相关。不得假设单次成功率为 `p` 时：

```text
recovery@K = 1 - (1 - p)^K
```

真实 `recovery@K` 必须在同一批冻结真实失败上下文上，通过完整候选生成和人工盲标直接测量。

### 4.5 R2 的冻结采样计划

V3 不预设“换 seed 一定有效”，也不引入动态 `ReplyFocus`。P0 实验至少比较：

1. `same_prompt_seed_v1`：同一正式 Prompt 和参数，只改变候选 seed；
2. `address_current_v1`：同一事实、状态、记忆和人物合同，增加一条固定且不含候选语义分析的最小重生成指令；
3. 不同但冻结的温度/`top_p` 组合。

`address_current_v1` 只能表达通用控制，例如：

```text
重新生成本轮台词。优先实质回应男主最后一句；
保持已批准的事实、动作、人格和关系边界；只输出角色说出口的话。
```

它不得包含评分器生成的理由、动态问题类型、R1 正文或程序编造的标准答案。最终使用哪个计划只由人工 `recovery@K`（首轮试验为 `@2`）、有害替换率和延迟共同决定。

### 4.6 端到端示例

以下概率只用于说明数据流，不是预设阈值：

```text
公开历史：角色刚说“外卖到了，我去端菜。”
玩家当前原话：外卖都还没有到，你端什么？

R1（7B）：我把糖醋排骨端开一点。
0.6B 输入：公开历史 + 玩家原话 + R1
0.6B 输出：p(clear_miss)=0.96，CLEAR_MISS
结果：丢弃 R1，不提交，也不让 7B 解释自己错在哪里。

R2（同一冻结请求、另一个预分配 seed）：……是我记错了，还没送到。
0.6B 输入：同一公开历史 + 同一玩家原话 + R2
0.6B 输出：p(clear_miss)=0.07，NOT_CLEAR_MISS
结果：R2 通过其余门禁后原子提交。
```

整个过程中没有生成 `ReplyFocus`。若未来遇到训练中未出现的新表达，7B 仍可能连续生成错位候选，0.6B 也可能漏检或返回 `UNCERTAIN`；这正是为什么发布结论必须是实测降错率，而不是“训练集已经覆盖”。

## 5. 为什么明确删除 ReplyFocus

### 5.1 同模型共同失效

若 7B 已经误解玩家，它可能同时生成错误的隐藏焦点和与该焦点一致的错误回复：

```text
误解 U
  ↓
错误 ReplyFocus
  ↓
忠实回答错误 Focus
```

这不会增加独立证据，只会把一次错误分成两个相互强化的步骤。

### 5.2 验证 Focus 会重复评分器职责

若另一个模型能够判断 `ReplyFocus` 是否准确，它已经具备直接判断 `(C, U, R)` 是否答错对象的主要能力。增加 Focus 生成、Focus 验证、回复生成、回复验证，会提高延迟、故障面和相关误差，而没有证明额外净收益。

### 5.3 当前仓库中的 reply_intent 不是可用替代

当前 Runtime 会把 `mind_result.reply_intent` 放入 `GameReplyRequest`，但真实 `GAME_REPLY` 网关调用的 `build_game_reply_messages()` 没有消费该字段。当前 `mind_patch_v2` 短协议还将它编译为泛化固定句，而不是候选盲的开放域理解结果。

V3 不依赖这个字段。未来若单独实验动态计划，必须作为独立消融，不得在 V3 主链路未验证前恢复。

## 6. 评分输入投影

### 6.1 完整真值与生产投影分离

必须分别保存：

- `C_full_pub`：人工评审能够看到的完整玩家可见语境；
- `C_score`：0.6B 实际收到的版本化投影。

人工金标由 `C_full_pub` 决定。如果 `C_full_pub` 下回复可理解，而 `C_score` 因裁剪无法恢复桥接，离线双视图审查应标记 `projection_failure`，不能把合法回复改标成语义负例。这个标记只能由离线对照得到，运行时投影器不得假装知道哪段历史“语义上必要”。

### 6.2 首版投影内容

`ReplyClearMissInputV3` 至少包含：

```text
固定 allowlist 的版本化公开场景字段
Manifest 冻结数量或 token 预算的最近完整已提交对白
当前玩家原话 U（不可摘要、不可静默截断）
与候选同步展示的本轮已批准动作 A_visible（没有则为空）
完整候选回复 R（不可静默截断）
裁剪数量、history_truncated、句法投影完整性和来源版本
```

不得包含：

- 角色私有情绪或玩家不可见作者设定，用来替怪回复寻找理由；
- 不会同步展示给玩家的内部动作、计划或状态变化；
- 评分器、阈值、候选序号或先前候选分数；
- 另一个生成模型推断出的隐藏意图；
- 根据候选 R 反向选择的历史片段。

### 6.3 裁剪与不可评分

投影必须是纯确定性函数，不做话题识别、未闭合议题判断、候选相关召回或“理解所需信息”推断。固定顺序为：

1. 保留 U 和完整 R；
2. 按固定 allowlist 序列化公开场景和 `A_visible`；
3. 按 Manifest 的轮数/token 预算保留最近完整已提交对白；
4. 超出预算时只从最旧历史开始裁剪，并记录精确计数；
5. U、A_visible 或 R 无法完整容纳时返回 `UNSCORABLE`；
6. `history_truncated` 或会话深度超出校准包络时返回 `UNCERTAIN`，不猜被删内容是否重要。

`projection_complete` 只表示必填字段和序列化成功，不表示语义信息完整。`projection_failure=true` 样本不进入明显错位分类损失或阈值校准，但必须保留在投影专项和完整部署管线测试中；发布不能通过剔除它们掩盖输入缺失。

## 7. 人工金标与数据合同

### 7.1 主标签不再依赖 F_t

每个候选由至少三名盲标者独立查看 `C_full_pub + U + A_visible + R`，回答固定的“是否明显答错对象”问题。保存原始票，而不是把多数票冒充无分歧真值：

```json
{
  "clear_miss_votes": {
    "yes": 2,
    "no": 1,
    "uncertain": 0
  },
  "annotation_status": "complete",
  "unscorable_reason": null
}
```

真实分歧保留为软标签和评测切片。`annotation_status`、输入不可评分、人工分歧和模型运行时不确定必须是不同字段。

首版聚合协议冻结为：

```text
n = yes + no + uncertain

训练软标签：
  y_miss = yes / (yes + no)             # yes + no = 0 时不进入分类损失
  sample_weight = (yes + no) / n         # uncertain 票降低权重，不伪装成 no

评测事件：
  yes / n >= 2/3  → HUMAN_CLEAR_MISS
  no  / n >= 2/3  → HUMAN_NOT_CLEAR_MISS
  其他            → HUMAN_DISPUTED
```

高一致度成对损失首版只使用全票 `yes` 对全票 `no`。发布风险同时报告确认错位数与争议数，正式保守闸门把已提交的 `HUMAN_DISPUTED` 计入错误；不得通过丢弃争议样本降低风险。聚合协议、标注人数和阈值一经测试集冻结，不得在看结果后修改。

自由文本会话前沿、回复承诺拆分或错误解释可以在 10%～20% 诊断集上标注，但不是全量数据前置条件，也不是生产学习目标。

### 7.3 数据来源

首批数据优先级：

1. 用户人工体验中的真实失败；
2. 当前发布 7B 多 seed 生成的流畅错位候选；
3. 同一会话旧回合回复错位交换；
4. 主体、客体、极性、时间或模态的最小编辑；
5. 候选不可见条件下构造的 context-flip；
6. 多个风格差异明显的非明显错位候选；
7. 真实低义务、含蓄、玩笑、拒绝、主动开题和自然漂移样本。

随机乱码、明显语法错误和与角色完全无关的文本不能成为主要负例，否则评分器只会学习流畅度。

### 7.4 强制困难对

每个上下文尽量提供：

- 一个直接但自然的 `NOT_CLEAR_MISS` 候选；
- 一个含蓄、短答、动作呼应或角色化的 `NOT_CLEAR_MISS` 候选；
- 一个同口吻、同长度的真实 `CLEAR_MISS` 候选；
- 一个关键词复述、万能拒绝或客服式过度回应候选，并分别标注明显错位与总体质量；
- 条件允许时，同一句回复在另一个上下文中的相反裁决。

必须控制两类候选的长度、口吻、事实合法性和来源，防止模型依赖拒绝词、问号、篇幅或生成器版本。客服腔、过长或不讨喜若仍在处理当前表达，明显错位标签必须是 `NOT_CLEAR_MISS`；这些缺陷由 `overall_quality` 和其他门禁处理，不能污染评分目标。

### 7.5 分组与泄漏

原始上下文、同义改写、反事实、同源候选和人工修订必须绑定同一个 `conversation_group_id`，整体进入同一 split。冻结测试集后不得继续改写；新失败进入下一版本。

生成器版本、角色和会话来源都要有独立留出切片，避免 0.6B 只学习当前白未晞 7B 的措辞特征。

冻结 test 只追加版本，不回写：新 7B 输出可扩充 train/dev，但不得在旧 test 解盲后加入训练；部署分布改变时，保留旧 test 做回归，并预注册新的 `deployment-test-vNext` 后一次性评估。每个发布结论必须绑定 `(7B hash, scorer base/adapter hash, renderer hash, calibrator/threshold hash, test version, K_policy)`，新 7B 不得沿用旧阈值直接发布。

### 7.6 基率与数据集职责

困难对可以在 train 中过采样，但不能用于声称线上概率已校准。数据必须拆为：

| 数据集 | 抽样方式 | 用途 |
|---|---|---|
| `hard-pair-train` | 失败、反事实和风格对照可过采样 | 学习表示和决策边界 |
| `slice-eval` | 按边界案例分层，可非自然基率 | 找切片退化，不计算线上 PPV |
| `calibration-dev` | 从目标部署流量按时间或随机抽样，保持自然基率 | 拟合校准器并冻结阈值 |
| `deployment-test` | 后续独立时间窗，保持自然基率且一次性解盲 | 最终风险、覆盖率和 PPV |

若 `calibration-dev` 使用病例-对照抽样，必须登记抽样概率、做先验校正，并在自然基率验证集复验；否则输出只能叫 score，不能叫 `p(clear_miss)`。`trigger_precision` 等 PPV 指标只从自然基率的完整管线样本计算。

## 8. 7B 生成训练

### 8.1 作用边界

7B 训练只负责：

- 提高 `good@1`；
- 提高前 `K` 个候选中至少存在一个人工合格回复的概率；
- 降低系统性旧话题固着和伪关联的生成概率。

它不负责证明未来所有输入都已覆盖，也不能替代独立明显错位检测器。

### 8.2 使用正式 GAME_REPLY 消息形态

新训练数据必须使用与生产 `build_game_reply_messages()` 同构的消息渲染，包含实际角色 Prompt、版本化公开状态、最近对白和当前原话。不得继续只追加静态短 ShareGPT 对话并假设它等价于生产输入。

训练金标记录应保存：

- 原始 `GameReplyRequest` 或确定性重建材料；
- Prompt、角色包、Schema 和渲染器版本；
- 冻结快照、批准状态、动作与记忆版本；
- 人工合格候选与非承接候选；
- 事实、能力、关系、人格和自然度裁决；
- `conversation_group_id` 与固定 split。

### 8.3 Targeted SFT

首选复用当前已验证的 LLaMA-Factory SFT + LoRA 路径：

- 现有人格数据作为回放集；
- 加入精确生产上下文的定向正例；
- 同一上下文提供多个不同表达的合格回复，但每个训练实例只监督一个最终回复；
- 重点加入当前输入反事实、纠错、追责、含蓄、低义务和自然转场；
- 小学习率、短周期和多 checkpoint 人工盲测，不能只看训练 loss。

### 8.4 DPO 的使用条件

DPO 只用于 SFT 后仍稳定存在、且 7B 能生成正确候选但经常选择错误候选的场景。`chosen/rejected` 必须满足：

- 同一精确生产上下文；
- `chosen` 人工确认承接成立；
- `rejected` 人工确认答错对象或固着失效旧状态；
- 二者事实、能力、安全、关系和人格均可比较；
- 总体人类盲评确认 chosen 更好，而不是仅承接分更高；
- 长度、口吻和直白程度不过度失衡。

两个候选都好、都坏、相当或不可裁决时不得强制进入 DPO。V3 默认优先 DPO 而非 ORPO，因为冻结参考模型更适合限制现有多模式 7B 的人格与协议漂移；ORPO 只能作为独立实验。

### 8.5 生成训练消融

至少比较：

```text
baseline
SFT-only
DPO-only
SFT → DPO
baseline + scorer/K_policy
SFT → DPO + scorer/K_policy
```

所有结论必须来自未参与训练和评分器金标制作的人工盲测，并在最终合并、量化的发布工件上复验。

其中 `DPO-only` 仅用于诊断“偏好训练相对 targeted SFT 的增量”，不是推荐发布顺序；正式路径仍先验证 targeted SFT，再决定是否增加 DPO。

## 9. 0.6B 独立明显错位检测器

### 9.1 模型职责

首选使用独立的 `Qwen3-Reranker-0.6B` 业务 Adapter，直接交叉编码 `(C_score, U, A_visible, R)`，输出 `p(clear_miss)`。它不生成解释、意图、Focus 或角色台词，也不比较两个正常回复谁更充分。

这里的“独立”只表示它不是生成回复的同一个 7B，且不读取 7B 自己编写的理由；不表示两者误差在统计上独立。它仍必须使用独立人工金标、独立阈值和独立测试集，并在新 7B 工件输出上重新验证。

### 9.2 训练目标

令 `s_theta(C, U, A_visible, R)` 为原始 `clear_miss_logit - not_clear_miss_logit`。训练可组合：

1. `clear_miss_votes.yes` 比例的软标签 BCE；
2. 只在高一致度 `CLEAR_MISS` 与高一致度 `NOT_CLEAR_MISS` 之间使用成对损失；
3. 人工确认明显错位裁决发生翻转的 context-flip 约束；
4. 等义改写稳定性；
5. response-only、no-current-turn、no-visible-action、长度和风格消融。

两个 `NOT_CLEAR_MISS` 候选之间禁止排序，不能奖励更长、更直白或更像客服的表达。人工分歧、不可评分和 OOD 不得伪装成硬二值标签。

### 9.3 校准与阈值

原始 logit、校准后的 `p(clear_miss)` 和运行时 decision 必须分开。两个阈值满足：

```text
tau_keep < tau_miss
```

- `p(clear_miss) >= tau_miss` 且输入处于校准域：`CLEAR_MISS`；
- `p(clear_miss) <= tau_keep` 且输入处于校准域：`NOT_CLEAR_MISS`；
- 中间区或输入超出冻结校准包络：`UNCERTAIN`；
- 输入/运行错误：`UNSCORABLE`。

阈值由独立开发集冻结，只在测试集上评估一次。不能根据最终测试结果回调阈值。

校准器在自然基率 `calibration-dev` 上使用 7.1 同一 `y_miss` 与 `sample_weight`；`yes + no = 0` 和 `projection_failure=true` 不进入拟合。阈值搜索使用冻结的三态人工事件，`HUMAN_DISPUTED` 在 trigger precision 下界中按未确认处理、在已提交风险上界中按错误处理，不能在不同指标间临时换口径。

Manifest 必须冻结可执行的校准包络：允许的 7B 工件哈希、角色/语言与文字脚本、会话深度和 token 范围、`C_score`/动作/renderer 版本、投影完整性、部署 profile、校准器与阈值哈希。单个 softmax 高置信不能充当 OOD 检测；只使用能由输入元数据确定的包络条件。

在线分布漂移属于聚合监控信号，不由单个候选的 softmax 猜测。漂移告警触发后，冻结策略必须选择“全部路由为 `UNCERTAIN`”“回退 Shadow”或停止正式拦截之一。`UNCERTAIN` 与 `UNSCORABLE` 的 reason code 至少区分 `SCORE_BAND`、`ENVELOPE_MISMATCH`、`PROJECTION_INCOMPLETE`、`CURRENT_UTTERANCE_OVERSIZE`、`CANDIDATE_OVERSIZE`、`VERSION_MISMATCH`、`TIMEOUT`、`NONFINITE_OUTPUT` 和 `SCORER_ERROR`。

### 9.4 可学性 Go/No-Go

0.6B 不是既定成功组件。第一目标是高 `CLEAR_MISS` 触发精度和低误干预；第二目标才是足够召回。若它在真实未见长会话、含蓄回复、主动开题和新 7B 输出上不能达到发布门槛，则必须：

1. 保持离线或 Shadow；
2. 评估能力更强且仍与 7B 生成器分离的检测模型；或
3. 放弃把它接入玩家可见路径。

不得用更多 if/else、关键词或同一个 7B 的自我解释掩盖 0.6B 能力不足。

## 10. 完整策略评测

### 10.1 不能只测单候选准确率

多候选管线会累积误放风险，而且候选之间不独立。最终发布门必须直接运行完整 `K` 次策略并人工裁决最终结果，不能从单次评分器准确率外推。

对独立冻结的 `N` 个请求：

- `M`：当前被评估的冻结正式策略最终提交的请求数；`PRECISION_FIRST` 与 `STRICT_SELECTIVE` 必须分别运行并报告；
- `E_confirmed`：提交结果中的 `HUMAN_CLEAR_MISS` 数量；
- `D`：提交结果中的 `HUMAN_DISPUTED` 数量；
- `E = E_confirmed + D`：用于正式风险闸门的保守错误数。

若 `M = 0`，`selective_risk` 不可估计，不能记为 0，发布直接因覆盖不足失败。

报告：

```text
selective_risk = E / M
coverage = M / N
visible_bad_per_request = E / N
visible_good_per_request = (M - E) / N
termination_rate = (N - M) / N
service_failure = (E + N - M) / N
```

若风险与覆盖率共同构成一个置信度为 `1 - alpha` 的发布声明，使用 Bonferroni 分配：

```text
U_CP(E, M, 1 - alpha/2) <= epsilon
L_CP(M, N, 1 - alpha/2) >= coverage_min
```

若还增加其他同时声明的统计闸门，必须在评测前继续分配显著性预算；不能让每项都单独使用同一个 `alpha` 后仍声称整体置信度为 `1 - alpha`。

候选测试规模必须由目标风险上界反推，不能用 600 个可行性上下文假装证明极低误放率。若 `q_i` 分别上界“实际策略到达候选位置 i 后发生错误放行”的条件分布风险，多次尝试在不假设独立时只能保守写成 `P(任一次错误放行) <= sum_i q_i`。R2...RK 的条件分布与 R1 不同，禁止用 R1 的 `q` 直接乘 `K`；正式结论仍必须来自完整 `K_policy` 状态机实测。

### 10.2 核心策略指标

至少冻结并报告：

- 基线 `good@1` 与最终玩家可见答非所问率；
- `oracle_good@K` 与真实策略 `retry_recovery_rate@K`，首轮另列 `@2`；
- `trigger_precision`：被判 `CLEAR_MISS` 的 R1 中，人工确认明显错位的比例；正式下界把 `HUMAN_DISPUTED` 视为未确认，不得从分母删除；
- `false_intervention_rate`：人工认为 R1 可用却触发重采样的比例；
- `NOT_CLEAR_MISS` 区的人工错位率；
- `UNCERTAIN`、`UNSCORABLE` 比例及其人工风险；
- `known_clear_miss_commit_rate`，`PRECISION_FIRST` 与严格模式必须为 0；它只验证状态机未提交分类器判坏候选，不能替代人工终态风险；
- `replacement_precision`：实际重采样候选提交中人工确认可用的比例；
- `harmful_replacement_rate`：可用 R1 被流程换成更差后续候选的比例；
- 最终玩家可见答非所问率及相对基线的配对降幅与置信下界；
- 每千请求净修复数、终止数和有害替换数；
- 普通路径与各候选深度路径分别的 P50/P95；
- 评分器超时、故障、漂移和投影不完整率。

### 10.3 防止靠终止刷低错误率

发布不能只要求低 `selective_risk`。还必须同时冻结：

- 最低 `coverage`；
- 最大 `termination_rate`；
- 相对基线的玩家可见坏回复降低下界；
- 综合服务失败率：答非所问提交与无回复终止之和。

否则系统可以通过拒绝所有请求获得零提交错误，却没有产品价值。

若要声明“相比当前路径解决了大量答非所问”，还必须在相同冻结上下文上做配对比较，预先冻结最小有意义改进量 `delta_min`，并满足：

```text
LCB[p_bad_baseline - visible_bad_per_request] >= delta_min
```

上式只能支持“减少了坏回复展示”。若要使用“修复”或“提高成功率”，还必须预先冻结 `gamma_min > 0` 并满足：

```text
LCB[good_per_request_new - good_per_request_baseline] >= gamma_min
```

同时为 `service_failure_new - service_failure_baseline` 冻结非劣效上界。置信下界方法、显著性水平、多重比较和缺失样本处理必须在看测试结果前冻结。

### 10.4 全区间 Shadow 抽样

Shadow 人工复核必须对 `CLEAR_MISS / NOT_CLEAR_MISS / UNCERTAIN / UNSCORABLE` 分层随机抽样。尤其需要估计 `NOT_CLEAR_MISS` 中的漏检，不能只检查触发重采样的案例。

### 10.5 体验非劣效

答非所问下降不能以角色退化为代价。每个候选模型和完整策略都必须报告：

- 有效含蓄回复保留率；
- 无依据拒绝和连续拒绝率；
- 过度直白率；
- 客服/助手腔率；
- 过度解释、建议和追问率；
- 主动开题与自然话题漂移误杀率；
- 回复长度、模板重复和多轮角色主动性；
- 回复内部逻辑连贯率：相邻命题是否矛盾、依据是否支持结论、指代与连接关系是否完整；
- 无依据认识来源率：自行声称“我确认过、我看见、我听见、我记得”等输入未提供的认识经历；
- 事实、能力、安全、关系、人格、情绪和自然度总体人类偏好。

## 12. Runtime 与资源合同

### 12.1 原子回合

所有候选必须共享：

- 同一 `request_id` 和预分配事件身份；
- 同一冻结世界快照；
- 同一批准后女主状态；
- 同一记忆选择结果；
- 同一批准动作和事实断言；
- 不重新召回、不读取新世界版本；
- 任何候选都不提前提交；
- 最终只调用一次 `commit_turn`。

`PRECISION_FIRST` 与 `STRICT_SELECTIVE` 候选耗尽必须回滚到零提交状态，不得留下玩家半回合、状态 Patch、记忆任务或后台整理作业。`SHADOW` 与 `SOFT_PILOT` 的例外行为只按 4.3 的转移矩阵执行。

每个候选都要写入追加式 `ReplySelectionRecord`：候选 ID、seed、采样计划、文本哈希或按隐私策略保存的正文、各门禁结果、`p(clear_miss)`、decision、检测器/阈值版本、耗时和最终选择理由。成功回合的最终选择记录与 `commit_turn` 同事务写入；未提交回合只写独立运维审计，不得产生世界、心智或记忆事件。现有最终结果表不得原地改造成多候选日志，应使用新 migration 扩展。

### 12.2 候选级 API

当前 `WorldMindModeProfile` 没有候选 seed 字段，`GAME_REPLY` 的 `_run_text()` 还会对后端、服务和输出协议异常做同逻辑调用重试。V3 必须区分：

- `semantic_candidate_index`：R1...RK；
- `candidate_attempt_id`：审计身份；
- `seed` 与 `sampling_profile_id`；
- 传输/服务技术重试；
- 版本化的 `K_policy` 与本轮最大语义候选数；
- 本轮最大 7B 后端调用次数和总超时预算。

传输/服务技术重试必须复用同一候选 ID、Prompt、seed 和采样参数，不消耗新的语义候选序号；后续语义候选必须使用预分配的不同候选 ID 和 seed，但继续共享同一冻结请求。总物理调用次数必须单独封顶并审计，不能把 `K_policy` 个语义候选实现成未受控的更多模型调用。

模型接口必须显式拆为：

```text
generate_reply(
    frozen_request: GameReplyRequest,
    attempt_plan: GameReplyAttemptPlan
)

GameReplyAttemptPlan = {
    generation_epoch,
    semantic_candidate_index,
    candidate_attempt_id,
    seed,
    sampling_profile_id,
    regeneration_instruction_profile_id
}
```

`attempt_plan` 不修改冻结的 `GameReplyRequest`；版本化 renderer 只在构造本次模型 messages 时组合二者。`address_current_v1` 属于 `regeneration_instruction_profile_id`，技术重试复用同一 plan，后续语义候选使用新 plan。V3 首次施工只接当前正式 `mind_patch_v2` 路径；其他心智协议必须另做兼容分支和回归，不能隐式复用。

`reply_candidate_exhausted` 的“可重试”只指产品可以发起新一轮生成，不表示原请求换 seed 重跑：

- 相同 `request_id + generation_epoch` 的重放必须返回同一已记录终态，不重新生成或评分；
- 玩家点击重试时创建新 `request_id`，保存 `retry_of_request_id`，递增 `generation_epoch`，重新冻结当时可见世界快照并预分配新采样计划；
- 产品层必须冻结最大 generation epoch 和总时延，超过上限返回最终技术失败，禁止无限循环。

### 12.3 0.6B 共享运行时

目标 8GB 设备不常驻第二份 0.6B 基座。若回复检测与现有记忆 Reranker 共享基座：

- 使用独立 Adapter 和业务 Schema；
- 由 stack 级单一所有者管理基座生命周期；
- Adapter 切换和推理处于同一全局临界区；
- 通过优先级队列协调前台记忆选择、回复检测和后台任务；
- `finally` 恢复正确 Adapter，禁止跨存档或并发任务串用；
- 若切换不稳定，使用含记忆回放的多任务 Adapter，并同时重跑两套冻结闸门。

现有 `MemoryReranker` Protocol、128 token 常量和 Manifest 不得原地修改或冒充回复检测合同。

“共享基座”是待验证施工目标，不是现状。当前记忆包若无法证明 base/Adapter 来源并可靠拆分，则不得伪装成多 Adapter 架构；应选择带完整记忆回放的多任务 Adapter、CPU 检测器或继续 Shadow，并重新跑资源与记忆回归。

### 12.4 Raw logit 与校准 API

当前记忆 Reranker 的底层接口主要返回 sigmoid/softmax 概率。V3 的共享底层需要暴露原始 yes/no logits 或 logit 差：

- 记忆业务按原合同转换为 activation probability；
- 回复业务使用独立校准器和阈值；
- 回复 Manifest 明确冻结 `yes == CLEAR_MISS`、`no == NOT_CLEAR_MISS`，以及两个单 token ID、模板 suffix、有效末位索引和 logit 差符号；
- 禁止从已归一化概率反推伪 raw logit；
- 训练与生产共用同一模板渲染、有效末位选择和截断实现。

### 12.5 延迟与显存

平均新增成本近似为：

```text
T_score
+ retry_rate * (T_candidate_2 + T_score)
```

但发布必须分别报告各候选深度路径的 P50/P95。只要第二候选触发率接近尾部分位，现有 P95 就会进入双 7B 路径。

组合显存、KV cache、0.6B 长输入、Adapter 切换峰值、碎片和并发队列必须在目标 8GB 卡实测。预估或 4090 结果不能替代目标卡证据。

V3 在新 release manifest 批准前继承当前 SYS12 数值门槛：组合 GPU 峰值 `< 5120 MiB`、80 token P95 `< 5000 ms`、160 token P95 `< 8000 ms`。新增检测、候选深度与 Adapter 切换必须在同一正式工作负载下重新通过；若产品决定修改门槛，必须发布新 manifest 版本、数值和理由，不能只写“适配 8GB”。历史组合测试曾出现 6825 MiB 和 7881 MiB 峰值，单次约 5087 MiB 的静态探针不能替代完整验收。

## 13. 当前仓库差距

当前仓库尚未具备 V3 运行时，至少存在以下缺口：

1. 没有 `ReplyClearMissScorer`、输入 Schema、Manifest、训练包或 Shadow 产物；
2. 当前 7B 训练包只有已跑通的 SFT + LoRA 路径和 train loss，没有冻结验证集/best checkpoint 证据，也没有仓库内已跑通的 DPO/ORPO 配置；
3. 现有训练数据是静态 ShareGPT 对话，不完全同构于正式 `GAME_REPLY` 消息；
4. 训练包实际数据量、README 和 YAML 注释存在 1987 / 1973 / 2882 的口径漂移，施工前必须统一；
5. 当前 `reply_intent` 被放入 `GameReplyRequest`，但真实 `GAME_REPLY` 消息没有消费；V3 将它保持为审计字段，不渲染为生成指令；
6. 底层 provider 支持 seed，但 WorldMind 候选 API 没有传递可冻结 seed 和候选身份；当前 retry 是技术重试，不是 R1/R2 语义候选；
7. 当前 0.6B 是记忆业务专用的完整模型包，backend 生命周期和接口不是共享基座、多 Adapter 所有者；
8. 当前 `HardInvariantValidator` 不能替代正文级事实、安全、关系、人格和自然度语义检查；
9. 当前选择审计只保存最终 `GAME_REPLY` 结果，缺少 R1...RK、seed、裁决、选择理由和未提交回合的追加式运维记录；
10. 8GB 目标卡只存在相互依赖工作负载的局部探针，历史组合峰值曾超过发布门槛，加入长输入评分和 Adapter 切换后必须重新实测。
11. 当前 1987 条 7B 训练数据全部包含至少两次玩家发言，但 1872 条、即 94.2% 只有两次玩家发言；103 条有三次，12 条有四次，平均 2.064 次。问题不是形式上的“多轮占比不足”，而是训练会话深度与生产长会话不匹配。
12. 当前 `list_recent_dialogue(limit=6)` 默认只送最近 6 条消息，约三轮问答；更早的指代对象、未闭合问题或纠正前提可能已经不在模型输入中。
13. 正式 `GAME_REPLY` 的 System 内容会注入 `living.attention`、`living.immediate_intent`、召回记忆和批准动作。如果这些字段停留在旧话题，它们会以高优先级把生成器拉回旧状态。
14. 当前 7B 配置为 `lora_target: all`、rank 32、alpha 64、学习率 `5e-5`、2 epoch，且训练结果中 `best_metric` 与 `best_model_checkpoint` 为空、`should_evaluate=false`。这是需要消融的高风险组合，不是 LoRA 已被判罪的证据。
15. 当前 `GAME_REPLY` 温度为 `0.75`、`top_p=0.9`。降低温度值得作为采样消融，但不能把系统性回答旧问题解释成单一随机性故障。
16. 历史 Q5 工件曾出现答非所问、外语碎片、数字串和重复词，后续重训并导出的 Q4_K_M 工件使这些症状消失。现有证据只能说明训练、合并、量化和运行链路都应保留为候选根因。

这些缺口说明 V3 是待施工设计，不是对现状能力的描述。

## 14. 施工顺序

### P-1：生成链路因果定位

P-1 必须先于继续扩充训练集、DPO、评分器硬拦截和正式候选重采样。首先收集并冻结用户人工体验中的真实答非所问上下文，冻结目标玩家分布、人工提问口径和统计口径；随后所有对照使用同一冻结失败集、逐字相同的消息、seed、采样参数和人工 Rubric，并把“当前问题相关性”与“人格保持”分别评分。

模型工件轴：

1. 原生 `Qwen2.5-7B-Instruct` BF16；
2. 原生基座的目标量化工件；
3. 基座 + LoRA Adapter BF16；
4. Adapter 合并后 BF16；
5. 最终 Q4_K_M 或目标发布量化工件。

判读合同：`1 vs 3` 定位 Adapter 净影响，`3 vs 4` 定位合并影响，`4 vs 5` 定位微调模型量化影响，`1 vs 2` 定位基座量化影响。不得只比较裸 BF16 与最终 GGUF 后把全部差异归因给 LoRA。

输入消融轴：

1. 角色 Prompt + 最近对白 + 玩家当前原话；
2. 增加当前世界；
3. 增加 `attention` 与 `immediate_intent`；
4. 增加召回记忆；
5. 增加批准动作，恢复完整正式输入。

如果加入某一字段后开始回答旧话题，优先修复该字段的生产、时效、冲突优先级或裁剪合同，而不是让 7B 再生成一层 `ReplyFocus`。历史深度还必须分别测试 0/2/4/6 条及更长窗口，并覆盖旧状态纠正、自然换题、无关话题插入、指代依赖即将被裁掉信息和 context-flip。

Adapter 消融轴：在未合并 Adapter 上测试 scale `0/0.25/0.5/0.75/1.0`。若 scale 越大人格越稳定但相关性越差，应选择经双指标验证的折中点，并按该 scale 重新合并、导出和复验；不得用人格得分掩盖答非所问。

P-1 输出一份逐失败上下文的归因报告：

- 若裸基座明显优于 Adapter，优先试裸 Instruct + 角色 Prompt/记忆、降低 Adapter scale，或用更保守配置重训角色 LoRA；
- 若基座与 Adapter 都漂移，优先修历史窗口、动态心智字段、记忆冲突和生产输入，再做 targeted SFT；
- 若只有合并后退化，修复合并路径，不重训；
- 若只有目标量化工件退化，修复导出/量化或调整量化等级，不重训；
- 若各工件只在加入特定输入字段后退化，修复输入合同，评分器仅处理剩余失败。

### P0：真实基线与产品决策

P0 不得早于 P-1 归因报告完成：

1. 在当前发布量化工件上以 `K=2` 做首轮多 seed 重放，测基线坏回复率与 `oracle recovery@2`；
2. 明确最终产品接受 `PRECISION_FIRST` 还是更高终止率的 `STRICT_SELECTIVE`；
3. 若坚持每轮必回，文档状态必须标记为 `best-effort`，并接受已知失败无法结构性归零。
4. 在查看正式测试结果前冻结 `reply-clear-miss-release-profile-v1` 的数值：family-wise `alpha`、风险上界、覆盖率下界、最低坏回复降幅、最低 `good_per_request` 增量、最大终止/误干预/有害替换率、服务失败非劣界和各体验切片门槛；任何字段仍写“可接受”时禁止上线。

### P1：数据合同与评分器可学性

1. 冻结 `reply-clear-miss-gold-v3` 与 `reply-clear-miss-input-v3`；
2. 建立不少于 600 个独立上下文组的可行性数据；
3. 同时建立完整玩家可见语境与生产评分投影；
4. 训练 0.6B，完成 response-only、no-current-turn、no-visible-action、context-flip、风格和长度消融；
5. 在生成器版本留出、长会话和微妙表达切片上做 Go/No-Go。

### P2：候选策略离线实验

1. 对同一真实失败集生成 R1/R2；
2. 比较 `same_prompt_seed_v1` 与固定最小重生成指令；
3. 人工盲标每个候选，不看分数和生成顺序；
4. 完整回放 `PRECISION_FIRST` 与 `STRICT_SELECTIVE`，测最终风险、覆盖率、终止率和延迟；
5. 冻结版本化 `K_policy`、采样计划和阈值，不凭经验写死。

### P3：7B 生成分布优化

1. 使用正式 `GAME_REPLY` renderer 建立精确生产上下文的 targeted SFT 数据；
2. 增加真实 4-8 轮会话，重点覆盖纠正旧状态、当前问题覆盖旧意图、自然换题、指代与省略、旧记忆和当前原话冲突、含蓄但相关回复及 context-flip；不得继续用两轮样本数量冒充长会话能力；
3. 保留人格与多模式回放；通用回放比例通过冻结验证集选择，不写死为 5%-10%；
4. 对 rank `8/16/32`、attention-only/all-linear、学习率 `1e-5/2e-5/5e-5` 和 Adapter scale 做小规模消融，并启用冻结验证集、人工终态相关性指标与 early stopping；
5. 对 baseline / SFT / DPO / SFT→DPO 做独立人工消融；DPO 只使用人工确认的总体偏好，不把评分器标签直接转成偏好数据；
6. 从新候选模型重新采样评分器 train/dev 候选，并预注册新的 deployment-test；不得回写或反复解盲旧 test；
7. 只在最终合并、量化工件上确认 `good@1` 和 `recovery@K` 提升，同时保留 BF16 阶段结果用于定位导出退化。

P3 与 P1 均不得早于 P-1；P-1 完成后两者可并行，但不得使用同一测试集相互自证。

### P4：Runtime 脚手架（不改变玩家行为）

1. 实现 Schema、唯一 renderer 与 golden test，保证训练/生产字节一致且 U、动作、R 不静默截断；
2. 实现 `GameReplyAttemptPlan`、显式 seed、技术重试/语义候选分离、selector 和 fake scorer 状态机测试；
3. 新增追加式候选/选择审计 migration，完成提交前后、崩溃、取消、重放和耗尽故障注入；
4. 实现独立回复检测适配器；共享基座未就绪时使用明确的 dedicated/CPU profile，不假设多 Adapter 已存在；
5. 实现 request 幂等、`generation_epoch`、产品重试上限和机器可枚举 failure code；
6. 所有测试通过前保持 feature flag 关闭，现有玩家路径不变。

P5 不得早于 P1、P2、P4 完成；若发布组合包含 P3 的新 7B，则还必须先为该组合重新冻结校准器、阈值和 deployment-test。

### P5：Shadow 与虚拟选择

1. 在现有回复硬校验之后、原子提交之前记录评分；
2. Shadow 故障不改变当前玩家路径；
3. 离线生成虚拟 R2，不提前提交；
4. 对四个 decision 区间分层人工抽样；
5. 实测显存、Adapter 切换、并发、P50/P95 和漂移。

### P6：Soft Pilot

1. 小流量启用 R2，但允许保留硬有效 R1；
2. 只用于测真实恢复率、误触发、有害替换和产品延迟；
3. 不得以 Soft Pilot 结果宣称已阻止已知失败；
4. 任一非承接切片、人格或关系指标退化立即回退 Shadow。

### P7：Precision First

只有以下条件全部通过，才允许正式拦截 `CLEAR_MISS`：

- `trigger_precision`、人工终态风险上界、最终可见答非所问配对降幅和 `harmful_replacement_rate` 达到预注册数值；
- 总体及含蓄、短答、动作呼应、自然转场切片的 `false_intervention_rate` 置信上界达标；
- `known_clear_miss_commit_rate = 0`，并明确它只是分类器决策不变量，不等于人工坏回复率为 0；
- 覆盖率下界、候选耗尽率上界、`service_failure` 非劣效界、`UNSCORABLE` 率和 P95 达到预注册数值；
- `good_per_request` 相对基线的置信下界为正，证明不是只把坏回复改成无回复；
- 人格、关系、事实、安全和自然度非劣效；
- 原子事务、恢复、隔离、队列和目标 8GB 卡全部通过；
- UI 已实现非角色层可重试失败状态。

### P8：Strict Selective（可选）

只有以下条件全部通过，才允许严格候选提交：

- 完整 `K_policy` 管线风险上界和覆盖率下界达到预注册 release profile；
- 最终玩家可见答非所问相对基线显著下降；
- 终止率、总体服务失败率达到预注册 release profile，P95 达到资源 manifest；
- 人格、关系、事实、安全和自然度非劣效；
- 含蓄对白相对直接对白的接受率、平均长度、直白率和角色主动性非劣效，证明严格筛选没有把输出推向客服式直答；
- 原子事务、恢复、隔离、队列和目标 8GB 卡全部通过；
- UI 已实现非角色层可重试失败状态。

## 16. 明确不施工的方案

V3 主路径不施工：

- 扩充七种回应形式或建立新的问题类型树；
- 逐话题关键词和 `if/else`；
- 让 7B 生成 `ReplyFocus`、隐藏推导链或理由后自我证明；
- 用同一个 7B 同时作为最终唯一生成器和最终唯一判官；
- 把 0.6B 高置信度称为语义证明；
- 把换 seed 称为必然修复；
- 在候选间最大化单一承接分；
- 从多个 `CLEAR_MISS` 或无法裁决候选中选择“相对最好”的一个；
- 已知 `CLEAR_MISS`、`UNCERTAIN` 或 `UNSCORABLE` 后仍在 `STRICT_SELECTIVE` 提交；
- 用固定角色拒绝句、澄清句或程序拼接台词掩盖失败；
- 将评分器标签直接自动转为 7B DPO 偏好；
- 未验证真实基率、完整策略风险和目标卡资源就进入在线硬门；
- 声称训练数据已经覆盖开放域全部未来表达。

## 18. 最终结论

V3 不再寻找一套能够覆盖所有未来表达的规则、训练集或隐藏计划，也不预设答非所问必然由 LoRA 导致。其待验证机制首先进行生成链路归因，再进行选择性生成：

```text
基座 / Adapter / 合并 / 量化 / 输入消融定位主要根因
        +
先修历史裁剪、动态状态和记忆污染等已定位问题
        +
定向训练以提高好候选出现概率为目标
        +
独立检测只在校准达标后拦截高置信明显错位候选
        +
有限候选只在 recovery@K 证明净收益后启用
        +
正式拦截模式候选耗尽时拒绝提交
```

这套方案仍不能保证任意开放域输入永远正确，但它建立了三个可验证的底线：

1. 不依赖同一个 7B 的自我解释；
2. `PRECISION_FIRST` 与 `STRICT_SELECTIVE` 不提交被当前版本检测器判为 `CLEAR_MISS` 的候选；
3. 不用规则数量或训练样本数量冒充开放域覆盖证明。

最终是否值得上线，只由完整管线在真实玩家分布上的人工可见答非所问率、覆盖率、终止率、总体体验和资源成本决定。
