# 问题记录：第 15 轮 LoRA 错误确认已失效预约时间

> 问题编号：REPLY-CORRECTION-001  
> 记录日期：2026-08-22  
> 状态：已由用户人工确认，主要根因已定位，待修复  
> 严重度：P0 对话正确性缺陷  
> 影响链路：冻结白未晞 7B Q4 LoRA 工件 + 完整 V6 程序  
> 来源测试：`product_main_60turn_20260822-112309` 第 15 轮

## 1. 结论

这是一个明确的“错误前提确认”问题，不只是回答不够具体。

玩家提出的命题是“预约仍为星期五下午”，权威世界明确说明该命题已经失效，正确回复必须先否定星期五，再给出星期六上午十点。完整 V6 回复以“嗯”开头，按正常汉语语义确认了玩家的错误命题；后续“明天、按时去”没有否定星期五，也没有恢复正确时间。

本轮已经确认：

1. 权威世界正确进入了 V6 冻结快照；
2. 最近对白中也存在正确的“星期六上午十点”；
3. 本轮没有召回旧记忆，不是记忆污染；
4. LoRA `GAME_REPLY` 仍然生成了错误承接；
5. V6 连续性审查没有审最终回复正文；
6. 回复硬校验只检查随请求复制的状态版本元数据，没有检查正文是否符合权威事实；
7. 因此错误回复被当作成功结果提交。

结合既有 Adapter 因果隔离测试和本轮新增的逐字相同正式输入复现，当前可以确认：裸基座本身存在一定错误概率，但当前 LoRA Adapter 会显著放大承接失败；Q4 量化不是主要起点。该结论只适用于当前 Adapter 和已测试分布，不等于“所有 LoRA”或“所有回复错误”都由 Adapter 导致。

## 2. 问题样本

### 2.1 输入

玩家：

> 所以我还是星期五下午去，对吗？

权威世界：

> 牙医预约是星期六上午十点；星期五的旧时段失效。

期望处理：

> 明确否定星期五下午，并纠正为星期六上午十点。

### 2.2 裸基座回复

> 不是的，你现在需要在星期六上午十点去医院。记得早点起床，我们赶早出发。

核心处理正确：否定了错误前提，并恢复了当前有效时间。

### 2.3 完整 V6 回复

> 嗯，你明天还是要去看牙。别想太多，按时去就行。

错误点：

- “嗯”确认了玩家提出的“星期五下午”；
- “明天”没有被权威世界定义为星期六，属于不必要的相对时间替换；
- 没有说出“星期六”；
- 没有说出“上午十点”；
- “按时去”在没有给出正确时间时不能完成纠正；
- “别想太多”是安抚性填充，不能修复错误确认。

即使额外假设“明天”碰巧是星期六，本回复仍然没有否定星期五下午，也没有回答十点，因此仍判失败。

合格回复示例：

> 不是，星期五下午的时间已经作废了。现在是星期六上午十点。

## 3. 已核实的运行证据

### 3.1 权威状态没有丢失

数据库中第 15 轮冻结快照为：

- `live_world_version = 15`；
- `protagonist.activity = 用旧时间再次确认预约`；
- `scene.item_states.场景 = 牙医预约是星期六上午十点；星期五的旧时段失效。`；
- `protagonist_utterance = 所以我还是星期五下午去，对吗？`。

因此不能把这次错误解释成“完整程序没有加入上下文”。

### 3.2 最近对白已经提供正确答案

正式 `GAME_REPLY` 默认携带最近 6 条已提交消息。本轮之前的相关对白包括：

1. 玩家：“诊所刚来电话，改成星期六上午十点了。”
2. 白未晞：“那就改一下吧……”
3. 玩家：“那最新时间是什么时候？”
4. 白未晞：“现在是星期五的旧时段失效了，新的预约时间是星期六上午十点。”
5. 玩家转问书本进度；
6. 白未晞回答书本问题。

当前世界和近期历史两处都支持星期六上午十点。模型不是无信息猜测，而是在证据充分时仍然生成了错误承接。

### 3.3 本轮没有长期记忆干扰

冻结快照中的 `selected_memory_frame` 为空：

- `selected_memories = []`；
- `source_memory_ids = []`；
- `token_count = 0`。

本例不能归因于旧长期记忆覆盖当前状态。

### 3.4 M2 没有形成当前回复义务

本轮 `mind_result` 是空心智 Patch，`reply_intent` 只是：

> 从本轮更新后的自身状态出发回应男主

它没有记录“否定星期五并告知星期六上午十点”这一必要语义。并且当前真实 `GAME_REPLY` 消息构造没有把 `reply_intent` 渲染给最终生成器；该字段目前主要作为审计字段存在。

因此，M2 既没有解决当前问题，也没有给最终回复提供可验证的承接目标。

### 3.5 连续性审查没有审最终回复

本轮连续性结果为：

```text
decision = approve
reason = short patch passed hard invariants without semantic risk trigger
```

这是对空 M2 心智 Patch 的自动批准，发生在 `GAME_REPLY` 生成之前。连续性审查没有看到后来生成的“嗯，你明天还是要去看牙”，所以它不可能拦截该错误。

### 3.6 回复硬校验验证的是元数据，不是正文语义

`GAME_REPLY` 返回的 `reply_state_assertions` 直接继承了请求中的快照断言：

- 世界版本；
- 男主位置；
- 男主活动；
- 游戏时间。

`HardInvariantValidator.validate_reply()` 只校验这些断言是否等于快照，以及回复是否为空、快照 ID 和心智版本是否一致。它没有从回复正文中提取或验证“星期五/星期六/十点”。

所以出现了以下假安全：

```text
正文：确认了错误的星期五
元数据：仍声称自己基于 world_version=15
校验：通过
结果：错误正文被提交
```

### 3.7 同一正式输入的模型工件复现

2026-08-22 使用第 15 轮逐字相同的正式 `GAME_REPLY` messages、相同 ChatML、相同采样参数和固定 seed，直接对照模型工件。测试输入 SHA256 为：

```text
0524a20197d71c3709d4385d97b580438d7ac092e3052f825fd981f155bce267
```

严格通过标准仍为：否定星期五旧时段，并恢复星期六上午十点。

| 工件 | 测试计划 | 严格通过 | 关键现象 |
|---|---:|---:|---|
| 裸基座 Q4_K_M | 贪心 + 5 个实际温度 seed | 4/6 | 2 个 seed 恢复星期五错误时间 |
| 最终 LoRA Q4_K_M | 贪心 + 5 个实际温度 seed | 0/6 | 贪心也只答“嗯。你记得很清楚”，其余为错误确认、矛盾或含糊 |
| 裸基座 F16 | 贪心 + 3 个实际温度 seed | 2/4 | 贪心正确；采样时仍有含糊和矛盾 |
| 基座 + Adapter F16 | 贪心 + 3 个实际温度 seed | 1/4 | 贪心只答“嗯。你记得就行”；仅一个 seed 明确纠正 |

代表性同 seed 结果：

```text
裸基座 F16 greedy：
嗯，按照新的安排，你是星期六上午十点去看牙医。

基座 + Adapter F16 greedy：
嗯。你记得就行。

裸基座 Q4 seed=101：
嗯，你应该在星期五下午过去确认一下细节。这样不会出错。

最终 LoRA Q4 seed=404：
嗯，你记得没错。我记得今天是周五，下午的事不会变。
```

这个对照说明：

1. 裸基座也不是确定性逻辑程序，采样时会犯同类错误；
2. 当前 LoRA 在同一输入下明显更容易选择“嗯 + 含糊承接/安抚”路径；
3. LoRA F16 已经复现，错误不是到 Q4 才出现；
4. 非零温度会改变具体错误形式，但 LoRA 贪心也失败，因此采样不是主要根因。

### 3.8 既有 Adapter 单变量因果证据

2026-08-21 的 Adapter 因果隔离测试共享同一 F16 基座层，只让实验组额外加载当前 LoRA Adapter；6 个上下文、12 个 seed，每个工件 72 次，所有成对调用收到字节完全相同的 Prompt。

| 工件 | 通过/总数 | 通过率 |
|---|---:|---:|
| 裸基座 F16 | 54/72 | 75.0% |
| 同一基座 + 当前 Adapter F16 | 31/72 | 43.1% |

Adapter 使通过率下降 `31.9` 个百分点。成对结果中仅裸基座通过 25 次、仅 Adapter 通过 2 次，成对符号检验双侧 `p=5.65e-06`。

这证明当前 Adapter 是该固定承接测试集上的因果退化因素，但不表示裸基座永不失败，也不表示 Adapter 是完整程序所有缺陷的唯一来源。

既有量化消融中 LoRA F16 为 `28/72`，LoRA Q4_K_M 为 `30/72`，两者都大量失败且差异很小。因此 Q4 不是当前承接退化的主要原因。

### 3.9 训练数据分布证据

对实际训练文件 `baiweixi_ready.jsonl` 的 1987 个会话、4101 条角色回复统计如下：

| 训练数据特征 | 数量 | 占比/结论 |
|---|---:|---|
| 角色回复总数 | 4101 | 100% |
| 以“嗯”起句的角色回复 | 1072 | 26.14% |
| 只有 2 次玩家发言的会话 | 1872/1987 | 94.2% |
| 3 次玩家发言的会话 | 103/1987 | 5.2% |
| 4 次及以上玩家发言的会话 | 12/1987 | 0.6% |
| 使用正式 `[当前世界]` renderer 的会话 | 0 | 生产输入同构覆盖为零 |
| 含“改成/作废/取消/移到”等变化词的会话 | 3 | 极少 |
| 状态改变后再次用旧值确认的会话 | 0 | 本问题结构没有训练覆盖 |
| 可检出的“对吗/是不是/对吧”确认问句 | 5 | 3 条回复以“嗯”起句，0 条以明确否定起句 |

该统计不是在要求训练集覆盖所有未来话题。它证明当前数据没有充分训练一种可泛化的关系：

```text
玩家当前命题与最新权威事实冲突
  -> 必须拒绝旧命题
  -> 必须恢复当前有效事实
```

相反，数据以很高频率奖励了“嗯”开头的简短角色化承接。SFT 会直接提高这种输出模式的概率；一旦自回归生成先选择“嗯”，后续更容易沿确认、安抚和关系表达继续，而不是回到权威世界完成纠正。

## 4. 为什么训练后的 LoRA 会出现这种错误

### 4.1 LoRA 不会把模型变成确定性逻辑程序

LoRA 改变的是下一个 token 的概率分布。即使输入中存在正确事实，7B 模型仍可能优先生成训练中常见、语气自然但语义错误的承接模式，例如：

```text
“……对吗？” -> “嗯……” -> 安抚或关系表达
```

本轮的“嗯 + 别想太多 + 按时去”很像一种高概率的温和陪伴模板。它在风格上像角色，在任务语义上却没有完成纠错。

### 4.2 当前训练配置存在指令跟随退化风险，但不是定罪证据

当前训练配置为：

- `lora_target: all`；
- rank 32；
- alpha 64；
- learning rate `5e-5`；
- 2 epoch；
- `best_model_checkpoint = null`；
- `should_evaluate = false`。

结合单变量 Adapter 测试和训练数据统计，当前可以确认 Adapter 显著放大了固定测试集上的承接失败。高风险训练配置不是单独的数学因果证明，但它与缺少验证集、长轨迹和状态纠正样本共同解释了为什么角色语气增强时，基座原有的精确指令跟随发生退化。

更精确的表述是：当前 Adapter 把输出概率从“读取事实并纠正”推向“简短、克制、先用嗯承接，再给安抚或关系表达”。合并和推理链仍需保留审计，但 Q4 量化已经不是主要嫌疑。

### 4.3 采样会让低概率错误偶发出现

完整程序 `GAME_REPLY` 当前使用温度 `0.65`、`top_p = 0.9`。非零温度意味着同一输入可能生成不同回复。降低温度可能减少偶发错误，但不能保证修复，因为高概率首选本身也可能就是错误的“嗯”。

### 4.4 系统没有最后一道正文语义门

模型犯错本身无法完全消除。产品级根因不只是“7B 生成错了”，还包括“错误生成后没有独立机制阻止它成为玩家可见回复”。

## 5. 根因分层

| 层级 | 结论 | 状态 |
|---|---|---|
| 直接故障 | `GAME_REPLY` 对错误前提输出肯定极性，并省略正确时间 | 已确认 |
| 输入缺失 | 权威世界或正确历史没有进入模型 | 已排除 |
| 记忆污染 | 旧长期记忆覆盖当前预约 | 已排除 |
| M2 失效 | M2 只处理心智变化，没有形成当前事实纠错义务 | 已确认 |
| 审查缺口 | 连续性审查发生在回复生成前，不审最终正文 | 已确认 |
| 校验缺口 | 回复断言来自快照元数据，不代表正文真的一致 | 已确认 |
| LoRA 净影响 | 同一 F16 基座加载 Adapter 后通过率下降 31.9 个百分点 | 已确认 |
| 合并/量化影响 | F16 Adapter 已复现；LoRA F16 与 Q4 既有结果接近 | Q4 非主要根因 |
| 采样影响 | 裸基座和 LoRA 均随 seed 波动，但 LoRA 贪心也失败 | 次要放大因素 |

## 6. 修复方向

### 6.1 立即纳入冻结失败集

把本轮完整正式输入、两侧输出、工件哈希、采样参数和人工结论登记为 `REPLY-CORRECTION-001`。后续任何训练、合并、量化、Prompt 或运行时变更都必须回归该样本。

回归不能只检查关键词。最低语义标准是：

1. 必须否定星期五下午；
2. 必须给出星期六上午十点；
3. 不能只说“明天”“按时去”或其他无法恢复准确状态的相对表达；
4. 不能在前半句确认星期五、后半句再含糊转向。

### 6.2 保留并扩大相同正式输入的工件消融

冻结本轮真实 `GAME_REPLY` messages，依次测试：

1. 原生基座 BF16；
2. 原生基座目标量化；
3. 基座 + 未合并 LoRA BF16；
4. LoRA 合并后 BF16；
5. 当前最终 Q4_K_M；
6. 不同 Adapter scale；
7. 固定 seed 的温度 `0/0.3/0.65`。

现有 F16 动态 Adapter 测试已经确认当前 Adapter 的负向净效应，F16/Q4 消融也已排除 Q4 是唯一或主要根因。后续扩大真实玩家失败集，是为了估计退化适用范围并选择新训练配置，不再把“是否存在 Adapter 退化”列为未知。

### 6.3 增加定向训练，但不宣称覆盖所有情况

训练集中增加跨话题的同构困难样本：

- 旧预约时间被新时间替代；
- 旧物品位置失效；
- 订单状态被纠正；
- 玩家以错误前提反问“对吗”；
- 中间插入无关话题后再次用旧状态确认；
- 正例必须明确否定旧值并给出当前值；
- 困难负例使用相同角色语气，但错误确认旧值或只给模糊相对表达。

这些样本训练的是“当前事实与玩家命题冲突时要纠正”的关系，不是建立牙医、钥匙、外卖等话题规则表。它只能降低错误概率，不能保证覆盖未来所有表达。

### 6.4 在最终回复之后增加独立正文检测

当前最关键的运行时缺口是没有审最终回复正文。应按《对话回应开放域承接性生成与验证方案_v3》执行：

```text
冻结 GameReplyRequest
  -> 7B 生成候选
  -> 独立检测候选是否明显错位或确认了已失效事实
  -> 失败时有界重生成
  -> 候选耗尽时不提交错误角色对白
```

不能让同一个 7B 用隐藏推导或自我解释证明自己正确，也不能把现有 M2 连续性审查冒充回复审查。

### 6.5 对程序拥有的结构化事实增加确定性保护

牙医预约属于游戏程序拥有的状态，后续不应只存成自由文本 `scene`。建议至少结构化为：

```text
appointment.status = active
appointment.active_time = 星期六上午十点
appointment.invalidated_times = [星期五下午三点]
```

当玩家确认的值与程序状态冲突时，可建立通用的状态一致性合同：回复必须拒绝旧值并包含当前值。该机制针对“程序拥有的结构化事实”，不是覆盖开放域自然语言的无限话题规则；开放域残余问题仍由独立语义检测处理。

## 7. 验收标准

本问题只有同时满足以下条件才能关闭：

1. 同一冻结输入在最终发布工件上通过人工复核；
2. 至少覆盖“对吗、是不是、我还是、没改吧”等等价错误前提表达；
3. 覆盖中间插入无关话题后的再次确认；
4. 多 seed 报告生成失败率，而不是只展示一次成功；
5. 独立正文检测能够拦截本轮原始错误回复；
6. 修复后不把正常含蓄回答全部改成客服式机械纠正；
7. 重新运行 60 轮产品测试并完成人工复核；
8. 发布记录包含模型、Adapter、合并、量化、Prompt、检测器和阈值版本。

## 9. 当前决策

本问题作为 V3 的首个真实冻结失败样本保留。当前不修改冻结模型、Prompt 或运行时，不用针对“星期五/星期六”增加临时关键词规则，也不把一次裸基座成功解释为 LoRA 因果已经完全确定。

当前主要生成侧根因定为：训练数据与正式长会话/权威状态输入分布不匹配，错误前提纠正样本近乎缺失，同时“嗯 + 简短角色化承接”被高频强化；当前高强度 Adapter 配置把该分布偏好注入模型并显著削弱承接能力。裸基座自身能力和采样仍贡献剩余错误，但不是 LoRA 退化的反证。

下一步主要投入应是重新设计并消融 Adapter 训练数据与训练强度，而不是优先更换 Q4 量化等级。同时仍必须施工最终回复正文检测与候选选择，因为即使重训后，裸基座和新 Adapter 都不可能保证开放域零错误。最终回复缺少正文级提交门是独立存在、必须修复的产品缺口。
