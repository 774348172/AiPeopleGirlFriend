# 数据生成器设计文档

> 状态：现行（秦未晞已投产）  
> 版本：v1.0  
> 日期：2026-08-04  
> 对应需求：`需求文档/项目框架需求.md`  
> 角色依据：`人物设定/秦/角色设定定稿.md` + `人物设定/秦/`  
> 代码实现：`data_gen/common.py`（框架）、`gen_qwx.py`（秦未晞实例）、`repair_qwx.py`（修复）

本文档规定人格训练数据如何生成：从角色正典到 Prompt 工厂、情景抽样、生成器、容错修复、质量门禁的完整机制。换新角色（苏念/夏晚晴）时按本文档流程复用。

---

## 1. 设计目标

- 用强模型（glm-5.2，经 aihub.lmdgame.com 中继）为虚构人格"演出"海量对话，训练出**权重里的人格**（非插件/非检索）。
- 每条样本必须是**独特的、符合角色正典的、无助手腔的、像真人说话不规律**的对话。
- 产出直接进入命门检查（consistency_check）→ sharegpt → 训练（LLaMA-Factory / MLX）。

## 2. 总体架构

```text
┌─ 第1层 角色正典 ──────────────────────────────────────┐
│ persona/<name>/bible.yaml     性格圣经（大五/价值观/口吻）│
│ persona/<name>/canon.json     事实表（可校验硬事实）      │
│ persona/<name>/timeline.yaml  人生编年史（戏剧张力来源）   │
└──────────────────────────────┬──────────────────────────┘
                               │ 渲染成文字块
┌─ 第2层 Prompt 工厂 ──────────▼─────────────────────────┐
│ render_identity_block / render_canon_block /           │
│ render_voice_block → 拼进 4 类模板（prompts/*.txt）      │
│ casual(闲聊) romance(暧昧) identity(身份锚) emotion(标签) │
└──────────────────────────────┬──────────────────────────┘
                               │ 每次调用注入随机情景
┌─ 第3层 情景抽样 ─────────────▼─────────────────────────┐
│ random.choice(话题池 × 场景池 × 情绪池)                 │
│ → 每条样本 = 独特组合（无重复，防单一数据淹没）           │
└──────────────────────────────┬──────────────────────────┘
                               │
┌─ 第4层 生成器 ───────────────▼─────────────────────────┐
│ gen_casual/gen_romance/gen_identity/gen_emotion        │
│ → glm-5.2 以第一人称即兴演出 4-8 轮                     │
│ → _parse_turns 容错解析 → JSONL（含 raw 供审计）         │
└──────────────────────────────┬──────────────────────────┘
                               ▼
┌─ 质量门禁 ─────────────────────────────────────────────┐
│ consistency_check（助手腔/canon矛盾/口吻匹配）           │
│ → to_sharegpt → data/sft/qwx_persona.jsonl             │
└─────────────────────────────────────────────────────────┘
```

## 3. 第 1 层：角色正典

三个文件分工明确，**正典是 prompt 约束与检查器的共同依据**：

| 文件 | 内容 | 用途 |
|---|---|---|
| `bible.yaml` | 姓名/年龄/职业/家庭/关系网/大五人格/价值观/口吻规范（语气词清单、句长、口头禅、禁区） | 生成 prompt 的"性格与口吻"来源 |
| `canon.json` | 扁平可校验事实表（`age:23`、`math_skill:数学白痴`、`other_world_duration:整整一年`…） | 硬事实约束 + 一致性检查比对 |
| `timeline.yaml` | 有序人生事件（童年→今），每条 {date, summary, valence, people, importance} | 生成器的"记忆素材"与戏剧张力来源 |

设计要点：
- **正典必须三者一致**——检查器用 canon.json 比对样本断言，bible/timeline 不一致会在样本里表现为事实矛盾。
- **戏剧张力放在 timeline**——秦未晞的核心张力（"18 岁异世界一年、只有她记得"）写在 timeline 与 canon 的 other_world 字段里，prompt 通过场景（暧昧-异世界暗示）让它自然流露，而不是明说。

## 4. 第 2 层：Prompt 工厂

### 4.1 三段文字块渲染（`data_gen/common.py`）

```python
render_identity_block(persona)  # → "姓名：秦未晞（女）……自由插画师。关系网：青梅竹马大叔（合租室友/暧昧对象）"
render_canon_block(canon)       # → "【必须严格遵守的事实正典（不得矛盾）】\n- age：23\n- ..."
render_voice_block(persona)     # → "【口吻规范】语域：……口头禅：哼、喂、啧……严禁出现助手腔"
```

- identity 块：身份事实（姓名/教育/家人/关系网）——回答"你是谁"
- canon 块：硬事实清单——**禁止模型编造矛盾事实**
- voice 块：口吻规范——句式、语气词、禁区，**防助手腔**

### 4.2 四类模板（`data_gen/prompts/*.txt`）

每个模板的公共骨架：

```text
你不是助手。你就是下面这个人本身。
{{IDENTITY_BLOCK}}
{{CANON_BLOCK}}
{{VOICE_BLOCK}}
【场景】{{SCENE}}
【任务】……（类型特有）
输出 JSON 数组：[{"role":"other","text":"..."},{"role":"person","text":"..."},...]
只输出 JSON，不要解释/思考/代码块/前后缀。
```

| 模板 | 任务 | 生成量（秦未晞） | 角色字段 |
|---|---|---|---|
| `qwx_casual.txt` | 日常闲聊（4-8 轮，可跑题/反问/怼/突然变轻） | 100 | other=大叔, person=秦未晞 |
| `qwx_romance.txt` | 12 种暧昧场景（生病/吃醋/深夜真心话/异世界暗示…） | 80 | 同上 |
| `qwx_identity.txt` | 20 个身份问题 Q&A | 30 | content={question, answer} |
| `qwx_emotion.txt` | 同闲聊 + **每条回复前加标签** | 100 | 同上 + 标签 |

### 4.3 真人感原则（防"AI 均匀感"）——`qwx_emotion.txt` 核心

标签用于驱动前端动作/特效/语音系统，但必须**克制不规律**，否则训练出的模型会每句都带标签、像机器人：

```text
- 70% 只加【emotion:xxx】（够了）
- 20% 加【emotion+action】（情绪强烈时）
- 5% 加【effect】（特殊时刻：惊讶/暧昧/暴怒）
- 5% 加【scene】或【voice】（场景/语调变化）
- 偶尔只有【action:look_away】没有正文（沉默但动作）
- 偶尔纯文字无标签（就是说话）
```

示例（prompt 内给模型的 few-shot）：

```text
【emotion:playful】喂！你是不是又偷吃我零食了？别以为我不知道！
【emotion:angry】【action:hand_on_hip】【effect:puff_cheeks】五分钟？！你知道五分钟能发生多少事吗？
【emotion:shy】【action:turn_away】【effect:heart】……突然说什么呢，又犯傻了吧。
【action:look_away】……没有。
```

## 5. 第 3 层：情景抽样

三个随机池（`gen_qwx.py` 常量）保证样本多样性：

```python
CASUAL_TOPICS   = [22 个日常话题]     # 今天吃什么/你偷吃我零食了吧/你昨天说梦话了…
ROMANCE_SCENES  = [12 种暧昧戏]       # (戏名, 场景描述) 如 ("暧昧-异世界暗示", "你无意中做了和异世界里一样的动作")
EMOTION_TOPICS  = [15 个情绪触发点]   # (触发, 情绪) 如 ("你提到别的女生", "吃醋")
IDENTITY_QUESTIONS = [20 个身份问题]  # 你叫什么/你和我什么关系/你为什么叫我大叔…
SCENES          = [10 个空间场景]     # 深夜阳台/雨天困在家/她画了一整天你端水过去…
```

```python
topic = random.choice(CASUAL_TOPICS)
scene = random.choice(SCENES)
```

**为什么随机**：上一版（于谦数据）踩过"单一数据淹没"的坑——同样的话反复出现会让模型回答固定。随机组合让每条样本唯一，同时把关系型张力（如"异世界暗示"）**只**放进 romance 类，防止在闲聊里过度泄漏。

## 6. 第 4 层：生成器

### 6.1 一次调用的完整流程

```python
# gen_qwx.py 内（以 gen_casual 为例）
prompt = render_prompt("qwx_casual",
    IDENTITY_BLOCK=ib, CANON_BLOCK=cb, VOICE_BLOCK=vb,
    SCENE=scene, TOPIC=topic)                        # 1. 拼 prompt
raw = client.chat([{"role":"system","content":prompt},
                   {"role":"user","content":"开始对话。"}])  # 2. 调用 glm-5.2
turns = _parse_turns(raw)                            # 3. 容错解析
out.append({"id": f"casual_{i}", "type":"chat", "date":"", "node_index":-1,
            "node_summary": f"casual:{topic}", "people":["大叔"],
            "content": turns, "model": client.model, "raw": raw})  # 4. 落盘(含 raw 审计)
```

### 6.2 产出 JSONL 结构（`data/life_corpus/qwx_all.jsonl`）

```json
{"id":"casual_3", "type":"chat", "node_summary":"casual:你觉得这周过得快不快",
 "content":[{"role":"other","text":"..."},{"role":"person","text":"..."}],
 "model":"tencent-glm-5.2", "raw":"<模型原始输出，供故障审计>"}
```

- `node_summary` 记录生成参数（topic/戏名）——**repair 脚本靠它重放 prompt**
- `raw` 保留原始输出——**故障排查唯一依据**（上次 51% 单轮问题的根因就是从 raw 定位的）

### 6.3 容错解析 `_parse_turns`

glm-5.2 是 reasoning 模型，输出不稳定。解析器多层兜底：

```python
1. parse_json_lenient(raw)          # 容忍前后缀/多余文本的 JSON 提取
2. dict → 尝试取 turns/conversation/messages/dialogue/data 数组
3. 元素兼容 str 与 {role,text} 两种形态
4. 全部失败 → 返回 [{"text": "[解析失败] 原因"}]，绝不抛异常中断批量
```

## 7. 修复机制（repair）

### 7.1 问题背景

首轮生成 310 条中 **143 条（51%）是 1 轮样本**。根因（从 raw 定位）：

> glm-5.2 先输出思考（reasoning_content）再输出正文（content），思考占满 `max_tokens=2048` 后正文 JSON 被截断 → 解析失败 → 只留 1 轮。

### 7.2 修复方案（`repair_qwx.py` / `repair_qwx2.py`）

| 手段 | 效果 |
|---|---|
| `max_tokens` 2048 → 4096 → 6144 | 正文有空间输出完 |
| user 消息追加「直接输出 JSON，不要思考」硬性要求 | 抑制思考 |
| 从 `raw` 正则恢复被截断的完整轮次（`TURN_RE`） | 零成本救回 7 条 |
| 只重生成失败样本（靠 `node_summary` 重放原 prompt） | 不浪费已成功的 167 条 |

最终 1 轮率 51% → **0%**，280 条 chat 全部多轮（8-16 轮为主）。

### 7.3 教训（写进未来流程）

- reasoning 模型做数据生成，**必须给足 max_tokens（≥4096）**，且"只输出 JSON"指令放 prompt 开头而非结尾。
- 失败样本**保留 raw**，修复一律靠重放参数（node_summary），不要整体重跑。

## 9. 换角色复用流程（苏念/夏晚晴）

1. **写正典**：`persona/<name>/bible.yaml` + `canon.json` + `timeline.yaml`（三段式）
2. **改常量池**：话题池/场景池/情绪池换成该角色的生活与关系（如苏念 → 实验室/自习室；晚晴 → 饭馆/打闹场景）
3. **改 prompt 口吻块**：voice 块的语气词、句长、称呼（苏念"嗯/呢/呀"、晚晴"喂/哼/哈哈"）
4. **改生成器调用**：复制 gen_qwx.py 改角色加载路径与输出文件名
5. **跑门禁**：一致性命门过了再扩量

**可复用不动**：common.py（ModelClient/渲染/解析）、四类模板骨架、repair 机制、检查器、转换器。
