### 改动

| 文件 | 改动 |
|---|---|

| `adapters/models/pool.py` | `_classify_api_error`：按 status_code 分类（401/402/403/400/404/422 → 不可重试；429/5xx/连接/超时 → 可重试），不依赖 openai 包类型；客户端初始化失败（缺包/配置）→ 不可重试；空内容 → 可重试 |

| `adapters/modes/reply.py` | `_parse_object` 容错：直接解析失败后尝试提取首个 `{` 到末个 `}` 的平衡子串（reasoning 模型夹带说明文字）；仍失败才报 parse_error |
| `prompts/reply_merge.txt` | 输出指令加"或空内容；如果思考过程很长，直接在最后输出完整的 JSON 对象" |

### 单测（`tests/core/test_error_retry_classification.py`，7 个）

- fail-fast：不可重试错误 1 次调用即抛（原逻辑 3 次）
- 可重试错误重试至成功 / 重试耗尽后抛
- `_classify_api_error`：402/401 → False；429/500 → True；按类型名（无 openai 包）也能分类
- `_parse_object`：夹带说明文字恢复解析；空/纯垃圾仍拒绝

## A-1：标签前缀实测（并入 T4）

**问题**：v1 训练数据 33.8% 回复带 `【emotion:xx】【voice:xx】` 标签并被烘焙进训练文本，当前 GGUF 是否还在输出？

**方法**：本地 llama-server（与 chat02 执行契约同配置）+ 运行时锚 + 10 条盲评题，temperature 0.75。工具 `tools/check_label_prefix.py`（可复跑）。

**结论：输出，30%（3/10）**：

```
【emotion:playful】哼，谁让你穿拖鞋出门的，回来不还，活该。
【emotion:jealous】【action:hand_on_hip】啧，你这镜头怎么又糊的？……
【emotion:playful】哼，谁让你自己看说明书的。……
```

v1 数据烘焙的标签行为在推理时仍在——A-1 确认此问题真实存在（此前仅从数据统计推断）。

**处置（已实现）**：
1. 锚输出协议改为"不要使用助手腔、Markdown、列表、emoji **或【】标签前缀**"（`renderers.py` 常量）；
2. 全链路同步：`runtime/_prompt.py` 快照（4791 bytes，sha `1ba13513...`）→ chat02 pins（execution_profile + alignment）→ 2500 条重锚 `qin_v4_2500_anchor_v2.jsonl`（2500/2500 PASS）；
3. 训练侧：新生成数据用新锚 + 门禁（rerender 工具 FAIL 词）保证标签不进训练。

**遗留**：新模型训练后需复测一次（旧 GGUF 的 30% 是 v1 数据造成，新数据 + 新锚应归零；若仍有，说明需要负例样本或更强的输出约束）。
