## 2. V1 生成管线机制（为什么 v1 长这样）

`gen_qwx.py`（单脚本，非 v4 的 package/engine 架构）：
- 硬编码话题池（`CASUAL_TOPICS` 22 条、`ROMANCE_SCENES` 若干），四类生成：闲聊/恋爱/身份/情绪；
- prompt = identity_block + canon_block + **voice_block** + 话题，一次调用出多轮；
- `render_voice_block`（`data_gen/common.py:215`）：把 bible voice 段的 `tics`（10 个）与 `catchphrases` 每轮直灌 prompt——**与 v4 `qin_style_resolver` 完全同源的机制**；
- 要求输出表现标签前缀（`【emotion:xx】【voice:xx】【action:xx】`），33.8% 的 v1 回复把标签**烘焙进训练文本**；
- 无证据状态、无质量门、无人工复核记录；`repair_qwx.py` 是事后修格式/编码的补丁脚本（对应 log 可见多次修复）。

**结论：v1 与 v4 不是两套不同的生成哲学，而是同一机制的两代实现。口癖密度（v1 20%→v4 36%）随 bible voice 段与生成量同步放大。降口癖只改数据清洗无效，必须改 voice 段渲染策略——这条对两代生成器同时成立。**

## 4. 关键发现

### 4-1 称呼口径全面冲突 → 295 条不可直接复用
100% 使用"大叔"（281 条回复）、0 个"B哥/浩然"；且 v1 锚口径为"23 岁/玩家 25 岁"（诊断 §4.1），与当前正典（22 岁/B哥/浩然/玩家 24 岁）冲突。**旧数据直接混训会重演称呼与年龄混淆**——m3_v2 的 `--legacy` 开关默认关闭正是这个原因。

### 4-2 无证据共同经历是 v1 的结构性缺陷，与 v4 同源
46.78% 会话含"上次/以前/你总是/还记得/每次/又在"类表述，典型样本：
- "……你还记得啊。哼，谁稀罕你记着。"
- "哼，我才不信呢……诶等下，你是不是又把暖气阀门调小了？上次就是你干的好事！"

这些样本在训练时**没有证据边界监督**（v1 管线无 evidence 概念），模型学到的就是"亲密 = 随时引用共同历史"。这与 v4 P0-2/P0-5 是同一机制，**不是 v1 独有的错误，而是生成式管线未接检查的必然结果**。

### 4-3 表现标签前缀烘焙进训练文本（新发现，v4 已消除但需确认影响）
33.8% 的 v1 回复以 `【emotion:sad】【voice:whisper】` 等标签开头且**作为训练文本进入 loss**。运行时 prompt 声称"正文可带白名单表现标签前缀"，但：
- v1 训练教了模型输出这些标签；
- v4 数据完全没有标签；
- **当前 GGUF（v1 训练）在推理时是否输出标签前缀，需要一次实测确认**。若输出，是训练/运行时合同不一致的又一处实例；若关闭，说明标签被微调掉了。

### 4-4 v1 没有秘密泄漏、属性朗读、关系越界问题
0 条秘密词、属性朗读极低、越界措辞仅 1 处。**这些是 v4 独有的新问题**（v4 池中 romance 场景 + style 直灌 + 无门禁共同造成）。审计口径下 v1 的失败集中在：无证据记忆、先怼模板、严肃稀疏——与盲评失败标签（fact_error/fabricated_reality/serious_support）一一对应。

### 4-5 严肃覆盖 5.08% 且无质量保证
15 个严肃候选会话，human 台词 22 条。诊断 P0-1 的"严肃时冒犯玩家"（"你也容易被别人牵着鼻子走"等）即来自这些稀疏且无行为约束的样本。

## 5. 可复用性判断

| 用途 | 判断 | 理由 |
|---|---|---|
| 直接混入新训练 | **禁止** | 称呼/年龄口径冲突（§4-1）+ 无证据记忆密度（§4-2） |
| 改写称呼后复用 | **不推荐** | 改写只能修表面（大叔→B哥），修不了无证据记忆与先怼模板；成本≈重生成 |
| 作为审计对照 | **推荐** | 295 条是"无检查管线"的完整样本，可用于对比 v4 门禁有效性（同一批话题池） |
| 严肃样本挑选复用 | **可少量** | 15 个严肃候选经人工复核后，改写口径、补充证据字段，可作为行为矩阵"严肃支持"类的种子（预计可留 5-10 条） |
| 标签前缀行为确认 | **必须先做** | §4-3 的实测（当前 GGUF 是否输出 `【emotion:xx】`）影响运行时合同是否需要清理 |

## 6. 对 V4 施工计划的影响（D2 / D5 决策输入）

1. **D5 确认**：老数据审计已完成（本文档）。结论：老数据不可复用，不承担"训练来源"角色；只做三件事——①保留为审计对照集；②严肃样本挑 5-10 条人工复核后作行为矩阵种子；③先实测标签前缀输出行为（§4-3）。
2. **D2 确认（M3 路线）**：冻结 `training_package_m3_v2` 脚本链（01/02/03/04 + MLX）为唯一训练路线，超参锁定（rank 16、lr 1e-5、num-layers 24、batch 1、seed 42、max-seq-len 2048）。数据量变更时只换算 iters：**新批次 N 条 → 1.5 epoch ≈ 1.5×N iters**（与现行 3000 iters/2296 条 ≈ 1.3 epoch 保持同一量级，避免"一次变两个变量"）。M3 Max 实测 600 iters ≈ 1-1.5h（README），3000 iters ≈ 5-7.5h 可过夜跑；M3 基础款约 3 倍耗时。h200 包归档为备选，本轮不使用。
3. **补 M3 路线的 provenance 缺口**（诊断 §7）：`02_train.sh` 增加 manifest 输出（base revision、adapter 哈希、完整命令、每 100 iters loss 采样），训练后随包交付——上一轮"训练机无 checkpoint 日志"的问题不允许重演。
4. **v1 审计输出作为 T12（行为矩阵）种子输入**：15 个严肃候选 + 挑选后的 5-10 条改写样本进入"严肃支持"类，其余 v1 内容不进新数据。
